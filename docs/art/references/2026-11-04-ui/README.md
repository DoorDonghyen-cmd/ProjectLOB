# 결과·상점·보상·관문 UI 레퍼런스 검토

2026-11-04 수집. [이미지 비교 보드](index.html) · [원본 출처/크기/해시](manifest.json).

5개 게임의 실제 화면16장, 4영역 각4장. 선택한16장은 모두 시각적으로 확인했다. 기존 LoB 캡처도 나란히 볼 수 있게 넣었다. 이번 자료는 **레퍼런스 조사와 디렉터 제안**이며 새 UI 시안·배치·팔레트 확정이나 본편 적용 완료가 아니다.

## 먼저 가져올 방향

| 대상 | 중심으로 볼 자료 | LoB에서 제안하는 방향 |
|---|---|---|
| 결과 | R02 Hades + R01 Balatro, 패배 R03/R04 | 실제 대표 코어/주력 탄과 승패·도달 구역을 먼저 표시하고 핵심 기록·상세 통계·다시 시작 행동의 무게를 구분. |
| 상점 | S04 Dead Cells의 상점 장면 + S01 Slay the Spire의 진열/가격 | 기존 상인/방/진열 공간에 실제 판매 물건을 연결하고 선택 상품의 효과·가격·구매 후 장착/보관/교체를 모음. |
| 보상 | W01 Hades의 효과 비교 + W02 Slay the Spire의 후보 선택 | 보상 자체를 먼저 보여 주고 효과/대가를 같은 위치에 표시. 실제 대상 지정이 필요한 곳만 W03의 선택/적용 구분 참고. |
| 관문 | G03 Moonlighter의 기능/장소 + G02 Slay the Spire의 전후 비교 | 관문 개조→실제 변화 확인→유료 재정비→출발의 현재 단계를 선명하게 구성. |

각 화면에 같은 작업대·황동색·카드 틀을 복제하지 않는다. 정비소처럼 없어도 되는 소품을 추가하지 않고 실제 물건과 선택을 장면에 연결한다. 위 조합은 다음 통합 시안을 만들기 위한 제안이다.

## 관찰과 검증 범위

- 원본 캡처의 화면 구성·정보 위치·선택/확정/취소의 표시를 관찰했다. 정지 화면에서 움직임이나 클릭 반응 시간을 추정하지 않는다.
- G01/G02는 휴식/강화와 전후 확인이라는 서로 다른 단계의 캡처를 연결해 볼 수 있다. 원본 게임을 직접 실행해 그 사이 입력/애니메이션을 검증한 것은 아니다.
- 구버전 UI가 포함된다. 특히 G04는2018년 가이드다. 현재 게임의 최신 규칙·밸런스·모바일 적합성을 이 자료로 보증하지 않는다.
- 도트/활자/재질 참고와 정보/장면 구성 참고를 구분했다. 원본의 작은 글씨·보라/녹색 발광·CRT 효과·넓은 빈 패널을 그대로 가져오지 않는다.
- W04는 수치 비교의 기능 참고이며 외형은 대조 사례다. 우리 게임에서 지적된 큰 동일 상자/낮은 정보 밀도 문제가 있어 외형의 주 레퍼런스로 쓰지 않는다.
- 이미지 확대/출처 링크/영역 분류는 로컬 보드 기능이다. 게임 UI를 변경하거나 원본 게임의 조작을 재현한 것은 아니다.

| 관문 | 기존 관문 배경·개조 아이콘·실제 변경값 | 여러 후보·변경 전후·한도/불가·무료/유료 구분·출발. |

레퍼런스 이미지는 연구용이며 게임 리소스로 임포트하지 않는다. 새 원화가 필요한지는 실제 LoB 통합 시안에서 판단한다. 게임의 계산/저장/경제를 참고 게임의 규칙으로 바꾸지 않는다.

## 선별 이력

- Balatro 결과의 최초 리뷰 이미지 링크는404여서 실제 공개 플레이어 캡처로 교체했다.
- 공식 Balatro `Arcana Packs.png`는 팩 그림 아틀라스로 확인돼 UI 사례에서 제외했다. 실제 개봉/선택 화면 W03으로 교체했다.
- Inscryption 후보는 카드3개 보상 선택이 아니라 전투 보드였다. W04를 실제 Dead Cells 성장 선택 화면으로 교체했다. 제외 자료와 이유는 `manifest.json`의 `rejected_sources` 및 `excluded/`에 구분해 보관했다.
- Game UI Database는 robots 제한이 있어 재시도하지 않고 공개 캡처 아카이브·리뷰·플레이어 자료를 사용했다.
- 원본 파일은 보존했고 자르기/색 보정 없이 축소 접촉표만 만들었다. 이 폴더의 HTML 외에 인터넷을 다시 연결하지 않아도 수집된 화면을 볼 수 있다. 출처 사이트 열기는 별도다.

## 후속 순서

다음은 결과창 통합 시안이다. R02의 대표 빌드와 R01의 결과 선언/다음 행동, R03/R04의 패배 맥락을 우리 실제 장면·데이터로 조합한다. 정비소에서 제거한 중복 탄환 소품 표시는 복원하지 않는다. 그 뒤 시안을 검토하고 기존 결과 행동/저장·PC와 S26비율을 연결한다. 나머지는 상점→보상→관문 순으로 이어간다.


## 자료 검수/열기

- [index.html](index.html)을 직접 열면 네 영역과16개 원본 캡처/메모를 볼 수 있다. 외부 라이브러리·서버·로그인이 필요하지 않다. 스크립트도 문서 안에 포함했다.
- 원본 이미지16개 시각 확인·해시 일치, 보드의 로컬 파일 연결과 JavaScript 문법 검사 통과. [검수 결과](validation.json).
- 브라우저에서 보드를 열어 보려 했으나 Work 설정이 `Local browser use is disabled`로 반환했다. 실제 브라우저 렌더/분류 클릭/확대 조작 검증은 미완료다. 이를 통과로 기록하지 않는다. 선택적 로컬 HTTP 서버도 지속 실행을 확인하지 못했으므로 최종 전달은 HTML 파일과 이미지/문서다.
- 게임/씬/저장 변경이 없는 조사 단계여서 Godot 기능/전투 회귀를 다시 실행하지 않았다.
