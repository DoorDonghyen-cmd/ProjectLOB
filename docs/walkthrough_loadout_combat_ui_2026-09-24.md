# 덱·장비 통합과 전투 작업대 UI 워크스루

## 결과

무기고에서 정한 장면 기반 UI를 덱·장비와 전투까지 확장했다. 파츠는 어느 화면에서 보더라도 같은 카드와 5칸 장착 규칙을 사용하며, 전투는 `탄 선택 → 순서 확인 → 발사`가 전장 바로 아래에서 이어진다. 전투 계산, 저장 형식, 경제 규칙은 바꾸지 않았다.

## 덱·장비 흐름

1. 상단에서 덱 장수, 탄창 용량, 재장전 비용, 압축 코어를 확인한다.
2. 현재 장착한 5개 파츠와 코어 제한을 한 줄에서 비교한다.
3. 보관함 카드의 도형, 이득, 대가를 보고 같은 자리에서 장착하거나 해제한다.
4. 아래 전술 덱에서 탄환 종류별 보유 수와 덱 비중을 확인한다.
5. 전투 중에는 장착 행동이 잠기고 `교전 종료 후 교체`를 표시한다.

## 전투 흐름

1. 전장에서 적 거리, 방어 규칙, 증원을 읽는다.
2. 단계 표시에서 현재 행동이 탄 선택, 순서 확인, 발사 중 어디인지 확인한다.
3. 왼쪽에서 탄환을 고르고 압축 코어, 패 교환, 다음 보충 탄을 함께 본다.
4. 오른쪽에서 실제 발사 순서와 탄별 결과를 확인한 뒤 끝 탄을 회수하거나 장전을 확정한다.
5. 발사 전 예측과 접촉 위험을 확인하고 발사 또는 재장전을 선택한다.

## 구조 변경

- `redesign/deck_loadout.tscn`: 요약, 5칸 현재 빌드, 보관함, 전술 덱을 고정 구역으로 제공한다.
- `redesign/combat_workbench.tscn`: 전장, 3단계 표시, 탄환 후보, 발사 큐, 예측과 행동 호스트를 제공한다.
- `campaign_ui.gd`: 상점과 덱·장비가 같은 파츠 렌더러를 사용하도록 화면별 행동만 주입한다.
- `screen.gd`: 기존 런타임 뷰를 새 장면의 호스트에 바인딩한다. `load_*`, `undo`, `confirm`, `fire`, `reload` 입력 계약은 유지했다.
- 1008×630에서는 전투 후보와 발사 큐를 나란히 유지한다. 900px 미만에서만 세로 배치와 탄환 2열로 전환한다.

## 검증

- Godot 4.7 편집기 로드와 전 스크립트·장면 파싱 통과
- 전체 자동 검증 3,730조건/0실패
- 실제 OpenGL UI 3,438조건/0실패, 1,103입력
- 보행자·쇄도 35층 UI 재생 통과
- 파츠 장착·해제, 압축 드래그, 장전·회수·확정·발사, 1008px·840px 반응형 검사 통과
