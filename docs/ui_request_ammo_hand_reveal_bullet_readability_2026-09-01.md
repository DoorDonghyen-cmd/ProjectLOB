# UI 요청 제작 기획서 — 랜덤 탄환 패 공개·탄환 식별 개선

> 작성일: 2026-09-01
> 상태: **1차 구현 완료 · 사람 플레이 검증 대기**
> 상위 실험: `docs/design_ammo_hand_randomness_2026-08-30.md`
> 기준 해상도: 960×540 가로형

## 1. 목표

- B안에서 `탄환이 무작위로 섞여 공개됐다`는 사건을 전투 시작과 리로드 순간에 체감시킨다.
- 탄환을 처음 보는 플레이어도 카드의 첫 시선에서 `명중 / 관통 / 화력 / 제어` 역할을 구분하게 한다.
- 원시 수치 나열보다 `무엇을 넘고, 무엇이 강화되는가`를 먼저 읽게 한다.
- 무작위는 장전 전 후보 공개에만 사용하고, LIFO 순서·명중·관통·피해·거리 결과는 계속 결정론적으로 유지한다.

## 2. 확인된 원인

1. 개발자 A/B 숏컷은 비교 재현성을 위해 게임플레이 시드 `731042`를 고정한다. B안을 반복 실행해도 같은 초기 패가 나오므로 랜덤 체감 테스트로는 부적합하다.
2. `ammo_hand_updated`를 받으면 패 목록을 즉시 다시 그린다. 셔플·공개·보충의 전환 상태가 화면에 없다.
3. 탄환 아이콘은 카드 우하단의 32px, 알파 45% 워터마크라 식별 수단이 되기 어렵다.
4. `[ACC] / [PEN] / [DMG] / [CTRL]` 축약 배지와 `DMG / ACC / PEN / KB / SLOW`가 비슷한 위계로 노출된다.
5. ACC·PEN은 적 EVA·DEF와 비교해야 의미가 생기지만 카드에는 숫자만 있어 실제 결과로 번역되지 않는다.
6. 기존 탄환 색은 효과군과 전문축 의미가 섞여 있다. 색만으로 역할을 암기시키면 같은 문제가 반복된다.

## 3. UX 원칙

- 목표 감정은 `좋은 탄을 뽑았다`가 아니라 **`이번에 공개된 탄을 읽고 순서를 만들었다`**이다.
- 셔플은 전투 결과가 아니라 **선택 재료를 준비하는 절차**로 표현한다.
- 정보 우선순위는 `역할 → 현재 효용 → 조건/연계 → 보조 수치` 순서다.
- 색각 차이와 작은 화면을 고려해 색만 사용하지 않고 한국어 역할명과 전용 기호를 항상 병기한다.
- 첫 패 공개는 짧고 분명하게, 리로드 보충은 더 짧게 처리해 반복 피로를 막는다.

## 4. 테스트 모드 분리

| 진입점 | 시드 | 목적 | 표시 |
|---|---:|---|---|
| A 전체 덱 · 비교 | 731042 고정 | 기존 방식 기준선 | 파란 A 배너 |
| B 공개 패 · 비교 | 731042 고정 | 동일 조건 A/B 비교 | 노란 B 배너 + `고정 시드 비교` |
| B 랜덤 체감 | 실행마다 신규 시드 | 패 변화·공개 연출 체감 | 노란 B 배너 + `새 패 체험` |
| 패 보충 연출 QA | 지정 패/지정 소모 | 유지·신규·예고 전환 회귀 | 개발자 전용 상태 표시 |

- 신규 시드는 기존 `RandomStreams.begin_run(0)`의 런타임 시드를 사용한다.
- 사용된 실제 시드는 플레이테스트 보고서에 저장해 모든 패를 재현 가능하게 한다.
- 일반 플레이어 화면에는 숫자 시드를 노출하지 않고, 개발자 모드와 보고서에만 표시한다.

## 5. 화면 흐름과 모션

### 5.1 전투 시작 — 첫 패 공개

```text
┌──────────────────────────────────────────────────────────────┐
│                 탄도 선택지 셔플                              │
│        ▣▣▣▣▣▣▣▣▣▣▣▣  →  공개 7 / 미공개 5                 │
│                                                              │
│ [명중] [관통] [화력] [제어] [명중] [화력] [관통]             │
│  표식    천공   증폭    충격    유도    교대    철갑           │
│                                                              │
│          공개된 탄환과 기본탄으로 LIFO 순서를 설계            │
└──────────────────────────────────────────────────────────────┘
```

- 카드 뒷면 묶음을 0.16초 동안 수평으로 두 번 교차시켜 `셔플`을 표현한다.
- 7장은 좌→우로 0.07초 간격 공개한다. 전체 연출은 0.75초 이내로 제한한다.
- 공개 중에는 전투 입력을 잠그고, 마지막 카드가 안착하면 즉시 조작 가능하게 한다.
- 카드 결과는 전부 공개되며 숨겨진 확률·룰렛·슬롯머신 표현은 사용하지 않는다.
- A안에서는 이 연출을 재생하지 않는다. A/B의 구조 차이가 행동으로도 구분되어야 한다.

### 5.2 리로드 — 유지와 신규 보충

```text
┌ 공개 패 7/7 ────────────────┬ 다음 보충 ───────────────┐
│ [유지] 표식  [유지] 충격      │ ① 유도탄  →  ② 철갑탄   │
│ [신규] 천공  [신규] 교대      │ 리로드 완료 시 순서 공개 │
│ [유지] 증폭  [신규] 파쇄      │                          │
│ [유지] 기본 보급탄             │ 미공개 덱 5              │
└──────────────────────────────┴─────────────────────────┘
```

- 미사용 탄은 제자리에서 0.85 밝기로 낮춘 뒤 `유지` 라벨을 0.35초 표시한다.
- 부족분만 우측 예고열에서 빈 슬롯으로 0.12초씩 이동시키고 `신규` 라벨을 0.8초 표시한다.
- 패 전체를 다시 섞는 것처럼 보이게 하지 않는다. 미사용 유지 규칙이 시각적으로 보존되어야 한다.
- 버린 더미가 재순환될 때만 짧은 `버린 탄 재혼합` 문구와 카드 뒷면 교차 모션을 재생한다.

## 6. 탄환 카드 정보 구조

### 6.1 넓은 카드

```text
┌──────────────────────────────┐
│ ◎ 명중           표식탄  신규 │
│                              │
│       [48px 탄환 이미지]      │
│                              │
│ 회피 9까지 명중               │
│ 적중 시 → 다음 1발 명중 +3    │
│ 현재 적: 명중 ✓ · 관통 ✕      │
│ 피해 2 · 관통 1               │
└──────────────────────────────┘
```

- 현재 32px·45% 워터마크를 **48px 이상·100% 불투명 주 이미지**로 승격한다.
- `[ACC]` 대신 `◎ 명중`, `[PEN]` 대신 `◫ 관통`, `[DMG]` 대신 `✦ 화력`, `[CTRL]` 대신 `↔ 제어`를 기본 표시한다.
- 첫 숫자 문장은 현재 탄 자체가 통과할 수 있는 게이트를 자연어로 설명한다.
- 둘째 문장은 효과를 `발동 조건 → 결과` 순서로 표시한다.
- 현재 강제 대상 기준 명중·관통 결과를 ✓/✕로 표시하며, 대상이나 버프가 바뀌면 갱신한다.
- 보조 수치는 마지막 줄로 내리고 0인 KB·SLOW는 숨긴다.

### 6.2 역할별 예시

| 역할 | 1차 문장 | 2차 문장 예시 |
|---|---|---|
| 명중 | `회피 9까지 명중` | `적중 시 → 다음 1발 명중 +3` |
| 관통 | `방어 4까지 관통` | `적중 시 → 대상 방어 -2` |
| 화력 | `관통 성공 시 피해 3` | `마지막 발이면 피해 +4` |
| 제어 | `명중 시 거리 +2m` | `다음 이동 속도 -2` |

### 6.3 좁은 탄창·예고 슬롯

```text
┌────────────┐
│ ◎ 명중     │
│  표식탄    │
│ 다음 명중+3│
└────────────┘
```

- 좁은 슬롯도 축약 영문 코드만 쓰지 않고 한국어 역할명을 유지한다.
- 툴팁에는 전체 수치·정확한 범위·LIFO 장전 힌트를 계속 제공한다.

## 7. 시각 언어

| 전문축 | 색 | 기호 | 프레임 패턴 |
|---|---|---|---|
| 화력 | 적색 `#FF5952` | 폭발점 `✦` | 하단 이중선 |
| 명중 | 황색 `#FFD147` | 조준점 `◎` | 네 모서리 조준선 |
| 관통 | 청색 `#52ADFF` | 갈라진 장갑 `◫` | 우측 쐐기선 |
| 제어 | 청록 `#59E6B8` | 거리 화살표 `↔` | 좌우 방향선 |

- 카드 프레임 색은 전문축, 탄환 실루엣은 구경, 기호와 문장은 전술 역할을 담당한다.
- 기존 128×128 탄환 PNG, 1시 방향 구도, 1px 검은 외곽선, Nearest 필터는 유지한다.
- 1차 구현에서는 기존 탄환 이미지를 폐기하거나 AI로 새로 만들지 않는다. 카드 프레임·역할 기호·크기·불투명도만으로 식별성을 먼저 검증한다.
- 색만으로 구분하지 않도록 모든 위치에 역할명과 기호를 함께 표시한다.
- 1차 사람 테스트에서도 개별 탄환 식별이 실패할 때만 기존 베이스 탄환의 탄두/탄피 밴드를 역할 체계에 맞게 재가공하는 2차 에셋 작업을 연다.

## 8. 구현 범위

### 런타임

- 고정 시드 비교 모드와 신규 시드 체감 모드를 분리한다.
- 패 변화 원인을 `initial / refill / reshuffle`로 UI에 전달하고, 이전 패 대비 `retained / added`를 식별한다.
- 사용 시드를 기존 플레이테스트 보고서와 QA 상태에 유지한다.
- 탄환 선택·소모·리로드·LIFO·전투 수식은 변경하지 않는다.

### UI

- B안 첫 패 공개 오버레이와 리로드 보충 모션을 추가한다.
- 가방 패 헤더를 `공개 / 미공개 / 다음 보충`의 물리적 영역으로 나눈다.
- 전투 가방과 확장 가방 카드가 동일한 역할 문구·색·결과 표현을 사용하게 한다.
- 현재 적 게이트 비교를 카드에 반영한다.
- 개발자 메뉴에 `B 랜덤 체감`, `패 보충 연출 QA`, `탄환 카드 가독성 QA` 숏컷을 추가한다.

### 비범위

- 공개 패 7발을 5~6발로 줄이는 밸런스 변경
- 명중·피해·관통 결과 랜덤화
- 탄창 안 순서 셔플
- 신규 탄환 효과나 스탯 변경
- 신규 SFX/BGM 제작
- 19종 탄환 PNG 전면 교체

## 9. 접근성·피로 가드레일

- 공개 애니메이션은 최초 0.75초 이내, 보충은 탄당 0.12초 이내로 제한한다.
- 모션 감소 옵션이 켜지면 트윈 대신 0.1초 크로스페이드만 사용한다.
- 모든 상태는 모션이 끝난 정지 화면에서도 읽을 수 있어야 한다.
- `신규 / 유지 / 다음 보충`은 색뿐 아니라 텍스트와 위치로 구분한다.
- 960×540에서 10px 미만의 핵심 정보 텍스트를 사용하지 않는다.

## 10. 검증 기준

### 자동 검증

- 고정 시드 B안은 실행마다 같은 패, 랜덤 체감 모드는 다른 시드를 사용하고 보고서에서 재현 가능하다.
- 패 변화 이벤트가 초기 공개·일부 보충·버린 더미 재혼합을 정확히 구분한다.
- 리로드 후 미사용 탄은 `retained`, 새로 뽑힌 탄만 `added`로 분류된다.
- A안에서는 패 공개 연출이 호출되지 않는다.
- 4전문축의 한국어 역할명·기호·색·핵심 결과 문장이 모든 카드 변형에서 동일하다.
- 현재 적 EVA·DEF 또는 대기 버프 변경 시 ✓/✕가 갱신된다.
- 기존 탄환 패·LIFO·소멸·기본탄 보장 및 전체 회귀 테스트를 통과한다.

### 사람 플레이 승인 기준

- B 랜덤 체감 모드 3회 중 3회에서 시작 패가 달랐다는 사실을 설명 없이 인지한다.
- 19종 중 임의 탄환 10개를 보고 3초 안에 전문축을 8개 이상 맞힌다.
- 카드 1장을 보고 `지금 이 적에게 명중/관통하는가`를 5초 안에 답한다.
- 리로드 뒤 어떤 탄이 유지되고 새로 들어왔는지 7발 중 6발 이상 구분한다.
- 연출이 장전 판단을 돕고 반복 피로 점수가 5점 만점 3 이하이다.

## 11. 승인 후 구현 순서

1. 시드 진입점 분리와 패 전환 데이터 계약
2. 역할 문구·현재 적 결과를 제공하는 공용 카드 표시 모델
3. 가방 카드 정보 위계 개편
4. 첫 패 공개·리로드 보충 연출
5. 개발자 QA 숏컷과 UI 스모크·회귀 테스트
6. 사람 플레이 3회 후 공개 패 크기 또는 탄환 에셋 2차 조정 여부 판단

## 12. 2026-09-01 구현 결과

- 고정 시드 A/B 비교와 실행마다 새 시드를 쓰는 `B 체감 · 매번 새 패`를 분리했다. 실제 실행 시드는 기존 플레이테스트 보고서와 QA 공개/오라클 상태에 기록된다.
- 패 전환 계약에 `initial / refill / reshuffle`, `retained / added`, 미공개 수, 다음 2발 예고를 포함했다.
- 전투 시작에는 `탄도 선택지 셔플`, 리로드에는 `공개 패 보충`, 버린 더미 재순환에는 `버린 전술탄 재혼합` 오버레이를 표시한다. 공개 중 전투 입력은 잠기며 전투 교체 시 이전 잠금은 즉시 정리된다.
- 가방 카드의 1차 정보를 `◎ 명중 / ◆ 관통 / ✦ 화력 / ↔ 제어`로 바꾸고, 원시 수치보다 `회피 9까지 명중`, `적중 시 → 다음 1발 명중 +3`, 현재 적 명중·관통 결과를 먼저 표시한다.
- 기존 탄환 PNG를 48px 이상, 완전 불투명, Nearest 필터의 주 이미지로 사용했다. 신규 이미지 제작과 전투 수치·패 크기·LIFO 규칙 변경은 하지 않았다.
