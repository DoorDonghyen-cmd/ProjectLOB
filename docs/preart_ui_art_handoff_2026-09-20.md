# 개편판 UI·아트 제작 인계

기준 소스: `prototype/core-redesign`  
기능 기준일: 2026-09-21
목표 뷰포트: 1280×800, 최소 검증 1008×630, 가로 화면

현재 기능·UI 계약은 완료 상태다. 이후에는 이 문서의 판독 순서와 터치 영역을 유지하면서 임시 도형·색·문자 아이콘을 최종 아트와 사운드로 교체한다. 새 게임 규칙이나 별도 화면을 추가해야만 아트를 시작할 수 있는 선행 작업은 남아 있지 않다.

## 교체 가능한 현재 구성

모든 주요 화면과 입력 흐름은 Godot Control로 동작한다. 최종 아트는 아래 플레이 정보의 위치와 판독 순서를 유지하면서 교체한다.

| 영역 | 구현된 기능 계약 | 필요한 최종 아트 |
|---|---|---|
| 타이틀 | 모드, 시작 보급, 난도, 무기5종, 이어하기, 안내, 설정, 규칙 | 로고, 배경, 무기 초상/실루엣 5종 |
| 거리 전장 | 0~32m, 자동 조준선, 적별 HP·장갑·접근·상태, 터치 상세 | 플레이어+총, 적 기본 실루엣 6종, 보스 변형 5종, 계층 배경 5종 |
| 탄환 카드 | 피해·관통·효과 아이콘, 속성색, 압축 결합부, 드래그 합성 | 회수탄+전술탄 6종, 영구/임시 압축 외곽, 소형 24px 대응 원본 |
| 탄창 | 3~7칸, 발사 순서, 2칸 점유, 앞/뒤 고정, 결과 미리보기 | 탄창 프레임, 빈 칸/선택/확정/소모 4상태 |
| 지도 | 5계층 노드 연결, 현재/방문/이동 가능 상태, 경로 비용 | 노드 아이콘 6종, 연결선 3상태, 계층별 패널 장식 |
| 선택 화면 | 보상, 무기고, 보급, 이벤트, 관문 비교 카드 | 카드 프레임 기본/강조/비활성/구매완료 4상태 |
| 파츠 | 일반 모듈 14종·코어 6종의 고유 도형, 핵심 이득, 강한 코어의 대가, 5칸 장착 상태 | 파츠 20종 대형/소형 아이콘, 장착·코어 외곽선, 빈 슬롯 |
| 무기고 작업대 | 현재 빌드, 상품 3종, 압축 코어, 장착 5칸, 보관함을 구역으로 분리한 `shop_workbench.tscn` | 각 구역 프레임, 상품 기본/선택/품절, 장착 작업대 장식 |
| 덱·장비 | 요약, 현재 빌드 5칸, 보관함, 전술 덱을 분리한 `deck_loadout.tscn` | 장비 보관함 프레임, 장착/코어 상태, 탄환 도감 배경 |
| 전투 작업대 | 전장, 3단계, 보유 탄환, 발사 순서, 예측·행동을 분리한 `combat_workbench.tscn` | 후보·탄창 영역 프레임, 현재 단계 강조, 확정/발사 상태 장식 |
| 성장 선택 | 압축 코어 충전, 탄창 확장, 2발→1발 압축, 크레딧 획득을 변화 전후 도형으로 표시 | 코어·탄창 셀·압축 화살표·크레딧 픽토그램 |
| 상태바 | 고도, 크레딧, 코어, 무기, 덱, 난도 | 6개 단색 아이콘, 작은 크기에서도 구분되는 픽토그램 |
| 기록/정산 | 수집 20칸, 완주 통계, 패배 조언 | 기록 잠김/해금, 승리/패배 배너 |

## 적 실루엣과 상태 결합

| 종류 | 형태 | UI와 겹치면 안 되는 영역 |
|---|---|---|
| 사족체 | 낮고 긴 네 다리 | 위쪽 HP 바, 우측 거리 라벨 |
| 장갑벽 | 폭이 넓은 직사각 | 중앙 장갑 면은 명암 2단계 유지 |
| 선체 | 세로로 얇은 마름모 | 좌우 흔들림 6px 여유 |
| 부유체 | 하반신 없는 오각형 | 머리 위 `충n/3` 16px 영역 |
| 흡수 구체 | 완전한 원형 | 머리 위 배리어 ◆ 최대 3칸 |
| 태세 드론 | 삼각/분리형 | 장갑 전환 시 외곽선 개폐 연출 |

적 본체 기준 박스는 48×52px 안에서 읽혀야 한다. 상태 표시는 스프라이트에 굽지 않고 UI가 별도로 그린다. 최종 보스는 배리어, 충전, 태세를 동시에 표시하므로 머리 위 28px를 비워 둔다.

## 색과 상태

- 배경 `#101920`, 패널 `#1B2A34`, 본문 `#E7E4D9`, 보조 `#A4B4BA`, 선택 `#A9DFBF`, 위험 `#F2A38D`를 현재 대비 기준으로 쓴다.
- 화염은 주황, 전기는 시안, 물리는 회백색을 유지한다.
- 색만으로 상태를 전달하지 않는다. 배리어 `◆`, 충전 `충`, 교대 장갑 `장→`, 압축 결합부 형태를 함께 유지한다.
- 버튼은 기본, 포커스/호버, 눌림, 비활성 상태가 필요하며 모바일 터치 높이 52px를 줄이지 않는다.

## 아트 검수 바로가기

메인 메뉴 `개발자 테스트`에서 다음 화면을 바로 연다.

- `상층 적 3규칙`: 부유체·흡수 구체·태세 드론과 상태 UI.
- `압축탄 장전 UI`: 앞 고정, 2칸 점유, 뒤 고정.
- `전투 중 임시 압축 UI`: 같은 카드 드래그와 압축 코어.
- `파츠 아이콘`: 파츠 4종의 실루엣·색·효과 수치를 한 화면에서 비교.
- 도시 분기 맵, 무기고, 보급, 이벤트, 관문, 승리/패배 정산, 덱·장비, 기록실.
- 처음 안내, 설정·접근성.

기능 원본 캡처는 `docs/qa/reports/preart_uiux_2026-09-20_assets/`에 모은다. 최종 리소스 연결 뒤 같은 장면을 1280×800과 1008×630에서 재촬영해 버튼 경계, 상태 겹침, 실루엣 판독을 비교한다.

파츠와 성장 선택의 최신 기준 캡처는 `docs/qa/reports/icon_first_parts_ui_2026-09-21_assets/`에 있다. 파츠 이름이나 긴 설명보다 실루엣과 큰 변화량이 먼저 읽혀야 하며, 최종 아트에서도 20종 파츠의 핵심 외곽 형태가 역할군 안에서 구분되어야 한다.

무기고의 최신 구조 기준은 `docs/qa/reports/shop_workbench_ui_2026-09-21_assets/`와 `res://redesign/shop_workbench.tscn`이다. 최종 아트는 `현재 빌드 → 진열 → 압축 코어 → 장착 작업대` 순서를 유지하고, 1280px 상품 3열·보관함 2열과 1120px 미만 상품 2열·보관함 1열을 모두 지원해야 한다.

덱·장비와 전투의 최신 구조 기준은 `docs/qa/reports/loadout_combat_ui_2026-09-24_assets/`, `res://redesign/deck_loadout.tscn`, `res://redesign/combat_workbench.tscn`이다. 전투는 1008×630에서 후보와 발사 순서를 함께 보이고, 900px 미만에서만 세로로 접는다. 최종 아트도 이 판독 순서와 카드 터치 영역을 유지한다.

## 다음 제작 단계

1. 계층 배경·플레이어·총기5종·적6종과 관문 변형을 현재 앵커 안에 교체한다.
2. 탄환·상태·노드 아이콘을 24px 최소 크기에서 다시 검수한다.
3. 장전·압축·격발·피격·적 전진·관문에 SFX를 연결하고 설정에 실제 음량 슬라이더를 추가한다.
4. 아트 적용 뒤 같은 QA 화면과 Galaxy 실기에서 대비, 발열, 터치 오입력을 확인한다.
