# UI·UX 선택 흐름 개편 결과

## 결과

게임의 핵심 조작을 `정보 확인 → 선택 결과 확인 → 확정` 순서로 다시 묶었다. 규칙과 밸런스, 저장 형식은 유지하면서 전투·지도·상점·덱 장비의 입력 구조를 바꿨다.

## 전투

- 후보 탄환 카드 아래에 이번 전열에서 예상되는 표적, 피해, 처치 수, 충돌 위험 변화를 표시한다.
- 상단 단계 문구가 탄 선택, 순서 확인, 발사 준비를 차례로 안내한다.
- 현재 단계의 `장전 확정` 또는 `발사`만 민트색 주 버튼으로 표시한다.
- 압축 가능한 탄환은 시안 표시와 함께 `2발 합치기` 버튼을 제공한다. 기존 드래그 앤 드롭도 유지한다.

## 지도

- 밝은 노드를 처음 누르면 목적지와 경로 효과만 선택한다.
- 하단에 선택한 시설, 노드 종류, 비용 또는 다음 전투 영향을 한 줄로 보여 준다.
- 선택한 경로의 `이 경로로 이동` 버튼을 눌러야 실제로 진입한다.

## 상점

- 진열 두 칸과 비교 패널 한 칸을 한 화면에 배치했다.
- 탄환은 보유량 변화와 피해·관통·속성을, 파츠는 이득·대가·현재 빌드 변화를 표시한다.
- 구매 버튼은 즉시 실행 행동으로 강조하고, 긴 규칙은 비교 패널의 상세 버튼으로 분리했다.

## 덱·장비

- `착용 중`, `보관함`, `탄환 덱` 세 탭으로 분리했다.
- 착용 중 탭은 5개 슬롯과 코어 사용량만, 보관함은 장착 행동만, 탄환 덱은 종류와 보유 비율만 보여 준다.

## 검증

- Godot 4.7 스크립트·씬 파싱 통과
- 전체 자동 테스트: 3,730 통과 / 0 실패 / 기존 경보 3
- 실제 OpenGL UI: 3,675 통과 / 0 실패 / 버튼 입력 1,179회
- 보행자·쇄도 각각 35층 기록 재생
- 1280×800, 1008×630, 840×630 레이아웃 검증
- 실제 사용자 저장은 격리했고 APK와 커밋·푸시는 만들지 않았다.

## 전투 시각 개편 2차

- 헤더 안에서 세로로 늘어나던 압축 코어 표시를 58×44px 독립 도구 칩으로 고정했다.
- 같은 탄환 합치기는 `탄환 두 발 → 압축 코어`를 직접 그리는 그래픽 버튼으로 교체했다.
- 현재 단계는 채운 민트색, 완료 단계는 어두운 청록, 다음 단계는 외곽선만 표시한다.
- 현재 조작해야 할 후보 또는 발사 순서 패널에 굵은 민트색 테두리를 적용했다.
- 탄환 후보는 물리·화염·전기 색을 얇게 입히고, 압축 가능한 카드는 시안 테두리로 구분한다.
- 후보 결과 문장을 짧은 하단 배지로 바꿔 모바일 카드에서도 처치·충돌 해제·피해 결과가 먼저 보이게 했다.
- 발사 순서 종합 결과도 별도 결과 띠로 강조했다.

최종 실제 OpenGL UI 검증은 3,677/0, 버튼 입력 1,179회다. 압축 칩 48px 이하와 그래픽 합치기 버튼 52px 이하를 회귀 조건으로 추가했다.
