# 탄창 여정 플레이 기록

이 문서는 다음 사람 플레이의 기록 양식이다. 작성 자체는 플레이 완료나 재미 검증이 아니다. 설계·결정은 [탄창 여정](../../direction/magazine-journey.md)에 둔다.

## 실행 조건

- PC 시작: 저장소의 `OPEN_COMBAT_UI_STUDY.cmd`. `OPEN_MAGAZINE_COMPARISON.cmd`는 독립 비교이므로 연속 성장 검증과 구분한다.
- 빌드/관련 파일 상태, 실행 모드, 기기, 화면 크기, 총기, 새 출발/이어하기를 적는다. 기본 경로·순서는 현행 설계를 사용하며 다른 조건으로 바꾸면 함께 적는다.
- 제작자 QA는 분리된 저장 경로에서 한다. 플레이어 저장의 초기화·삭제를 요구하지 않는다. 다른 무기나 같은 조건 재도전은 자연 플레이 기록 뒤 필요한 질문에만 사용한다.
- 진행 중 정답·빼내기 사용·특정 보상을 유도하지 않는다. 조작 안내가 필요했다면 내용과 시점을 기록해 첫 이해도와 구분한다.
- 현재 배포 APK는 독립 비교본이다. 연속 여정/최신 HUD가 포함된 모바일 빌드로 가정하지 않는다. 새 APK는 요청에 따라 별도로 만든다.
- 여정 전달용 `magazine-journey` 모드와 컴파일 리소스 검사는 준비됐다. [준비 범위](../reports/mobile_journey_ready_2026-11-01.md). 설치한 APK의 manifest가 이 모드인지 확인하며, 도구 지원만으로 휴대폰 빌드가 이미 교체됐다고 보지 않는다.

## 관찰할 순간

| 순간 | 기록할 내용 | 해석할 때 주의할 점 |
| --- | --- | --- |
| 첫 전투 | 실제로 택한 행동, 보이는 근거, 예상과 실제의 차이 | 사전 설명을 이해도 성과로 세지 않음 |
| 첫 코어·특수탄 이후 | 새 보상 때문에 바뀐 사격/냉각/교체, 그대로였다면 이유 | 피해 숫자 증가와 선택 변화는 다름 |
| 방패·사수 대응 | 가장 급하다고 본 적과 근거, 남겨 둔 행동 여유 | 내부 거리/난수로 플레이어 판단을 대신하지 않음 |
| 빼내기 또는 유지 | 공개 정보, 포기할 탄과 이유, 실행 후 이득/대가 | 쓰지 않아도 합리적인 선택일 수 있음 |
| 정비·관문 | 고른/건너뛴 보상의 이유, 긴장감이 가장 높고 낮았던 순간 | 모든 전투를 오래·위험하게 만드는 것이 목표가 아님 |

처음에는 “어떤 순간이 기억에 남았나요?”처럼 자유 후기를 받고, 필요한 경우에만 다음을 보충한다. “보상 전후 무엇이 달라졌나요?”, “그때 그대로 쏘거나 탄을 뺀 이유는 무엇인가요?”, “반복 작업처럼 느낀 구간이 있었나요?” 답변을 긍정 평가로 유도하지 않는다.

| 항목 | 기록 |

| 빌드/모드/기기/총기/시작 상태 | 미기록 |

## 기존 기록으로 확인할 수 있는 범위

`새-게임-프로젝트/redesign/magazine_journey.gd`는 전투별 `node`, `won`, `turns`, `shots`, `used`, `ejected`, `deck`, `growth`를 저장한다. 종료 요약과 실제 저장의 전투 이력을 함께 참조한다. `shots` 등 필드의 뜻은 실제 모델에서 확인하고 사격 입력 횟수·발사 탄 수를 임의로 바꿔 해석하지 않는다. 같은 조건 재도전은 현재 전투 진입 상태를 복원한다.

이 기록만으로 선택 이유·망설임·재미·기기 프레임/온도를 알 수는 없다. 이유는 후기/관찰로 보완하며 추가 계측은 실제 누락을 확인한 뒤 최소한으로 붙인다. 외부 분석 SDK나 원격 수집은 도입하지 않는다.

결론은 [본편 연결 판단 조건](../../direction/magazine-journey.md#본편-연결-판단-조건)에 연결한다. 빼내기 횟수, 자동 완주, 표본 하나만으로 채택/폐기를 확정하지 않는다. 후기는 `docs/history/daily/`에, 화면·재현 근거는 해당 QA 보고서에 남긴다.
