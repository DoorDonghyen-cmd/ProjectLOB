# 모바일 지속 플레이·복귀 검증

목적은 사용자가 보고한 **플레이 후반 프레임 저하와 기기 발열**을 같은 기기의 초기 상태와 비교하는 것이다. 이 문서는 실행 절차이며 실기기 결과가 아니다. [현재 PC 측정과 한계](../reports/mobile_revision_2026-10-28.md).

## 비교 준비

- 기종·OS·빌드 ID/해시·실행 모드·렌더러·화면/주사율·밝기·배터리·충전 여부·절전/게임 모드·주변 온도를 가능한 범위에서 기록한다. 계측에 USB 충전이 필요하면 그 조건을 밝히고 일반 무충전 플레이와 섞지 않는다.
- 같은 기기·설정·실제 획득 경로로 전후를 비교한다. 차가운 시작과 이미 열이 오른 시작은 별도다. 새 규칙의 여정, 독립 비교, 기존 본편 후반 저장은 각각 다른 시험으로 표기한다.
- 사용자 저장을 덮어쓰지 않는 테스트 기기/프로필·복사본을 사용한다. 일반 플레이 저장에 임의 초기화나 앱 삭제를 수행하지 않는다.
- 계측 방식과 목표를 시작 전에 정한다. 현재 60FPS 상한은 설정일 뿐 유지 성능의 증거가 아니다. 목표 FPS·허용 지연·메모리 범위가 미정이면 결과를 먼저 보고하고 통과 기준을 사후에 꾸며내지 않는다.
- 숫자를 수집할 장치가 없으면 `미측정`으로 적는다. 화면 녹화·프로파일러 자체의 부하, 측정 주기와 단위도 함께 기록한다.

## 1회 실행

1. 시작 직후의 짧은 워밍업과 초기 표본을 구분한다. 첫 전투의 대기·발사·냉각·교체·자동 저장에서 프레임과 입력 지연을 관찰한다.
2. 실제로 보상과 정비를 거쳐 관문까지 플레이한다. 첫 회는 자연 행동을 남기고, 재현 비교가 필요하면 같은 합법 행동 기록을 사용한다. 자동 난수 탐색을 사람 플레이로 대체하지 않는다.
3. 초기 조사에서는 약30분을 시작점으로 삼되, 원래 저하가 나타난 시점과 실제 세션 길이에 맞춰 조정한다. 약5분 간격 및 전투/보상 전환에서 기록한다. 준비 시간과 앱이 뒤에 있던 시간을 구분한다.
4. 여정이 끝나면 같은 모드로 반복하고 새 출발/재도전·덱/상세/메뉴 열기와 닫기를 포함한다. 후반 본편의 큰 덱·긴 이력 재현은 별도 복사 상태로 측정한다. 여정 반복만으로 전체 등반을 검증했다고 하지 않는다.
5. 끝부분에서 초기와 같은 장면·행동을 다시 측정한다. 증가한 메모리가 장면 이탈/휴식 뒤 안정되는지 확인한다. 캐시 성장과 누수를 구분하며 특정 증가율 하나만으로 누수를 단정하지 않는다.
6. 크래시·입력 불능·저장 오류·OS 온도 경고 또는 기기를 잡기 불편한 발열이 발생하면 해당 실행을 중단하고 시간/상태/로그를 남긴다. 정해진 시간을 채우는 것이 목표가 아니다.

## 기록과 판정

| 항목 | 권장 기록 | 해석 제한 |
| --- | --- | --- |
| 프레임 | 같은 표본 길이의 FPS, 프레임 시간 중앙값/p95/최대 지연과 발생 행동 | 평균 FPS 하나로 끊김을 숨기지 않음 |
| 반응/저장 | 입력→반응, 최초/반복 저장, 장면 전환 지연 | CPU 함수 시간과 전체 입력 지연을 혼동하지 않음 |
| 메모리 | 같은 계측기의 프로세스 메모리, 접근 가능하면 노드/객체 수, 이력 크기 | Godot 정적 메모리와 OS 전체 메모리를 혼합하지 않음 |
| 온도/전력 | 제공되는 센서 이름·값·단위, 배터리/충전, OS 열 상태, 손의 체감 | 배터리 온도를 SoC/표면 온도로 부르지 않음; 센서 없으면 수치 미측정 |
| 플레이 | 경과 시간, 전투/화면, 총기/덱/이력, 발생한 문제와 재현 | 후반 적·효과 수 변화와 열 누적 원인을 구분 |

기록 행: `경과 시간 | 장면/행동 | 프레임 표본 | 반응/저장 | 메모리 | 온도/충전 | 현상 | 로그 위치`.

같은 조건의 초기/후반 차이와 반복 재현 여부를 보고 원인 후보를 좁힌다. 충전·녹화·다른 앱 등의 차이를 밝힌다. 수치가 없는 영역은 미검증으로 남기고 PC 검사 성공을 대신 넣지 않는다. 수정 후에는 실패가 나타났던 길이와 조건을 우선 재검사한다.

## 저장·앱 복귀

전투 행동 후, 보상 선택 전/부분 선택 후, 정비 후 등 **해당 모드에 실제 존재하는 상태**에서 진행한다.

- 홈/다른 앱으로 나갔다가 돌아오기: 입력·소리·표시·시간 진행이 정상인지 확인.
- 앱 프로세스 종료 후 재실행: 마지막 저장 시점의 덱/성장/열/탄창/빼내기 한도와 진행 위치 확인. 종료 시점의 아직 저장되지 않은 입력을 별도로 기록.
- 같은 서명·패키지의 새 테스트 빌드로 업데이트: 분리된 이전 저장 복사본이 유지되는지, 본편/비교 모드가 섞이지 않는지 확인. 업데이트 대상 APK가 준비된 요청에서만 수행.

## 기존 검사와 연결

`tools/run_playtest_revision_checks.ps1`의 `mobile_ui`, `mobile_save`, `ui`와 기존 성능 실행기는 PC의 회귀·표시·저장 검사다. 실기기 지속 측정기나 자동 장시간 플레이 도구로 간주하지 않는다. 현행 빌드에서 지원하는 모드와 격리 저장 경로를 확인한 뒤 필요한 검사만 사용한다.

결과는 `docs/qa/reports/`에 빌드·환경·원본 측정·실행 길이·재현/미재현·미측정을 함께 남긴다. APK/ZIP 무결성과 전달은 [기존 모바일 절차](../../mobile-delivery.md)로 따로 확인한다.
