# 거시 UI/UX 구조 개편 QA

## 범위

`campaign_ui.gd`, `screen.gd`, `city_ui_runner.gd`의 화면 셸, 지도 확정, 보상 선택, 상점 역할 분리, 전체 화면 빌드 작업실, 전투 헤더를 검증했다.

## 자동 결과

| 검증 | 결과 |
|---|---:|
| 전체 Godot 테스트 | 3,730 / 0 실패 |
| 결정론적 캠페인 | 22,632 / 0 실패 |
| 실제 OpenGL UI | 3,684 / 0 실패 |
| 실제 버튼 입력 | 1,181회 |
| 모바일 레이아웃 | 495 / 0 실패 |

캠페인 보고서는 `qa_runtime/city/campaign_macro_uiux/city_campaign_report.json`, 최종 UI 캡처와 보고서는 `qa_runtime/city/ui_macro_uiux_final/`에 있다. 실제 사용자 저장과 분리된 QA 경로를 사용했다.

## 새 회귀 계약

- 지도에 압축 런 헤더와 단일 목적지 시트가 존재한다.
- 상점의 장착 편집기는 숨겨지고 빌드 작업실 버튼이 전체 화면 작업 공간을 연다.
- 빌드 작업실의 크기는 게임 화면과 같고 세 탭을 유지한다.
- 목적지 선택 뒤에만 해당 경로 확정 버튼이 보인다.
- 1008×630에서 지도, 상점, 전투의 주요 컨트롤이 논리 화면 밖으로 나가지 않는다.

## 관찰

지도는 건물 단면과 확정 행동이 한 화면에 들어왔고, 상점은 구매 비교가 첫 화면에 남았다. 빌드 작업실은 배경 지도와 분리되어 핵심 빌드 시스템의 독립성이 생겼다. 최종 아트가 들어오기 전까지 사용할 수 있는 정보 구조와 화면 구분은 마련됐으며, 이해 속도와 반복 피로는 사람 플레이 항목으로 남긴다.
