# 화력 성장 코어 — 본편 적용과 검증

2026-10-16 · `prototype/core-redesign` · Godot 4.7 Windows

## 적용 범위

[현재 규칙](../../direction/damage-growth.md)을 본편에 구현했다. 사용자 승인 방향은 탄환·총기·파츠로 피해 값을 키우는 플레이다. 코어3종/첫 승리 선택/성장 조건과 수치는 디렉터 구현안이며 장기 밸런스 확정은 아니다.

- 연쇄 구동핵: 타격당 가산 성장 + 남은 타격 연결. 다회 타격탄 추가 열1.
- 열압 구동핵: 발사 전 고열 조건의 배율 성장. 열 한계−2.
- 돌파 구동핵: 1회 타격 공격의 배율 성장 + 초과 피해 전달. 탄창−1.
- 전투 승리 후 한 번 성장, 등반 중 유지/새 등반 초기화, 장착 해제 시 효과만 비활성화.
- 신규 탄환은 이번에 추가하지 않았다. 기존 가산 지원·배율 지원·다회 타격·관통·냉각·조건부 공격을 활용한다.
- 전투의 별도 ‘연계’ 버튼과 후보 강조를 제거했다. 발열 수치 공개/LIFO/확정 전 편집/기존 저장 진행을 유지했다.
- 카드/상세/레일/피해 숫자/승리 성장 표시, 새 코어 도트 아이콘, 개발 빌드3개를 연결했다.

## 수치가 실제로 커지는지

보행자, 장갑0, 충분한 HP의 표적을 둔 실제 Model.fire 비교다. 일반 기본탄의 현재 무기 포함 직접 피해는3이며 아래는 지원탄 없이 해당 코어만 착용한 결과다. 열압만 발사 전 고열을 충족했다.

| 코어 | 성장0 | 성장4 | 성장8 |
| --- | ---: | ---: | ---: |
| 연쇄 |4|8|12|
| 열압 |4|7|10|
| 돌파 |6|9|12|

성장4에서 **증폭탄 → 배율탄 → 기본탄**으로 실제 발사하면 연쇄22 / 열압30 / 돌파36피해다. 각각 `(3+3+5)×2`, `(3+3)×2×2.5`, `(3+3)×2×3`이다. 이 비교는 고HP·무장갑 조건이며 장갑/배리어/남은 HP에 따라 실제 적 처치 결과는 달라진다. 세 탄의 발열 비용 때문에 이 사례에서는 과열과 강제 재장전도 발생한다. 공짜 피해 증가가 아니다.

남은 타격이 서로 다른 적2기를 추가 처치하고, 돌파12피해가 첫 적HP2를 소모한 뒤 다음 장갑1/HP6 적에게6, 그 다음 장갑2 적에게1만 전달되는 것을 검사했다. 배율을 대상마다 다시 곱하지 않는다. 배리어 차단, 최근접 압력탄 요격, 지원탄 피해0, 재장전 화상 승리 정산도 포함한다.

모두 `qa_runtime`의 격리 APPDATA/LOCALAPPDATA에서 실행. UI는 저장 비활성화.

| 검사 | 결과 |
| --- | --- |
| 전용 규칙·예측·성장·저장·압력탄·표시 비용 |657검사 / 실패0|
| 실제 UI·터치·첫 코어 선택·발사·상세·레이아웃 |684검사 / 실패0|
| 기존 지원탄/강화 회귀 |953검사 / 실패0|
| 첫 지역 캠페인 5총기×3코어 |15경로 관문 도달 / 5823검사 / 실패0|

UI 해상도는1008×630,1280×900,1440×630이다. 실제 장전/확정/발사/보상 선택은 터치 이벤트로 실행했다. 성장 결과/상세 비교용 일부 화면은 레벨4 또는 보상 상태를 설정한 QA 표본이다. 코어 선택3버튼을 좁은 화면 안에서 동시에 볼 수 있게 긴 설명을 상세 창으로 이동했고 버튼 높이를 정렬했다. 같은 대상의 여러 후속 타격은 하나의 피해 합계로 그리며 HP 변화 시작점도 첫 타격 이전값을 유지한다.

예측은 live state/RNG/성장을 바꾸지 않는다. 산개는3코어×12시드에서 실제 결과가 정확 분포의 HP 범위 안에 들어감을 확인했다. v14→v15 마이그레이션은 기존 강화 값을 유지하며 잘못된 성장 타입/범위를 거부한다. 실제 캠페인 명령마다 전체 저장/복원 동등성을 확인했다.

캠페인 시드는731042 하나다. 모두4전투/8노드 후 관문에 도달했고 대부분 코어3단계, 돌파는 산개2/압쇄1단계였다. 탐색기는 미래 RNG 상태를 사용할 수 있는 기능 검증용 경로 탐색기다. 이 결과를 플레이어 승률, 공정한 정책 비교, 최적 전략 또는 전체 난도 균형의 근거로 사용하지 않는다. 원자료는 `qa_runtime/damage_engines/campaign/campaign.json`, 작은 요약은 아래 링크에 보존했다.

초기 원거리 fixture가 실제 저장 스키마와 다른 uid/source/speed를 사용해 새 검사4개가 실패했다. 실제 압력탄 스키마로 표본을 고친 뒤657검사를 통과했다. 제품 코드의 저장 검증을 완화하지 않았다. 초기 비격리 에디터 검사에서 권한 오류가 난 실행은 통과 근거에서 제외했다.

## 플레이와 남은 확인

`D:/ProjectLoB/worktrees/core-redesign/PLAY.cmd` → 새 등반 → 첫 전투 승리 → 코어 선택. 기존 저장에서는 진행 중 보상을 바꾸지 않는다. 빠른 비교는 메인 → 개발 → 파츠 빌드 · 연속 타격/고열 화력/단발 집중이다.

다음 사람 테스트에서는 같은 패를 코어별로 다르게 쓰는지, 성장 후 새로운 탄을 모으고 싶은지, 초과 피해/남은 타격 전달을 이해하는지, 고열의 위험을 감수할 이유가 있는지 확인한다. 기존 비성장 코어가 열등한 선택으로 밀리는지와 상위 구역에서 성장8단계가 너무 강한지는 별도 밸런스 검토가 필요하다. Galaxy 실기기/전체 캠페인/사람 재미 검증은 수행하지 않았다. APK·커밋·푸시 없음.
