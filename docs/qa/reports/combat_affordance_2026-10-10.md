# 전투 조작 단서와 상태 통일

사용자가 채택한 청회색 도트 UI를 유지하면서 행동 전 단서와 실행 중 상태를 연결했다. 세계관/배우/배경/피해·발열·턴 계산은 변경하지 않았다.

## 참고와 판단

- 사용자 제공 [Interface In Game 픽셀 게임 목록](https://interfaceingame.com/games/?themes=pixel-art)을 열고 [The Final Station — Battery](https://interfaceingame.com/screenshots/the-final-station-battery/)의 원본 이미지를 브라우저로 확인했다. 큰 현재/사용 수치와 그 아래 세부 사용처를 연결하는 위계가 참고 대상이다. 우리 게임에는 열 게이지와 재장전 결과의 연결로 해석했다. 원본 이미지는 게임에 복제/포함하지 않았다.
- 도구: game-ui-ux, game-feel, godot-ui-integration. Godot MCP 프로젝트 조회 정상(4.7). 기존 CLI 검증 경로를 사용했다.
- 새로운 테마보다 기존 카드·탄창·열계·주 행동의 상태 규칙을 우선했다. 장전됨/공간 부족을 같은 비활성 색만으로 추측하던 문제를 짧은 이유로 구분한다.

## 구현

- 빈 탄창 첫 칸에 장전 안내. 손패의 마우스/키보드 포커스는 실제 삽입 위치의 모서리를 강조하고 2칸 탄은 2칸 폭을 표시한다. 보유량/비활성·확정·위치 제약을 존중하며 후보 계산은 모델을 변경하지 않는다.
- 재장전 hover/focus에서 열계의 제거 예정 구간을 푸른 빈 셀과 빼기 표시로 표현한다. 현재 열은 유지하고 오른쪽에 재장전 후 열과 감소량을 표시한다. 포커스를 옮기면 사격 최고 열 예측으로 복귀한다. 모바일에서도 냉각 전후/적 턴은 재장전 버튼에 항상 남는다.
- 카드 하단은 장전됨/탄창 공간 부족/발사 대기 상태를 설명한다. 주 행동에는 점유 칸 수와 구별되는 실제 탄 수를 표시한다.
- 보조 버튼은 중립색, 선택/실행은 민트, 재장전은 청회색, 접촉 위험 재장전은 주황을 유지한다. 누름 반응도 같은 역할 색을 사용한다. 재장전 버튼 하단의 분절은 실제 reload_turn/cooling_turn 진행에 맞춰 채워진다.
- 전장→탄창/행동→손패의 주요 배치를 combat_workbench.tscn에 직렬화했다. 실행 전에 대표 위치와 예시를 볼 수 있고 런타임은 에디터 예시만 제거한 뒤 실제 데이터로 채운다. [실행 전 구성 캡처](combat_affordance_2026-10-10_assets/scene_before_ready.png)는 스크립트의 _ready를 비활성화하고 직렬화 씬만 렌더한 증거다. 최종 자산·동적 카드까지 에디터에서 그대로 보이는 수준은 아니며 아래 본편 캡처가 시각 판정 기준이다.

## 검증

- `tools/run_combat_affordance_checks.ps1`: **340검사 / 0실패**. 1008×630, 1280×900, 1440×630 실제 렌더. 키보드/포인터 미리보기, 터치 장전·확정·발사, 2칸 표시, 보유/공간 이유, 정확한 냉각 결과와 무소모, 확정 이후 잔류 표시 제거, 강제 재장전 실제 턴 분절, 상태별 고정 배치 및 경계, 실행 전 씬 구성 확인.
- 피드백 회귀 **489검사 / 0실패**. 피해 숫자 충돌·실제 피해/모델 RNG 동일성·즉시 연출. 버튼 상태/열계 변경 후 실시했다. 이후 씬 배치 직렬화의 최종 검증은 아래 연출 회귀와 위 340검사다.
- 최종 씬 배치 변경 후 연출 회귀 **784검사 / 0실패**. 실제 연쇄 발사/처치·과열·강제 재장전·즉시 연출 및 5총기×10장 손패를 확인했다. `finish_stdout.log`에 결과를 보관한다. 테스트 저장은 각 qa_runtime 하위 격리 경로이며 본 저장을 수정하지 않는다.
- 1008 장전/냉각 및 1280 삽입 미리보기, 실행 전 씬 렌더를 직접 열어 확인했다. 구경별 손맛, 작은 실제 폰에서의 읽는 시간은 사람 확인 전이다.
