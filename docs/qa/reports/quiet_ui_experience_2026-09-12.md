# 텍스트 밀도 완화 후보 독립 UX 검토 — 2026-09-12

**판정: 제공 화면에서 텍스트 밀도 감소와 주요 행동의 분리를 확인했다. 명백한 잘림·가림은 발견하지 못했다. 탄환 수치의 확인 경로를 처음 보는 사람이 쉽게 찾는지는 추가 확인이 필요하다.**

## 밀도와 시선의 구분

같은 세 적 배치의 기준 화면과 최신 `07_final_fixture`를 비교하면, 기본 화면에서 읽어야 하는 문장이 줄었다.

| 영역 | 기준 원본 | 최신 원본에서 보이는 상태 |
|---|---|---|
| 상단 | 총기·시드·파츠·턴, 교전 이름과 서술 문장 | 총기·턴과 진행 번호가 남고 전장 앞의 설명량이 줄어듦. 개발자 연습 표시는 유지. |
| 적 정보 | 이름, HP·장갑·회피, 속도·다음 전진의 세 줄 | 이름·HP와 장갑·회피·접근의 두 줄. 적 사이에 분리된 간격이 보임. |
| 탄환 후보 | 각 카드의 이름·수치·효과 세 줄 | 각 카드에는 이름·개수와 역할/효과 두 줄. 하단 한 줄에 회수탄의 피해·관통·명중이 별도 표시됨. |
| 탄창 | 순서 제목, 빈 칸, 취소·확정, 역순과 준비탄 설명 문장 | 순서 제목과 네 칸, 되돌리기·확정, 현재 단계의 짧은 안내 중심. |
| 하단 | 계속 보이는 조작 순서 안내 | 기본 화면 하단의 반복 안내가 줄어듦. |

전장 그래픽과 거리 눈금은 유지된다. 현재 대상의 원과 조준선, 적의 형태, HP 막대, 0m 접촉 패배선이 시각 중심을 이룬다. 하단도 “보유 탄환”과 “발사 순서” 두 영역으로 읽힌다. **시각적으로 정보가 줄고 영역이 분리된 것은 원본 비교로 확인되는 사실**이다. 실제로 사용자가 덜 정신없다고 느끼는지와 원하는 수준까지 줄었는지는 측정하지 않았다.

## 실제 행동과 필수 수치의 발견성

### 장전에서 발사까지

`02_plan`은 빈 탄창 아래 “탄환을 눌러 장전하세요”를 표시한다. 왼쪽에 여섯 후보가 있고 오른쪽에 1–4번 슬롯과 왼쪽을 가리키는 발사 순서 제목이 있어 행동 대상과 결과 영역이 구분된다.

`03_planned`에서는 두 회수탄이 탄창에 들어 있고 “첫 발 · 피해 4”와 “장전 확정”이 보인다. `04_ready`에서는 후보가 회색으로 바뀌고 “발사 · 1턴”, “재장전 · 1턴” 버튼이 나타난다. 이 세 원본으로 **현재 단계에서 할 행동의 이름과, 확정 뒤 두 행동의 시간 비용이 유지된 것**을 확인했다. 실제 활성 상태·클릭 결과를 시험한 것은 아니다.

“되돌리기”는 이전의 “최근 장전 취소 · 무료”보다 짧다. 지금 화면에서는 무엇을 한 단계 되돌리는지, 시간이 드는지가 버튼 자체에 명시되지 않는다. 다만 되돌리기를 실제로 두려워하거나 오해한 사용자가 있는 것은 아니다. 첫 사용자에게 최근 한 발 취소와 비용을 설명하게 해 볼 **발견성 가설**로 남긴다. 이 검토만으로 긴 안내를 기본 화면에 다시 넣어야 한다고 제안하지 않는다.

### 적의 조건과 거리

현재 적 HP·장갑·회피·접근 거리는 기본 전장 오른쪽에서 읽힌다. 거리 자체는 적 아래와 전장 눈금에 남는다. `07_final_fixture`의 세 적 정보는 서로 덮지 않으며 몸체와 이름의 순서도 대응한다. 따라서 어떤 적이 가까운지, 관통·명중에 필요한 상대 수치가 얼마인지를 보기 위해 반드시 정보 창을 열 필요는 없다.

최대 HP와 속도 같은 상세 표현은 `10_details`에서 볼 수 있다. 기본 화면의 “접근 3m” 등을 실제 어떤 행동의 비용에 적용해 해석하는지는 정지 화면으로 검증하지 않았다. 단발의 발사·재장전 1턴 사례만 제공됐으므로 다른 총기의 여러 턴 비용까지 이 화면으로 통과 판정하지 않는다.

### 탄환 수치와 상세 정보

후보 카드에는 준비탄의 “다음 탄 관통 +3”, “다음 탄 명중 +4”, “다음 탄 피해 +4”, 철갑탄의 “장갑 대응”, 정밀탄의 “회피 대응”처럼 차이를 설명하는 짧은 문구가 남아 있다. 기본 화면 하단에는 “회수탄 피해 4 관통 1 명중 6”이 보인다.

`10_details`는 “탄환 · 현재 총기/파츠 반영” 아래 탄 이름별 피해·관통·명중과 상세 효과를 제공한다. 첫 번째 보이는 탄의 이름과 수치가 연결되어 있고, 적 수치·총기 비용도 같은 창에서 확인할 수 있다. 정보가 단순히 삭제된 것으로 판단하지 않는다.

반면 이 원본들만으로는 카드에 마우스를 올리거나 선택할 때 하단 수치가 어떻게 바뀌는지 알 수 없다. **여섯 탄의 수치가 동시에 기본 노출되지 않는 것은 관찰 사실**이고, 그 때문에 필요한 비교가 느려지거나 “정보” 버튼을 찾지 못한다는 것은 가설이다. “장갑 대응”이라는 역할명만으로는 현재 장갑을 통과할 정확한 관통값을 알 수 없으므로, 해당 탄의 수치를 장전 전에 찾을 수 있는지를 우선 확인할 필요가 있다.

### 보상 선택

`05_reward`에는 다음 교전의 적 수치, 현재 덱 개수·파츠 상태, 두 보상 카드와 각각의 효과·피해·관통·명중이 보인다. 추가·현재 구성 유지·특정 탄 제거가 다른 버튼으로 구분된다. 제거가 보상 하나를 대신 쓴다는 설명도 유지된다.

수치 중복 없이 카드 한 개당 한 세트의 수치를 읽을 수 있고, 제공 화면에서 보상 효과나 제거 비용을 가리는 요소는 없다. 기존 덱 전체의 수량·조합을 이 화면에서 얼마나 빠르게 비교하는지, 보상을 고른 이유와 포기한 대안의 비용을 실제로 이해하는지는 별도 플레이 확인이 필요하다.

## 잘림과 작은 창

제공된 기본 화면과 보상 화면에서는 탄 이름·주요 행동 버튼·적 필수 수치가 화면 밖으로 잘리거나 서로 덮이는 현상을 발견하지 못했다.

`09_small_window`에서도 한 적의 이름과 조건, 여섯 후보, 네 슬롯, 장전 확정 버튼, 하단의 현재 탄 수치가 화면 안에 보인다. 텍스트는 작아지지만 영역끼리 겹치지 않는다. 이 원본은 **한 적·빈 탄창** 상태다. 작은 창의 세 적 전장이나 준비탄 연결·피격 문구가 동시에 나타난 상황까지 검증했다고 하지 않는다.

`10_details`는 상세 정보가 많아 하단의 후속 내용이 첫 화면 밖에 있다. 오른쪽 스크롤바와 X·OK 버튼은 보이고, 현재 보이는 항목의 이름과 수치가 모달 테두리에 잘리지는 않는다. 스크롤로 모든 후속 항목에 접근할 수 있는지는 직접 조작하지 않았다. 기본 전투 화면을 가리는 것은 열린 모달의 표시 상태이며, 그것만으로 가림 결함으로 분류하지 않는다.

## 우선 확인할 사항과 판정 경계

명백한 표시 결함의 재현 증거가 없어 이번 원본만으로 필수 코드 수정을 요청하지 않는다. 텍스트 감소가 플레이 판단을 방해하지 않는지 다음 두 가지를 짧게 확인하는 것이 적절하다.

1. 처음 보는 사람이 장갑이 높은 적 앞에서 철갑탄의 실제 관통값, 회피가 높은 적 앞에서 정밀탄의 실제 명중값을 **장전 전에** 찾을 수 있는지. 하단 수치 갱신 경로와 “정보” 버튼의 발견성을 확인한다. 찾지 못하는 경우에만 해당 경로의 표시를 작게 보완한다.
2. 두 발을 계획한 사람이 되돌리기로 무엇이 바뀌고 비용이 드는지, 확정하면 다음 행동이 무엇인지 설명할 수 있는지. 필요한 경우 짧은 버튼 문구나 해당 상태의 설명을 검토한다.

밀도 감소와 주요 수치·행동의 노출은 확인됐다. 실제 사용자의 부담 감소, 비교 속도, 학습 성공, 클릭 수, 반복 피로와 재미는 **인간 확인 필요**다. UI의 실행 기능 전체를 검증한 보고가 아니며, 이 결과를 게임 전체의 UX 통과로 확대하지 않는다.
