## 결론

아트 전에 고쳐야 할 재현된 기능 문제는 **연발 넉백 상한 우회**다. 현재 2칸 상한을 선제탄 효과와 언더플로우 파츠가 각각 우회해 4칸 넉백을 만든다. 이 결과만으로 무한 넉백 락이 입증된 것은 아니다. 하지만 이미 선언된 제어 상한을 어기는 실제 동작이며, 스탯 튜닝보다 먼저 정산 순서를 고쳐야 한다.

이번 집중 검사에서 새 경제 계산 오류나 맵 연결 결함은 발견하지 못했다. 단, 기존 9총기×13적 검사의 성공 조건은 생존이나 처치를 보장하지 않으므로, 이를 완주 밸런스 인증으로 사용할 수 없다.

## 재현된 문제: 연발 넉백 2칸 상한 우회

두 총기 `smg`(Tempo), `suppressor`에서 같은 결과다. 실제 리소스 `neuro_caster`(HP 12, SPD 0, 넉백 저항 0)를 사용했다. 거리 변화는 이동이 없는 적으로 측정하고, `enemy_knocked_back` 이벤트도 함께 수집했다. 임의 적 스탯이나 런타임 강제 조작은 사용하지 않았다. 전술탄은 합법적인 부분 장전이다.

| 발사 순서 | 파츠 | 실제 넉백 이벤트 | 총 거리 증가 | 결과 |
|---|---|---|---:|---|
| 충격 | 없음 | `[2]` | 2 | 대조군 정상 |
| 선제 → 충격 | 없음 | `[2, 1, 1]` | 4 | 상한 우회 |
| 충격 | 언더플로우 | `[4]` | 4 | 상한 우회 |

원인 위치(감사 시점):

1. `combat_manager.gd::_apply_post_hit_effects`의 `OPENING_SHOT`은 `target.apply_knockback(bullet.effect_value)`를 직접 호출한다. 버스트 예산을 소모하지 않는다.
2. `_fire_internal`의 일반 넉백은 먼저 `_burst_knockback_budget`으로 제한하고, 그 다음 `UNDERFLOW`가 `kb *= 2`를 적용한다. 제한 이후 증폭되어 실제 적용량이 상한을 넘는다.

수정 기준:

- 최종 적용되는 주 대상 넉백이 동일한 버스트 예산을 거치도록 정산을 통일한다.
- 선제 효과, 파츠 배율, 저항 적용 순서를 명시하고 예고 계산과 일치시킨다.
- 기존 단발 총기의 선제·언더플로우 효과와 저항 동작을 보존한다.
- 위 6개 실제 리소스 사례를 회귀 검사로 고정한다. 확산·처치 후 넉백도 상한 계약의 적용 범위를 함께 확인한다.

## 실제 실행한 기존 검증

아래 5개 스위트를 집중 실행한 합계는 **185 통과 / 0 실패 / 0 경보**다. 전체 3,655개 스위트의 중복 실행은 하지 않았다. 부모 작업의 전체 회귀 결과와 합산하지 않는다.

- `suite_full_run`: 구역 맵 도달성, 적·보스 전투 코드 종결.
- `suite_ammo_specialization`: 9총기×13적, 기본/환기구 조건의 첫 탄창 유효 변화 존재.
- `suite_ascension`: 누적 압박, 해금, 저장, 자원 바닥선.
- `suite_difficulty_curve`: 35층 거리 밴드, 스탯 비인플레 계약.
- `suite_parts`: 대표 파츠의 전투 적용.

초기 직접 엔진 실행은 종료 코드 0이었다. 경제 프로브 추가 후 실행에서도 스위트 185/0/0과 JSON 생성을 확인했다. PowerShell의 `2>&1 | Select-Object`를 사용한 두 번째 래퍼는 엔진의 루트 인증서 저장소 경고를 stderr로 받아 래퍼 종료 코드 1을 반환했으므로 이를 게임 회귀 실패로 합산하지 않았다. 네트워크 기능은 감사하지 않았다.

## 경제: 상수를 재계산하는 대신 실제 메서드 확인

기존 `suite_difficulty_curve`의 메타 비용/수입 검사는 숫자를 테스트 내부에서 직접 계산한다. 따라서 독립 프로브에서 실제 구매 함수와 정산 함수를 호출했다.

## 완주·해법 보장의 정확한 범위

코드 감사로 확인한 검증 한계다. 게임의 불가능한 전투가 새로 재현되었다는 뜻은 아니다.

- `suite_full_run::_encounter`는 리로드 없는 한 탄창 검사이고, `out_of_ammo`도 정상 종결로 인정한다. 따라서 보스 격파와 35층 실제 완주를 입증하지 않는다.
- `suite_ammo_specialization::_safe_progress`는 적 HP/배리어/DEF/EVA/거리 중 하나가 유리하게 변하면 성공이다. 그 뒤 플레이어가 죽어도 성공이 될 수 있다. 함수 이름과 달리 안전한 생존을 요구하지 않는다.
- 승천 검사의 최소 사격 기회는 대표 적 3종의 개별 시작 거리 기준이다. 마지막 계층 거리 감소, 환기구, 다중 적 조합, 빌드 자원까지 합친 완주 가능성은 별도 검증 대상이다.
- `qa_campaign_replay_runner.gd`는 명시적인 승리 fixture를 사용하고 첫 두 계층까지만 이동한다. 전투 난이도나 35층 완주 증거로 취급하지 않는다.

아트 이전 기능 완료 판정에는 기존 구조 검증을 유지하면서 실제 전투 정산을 통한 캠페인 샘플의 출처·시드·빌드·승천·종료 이유를 남겨야 한다. 패배 샘플은 즉시 밸런스 결함으로 분류하지 말고, 공개 정보로 다른 해법이나 경로가 있었는지 확인한다. 사람의 조합 성공감·피로는 자동 검사의 대체 대상이 아니다.

## 후속 유한 탐색: 실제 초반 패배 2표본의 승리 반례
