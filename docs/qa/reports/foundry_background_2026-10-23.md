# 축열 주조장 — 높이별 전투 배경

2026-10-23. 사용자 ‘진행해 줘’에 따라 이전 단계에서 제안한 2구역 전용 배경 3장을 제작하고 본편에 적용했다. 디자인은 디렉터 구현안이며 사용자 미감 승인은 아직 받지 않았다.

## 적용 결과

| 진행 구간 | 풍경 | 전투 화면 |
|---|---|---|
| 초반 1~3 | 자재 반입 통로: 멈춘 운반 케이지, 금형 적재대, 작은 작업등 | [1280×800](assets/foundry_background_2026-10-23/stage0_1280.png) |
| 중반 4~6 | 압력·금형 작업장: 굵은 배관, 피스톤과 프레스, 주황 점검창 | [1280×800](assets/foundry_background_2026-10-23/stage1_1280.png) |
| 상층 7~9 | 대형 주조로 제어부: 원통형 설비, 조절륜, 잔열이 남은 하부 노체 | [1280×800](assets/foundry_background_2026-10-23/stage2_1280.png) |

숫자는 현행 경로의 내부 진행 위치이며 화면에 층수로 추가하지 않는다. 공통 `ascent_background.gd` 규칙에 region 1의 세 자산을 등록했다. 같은 높이의 분기는 같은 그림을 사용한다. 이전 맵 버전도 자기 길이를 3등분한다. 배경용 저장 필드/RNG/전투 수치는 추가하지 않았다. 기존 저장의 적 편성은 그대로이며 배경만 새로 표시한다. 3~5구역의 전용 환경과 지역별 지도 배경은 이번 범위가 아니다.

## 제작·등록

- 내장 `image_gen`으로 각 1회 생성했다. 승인 주거 통로 원본과 실제 주조장 전투 화면을 실제 이미지 입력으로 전달했다. 첫 이미지는 화풍, 두 번째는 배우·HUD가 놓이는 영역의 참조다. 그림에 배우/UI를 넣지 않았다.
- [전체 프롬프트·참조·SHA256·원본 위치](../../art/foundry-ascent-20261023.json).
- 게임 자산: `새-게임-프로젝트/assets/art/foundry_ascent_20261023/{lower,middle,upper}_v1.png`.
- 모두 1672×941 RGB 원본을 그대로 복사했다. 그림 편집/축소/팔레트 후처리 없이 Godot에서 표시 영역을 잡았다. 등록한 지면 y는 702 / 713 / 713이다. 기존 배우 크기·위치와 거리 배치를 유지했다.
- 큰 청회색 면, 어두운 철골, 소량의 주황 열원을 사용했다. 밝은 열원은 주로 왼쪽/중앙 깊은 설비에 두고 적이 서는 오른쪽은 차분하게 유지했다. 원화 전체를 다 보이게 늘이지 않고 실제 전투 띠 안에 보이는 하부 구조로 장소를 구별한다.

## 기능 검증

Godot 4.7, Compatibility, seed 731042, QA 저장 `qa_runtime/foundry_background/` 및 기존 `qa_runtime/ascent_background/`. 사용자 저장을 사용하지 않았다.

- 1280×800 / 1008×630 / 1440×630에서 3단계와 정예 축압 상태 렌더 12장, 보스 피니시 1장.
- 새/이전 맵의 높이·분기 일치, 이전 편성6 실제 첫 노드 입장→격리 저장/복원, 배경 교체 전후 전투 상태/RNG/배우 발 위치 동일.
- 그림 영역이 PNG 내부에 있고, 등록 지면과 주인공/적의 발 위치가 일치. 본문 스크롤 넘침 없음. 본편 적 아트와 HP 영역의 화면 경계/겹침 검사.
- 실제 장전→확정→발사→재장전 후에도 현재 배경 유지. 재장전은 실제 계산 모델과 비교했다.
- 좁은 화면에서 개발 메뉴를 스크롤해 세 버튼을 터치, 해당 전투/배경 진입 및 저장 방지 확인.
- 피니시 검증만 보스 HP1/호위 없음으로 만든 연출용 조건이다. [확대 중 화면](assets/foundry_background_2026-10-23/boss_finish.png)에서 배경·발판·보스가 함께 확대되고 대미지가 앞에 표시됨. 실제 난이도 통과 증거가 아니다.
- 최초 QA는 구형 보스 직접 점프 시연을 저장 복원 대상으로 사용해 실패했다. 정상 등반의 도달 이력이 없는 개발 시연이므로, 구형 입구에서 실제 선택 가능한 노드로 입장한 저장을 검증하도록 수정했다. 게임 저장 검증을 완화하지 않았다.
- 최종 stderr와 에디터 가져오기 로그에 스크립트 오류 없음. [새 검사 출력](assets/foundry_background_2026-10-23/stdout.log), [주거 회귀 출력](assets/foundry_background_2026-10-23/residential_regression.log).

재실행: `tools/run_foundry_background_checks.ps1`, `tools/run_ascent_background_checks.ps1`.

## 시각 검수·남은 확인

실제 캡처 13장을 열어 확인했다. 적/체력/거리의 판독 영역, 지면 접지, 배경 구조물의 크기, 가로가 긴 화면의 잘림과 피니시 상태를 확인했다. 넓은 화면에서는 상부 조절륜 일부가 잘리지만 주조로 하부가 남아 상층 장소를 구분할 수 있다. 배경은 새로 움직이는 설비 애니메이션이 아닌 정지 원화이며 기존 환경 입자를 사용한다.

기능 통과와 내부 시각 검수는 완료했다. Galaxy 실제 기기의 밝기·성능, 사용자의 미감/장소 구별 체감은 미확인이다. 이번 작업은 밸런스를 바꾸지 않았으므로 압쇄 탄약 부담이나 새 편성의 전체 지역 연속 플레이가 해결됐다고 판단하지 않는다.

## 바로 확인

`PLAY.cmd` → 메인 **개발** → **주조장 배경 · 초반 / 중반 / 상층**. 초반/중반은 1구역 통과 덱, 상층은 보스 지점까지 도달한 실제 획득 덱을 사용한다. 개발 시연은 정상 저장을 덮어쓰지 않는다. 정상 플레이에서 2구역에 도달해도 자동 적용된다.

APK·커밋·푸시·외부 게시·PC 종료는 이번 요청에 포함되지 않아 실행하지 않았다.
