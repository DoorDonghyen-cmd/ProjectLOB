# 정비소 승인 시안 본편 연결 — 2026-11-04

사용자가 가장 좋은 결과로 평가한 [작업 장면/탭 시안](workbench_theme_2026-11-04.md)을 실제 정비소에 연결했다. 작업대·배우·먹색/아이보리/황동·5탭·작은 보유 탄 목록을 유지하면서 실제 후보와 게임 명령, 완료/지도 복귀 및 자동 저장을 연결했다. 전투 계산·정비 가격/횟수·탄환 수치·저장 형식을 변경하지 않았다. 결과창·상점·캐릭터 선택의 배치도 이번 범위에 포함하지 않았다.

시안은 표시 예시20발/5종이고 본편 캡처는 현재 규칙으로 시작한 시드17·연발총·운반 복장의 실제 보유20발/2성능이다. 수치/탄종 개수가 다른 것은 실제 데이터 연결 결과다. 나란히 이미지는 각1280×800 원본을 축소/보정 없이 배치하고 제목만 화면 밖에 붙였다.

기존 장소 그림·복장별 배우·탄환 아틀라스를 그대로 사용했다. 승인 시안의 따뜻한 재질/Theme를 제품 폴더로 옮겼으며 새 이미지 생성이나 원본 비트맵 수정은 없다. 첨부 레퍼런스의 픽셀을 게임에 복사하지 않았다.

## 실제 흐름

`map → modern workshop supply → 작업 탭/보유 탄 선택 → 변화 확인 → 작업 확정 → 같은 작업대의 완료 표시 → 지도`.

| 작업/입력 | 현재 데이터 연결과 검증 |
|---|---|
| 탄종 교체 | 실제 `workshop_ammo_options()` 전체 후보 + 실제 보유 성능별 선택. 들어올1발/내보낼1발을 확인하고 기존 `resolve(refit)` 실행. 동일 성능 교체 등 불가 상태는 확정 차단. |
| 탄환 압축 | 실제 `compressible_ids()`와 압축 결과. 같은 성능2발 → 압축1발, 피해/발열/점유 변화. 최소 보유 제한 적용. |
| 탄환 개조 | 기존 화력/방열 두 경로, 실제 `Variants.tuned()` 결과 및 `tune(index, mode)` 사용. 선택 사본1발만 변경. |
| 덱 정리 | 선택 성능1발 제거. 복장별 실제 최소 보유 수를 표시하고 제한에서 확정 차단. |
| 가방 확장 | 현재 복장/구역의 실제 `can_grow_bag()` 및 실제 명령 실행 뒤 상한을 비교. 탄약을 지급하지 않음. 제한 사유와 기존 저장의 규칙 유지. |
| 선택/취소 | 탭/보유 탄/후보 선택은 UI 상태만 변경. `선택 취소`는 선택을 비우고 탄환 작업 확정을 비활성화. 가방은 탄 선택이 필요 없어 취소 버튼을 표시하지 않음. |
| 무료 횟수/완료 | 기존 다섯 작업 중1회만 사용. 확정 뒤 실제 결과 메시지·보유 탄 갱신, 추가 작업 차단. 완료 저장을 불러와도 같은 화면에서 나가기 가능. |
| 작업 없이 나가기 | 미해결이면 기존 `resolve(skip)`와 `leave()`를 순서대로 실행. 탄 보유량 유지 및 지도 상태 자동 저장. |
| 보조 메뉴 | 기존 빌드·기록·설정·타이틀 접근. 해당 기능의 기존 창을 사용하며 열람만으로 정비를 쓰지 않음. |

미리보기는 현재 Campaign/Model/Profile의 메모리 복제에 **같은 실제 명령**을 실행한다. 파일 저장이나 현재 상태 변경은 하지 않는다. 후보 자동 선택은 읽기 전용 적격성 함수로 고르고 실제 미리보기는 선택 갱신 때 한 번 계산한다. 확정 직전도 현재 상태에서 재검사한 뒤 기존 `screen._campaign_action()`을 호출한다. 창 크기/설정 재렌더 시 선택한 탭·내보낼 탄·받을 탄을 유지한다.

## 구성과 화면 대응

정식 씬은 `redesign/workbench/screen.tscn`이며 에디터에서 실행 전에도 장면·탭·대표 탄·변화 정보가 보인다. 반복 보유 탄과 교체 후보는 각각 `item.tscn`/`candidate.tscn`, 외형은 `theme.tres`, 실제 바인딩은 `screen.gd`가 맡는다. `campaign_ui.gd`는 실제 정비소에서 이 씬을 호출하고, `screen.gd`는 이 화면에 기존 안전 영역을 제외한 추가 바깥 여백을 주지 않는다.

제목32/나머지16px, 행동 높이44, native/정수 배율을 유지한다. 같은 탄종명이라도 성능 ID가 다른 탄은 나누고 대표 성능/수량을 표시한다. 우측은 정보 내부만 스크롤하고 행동은 고정한다. 전투 전체 설명과 중복 발열 문구는 기본 정보에서 제외하고 선택한 탄의 효과·변화/제약을 보여 준다. 기존 저장 오류 메시지도 노출한다.

검사한 창은1280×800,1008×630,844×390,2340×1080,2160×1032. S26 기본형 비율은 논리1170×540에서 전체가 보인다. 이 정비소의 최소 논리 높이는540이므로844×390이나 감소 영역2160×1032에서는 바깥 세로 스크롤이 생길 수 있다. 글자/버튼을 축소하거나 다른 화면의 배치를 변경해 맞추지 않았다. 긴 보유/교체 목록은 가로 스크롤로 접근한다.

시각 확인 중 S26비율의 교체 후보와 작업대 탄이 겹치는 것을 발견해 후보만72px 높이의 간결한 항목으로 정리했다. 최종 캡처와 5크기 배치 검사에서 서로 겹치지 않는다. 기존 기능을 유지하는 보조 메뉴와 선택 취소가 승인 시안에 추가됐으며, 수치는 전부 예시 대신 현재 모델을 읽는다.

## 검증

모든 실행은 `qa_runtime/`의 격리 APPDATA/LOCALAPPDATA에서 수행했다. 사용자 진행 저장을 QA에 사용하지 않았다. 장소 화면에 도달하기 위한 전투 완료는 명시적인 화면 준비 fixture이며 사람의 등반/승리 기록이 아니다.

|---|---|---|
| `tools/run_workshop_ui.ps1 -Label workbench_complete` | 2,057확인, 실패0 | 5크기×3글자 설정, 5작업/화력·방열 터치 확정, 미리보기/취소 무변화, 저장 일치/완료 복원, 보류/지도 복귀, 제한/대량 목록, 실제 창 변경/선택 유지, 키보드 탭 선택, 기존 보조 메뉴 |

최종 실행 로그에서 새 파싱/실행 오류 없음. 기존 지도/캡처 검사의 정비소 식별과 나가기 입력도 새 화면에 맞췄다. 과거 폐기된 정비 기능/배치를 전제하는 역사적 UI 검사 전체를 실행한 것은 아니다. 신규 정비소 검사가 현행 5작업과 기존 현대 장소 저장을 담당한다.

중간 보조 메뉴 검사에서 설정을 Workspace로 가정한 부분은 기존 설정 모달/닫기 경로로 고쳤다. 타이틀 버튼은 `Title` 라벨과 구분되는 `ReturnTitle` 이름으로 명확히 한 뒤 공개 입력으로 재검사했다. 최종 실패0이며, 이 중간 실패를 제품 규칙 변경으로 해결하지 않았다.

## 실행과 남은 범위

본편은 저장소 루트 `PLAY.cmd`로 실행하고 지도에서 정비소에 진입하면 새 화면을 사용한다. `OPEN_WORKBENCH_UI_PREVIEW.cmd`는 승인된 **표시용 시안**을 보존한 실행 경로이므로 실제 정비/저장 테스트 경로와 다르다.

Android/S26 실기기 안전 영역·터치 체감·지속 성능은 미검증이다. 이번에 실제 손/작업물 근접 원화나 압축/교체 애니메이션을 추가하지 않았다. 사용자 미감 승인은 시안에 관한 것으로, 이번 본편 기능 연결 후의 사용자 플레이 확인은 별도다. 다음 UI 대상은 결과창→상점의 기능/장소에 맞는 구성. APK·커밋·푸시·외부 게시 없음.
