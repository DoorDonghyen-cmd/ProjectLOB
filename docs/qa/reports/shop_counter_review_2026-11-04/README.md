# 카운터 상점 시안

[본편과 시안 비교](compare_1280x800.png)는 왼쪽이 기존 본편, 오른쪽이 별도 Godot 시안이다. 두 화면 모두 1280×800, 18 Cr 보유 상태에서 열축전 코일을 선택했다. [상인 유무를 같은 상품으로 비교](compare_counter_1280x800.png) · [상품 3개 진열](stocked_1280x800.png) · [S26 가로 진열](stocked_2340x1080.png) · [S26 안전 영역 크기에서 탄 교체](replacement_2160x1032.png).

## 실행

저장소 루트의 `OPEN_SHOP_COUNTER_PREVIEW.cmd`를 연다. F1은 첫 할인과 잔액 부족, F2는 상품 세 개가 모두 있는 진열, F3은 가방 한도와 교체, F4는 장착 슬롯이 찼을 때 구매 후 보관이다. 기본 진입은 F2다. ‘시안 초기화’는 현재 예시를 처음 상태로 되돌린다.

## 디자인과 데이터

- [상점 레퍼런스](../../../art/references/2026-11-04-ui/shop-followup.md)의 진열·가격표의 위치를 실제 상점 원화에 적용했다. 카운터 상판에 판매품과 받침을 두고, 가격표는 바로 밑에 놓았다. 선택 상품의 효과, 보유 수량이나 장착 슬롯, 결제 후 잔액은 화면 하단 한 곳에서 확인한다.
- 기존 상점 배경과 탄환·파츠 아트를 사용한다. 구역마다 같은 인물이 보이는 어색함을 줄이기 위해 상인 그림과 상인 이름을 제거하고, 카운터 중앙 조명 아래에 세 상품을 모았다. 현재 시안은 공통 배경에 구역별 장소 이름과 해당 상점 재고를 표시한다. 배치 원본은 `redesign/samples/shop_counter_review/preview.tscn`과 `offer.tscn`이다.
- 기존 플레이 기록의 상점 스냅샷을 메모리로 복원한다. F3은 그 스냅샷의 가방만 기존 탄으로 채운 통제 사례다. 구매·탄 교체·새 진열은 실제 Campaign 명령을 실행하고 저장은 만들지 않는다. 본편 상점은 기존 화면을 사용한다.
- 이번 시안은 진열과 구매 확인에 집중한다. 본편 반영 시 탄환 가방, 파츠 관리, 지도 복귀, 구버전 저장의 압축 서비스, 저장 실패 표시와 같은 기존 연결을 함께 검증한다.

## 검증

`OPEN_SHOP_COUNTER_PREVIEW.cmd -Capture`에서 **349개 검사, 실패 0건**. 1280×800, 2340×1080, 2160×1032에서 가격 할인, 구매 불가, 장착·보관, 품절 진열, 새 진열, 한도 교체와 취소를 실제 터치 이벤트로 확인했다. 버튼 크기, 가시 영역, 한글 글리프, 격리 저장 미생성을 검사했다. Godot MCP로 프로젝트를 확인하고 실제 렌더는 로컬 Godot 4.7에서 실행했다. Android 실기기와 본편 연결은 후속 범위다.
