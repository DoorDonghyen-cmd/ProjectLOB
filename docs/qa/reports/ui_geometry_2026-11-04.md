# 기존 UI 복원 후 배율·최소 높이·여백 점검 — 2026-11-04

사용자는 캐릭터 선택의 스크롤을 정상 동작으로 정정했고, 이번 모바일 스크롤 대응을 전부 되돌린 뒤 기존 배치에서 수치부터 점검하도록 지시했다. **이번에는 게임 코드·씬·글꼴·배치·수치를 수정하지 않았다.** 목록 스크롤이나 화면 높이 초과 자체를 결함 판정으로 사용하지 않았다.

## 복원과 점검 범위

- 이번 대응 직전 스냅샷과 현재 게임·검사 파일 **743개가 바이트 단위 일치**한다. 새 compact 화면·프레임·검사 파일도 본편에서 제거되어 있다. 이전에 완료한 가독성·코어/전투 수정은 포함된 상태다.
- Godot MCP 프로젝트 조회 정상, Godot 4.7 확인. 기존 `ui_readability_ui.gd`를 상속한 임시 진단 스크립트는 `qa_runtime/`에만 두었다. 제품 파일을 바꾸지 않고 실제 노드의 배율·경계·최소 크기·스크롤 범위·여백을 수집했다.
- 1280×800, 1008×630, 844×390, 2340×1080, 2160×1032의 5개 PC 창 크기 × 21개 화면 상태 = 105개 캡처/측정. 상점 구매·저장·상세·지도 이동·전투/메뉴 복귀도 기존 검사로 실행했다.
- **9,734검사 실패 0**, stderr 비어 있음. 캐릭터 선택·두 폭의 상점 캡처를 직접 검수했다. 이는 Android 실기기·손가락 체감 검증이 아니다. 2160×1032는 가용 화면 감소를 살핀 PC 창이며 실제 Android 안전 영역을 재현한 결과로 표시하지 않는다.
- 보급/작업실/이벤트는 기존 QA의 장소 fixture, 상점·관문·전투는 기존 실제 획득 저장 fixture를 사용했다. 보상 화면은 명시적인 승리 상태 fixture이며 이번 자동 실행을 실제 등반 승리로 세지 않는다.

## 배율

비전투 화면의 `scale_for()`는 `max(1, floor(min(가로/1008, 세로/454)))`다. PC 1280×800·1008×630·844×390은 1배, 2340×1080은 2배여서 논리 공간 1170×540, 2160×1032는 2배여서 1080×516이었다. 상점 내부 Canvas는 1배다. 비전투 화면의 검사 대상 글자는 16px 배수였고 가로 스크롤 초과는 없었다.

기존 검사에서 창 크기 변경과 전투→메뉴→이어하기 뒤 배율 복원 및 저장 불변을 확인했다. **검사한 PC 경로에서는 잘못된 배율 잔류를 재현하지 못했다.** Android의 디스플레이 크기 설정·내비게이션/컷아웃 안전 영역·실제 출력 크기는 아직 미검증이다. 공통 안전 영역의 좌표 변환 수학 검사는 통과했지만 이것만으로 실기기 처리를 완료 판정하지 않는다.

## 최소 높이와 여백

아래는 2340×1080 창, 2배/논리 높이 540에서 측정한 값이다. 단위는 논리 px이며 넘침은 페이지 전체의 이동 범위다. 내부 목록 스크롤과는 별도다.

| 화면 | 전체 콘텐츠 높이 | 페이지 이동 범위 | 주된 구성 |
|---|---:|---:|---|
| 캐릭터/장비 선택 | 617 | 77 | 전시 영역 336 + 헤더 48 + 무기 선택 113 + 하단 54 + 간격 30 + 상하 여백 36 |
| 상점 | 854 | 314 | 헤더 58 + 상단 정보 236 + 상품/상세 324 + 하단 162 + 간격 42 + 상하 여백 32 |
| 이벤트 | 583 | 43 | 기존 장소·선택·이동 구성 |
| 작업실 | 791 | 251 | 장소 165 + 작업 선택 396 등 |
| 보급 | 715 | 175 | 기존 보급 선택 구성 |
| 관문 개조 | 848 | 308 | 상태줄 78 + 소개 96 + 개조 영역 614 + 간격 20 + 상하 여백 40 |
| 관문 재정비 | 770 | 230 | 기존 정비·장비 정보 구성 |

- **캐릭터 선택:** 오른쪽 복장 목록은 내용 594/표시 276으로 내부 이동 범위 318이다. 이 목록 스크롤은 유지 대상이다. 최초 생성 코드의 `620`은 후속 계산으로 **617**이 되므로, 앞서 이를 단순히 “620 고정값 때문”이라고 설명한 것은 불완전했다. 실제 원인은 기존 구성 요소의 최소 높이 합이다. 1280×800에서는 전체 페이지 스크롤 없이 내부 목록만 스크롤한다.
- **상점:** 상품 카드와 행의 최소 높이는 324, 이야기 영역은 180이다. 조사한 선택 상품의 상세 내용 최소 높이는 여백 포함 226이지만 패널은 324라 내부 가변 공백이 98 남았다. 상품 카드도 조사한 상태에서 내용 최소 240에 비해 카드 높이 324로 84의 여유가 있었다. 긴 상품명·설명이나 큰 글씨 설정의 필요 공간을 재확인하기 전에는 이 차이를 모두 제거 가능한 낭비로 단정하지 않는다.
- **상점 폭 조건:** 논리 폭 1100 미만에서 기존 코드가 상품/상세를 세로로 배치한다. 가용 폭 감소 조건에서는 전체 높이가 854→1118, 페이지 이동 범위가 314→602로 늘었다. 이는 배율 오류가 아니라 기존 반응형 분기와 최소 높이의 합이다. 이번에 이 분기나 배치를 변경하지 않았다.
- **여백:** 장비 선택 좌우 28/상하 18, 상점 바깥 16, 일반 장소/관문 바깥 20을 확인했다. PC 검사에서 공통 바깥 여백이 중복 적용되는 오류는 발견하지 못했다. 상점 바깥 상하 여백 32를 전부 제거해도 282가 남으므로 여백만으로 모든 스크롤이 없어지지는 않는다. 내부 프레임의 추가 여백은 별도 존재하며 현재 디자인 구성으로 유지했다.

## 후속 판단

캐릭터 선택의 정상 목록 스크롤을 제거하거나 탭/버튼 위치를 바꾸지 않는다. 필요하다면 **상점의 기존 고정 높이와 가변 공백**을 먼저 검토하고, 긴 설명/큰 글씨까지 포함해 줄일 수 있는 수치를 제시한다. 글로벌 배율 변경이나 모든 화면을 한 화면에 억지로 맞추는 작업은 이번 점검의 결론이 아니다. 다른 구간의 스크롤도 콘텐츠 길이와 조작 불편을 구분해 판단한다.
