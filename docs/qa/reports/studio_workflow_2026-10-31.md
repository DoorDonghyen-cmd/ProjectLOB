# 프로젝트 전반 개발 절차 선별 반영

2026-10-31. 사용자가 Claude Code Game Studios 검토 뒤 UI 이외의 프로젝트 전체에 도움이 되는 항목을 반영하도록 승인했다. **기존 스킬·작업 절차에 반영했다. 게임 기능·규칙·기본 진입·APK는 이 작업에서 변경하지 않았다.**

## 실제 반영

| 영역 | 적용 위치와 결과 |
| --- | --- |
| 실험과 다음 결정 | [개편·검증 기준](../../direction/development-workflow.md)에 질문/근거/비교 조건/유지·수정·보류 연결. 사용률 대신 선택 이유와 대가를 평가 |
| 본편 통합 | [탄창 여정](../../direction/magazine-journey.md#본편-연결-판단-조건)에 여섯 판단·통합 조건과 현재 증거/미검증을 실제로 기입 |
| 사람 플레이 | [여정 기록지](../protocols/magazine-journey-playtest.md)에 공개 정보·선택 이유·보상 전후 변화·긴장감과 기존 로그의 한계 연결 |
| 변경 영향 | 실제 모델/예측/적 행동/성장/저장/문구·사운드의 연결에 기존 검사 파일을 대응 |
| 모바일 | [지속 검증 절차](../protocols/mobile-sustained.md)에 같은 기기의 초기/후반, 프레임·지연·메모리·온도·충전 조건, 앱 종료/복귀·저장 업데이트 포함 |
| 전투·경제·피드백 | 조우의 다른 판단 요구, 획득 전후 선택, 소비처/가격/건너뛰기, 소리의 의미·시점·동시 효과 우선순위 보강 |
| QA·전달 | 관련 코드 상태와 증거 연결, 의미 있는 회귀 검사, [기존 APK 전달](../../mobile-delivery.md)과 실기기 결과 분리 |

역할은 기존 8개(`00`, `08`, `09`, `10`, `12`, `14`, `15`, `16`)를 보강했다. 활성 체크아웃의 스킬 원본과 작업공간 검색용 사본을 동일하게 맞췄다. 라이선스·출처 2개를 포함해 동기화한 파일은 10개다. `game-feel` 등 기존 외부 스킬 원문/설정은 변경하지 않았다.

원본은 [Claude Code Game Studios, 고정 커밋](https://github.com/Donchitos/Claude-Code-Game-Studios/tree/05ad7c8a5b8aa2aa86bbd3439ae7cf7295cac418), framework 1.2.0이다. [참조 항목과 적용 범위](../../../.agents/skills/THIRD_PARTY_NOTICES.md), [MIT 고지](../../../.agents/skills/CCGS_LICENSE)를 보존했다. 원본 전체 설치, Claude hooks/도구·모델 설정, 자동 위임, 파일별 승인, 별도 GDD/ADR 원본, 실제 모델 재사용 금지/전면 재작성, assert 개수 기준은 도입하지 않았다.

## 내용 검토

아래는 작성자가 실제 파일·지시와 대조한 절차 검토이며 독립 에이전트 테스트나 플레이 결과가 아니다.

| 요청/상황 | 적용 후 판단 |
| --- | --- |
| 빼내기를 적게 쓴다 | 빈도만으로 실패 처리하지 않고 그대로 사격한 이유·기회·탄 소모의 대가를 조사. 사용 강제 수치 변경 없음 |
| 비교판 기능 검사를 통과했다 | 연속 성장의 사람 체감, 다른 조건/저장/전달 경로의 미검증을 유지. 자동으로 본편 활성화하지 않음 |
| PC에서 빨라졌다 | 모바일 지속 성능·기기 온도는 미측정 유지. 같은 기기의 실제 초기/후반 비교가 필요 |
| 최신 연속 여정 APK가 필요하다 | 현행 `campaign`/`weapon-magazine` 도구에 여정 지원이 없음을 표시. 요청 시 지원 연결·포함 리소스 검증 후 전달; 독립 비교를 여정으로 오표기하지 않음 |
| 타격감/경제를 보강한다 | 기존 소리·실제 계산·획득 상태를 사용. 추가 효과 수나 피해 수치만으로 개선을 주장하지 않음 |
| 작은 문구/배치 수정이다 | 관련 영향만 확인. 새 실험 보고서·전체 회귀·정식 출시 절차를 매번 요구하지 않음 |

## 확인과 남은 범위

- 기존 `skill-creator` 검증기로 수정 스킬 8개 형식 통과. 시스템 Python에는 YAML 모듈이 없어 첫 실행이 실패했고, `qa_runtime/` 전용 의존성 폴더에 PyYAML을 설치한 뒤 같은 검증기를 정상 실행했다. 전역 Python 환경은 변경하지 않았다.
- 절차/여정/기록지의 로컬 링크·앵커 18개와 실제 구현·검사 이름 17개를 확인했다. 스킬 검색 사본 10개는 원본 해시와 일치한다.
- 변경 영역의 공백 오류 검사 통과. 문서·스킬 변경이므로 Godot 기능 검사를 새로 돌리거나 기존 검사 횟수를 이번 통과 수로 집계하지 않았다.
- 시작 작업 트리의 기존 변경 654개와 파일 6,759개의 해시를 보관하고 최종 대조했다. 예상한 기존 문서/스킬 16개 수정·신규 5개만 확인됐으며 파일 누락·범위 밖 변경·예상 밖 추가는 없다. 게임 코드·원화·저장/빌드 설정은 시작 상태와 동일하다.

원본 검증 자료는 `qa_runtime/studio_workflow_20261031/`에 있다. 사람의 연속 선택/성장 체감, 최신 HUD 선호, 모바일 지속 성능, 본편 전환은 미완료다. 이번 완료 범위는 그 작업에 사용할 절차·판단 기준과 검색 가능한 역할 스킬의 반영이다.
