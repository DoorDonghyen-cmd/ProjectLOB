# UI 공통 규격 v1·정비소 첫 적용 — 2026-11-04

사용자 실행 승인에 따라 [공통 규격](../../direction/ui-standards.md)과 역할별 Theme/컴포넌트를 만들고 **현행 정비소 기본 화면**에 연결했다. 기존 2열·5작업 순서·중앙 열·장소 아트·선택창 진입 및 기존 게임 규칙을 유지했다. 결과/상점·캐릭터 선택·전투 HUD에는 새 규격을 일괄 적용하지 않았다.

## 실제 변화

| 항목 | 이전 | 적용 |
|---|---|---|
| 글자 | 작업 제목/설명/버튼16/16/16 | 제목32, 조건·설명16, 버튼16 |
| 작업 영역 | 동일 청록 프레임·디더 면 반복 | 낮은 강도의 면과 아래 구분선 |
| 일반 작업 버튼 | 기본216×52 | 내용 폭130×44(현재 문구), 최대216 |
| 가방 확장 버튼 | 설명과 증가량 반복 | 설명에 실제 증가량·조건, 버튼은 ‘확장’96×44 |
| 소개 | 무료 작업 안내 + 선택 권유 | ‘무료 작업 1회’ |
| 주 배치 | 코드에서 Grid/패널/문구/버튼 조립 | 동일 구성의 `workshop_screen.tscn` + 공통 `operation_card.tscn` |

버튼은 글자와 좌우12 여백으로 폭을 정하며 일반 역할 최소96/최대216, 최소 터치 높이44를 가진다. 부모 영역이 넓어져도 늘리지 않는다. 기존 픽셀 글꼴과 라인+도트 자산을 재사용했고 새 그림 생성은 하지 않았다. Primary/Icon 역할도 정의했지만 이 정비소는 동등한 작업 선택이라 일반 ActionButton만 사용한다.

정비소 기본 화면만 역할 Theme를 사용하며 기존 글로벌 `_button()`과 가독성 처리·배율을 바꾸지 않았다. `service_location.gd`의 기존 `decision_layout` 변수를 export하여 새 씬의 편집기 대표 구성을 저장할 수 있게 했다. 다른 장소의 기본값은 그대로 false다. 실제 내용·사용 가능 여부·콜백과 복장은 기존 Campaign에 연결한다.

## 배치 보존

1280×800 및 S26 비율 PC2340×1080의 5개 작업 영역은 **전후 위치·크기 일치**를 확인했다. 1280에서 시작 좌표(190,289)/(646,289), 다음 줄425, 마지막 줄561이며 각 영역444×124다. 버튼 자체의 폭·높이와 내부 활자 비율은 요청대로 조정했다. 계속 행 최소52를 보존하고 내부 버튼 높이44로 맞췄다. 정상 스크롤은 유지한다.

[영역 실측 전후 비교](ui_standard_workshop_2026-11-04/placement_comparison.json). 이전 기하 자료는 직전 공통 가독성 장소 fixture이고, 전후 이미지와 새 기능 검사는 현행 새 등반 fixture다. 두 fixture의 일부 덱 문구 차이를 규칙 변화로 취급하지 않았다. 새 등반 fixture 역시 중간 전투를 강제 완료하여 정비소에 도달한 표시/입력 검사이며 실제 플레이 승리 증거가 아니다.

## 검증

| 실행 | 결과 | 확인 범위 |
|---|---:|---|
| `tools/run_workshop_ui.ps1`과 동일 인자의 격리 QA 실행 | 668검사 실패0 | 편집기 대표 노드, 5크기×3글자 설정, 실제 위계·2열·폭 상한·터치/범위, 작업별 진입/취소, 압축·가방·보류 실행/저장, 비활성, 키보드, 긴 한글, Primary 상태 재질 |
| `tools/run_ui_readability.ps1 -Label workshop_standard` | 9,734검사 실패0 | 기존21상태×5크기, 글꼴/문자/가로 넘침·공개 조작·구매/저장·배율 복귀 |
| `tools/run_prototype_hud.ps1 -Mode ui -Fast` | 11,536검사 실패0 | 기존 전투 HUD 회귀 |

사용자 저장과 분리한 APPDATA/LOCALAPPDATA에서 실행했다. 압축은2장을 소모해 고급1장을 주고, 가방은 상한+2·탄약/Cr 유지, 보류는 구성·Cr 유지하며 실제 공개 입력 이후 저장 복원이 정확히 일치했다. 교체/압축/개조/제거의 선택창은 각각 올바른 후보를 열고 닫으면 정비 기회·상태가 유지됐다.

기본·작은 화면·비활성 캡처를 제작자가 직접 확인했다. 긴 한글은216 내 줄바꿈·최소44의 최종 수치를 확인했다. 일부 오프스크린 캡처에서 모달 종료 후 상단 그림/글자가 누락된 프레임이 있어 전체 화면 시각 근거에서 제외했다. 기본/비활성의 유효 캡처를 확인해 첨부했으며 모든 수집 이미지가 완전하다고 주장하지 않는다. 자동 검사를 시각/사람 미감 합격 점수로 사용하지 않았다.

Godot MCP 프로젝트 조회 정상(4.7). 파일 제작과 렌더/검사는 기존 로컬 경로로 수행했다. APK·커밋·푸시·외부 게시 없음. Android 실기기 안전 영역·손가락 체감·사용자 미감 확인은 남는다.

## 남은 작업

- 사용자가 보는 실제 정비소의 제목 크기·선 구분·버튼 비율의 미감 확인.
- 같은 역할 규격을 결과창 → 상점에 적용. 현재 ‘다음 설계’ 등 다른 화면의 문구는 아직 이전 상태다.
- 해당 화면의 주 행동/보조·수치/설명 역할과 기존 배치/예외를 정리한 뒤 순차 연결한다. 프로젝트 전체 규격화 완료로 표시하지 않는다.
