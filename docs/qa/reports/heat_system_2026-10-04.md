# 탄환별 발열·강제 재장전 본편 적용

2026-10-04 · Godot4.7 · `prototype/core-redesign` · 실행 [PLAY.cmd](../../../PLAY.cmd).

## 적용 결과

사용자가 승인한 탄환별 발열·무기별 한계·상시 열 게이지를 본편에 구현했다. [현재 규칙과 수치](../../direction/heat-system.md): 보행자12/쇄도14/산개16/압쇄13/증강10. 한계 도달 탄의 효과를 처리한 뒤 후속 발사를 중단하며 전투가 계속되면 기본 재장전+1턴을 자동 실행한다. 미발사 냉각은 과열을 취소하지 않는다.

보행자·열0·생존 적 조건에서 고출력→연발→철갑→냉각은3발·최고12·총3턴, 고출력→연발→냉각→철갑은4발·최고9·1턴이다. 후자는 냉각이 증폭의 두 번째 적용을 소비하므로 화력이 동일하지 않다. 가까운 적 편성에서 첫 순서는 강제 재장전 중 패배하고 두 번째는 생존하는 실제 모델 사례도 검증했다.

강제 재장전은 실제 이동·화상·투사체·증원·파츠 비용을 처리한다. 이미 종료된 전투는 추가 시간을 쓰지 않는다. 증강은 입력 사이 열을 보존하고, 산개는 표적 분기를 모두 계산한다. 공통 사격 종료 처리로 실제 발사와 분기 예측이 같은 자동 재장전을 실행한다.

전투 저장v9는 기존 덱·파츠·진행을 유지한다. 이전 `reload_heat` 추가 턴은 열로 바꾸지 않고 별도 부채로 한 번 소진한다. 열의 음수/소수/한계 이상 상태를 거부하며 정상·강제 재장전 뒤0으로 돌아간다. QA는 격리 저장으로 수행했고 사용자 플레이 저장은 변경하지 않았다.

## 선택 가치 비교

발열만 추가한 중간 비교에서는 보행자·쇄도·압쇄의 회수탄 반복216/216승이 그대로였다. 보행자의 공격탄+2를 증폭/파쇄/냉각에 적용하지 않고 첫 적을HP8/12·거리18/22m로 조정했다. 다른 실제 편성은 기존 작성 거리의65% 올림 후 기존 압박을 적용한다. 최소6m이며 증원과 보스에도 적용한다. 적의 공개된 행동/거리로 판단한다.

조건: 5무기·6시드·실제36편성의 **독립 전투**, 시작 덱·무파츠·무성장. 교환/압축은 사용하지 않는다. 무작위는 실제 패를 섞어 장전하고 회수탄 정책은 보급 기본탄만 쓴다. 보행자/압쇄의 의도적 선택은 현재 사격 결과로32후보를 비교한다. 전체 런/사람 승률이 아니며 무작위 정책은 냉각을 의도적으로 관리하지 않는다.

## 남은 성능 한계

산개 정확 분기 예측을 PC에서 두 번 측정했다. 최종 측정은 전체 재생 종료 후 진행했다. 5발 편성은 약160~168ms, 고출력8칸 편성은 약613~697ms였다. 이8칸 편성은 과열 때문에6발만 실행되므로 이전8발 측정 대비 알고리즘 개선으로 해석하지 않는다.

냉각을 끼워8발 모두 발사하는 별도 편성은3,200분기, 약1.17~1.59초였다. UI 입력 지연이 남으며 추가 최적화 대상이다. 결과를 근사하거나 불리한 분기를 버려 속도를 높이지 않았다. Galaxy 성능과 반복 측정의 통계값은 미검증이다. [최종 측정](heat_system_2026-10-04_assets/forecast_performance.json), [재생 작업 중 첫 측정](heat_system_2026-10-04_assets/forecast_performance_during_replay.json).
