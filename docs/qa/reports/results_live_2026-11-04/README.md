# 도전 결과창 본편 적용

승인된 [Godot 시안](../results_review_2026-11-04/README.md)을 본편 결과창으로 사용한다. 1280×800에서 승리와 패배 본편 캡처는 시안과 픽셀이 일치했다. [PC 승리](won_1280x800.png) · [PC 패배](lost_1280x800.png) · [S26 가로 패배](lost_2340x1080.png) · [인셋 제외 크기의 상세](details_2160x1032.png).

## 연결

- `redesign/results/screen.tscn`이 장면 원본이며 미리보기는 이 씬을 상속한다. 기존 게임 장면·복장·코어·탄환 아트와 공통 글꼴을 쓴다. 오른쪽은 실제 Campaign과 전투 기록을 읽는다. 최고 단발 피해는 저장된 사격 기록 내 최고값이다.
- 승리는 공급 복구와 귀환 뒤 결과를 연다. 패배는 전투 종료 직후 빈 전장과 원인을 표시한다. 배경의 어두워짐은 화면 진입 시 한 번 재생하며 즉시 연출 설정에서는 완료 색으로 표시한다. 창 크기를 바꿔도 상세 열림 상태가 유지된다.
- 시작 행동은 ‘새 도전’ 하나다. 기존 장비 선택을 열고 새 시드로 입력을 초기화한다. 실제 시작 전까지 완료 저장을 보존하며 새 도전이 시작되어도 기존 프로필 기록은 이어진다. ‘기록실’은 기존 기록과 해금 화면을 연다.
- 짧은 화면에서 간격과 인물 크기를 줄인다. S26 가로 비율과 인셋 제외 크기에서 기본 결과와 상세를 스크롤 없이 읽을 수 있었다. 높이 390인 작은 창은 글자 크기를 유지하고 필요한 경우 세로 스크롤을 쓴다.

## 검증

- `tools/run_results_ui.ps1 -Label verified`에서 1,211개 통과, 실패 0건. 1280×800, 1008×630, 844×390, 2340×1080, 2160×1032. 실제 완주 기록과 합법적 탄창 교체로 발생한 패배에서 진입을 확인했다. 상세·기록실·새 도전 입력과 저장 경계, 원인 표시, 창 크기 변경, 글리프·버튼 가시성을 확인했다.
- 미리보기 검사 261개 통과. 기존 HUD 11,536개와 UI 읽기 검사 9,785개 통과. Godot MCP로 프로젝트와 버전을 확인하고 실제 렌더는 로컬 엔진으로 실행했다.
- 구형 `run_story_checks.ps1`도 실행했으나 현재 관문에서 지원하지 않는 `gate("credits")`를 반복하는 픽스처와 상점 문구 검사에서 실패했다. 승리 복구→귀환→결과 경로는 현행 완주 기록으로 위 본편 검사에서 확인했다. Android 실기기는 미검증이다.
