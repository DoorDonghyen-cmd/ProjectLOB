# 추가 할 일 검토 — 총기·학습·정식 해금

사용자는 기존40개 외 누락 작업 점검과 총기 약2종 확장·리벳 양손형 디자인 선호를 전달했다. 이번은 현재 코드/방향 대조와 격리 선택 비교이며 제품 기능·아트 변경이 아니다. [현재44개 목록](../../direction/playtest-priorities.md), [무기 방향](../../direction/weapon-design.md).

## 무기 확인

- 실제 `redesign/content.gd::GUNS`는5종이다. 리벳은 안정 조합, 래칫은 동일 표적 집중 적중, 스플린터는 무작위 분산, 리액터는 과열 강행, 스파이크는 단발 효과 강화/처치 연속이다. 문서의 과거 탄창/열 수치를 새 제안에 복제하지 않는다.
- `weapon_art.gd`에서 리벳/스파이크는 현재 `pistol`, 다른3종은 `long` 파지 계열이다. `weapon_actor.gd`의 몸체/상태별 합성과 기본 권총 전용 접점을 함께 사용한다. 양손 리벳은 원화뿐 아니라 손/몸체·총구·반동·장전·실내/선택 화면과 복장 조합 검수가 필요하다. 팔 제보의 원인을 이번 코드 확인만으로 확정하지 않았다.
- 새2종은 역할 비교 뒤 외형을 결정하는 것을 권장한다. 직선 다중표적형/열 회수형과 카빈형 리벳은 디렉터 후보이며 사용자 확정 능력·원화가 아니다. 현재 총기 수/규칙은 바뀌지 않았다.

## 첫 플레이와 해금 확인

기존 도움말·초반 편성·보급 선택·프로필/난도 해금이 있다. 신규 규칙을 처음 접하는 사람의 학습 동선은 기존29번 전체 플레이/22번 문구 정리와 구분해43번으로 명시했다. 기존 전술 데이터/보급 선호와 테스트 개방 복장·새 총기의 정식 공개 범위는44번으로 연결한다. 별도의 새 영구 성장 수치를 채택하지 않았다.

`equipment_screen.gd::_options()`는 ‘첫 특수탄 보급 선호’를 고르게 하고, 시작 덱은 기본탄이며 첫 승리 후 후보에 선호 탄종이 포함된다고 안내한다. `campaign.gd::unlock()`은 기존 보급 선택을 전술 데이터로 해금한다. 최신 집중 보상 경로는 `FocusBuild.opening_options(model.s)`를 사용한다.

실제 Campaign/Model로 같은 리벳·시드17·운반복에서4보급 선호를 비교했다. 접근을 위한 프로필 해금 목록만 제어한 명시적 픽스처이며 재화를 지불해 해금하는 과정을 자연 플레이로 획득한 실험은 아니다. 시작 상태는4개 모두14발로 동일했다. 이어 실제 획득한 첫 전투의 동일 저장/명령을 재생하고 돌파 구동핵을 선택했다.4분기 모두 저장 복원·합법 명령·코어 선택·첫 탄 보상 단계가 정상이며, 보상 후보는 다음과 같이 동일했다.

| 보급 선택 | 첫 탄 보상 후보 |
|---|---|
| 코어·무기 맞춤 | 철갑탄·연타탄·열방출탄·소이탄·전격탄 |
| 연타 보급 | 철갑탄·연타탄·열방출탄·소이탄·전격탄 |
| 소이 보급 | 철갑탄·연타탄·열방출탄·소이탄·전격탄 |
| 전격 보급 | 철갑탄·연타탄·열방출탄·소이탄·전격탄 |

기본탄 시작은 UI가 명시한 현재 설계이며, 모든 후보에 해당 선호 계열이 포함되므로 이 결과만으로 ‘UI 약속 불이행’이나 모든 보급 선택이 모든 상태에서 무효라고 단정하지 않는다. 다만 같은 선택지가 나오는 상태에서 유료 해금/선호 선택이 어떤 의미를 갖는지 정리할 근거다. 다른 총기/코어·실제 해금 과정·미해금/재화 부족 화면은 후속 확인 범위다. 영구 성장/신규 화폐를 새로 만드는 것을 결론으로 삼지 않는다.

전용 `qa_runtime/backlog_review_20261106/`의 APPDATA/LOCALAPPDATA에서 실행했고 일반 사용자 저장·프로필·실제 무기 자산을 바꾸지 않았다. 첫 진단은 출력 경로 보호 조건의 끝 슬래시 차이로 실행을 종료해 결과 파일이 없었고, 조건을 정확한 전용 디렉터리로 수정한 뒤 재실행했다. 제품 기능 결함으로 분류하지 않는다. 이번은 화면/실제 사람 학습 검증이나 무기 구현 완료가 아니다.
