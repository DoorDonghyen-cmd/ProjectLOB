# 캐릭터 선택·상점·정비소·결과창 시각 평가 — 2026-11-04

Method: dual-agent (A: /root/visual_critique · B: /root/ui_structure_evidence). Godot 실화면과 소스 근거를 나눠 조사했으며 A가 독립 평가를 끝낸 뒤 B의 detector 출력을 읽었다. 프로젝트 현행 방향에 맞춰 외부 웹 비평 절차를 선별 적용했다.

**현재 화면을 비교하면 사용자의 인상을 설명할 구체적인 차이가 있다. 캐릭터 선택은 인물과 공간이 화면을 이끌고, 상점·정비소·결과는 공통 패널의 반복이 화면을 이끈다.** ‘AI 슬롭’은 표준화된 검사 항목이나 제작 주체 판정이 아니다. 반복·면적·크기·위계·재질 중첩은 관측 근거이고, 그 때문에 상투적이라고 느껴진다는 결론은 디자이너 평가다. 다른 사람들의 선호를 조사한 결과로 일반화하지 않는다.

## 주요 문제와 관측 근거

1. **중요도가 다른 요소에 같은 무게의 틀이 반복된다.** 상태줄·상품·정비 항목·결과 수치가 비슷한 청록 경계, 깎인 모서리와 디더 면을 쓴다. 같은 계열을 재사용하는 것 자체는 장점이지만, 이 화면들에서는 작은 정보와 핵심 선택의 시각적 무게가 평준화된다. 캐릭터 선택도 같은 테마를 쓰므로 청록색이나 도트풍 자체를 원인으로 볼 근거는 약하다.
2. **상점·정비소의 장소는 그림 안에서 끝난다.** 배경의 온기와 장비의 생활감은 좋다. 다만 아래 조작 영역은 별도의 넓은 단색 패널 목록이어서, 장소 그림을 다른 것으로 바꿔도 대부분 그대로 사용할 수 있게 보인다. 완전히 다른 레이아웃이 필요하다는 결론은 아니다. 현재 영역 안에서 장면과 조작이 공유하는 시각적 관계가 부족하다는 평가다.
3. **공백이 호흡보다 고정 틀의 잔여 공간으로 읽힌다.** 실제 측정한 상점 선택 상태에서 상품 높이 324, 내부 내용 최소 240, 상세 내용 최소 226/패널 324였다. 작은 그림·짧은 성능과 낮은 위치의 가격/구매 사이에 큰 질감 면이 남는다. 긴 문구/다른 상태에는 필요할 수 있으므로 전부 삭제 가능한 여백이라고 단정하지 않는다. 앞선 [수치 점검](ui_geometry_2026-11-04.md)과 이번 인상이 연결되는 부분이다.
4. **결과의 정보가 감정의 흐름을 고르지 못한다.** 실제 승리 기록은 30전투, 409턴, 393발, 재장전40회이고 의미 있는 데이터다. 하지만 5개 지표가 같은 틀에 실리고, 어떤 빌드나 성취가 이번 등반의 중심인지 먼저 읽히지 않는다. 승리의 귀환 문구는 장점이며, 그 뒤 정보 표현에서 정서가 약해진다. 실패도 같은 집계 구조를 공유한다.
5. **외곽의 과한 통일과 내부 재질 혼합이 공존한다.** 보상의 얇은 청록 패널 안에는 두꺼운 금속 파츠 카드가 들어가고, 최종 결과에도 같은 금속 파츠 띠가 나타난다. 같은 세계의 부품으로 느껴지는 공통성과 서로 다른 화면의 역할 표현이 모두 필요한데, 현재는 외곽은 반복되고 내부 부품의 제작 방식은 달라 보인다.

## 구현 대조에서 추가로 확인한 원인

- **정비소 글자 위계가 실제로 합쳐진다.** `modern_workshop()`은 제목23/설명18/버튼18을 요청하지만 공통 가독성 처리 후 모두16px가 된다. 기존 계측의 작업 항목15개 텍스트(5항목×3)는 모두16이었다. 결과 통계의 제목13/값18도 최종16/16이다. 글자를 읽기 쉽게 정수 단계로 정리하는 과정에서 제목/본문/수치 사이의 크기 차이가 사라진 점은 미감 판단과 별개로 확인 가능한 사실이다.
- 상점은 전용 장면·선택·주황 구매 버튼이 있고, 1280 상태에서 장소 제목·상품 이름/수치·상세 제목 등 여러 요소가32px로 경쟁한다. 완전한 무위계라고 할 수는 없지만 무엇을 먼저 볼지 고르는 힘이 약하다.
- 탄환 상품의 카드 설명과 상세의 변화 문구는 `ammo_note(id)`를 반복 사용한다. 선택 상품명을 상세에 다시 보여 주거나 가격/잔액을 반복하는 것은 확인을 돕는 기능도 있으므로 모두 불필요한 중복으로 세지 않았다.
- 공통 `_panel()`과 `_stat()`이 같은 자산 계열을 사용하고, 상점 상세와 일반 패널도 같은 `px_panel.png`를 참조한다. 단, 상품 선택/내부 수치판은 각각 다른 자산이므로 ‘전부 같은 프레임 파일’이라고 단순화하지 않는다. 같은 어휘의 **강도와 빈도, 위계**가 문제다.

## 잘 된 점

- 캐릭터 선택의 인물·무기·가로등이 하나의 시선 흐름을 만든다. 유지할 만한 기준 화면이다. 다만 모든 UI 요소가 완벽하다는 뜻은 아니며 반복 카드/작은 보조 설명은 이 화면에도 있다.
- 상점·정비소 원화와 구체적인 생활 대사에는 이미 게임의 개성이 있다. ‘돌아갈 곳에 불이 켜졌다’, 동료가 그릇을 놓는 귀환 문구도 세계관과 맞는다.
- 선택 테두리·가격·구매 후 잔액 등 기능 상태가 구분된다. 공통 색과 도트 글꼴의 기반도 존재한다. 현재 UI 전체가 무방향하거나 모두 같은 품질이라는 평가는 과하다.

## 추가 사용자 후기 — 불필요한 문구·모호한 제목·버튼 크기

사용자는 없어도 되는 텍스트, ‘다음 설계’ 같은 모호한 표현과 화면에 맞춰 과하게 커지는 버튼도 상투적인 인상의 원인이라고 지적했다. 현재 소스와 기존 실측을 대조했다. 제품 파일은 변경하지 않았다.

- `campaign_ui.ending()`은 실패 시 ‘다음 설계’라는 제목과 별도 조언 패널을 항상 만든다. 제목은 정보의 종류나 다음 행동을 구체적으로 알려 주지 않는다. 실패 부제 ‘적이 닿기 전에 완성할 순서를 다시 설계해 보세요’도 원인 보고보다 추상적인 권유다. 제거 또는 실제 실패 사실 중심의 짧은 표현이 후보이며 새로운 카피를 확정하지 않았다.
- `run_insight.loss_advice()`에는 ‘재장전 중 ○○가 도달했습니다’ 같은 구체적인 분기도 있지만, 마지막 기록/도달 적을 특정하지 못할 때 ‘마지막 행동의 탄환 순서와 발사 예상을 다시 확인하세요’라는 일반 문장을 표시한다. 후자를 실제 원인처럼 제시하지 않는 것이 적절하다. 탄약·비용·행동 시간·실제 효과 및 판단에 필요한 실패 사실은 보존 대상이다. ‘다음 설계’를 다른 추상적인 제목으로 바꾸는 것만으로는 해결되지 않는다.
- 공통 `_button()`은 최소 높이52와 `SIZE_EXPAND_FILL`을 기본으로 사용한다. 결과의 ‘같은 경로로 다시 등반 / 기록실 / 새 등반 선택’은 세 버튼이 행의 남는 폭을 나눠 갖는다. 상점 구매·나가기도 부모 열 폭을 채운다. 짧은 문구라도 주변 공간 때문에 긴 버튼이 된다.
- 모든 버튼이 화면 폭에 따라 늘어나는 것은 아니다. 정비소의 `_place_action()`은 `SIZE_SHRINK_END`, 기본216×52로 이미 제한되어 있다. 실제1280/2340 측정에서도 논리 크기는216×52로 같았다. 정비소에서 커 보이는 것은 그 버튼의 고정 비율과 화면 전체1/2배 표시, 반복 카드 면적도 함께 판단해야 한다. 상점 Buy는370×56→334×56, Exit는398×58→362×58로 열 폭에 따라 달랐다. 노드 자체scale은1이다. 사용자가 말한 시각적인 ‘커짐’을 이 용어 차이로 부정하지 않는다.

개선 검토 기준: 행동·조건·비용·결과를 추가하지 않는 문구는 덜어내고, 원인을 모르면 추측성 조언으로 채우지 않는다. 버튼은 문구+좌우 여백과 화면별 폭 상한을 기준으로 검토하며 필요한 터치 영역을 유지한다. 공통 기본값 일괄 변경으로 기존 전체 화면을 바꾸지 않고 실제 문제가 있는 버튼을 특정한다. 이는 후속 후보이며 이번에 카피·폭·글자 배율·배치를 수정한 것은 아니다.

## 개선 후보와 현재 결정

**후보:** 기존 라인+도트와 현재 배치를 유지하면서 중요하지 않은 반복 면/테두리의 강도를 낮추고, 상점의 고정 높이·가변 공백을 점검하며, 정비 항목의 작업 차이와 결과의 대표 성취에 위계를 주는 접근이 적절하다. 장면 원화와 실제 물건이 프레임보다 먼저 읽히도록 조절한다. 기능별 카드/결과 구조의 큰 변경은 별도 화면 비교로 검토할 사항이다.

이는 디자인 평가/개선 후보이며 사용자 확정 개편안이 아니다. **이번 요청으로 제품 코드·씬·배치·수치·아트는 변경하지 않았다.** 캐릭터 선택의 정상 스크롤을 문제로 다시 분류하지 않았다. 사용자가 요청한 검토의 답을 위해 인터뷰나 추가 승인을 만들지 않았다.

## 검증과 한계

- 기존 배치의 현재 빌드를 격리 저장으로 실행하여 1280×800과 2340×1080에서 상점·현행 정비소·성공/실패의 상단/하단을 캡처했다. 이는 PC 렌더링이며 Android 실기기 미감/터치 검증은 아니다.
- 성공은 `qa_runtime/core_choice_20261103/climb_fresh17/won_heavy_17.json` 실제 획득 완료 저장에서 `story_restore`→`story_results` 공개 입력을 거쳐 통계 결과에 도달했다. 38개 캡처/진입 관련 확인 실패0은 화면을 제대로 열었다는 근거이며 미적 완성도를 입증하지 않는다.
- 정비소는 현행 새 등반 경로의 장소 표시용 fixture(중간 전투 완료 상태 주입 포함), 실패는 표시용 fixture다. 실패의 0값은 진짜 플레이 결과나 비평의 원인으로 취급하지 않았다. 보상/캐릭터 선택의 직전 캡처는 해당 소스가 작업 전 스냅샷과 일치함을 확인하고 사용했다.
- 초기 성공 캡처가 복구 이야기 분기에 머문 것을 확인하여 실제 결과 진입으로 보완했다. 빈 하단 프레임은 평가/첨부에서 제외했다. 모든 하단 파일이 유효하다고 주장하지 않는다.
- 기존 9,734개 가독성/조작 검사는 이번 미감 평가와 별개다. 검사가 통과했어도 패널의 상투성·정서·개성 문제는 남을 수 있다.
- Impeccable CLI에 Godot `.tscn`을 전달한 출력은 `[]`였다. 도움말은 비 HTML에 정규식 분석을 설명하지만 Godot 노드/Theme 해석 보장은 없으므로 이 무출력으로 Godot 디자인 합격을 판정하지 않았다. Godot 실캡처·TSCN/GDScript·실측을 평가 근거로 사용했다. HTML/브라우저 DOM 검사를 Godot 시각 검증으로 대체하지 않았다.
