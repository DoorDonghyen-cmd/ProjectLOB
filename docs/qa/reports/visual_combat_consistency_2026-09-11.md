## 실제 실행한 독립 검사

| 상황 | 실제 표시된 탄종 | 표시 표적 순서 | 모델 종료·비용 |
|---|---|---|---|

| 같은 일제 + 연출 생략 | 동일 | **0, 1, 1, 0** | 위 모델 전체 상태와 동일 |

| 일제 첫발에서 마지막 적 처치 | charge만 표시 | 0 | reward, **1발·1턴·잔탄3** |

첫 밀기 사례의 적0은 HP5·거리10, 적1은 HP6·거리11이다. push가 적0을 거리12로 밀어 적1을 다음 표적으로 만들고, 적1을 죽인 뒤 살아 있는 적0으로 돌아온다. 표시된 결과와 모델의 결과 목록을 직접 대조했다. 처치만으로 표적이 바뀌는 기존 테스트와 달리 밀기로 표적이 바뀌는 경우도 포함한다.

모든6사례에서 다음을 확인했다.

- `_fire` 또는 `_reload` 호출 직후, 첫 시각 await가 끝나기 전에 이미 최종 상태 파일이 존재한다. 새 Model의 `restore_run()` 결과가 별도로 실행한 권위 모델 결과와 일치한다.
- 연출 시작 당시 모델은 이미 정산 후 상태지만 BattleView의 적은 **정산 전** 복제 상태다.
- BattleView 적 배열과 내부 적 Dictionary는 모델과 같은 객체가 아니다. 각 연출 종료 후 모델 전체 상태는 처음 계산한 결과 그대로다.
- 연출 중 발사·리로드·취소·확정·메뉴·이어하기·추가 장전·보상·재시도 명령은 상태를 바꾸지 않는다.
- 표시된 탄종/표적 목록은 모델의 LIFO 결과 목록과 완전히 같다. 마지막 표시 적 HP·거리·둔화도 모델과 같다.
- 시각 전진 구간은 모든 격발 뒤에1개만 실행된다. 조기 승리에서 미발사 탄을 소비하거나 추가 피해를 주지 않는다.
- 연출 종료 시 busy가 해제되고 화면을 다시 그린다. 제한 시간15초 안에 잠금이 끝나지 않는 상황은 없었다.

장전은 별도로 확인했다. `_load("basic")` 직후부터 busy가 참이고 계획이 이미 저장되어 있었다. 이동 중 추가 명령을 거절하며, 종료 후 시각 탄창 스택이 모델 계획과 일치하고 incoming 표시가 사라졌다.

## 코드 감사

- `_present`는 동기적으로 busy 설정 → `_persist` → 버튼 비활성화 → `play_action` 순으로 실행한다. 저장은 시각 연출 완료를 기다리지 않는다.
- 모델의 `fire()`가 반환한 결과 목록을 순서대로 넘기므로 프레임 속도가 전투 타깃 선택이나 피해에 개입하지 않는다. 새 시각 파일에서 게임 명령이나 난수 스트림 호출은 발견하지 못했다.
- `BattleView.sync`는 적 상태를 깊은 복제하고, 피격 뒤 HP/둔화/밀기 표시를 해당 복제본에 적용한다. 마지막에는 모델의 정산 후 적을 다시 깊게 복제한다.
- `MagazineView.stack`도 모델 스택의 복제다. `shot_started`에서 시각 스택만 `pop_back()`하므로 탄환을 이중 소비하지 않는다.
- 준비탄 연결은 실제 표시 발사 순서에서 뒤의1발을 향한다. AmmoVisual의 이름·힌트·색·형태 데이터는 콘텐츠의8종을 모두 포함한다.
- 모델 SHA256은 이전 규칙 freeze와 같아 시각 변경으로 모델이 수정되지 않았음을 확인했다.

## 결함과 구분한 표시/검증 한계

- 마지막 적이 죽어 실제 이동이 없는 경우에도 시각 이벤트에 `advance` 구간을1개 남긴다. 독립 검사에서 모델 턴·거리·잔탄은 올바르며 이중 전진은 없다. 이는 시각 구간 메타데이터이고 전투의 이동 턴 횟수로 집계하면 안 된다. 필요하면 무이동 마무리 구간의 이름/지연을 다듬을 수 있으나 이번 검사에서 게임 규칙 결함으로 분류하지 않았다.
- headless 검사이므로 상태·이벤트·프레임 동기화는 확인했지만 픽셀 가독성, 글자 겹침, 좁은 창, 실제 마우스 명중 영역, 연출 속도의 인간 체감은 확인하지 않았다. 별도 화면 리뷰를 대체하지 않는다.
- 정상 파일 시스템에서 저장 완료 시점을 검증했다. 앱을 실제 강제 종료하거나 디스크 쓰기 실패를 주입한 검사는 아니다. `_persist()`가 기록한 파일을 연출 중 곧바로 복원하여 이중 정산 없는 재개 조건을 확인했다.
- 참고 가능한 기존 motion 원본은39/0을 기록하고 있었지만, 본 독립100체크의 실측에 그 결과를 합산하지 않았다.
- 초기 QA 스크립트에서 `_choose`의 두 번째 인자를 빠뜨려 한 번 스크립트 호출 오류가 났다. 해당 QA 실행을 중단하고 **QA 스크립트만** 수정했다. 위100/0은 수정한 독립 스크립트의 완료 실행 결과이며 제품 결함으로 합산하지 않는다.
