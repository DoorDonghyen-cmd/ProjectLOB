# 기본탄 개별 카드·덱 순환 검증

2026-10-09 · 활성 `prototype/core-redesign` 작업 트리. 선행 변경 보존, APK/커밋/푸시 없음.

## 변경

[현행 규칙](../../direction/ammo-cycle.md). 새 등반의 기본탄은 유한한 개별 카드이며 가방에 포함된다. 모든 일반 탄환은 런 동안 덱에 유지되고, 사용 후 버린 더미를 거쳐 돌아온다. 새 시작 덱3+7, 기본탄 교환/예약/제거, 편집 중 턴을 지불하는 재장전, 기본탄별 개별 UI, 보급 파츠 설명과 시작 보급 미리보기 적용. 구 저장의 별도 보급은 `ammo_cycle` 마커가 없을 때 유지한다.

## 기능

Godot4.7, `qa_runtime/` 아래 격리 APPDATA/LOCALAPPDATA. 실제 사용자 저장에 접근하지 않는 전용 QA. UI는 save_enabled=false.

- `tools/run_ammo_cycle_checks.ps1 -Mode rules`: **11,842검사 / 0실패**. 5총기×3복장×24시드, 반복 재장전·사격, 카드 소유 수 보존과 JSON 복구, 뽑을 더미 선소진, 실제 기본탄 장수 제한, LIFO/회수/교환, 임시 압축 복원, 기본탄 예약, 과열, 위조 저장 거부,4시작 보급, 덱 제거, 훈련, 구 규칙 저장, 파츠.
- 같은 검사 안에서5총기×2시드의 실제 첫 전투를 제한된 탐색기로 찾고 실제 load/confirm/fire/reload 명령으로 재생해 클리어. 미래 RNG를 읽는 도달성 검사로, 승률이나 사람 체감 검증은 아니다.
- `tools/run_ammo_cycle_checks.ps1 -Mode ui`: **341검사 / 0실패**. 실제 Godot 터치 입력,1008×630/1280×900/1440×630. 기본탄 두 장 독립 장전/회수·교환·사격, 기본탄 없는 패, 공격 없이 재장전,10장 페이지2와 마지막 탄환 입력, 화면 경계/카드 글자/오버플로.
- 기존 `bag_growth_rules_runner.gd`: **756검사 / 0실패**, 격리 `qa_runtime/bag_growth/rules`. 가방 성장·구역 상한·실제 연결 경로·저장 회귀.
- 기존 `parts_revision_rules_runner.gd`: **2,265검사 / 0실패**, 격리 `qa_runtime/parts_revision/rules`. 기본탄을 별도 공급으로 가정했던2개 테스트 fixture를 실제 소유 카드로 수정한 뒤 파츠 발동·예측 회귀.
- 규칙 검사 초기에 캠페인 roundtrip1건이 실패했으나 테스트에서 이미 해금된 balanced를 중복 추가한 fixture 오류였으며, 중복을 제거한 최종 검사에서 통과했다.
- 과열 직후에는 이미 새 패를 뽑았으므로 사격 예측이 추가 재장전을 청구하지 않게 유지했다. 사용자가 직접 편집 중 재장전을 선택하는 예측만 별도 허용한다.

## 시각 확인

작은 화면의 시작 보급·기본탄2장 손패·장전 후 상태·가방10장 두 번째 페이지를 실제 캡처로 확인했다. 기본탄은 동일 디자인의 독립 카드이고, 기존 고정 공급 카드가 더 붙지 않는다. 수량/열/피해와 재장전 버튼이 화면 안에 들어간다.

## 남은 검증

Galaxy 실제 터치, 사람의 패 이해도, 한 런 전체의 난도/반복성, 기본탄3장 비율과 복장·총기별 승률은 미검증. 별도 소진 탄종·기본탄 압축 계열·복장 해금 경로는 이번 범위가 아니다. 플레이는 `PLAY.cmd` → 새 등반에서 확인한다.
