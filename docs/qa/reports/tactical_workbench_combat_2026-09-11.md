# Tactical Workbench — 독립 후반 전투 감사

작성일: 2026-09-11. 기준 HEAD: `3a116ad`. 역할: 전투 시뮬레이터/밸런스 QA. 이 원본 보고를 작성하기 전 다른 QA 담당자의 결론을 받지 않았다. 게임 기능·수치·데이터는 변경하지 않았다.

## 판정

1. **재현된 데이터 계약 결함:** 전투 UI가 적 리소스를 복제하는 경로에서 CSV 정본 조회가 빠진다. 같은 돌격병을 직접 `EnemyInstance`로 만들면 HP6·거리10, UI처럼 복제하면 HP8·거리8이다. 굴절병은 HP8·거리9 대 HP6·거리10이다. 단위 검사와 실제 전투가 서로 다른 적을 검사할 수 있다. 두 번 동일하게 재현했다.
2. **정의한 후반 10사례 중 9사례에서 합법 승리 순서를 확보했다.** section_c/d 관문 및 section_e 승천0/3/8이다. 각 증거를 새 CombatManager로 두 번 실행해 초기 상태·장전·격발·리로드·최종 상태가 완전히 일치했다.
3. **section_e 승천10의 지정 빌드는 193후보에서 승리를 찾지 못했다.** 가장 진행한 후보는 두 적 처치 뒤 방패병 HP1에서 사망했다. 전수탐색이 아니므로 무해법 판정은 아니다. 데이터 계약 수정 후 다시 볼 집중 QA 후보로 남긴다.

## 실행 범위와 고정 조건

- 실행 도구: `tests/qa_tactical_combat_probe.gd`, Godot 4.7 stable headless. 최종 실행 종료 코드0, 약3.5초.
- 총10사례. 사례별193정책 × 최대5탄창. 36개 반복 패턴, 156개 고정 시드 선택 정책, 추가로 조합을 지정한 1정책이다. 전체 후보1,930개와 선정 증거 재실행10개로 끝냈다. 결과에서 가장 적은 격발의 승리를 우선하며, 승리 없음은 처치 수·남은 내구도를 사용해 대표 실패를 선택했다.

### 승리 순서와 계약 확인

아래는 **발사 순서**이며 UI 장전은 역순이다.

- C 정책44: **천공 → 장약 증폭 → 기본 소총 → 점착 → 천공**. Ω HP는25→23→18→10→5→0. 단순 화력뿐 아니라 Stance Hunter의 태세 전환 타이밍과 전문축 교대 파츠가 작동하며, 점착이 전진 비용을 줄인다. A0/5/10에서 같은5발로 처치하고 긴급 격퇴를 쓰지 않았다.
- D 정책67: **천공 → 교란 → 천공 → 장약 증폭 → 점착**. 실제5발이 단 한 번의 연발 행동에서3적을 처치한다. 탄환별 가족 보조 피해와 적 타깃 변경은 실제 CombatManager가 정산한다. 이를 D 전체가 쉽다는 근거로 일반화하지 않는다.
- E 정책2: 첫3탄창은 각각 **기본 경량 → 천공 → 기본 경량 → 천공 → 기본 경량**, 네 번째는 **기본 경량 → 천공 → 기본 경량 → 장약 증폭 → 기본 경량**으로 장전한다. 네 번째 탄창3번째 발까지, 총18발에서 종료한다. 천공의 다음1발 관통 보정, 전문축 교대, 배리어 소거와 코어 페이즈2를 모두 통과한다. A8에서는 긴급 격퇴와 마지막 거리1을 사용하므로 여유 있는 해법이라고 표현하지 않는다.

E10 대표 실패 정책79의 발사 순서는 첫 탄창 **점착 → 기본 → 기본 → 점착 → 천공**, 두 번째 **기본 → 점착 → 기본 → 천공 → 파쇄**다. 첫5발 뒤 돌격병·굴절병은 죽고 방패병 HP7/거리4, 코어 배리어5/거리16이다. 리로드1턴에서 차징 강제 전진이 함께 발생해 방패병 거리1이 되고, 다음 기본탄이 HP를1까지 깎지만 접촉 사망한다. 긴급 격퇴는 이미 소모했다. 동일 종결을 두 번 확인했다. 다른 파츠·탄환·부분 장전·중간 리로드·다른 경로에 대해 불가능을 증명한 결과는 아니다.

## 재현된 데이터 계약 결함 — 수정 우선순위 P1

같은 적 리소스에서 아래 두 경로만 비교했다. 승천0·침투 위험도1, 거리 보정0, 대열 간격0이다.

| 적 | CSV와 원본 리소스로 만든 EnemyInstance | `.duplicate()` 후 만든 EnemyInstance |
|---|---|---|
| 돌격병 | HP6, 시작 거리10 | **HP8, 시작 거리8** |
| 굴절병 | HP8, 시작 거리9 | **HP6, 시작 거리10** |
| 방패병(대조군) | HP12, 시작 거리12 | HP12, 시작 거리12 |

원인은 `EnemyInstance._init()`이 `enemy_data.resource_path`의 파일명으로 CSV를 조회하는 반면, UI `CombatOverlayV2`는 층별 거리 보정을 위해 먼저 리소스를 복제하기 때문이다. 복제 리소스에는 원본 경로가 없어 CSV 행을 찾지 못하고 `.tres` 값을 사용한다. 이 보고서의 관문 시뮬레이션은 **실제 UI와 같은 복제 경로**를 사용했으므로 위 관문 결과를 임의로 CSV 값으로 보정하지 않았다.

CSV를 정본으로 유지하려면 원본 식별자를 보존하거나 CSV를 적용한 템플릿을 만든 뒤 조우별 거리 보정을 적용해야 한다. 합법적인 합성 적 픽스처의 오버라이드와 거리 보정을 지우는 일괄 덮어쓰기는 피해야 한다. 수치 튜닝 이전에 직접 생성과 UI 생성의 기준 스탯이 같은지 회귀 검사를 고정하는 것이 필요하다. 특히 E10의 돌격병은 CSV 기준이라면 현재 UI보다 HP2 낮고 거리2 길어져 첫 탄창 조건이 달라진다. 수정 후에도 동일한 실패가 유지된다고 가정할 수 없다.
