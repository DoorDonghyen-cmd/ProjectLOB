# 첫 등반 UX 공개 화면 검토

검토일: 2026-09-25  
대상: 거시 UI/UX 개편 직후 `prototype/core-redesign`  
범위: 지도 선택, 전투 준비, 보상, 상점 구매, 빌드 작업실 편집

## 검토 방식

`16-gameplay-experience-tester`의 공개 정보 원칙을 사용했다. 실제 화면 캡처와 화면에서 가능한 행동만 비교했으며, 원인 확인과 코드 수정은 관찰을 확정한 뒤 별도 단계에서 수행했다.

## 프로필별 공개 화면 판단

| 프로필 | 먼저 읽는 정보 | 상점·빌드 행동 | 관찰 |
|---|---|---|---|
| beginner | 큰 제목, 채운 버튼, 탭 이름 | 신규 파츠 구매 후 보관함 탭에서 장착 상태 확인 | 구매 결과가 현재 빌드 띠에만 반영되어 방금 일어난 변화 확인에 재탐색이 필요했다. |
| aggressive | 피해 증가와 즉시 장착 | 공격 파츠를 연속 비교하고 보관함에서 교체 | 교체 뒤 작업실이 `착용 중` 탭으로 돌아가 후보 비교 흐름이 끊겼다. |
| conservative | 패널티, 코어 제한, 장착 상태 | 보관함에서 장착·해제를 반복하며 위험 확인 | 같은 탭 복귀 문제 때문에 장착 전후를 연속해서 확인하기 어려웠다. |

## 판단

- 지도, 전투, 보상, 상점의 다음 행동 발견성은 거시 개편 뒤 개선됐다.
- 빌드 작업실의 탭 초기화는 세 성향 모두에서 같은 조작 흐름을 끊는 반복 신호다.
- 상점 구매 결과의 직접 피드백 부족은 초심자와 연속 비교 플레이에서 반복되는 신호다.
- 전투 촉감, 장시간 피로도, 실제 신규 플레이어의 첫 행동 시간은 자동 화면 검토로 승인하지 않으며 인간 확인으로 남긴다.

## 반영 결과

- 작업실이 장착 변경 전의 `착용 중`, `보관함`, `탄환 덱` 탭을 기억한다.
- 장착·해제 뒤 작업실 상단에 결과 띠를 표시한다.
- 상점 구매, 압축 코어 충전, 리롤 뒤 현재 빌드 위에 결과 띠를 표시한다.
- 파츠 구매 결과 문장은 자동 장착과 보관함 이동을 구분한다.

## 검증

- 전체 자동 테스트: 3,730 통과, 0 실패, 기존 경보 3.

- 구매 후 화면: `qa_runtime/city/ui_first_run_ux/city_shop_equipped_part.png`.
- 실제 사용자 저장은 QA 경로로 격리했다.
