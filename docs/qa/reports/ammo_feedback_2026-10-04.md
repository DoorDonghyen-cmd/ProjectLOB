# 고출력·과열 화면 반응 보강

2026-10-04 · `prototype/core-redesign` 작업 트리 · Godot 4.7 / Compatibility · [실행](../../../PLAY_AMMO_RISK.cmd).

## 요청과 범위

사용자는 첫 샘플의 피드백이 약하다는 말을 **‘강한 발사와 과열을 표현하는 화면 반응이 약하다’**로 명확히 했다. 이번 변경은 그 표현을 보강한다. 피해, 증폭 +2/+4, 발사당 과열 +1턴, 적 편성, 저장·공급 규칙은 바꾸지 않았다. 비교 샘플에 적용하며 캠페인에 고출력탄을 공급한 것은 아니다.

기존에는 일반·고출력의 발사 효과가 같았고, 두 턴 재장전도 최종 거리까지 한 번에 이동했다. 숫자로 비용은 표시했지만 ‘강하게 쐈다 → 총이 뜨거워졌다 → 적이 한 번 더 움직였다’는 연결이 약했다.

## 변경한 화면 반응

- 고출력탄: 짧은 총구 집중 효과, 가열된 총열, 사격 후에도 남는 픽셀 증기와 과열 표시.
- 증폭을 받는 다음 두 발: 발사 레일에서 효과를 받는 탄과 +2/+4 표시를 강조한다. 실제 강화량에 따라 총구 섬광·탄 궤적·피해 숫자·피격 반동의 강도를 구별한다. 고출력 증폭탄 자체의 직접 피해를 강한 타격으로 과장하지 않는다.
- 강화된 명중: 일반 증폭은 35ms, +4 이상은 65ms 동안 시각 프레임만 유지한다. 전역 시간·입력·전투 계산은 멈추지 않는다. 보호막에 막혀 HP 피해가 0이면 방어 반응을 사용한다.
- 과열 재장전: 기본 턴과 추가 냉각 턴을 구분한다. 모델의 화상→충전/끌어당김→이동→태세 전환을 실제 턴 순서로 재생한다. 잔열은 재장전 완료나 전투 종료 때 해소된다.
- 냉각 턴에는 열 아이콘과 주황색 진행 구간, 일반 재장전에는 시계 아이콘을 쓴다. 턴 구간은 기존 비용의 표현이며 별도 열 자원을 추가하지 않았다.
- 상단 `연출 줄임`은 추가 반동·충격 정지·움직이는 증기를 줄이고 과열 정보와 턴 구분은 유지한다. 현재 비교 실행 중 유지하는 설정이다. 기존 `건너뜀`도 동작한다.

캐릭터 크기·배경·카드 디자인을 유지했다. 효과는 엔진의 픽셀 도형으로 그리며 새 캐릭터 포즈, 조준/재장전 스프라이트와 사운드 제작은 이번 범위에 포함하지 않았다.

## 구현 구조

- `redesign/samples/risk_battle_view.tscn/gd`: 샘플 시각 반응 및 턴별 이벤트 재생. 표시용 복사본만 변경한다.
- `redesign/battle_view.gd`: 준비·충격·행동 후 진행·피해 위치의 확장 지점 분리. 기존 기본 화면은 같은 처리를 유지한다.
- `redesign/samples/ammo_risk.gd`, `risk_header.tscn`: 과열/냉각과 기존 위험 스트립·버튼 연결, 연출 줄임.
- `redesign/magazine_view.gd`: 실제 발동한 증폭의 후속 탄 강조. 기본값은 비활성이다.
- `tests/ammo_risk_feedback_runner.gd`, `tools/ammo_risk_sample.ps1 -Feedback`: 실제 클릭·정상 속도 캡처·격리 재생 검사.

화면 전체를 에디터 장면으로 재구성한 것은 아니다. 새 전장과 과열 라벨은 `.tscn`에 정의하고 기존 런타임 화면 조립을 재사용한다.

## 기능 검증

`qa_runtime/ammo_risk/` 또는 기존 `qa_runtime/art_sample/`의 격리 APPDATA를 사용했다. 캠페인 저장 비활성 샘플이며 사용자 저장을 불러오지 않았다.

| 검사 | 결과 | 범위 |
| --- | --- | --- |
| 고출력 규칙 | 296 / 실패 0 | +4/+1 비용, 예측, 저장 호환, 다섯 무기·파츠·증원 |
| 비교 샘플 UI | 149 / 실패 0 | 두 승리·두 패배 경로, 다시 비교, 4개 화면 비율 |
| 신규 화면 반응 | 165 / 실패 0 | 정상 속도 실제 입력, 강화된 두 발/보호막, 잔열/해소, 턴별 이동, 줄임·건너뜀, 작은 화면 숫자 |
| 기존 기상탑 샘플 | 68 / 실패 0 | 공유 전투의 카드·확정·발사·재장전 및 기존 비율 |

긴급 제압의 사격 후 C는 17m에 남고 재장전에서 **16m → 15m**로 이동했다. 실제 결과·예측·표시용 최종 적 상태가 일치했다. 별도 실제 모델 재생 6개는 화상, 다중 지원 적의 충전/끌어당김 순서, 태세 전환, 기본 턴 중 접촉, 끌어당김 조기 패배, 화상 조기 승리, 대기 증원이 있는 경우를 확인한다. 없는 추가 턴을 만들어 내거나 모델 상태를 수정하지 않는다.

중간에 창 크기 변경 직후 클릭한 테스트가 폐기된 버튼을 참조했다. 변경 후 기존 `settle()`을 기다리도록 검사 순서를 수정해 재통과했다. 실제 캡처에서 발견한 짧은 화면의 피해 숫자/적 정보판 겹침은 숫자를 줄이지 않고 정보판 아래로 옮겼으며 교차·경계 검사도 추가했다.

최종 로그에는 기존 격리 Windows 환경의 `Failed to read the root certificate store`가 남는다. 스크립트/파싱 오류는 없고 완료 표식·종료 코드가 정상이다. 해당 환경 메시지를 빈 stderr로 보고하지 않는다.
