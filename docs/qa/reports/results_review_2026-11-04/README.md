# 도전 결과창 시안

[채택 후 본편 연결 및 검증](../results_live_2026-11-04/README.md). 아래는 시안 단계의 기록이다.

사용자가 승인한 레퍼런스 수집 다음 단계의 Godot 비교 시안이다. [결과 레퍼런스와 판단](../../../art/references/2026-11-04-ui/README.md). 최종 구도와 색상은 사용자 검토 대기 상태다.

## 보기

- 루트의 `OPEN_RESULTS_UI_PREVIEW.cmd`를 실행한다. F1은 승리, F2는 패배다. 상세 기록 버튼으로 통계를 열고 닫는다.
- [승리 전후 비교](compare_won_1280x800.png) · [패배 전후 비교](compare_lost_1280x800.png). 왼쪽은 본편 1280×800, 오른쪽은 시안 1280×800이다. 승리 전후는 같은 등반이다. 패배는 도달 지점과 패배 원인이 다른 두 기록이므로 구도 비교에 사용한다.
- [S26 가로 승리](won_2340x1080.png) · [S26 가로 패배](lost_2340x1080.png) · [인셋을 제외한 크기의 상세 기록](details_2160x1032.png).

## 구성과 자료

- 사용자는 같은 경로 재시작 버튼을 덜어 달라고 했다. 새 시작 행동은 ‘새 도전’ 하나로 정리하고 ‘기록실’을 보조 행동으로 뒀다. 결과 제목은 ‘탑 돌파’와 ‘돌파 실패’, 상세는 ‘도전 기록’으로 시안에 반영했다.

- 떨어진 총의 자세가 어색하다는 사용자 피드백을 반영해 빈 전장 시안으로 바꿨다. 왼쪽 배경의 색만 0.85초 동안 어두워지며 창문과 가로등 불빛이 남는다. [문구 수정 전 같은 패배 기록의 연출 비교](compare_lost_staging_1280x800.png)는 왼쪽이 총기 연출, 오른쪽이 빈 전장 연출이 끝난 화면이다. PC/S26 가로 화면에서 색 전환의 시작과 끝을 확인했고, PC 승리 캡처는 픽셀이 일치했다.

- 승리는 주거 구역의 불 켜진 귀환 길, 패배는 실제 등반이 중단된 귀족 거주구 5층을 보여 준다. 기존 배경·복장·탄환·코어 아트와 공통 픽셀 글꼴을 썼다. 장면과 기록은 얇은 선으로 구분하고, 먹자색 기록 면 위에서 승리와 패배의 색을 나눴다.
- 결과와 직접 원인, 통과한 전투 수, 마지막 장비, 장착 코어, 저장된 사격 기록에서 가장 큰 단발 피해를 첫 화면에 배치했다. 이 피해는 저장된 개별 탄의 피해 값이며 전체 등반 기록을 보장하지 않는다. 방문·행동·사격·재장전·열·최종 덱은 상세에 배치했다. 귀환 대사와 ‘다음 설계’는 시안에서 덜었다.
- `redesign/samples/results_review/preview.tscn`에 구도를 저장했다. 승리는 `qa_runtime/core_choice_20261103/climb_fresh17/won_heavy_17.json`을 복원하고 필요한 경우 기존 공급 복구 명령을 메모리에서 실행한다. 패배는 같은 폴더의 `combat_heavy_17_r4_n30501.json`을 복원한 뒤 실제 탄창 교체와 전투 동기화를 거쳐 발사체 패배에 도달한다. 이 두 파일은 로컬 미리보기의 입력 자료다.
- 본편의 진입 경로와 화면은 기존 구현을 사용한다. 새 도전·기록실 버튼은 미리보기에서 이름만 확인할 수 있다. 채택 후 실제 화면으로 연결할 때 기존 결과창의 경로와 상태를 검증한다.

## 검증

`OPEN_RESULTS_UI_PREVIEW.cmd -Capture`로 Godot 4.7 Compatibility 렌더를 실행했다. 1280×800, 2340×1080, 2160×1032에서 261개 검사, 실패 0건. 패배 전장 어두워짐의 시작과 끝을 세 크기에서 확인했다. 실제 QA 기록, 패배 원인, 상세 펼치기/접기 터치, 두 행동 버튼의 터치 피드백, 가시 영역과 글리프, 버튼 높이, 캡처 크기, 시안 조작 뒤 메모리 상태 보존과 격리 저장 미생성을 확인했다. Godot MCP로 프로젝트와 버전을 확인하고 실제 캡처는 로컬 엔진으로 했다.

PC와 가로 크기를 맞춘 Godot 캡처를 확인했다. Android 실기기, 최종 모바일 정수 배율, 본편 결과창의 이동 경로는 후속 검증 범위다.
