# 탄환 출력 비교 샘플 — 구현과 검증

2026-10-04 · `prototype/core-redesign` · Godot 4.7.stable. 작업 전부터 존재한 변경을 보존했다.

## 실행과 조작

- 실행: [PLAY_AMMO_RISK.cmd](../../../PLAY_AMMO_RISK.cmd).
- 씬: [ammo_risk.tscn](../../../새-게임-프로젝트/redesign/samples/ammo_risk.tscn).
- 상단 `01 긴급 제압` / `02 보호막 전열`로 전투 선택. `일반 +2` / `고출력 +4`는 같은 적·같은 패로 해당 첫 증폭탄을 넣어 처음부터 비교한다.
- 손패와 발사 순서는 기존처럼 직접 수정할 수 있다. 장전 확정 → 발사 → 필요한 경우 재장전. `R` 또는 `다시`로 현재 시작 구성을 복구하고 `종료`/Esc로 닫는다.
- `qa_runtime/ammo_risk/sample`의 APPDATA/LOCALAPPDATA를 사용한다. 샘플은 `save_enabled=false`, `debug_session=true`이며 캠페인 저장을 쓰지 않는다.

## 이번에 구현한 범위

[설계](../../direction/ammo-risk.md)의 첫 단계다. 일반 증폭탄은 유지하고 `charge_hot` 변형을 샘플에 지급했다. 피해 1·물리·다음 두 발의 타격당 +4, 실제 발사마다 다음 재장전 +1턴이다. 증폭 계열로 인식하지만 압축탄과는 구별한다. 캠페인 시작 덱·보상·상점 풀에는 추가하지 않았다.

과열은 기존 무기/파츠의 기본 재장전 비용에 더하고 실제 시간 처리에 포함한다. 장전/회수/발사하지 않은 탄에는 붙지 않는다. 증강의 여러 사격 행동 사이에는 남고 재장전 또는 교전 종료 때 해소한다. 이전 v8 저장의 누락 필드는 0으로 읽으며 비정수·음수 등 잘못된 값은 기존 라이브 상태를 바꾸지 않고 거부한다.

`Forecast.analyze(..., include_reload=true)`와 `reload_now`는 복제 모델에서 실제 발사·재장전 명령을 실행한다. 화상·충전·태세·증원도 포함한다. 산개는 각 분기의 재장전 비용/HP/거리 범위와 접촉 확률을 집계하고 과열 잔량을 캐시 키·분기 구분에 넣었다. 화면 샘플은 보행자로 비교하며 다른 무기는 규칙 검사에서 다룬다.

새 [헤더](../../../새-게임-프로젝트/redesign/samples/risk_header.tscn), [결과 스트립](../../../새-게임-프로젝트/redesign/samples/risk_status.tscn), [종료 패널](../../../새-게임-프로젝트/redesign/samples/risk_result.tscn)은 편집 가능한 씬으로 분리했다. 전투 본체는 기존 `CombatWorkbench`와 실제 컨트롤러를 재사용한다. 전체 기존 화면의 절차적 UI 구성을 모두 씬으로 전환한 작업은 아니다. 새 결과 스트립은 사격 피해/처치 → 다음 재장전 시간/과열 → 재장전 후 거리 순으로 읽힌다. 과열 탄은 색 외에도 열 표시·+1과 효과 +4, 상세 설명으로 구별한다.

주인공·배경은 승인된 샘플 자산과 0.65 배율을 유지한다. 기존 적 아트는 임시다. 원거리 적·요격, 새 몬스터 이미지, 캠페인 공급/경제 확장은 다음 단계이며 이번 완료 항목에 포함하지 않는다.

## 두 전투에서 확인한 선택

| 상황 / 시작 조합 | 실제 첫 사격 | 곧바로 재장전하면 |
| --- | --- | --- |
| 긴급 제압 / 일반 증폭 | A 처치, B가 살아 접근해 패배 | 사격 뒤 이미 패배 |
| 긴급 제압 / 고출력 | 가까운 A·B 처치, C HP 18→13 | 2턴 재장전 후 C 15m. 후속 소유 탄 조합으로 승리 가능 |
| 보호막 전열 / 일반 증폭 | 보호막 제거, A HP 16→5 | 1턴 후 A 2m. 회수탄으로 마무리하고 남은 적까지 승리 가능 |
| 보호막 전열 / 고출력 | 보호막 제거, A HP 16→3 | 2턴째 A가 0m에 도달해 패배 |

비교 전투는 선택의 차이를 확인하도록 구성한 조건이다. 모든 전투·덱에서 고출력의 균형이나 재미가 입증됐다는 뜻은 아니다. 보호막 전열의 정상 승리 경로에서는 초반 일반 증폭으로 시간을 확보하고 마지막 사격에 고출력을 사용했다. 전투 종료 시 추가 재장전이 필요 없는 마무리 특성도 유지한다.

합계 8158개 확인, 최종 실패 0. 새 검사는 장전 중 비용 없음, 미발사 탄 폐기, 다중 과열, 증강 중간 사격, 재장전 파츠, 화상 승리, 지원 충전, 태세 교대, 증원 직후 위험, 산개 32개 시드의 범위 포함, 저장 호환/거부를 다룬다. 실제 UI 입력으로 두 전투의 승리와 비교 재시작·패배·일반/고출력 전환을 확인했다.

첫 기존 적 검사에서 오래된 기대값 두 개를 발견했다. 압축 연발탄의 3번째 타격을 4피해로 가정했지만 현재 보행자는 기본 3+보너스 2로 5피해다. 이 변경 전부터 존재하던 보행자 +2에 맞춰 기대값을 갱신하고 27개를 재확인했다. 배리어의 두 타격 흡수 규칙은 바꾸지 않았다.

실행 명령:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ammo_risk_sample.ps1 -Rules
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ammo_risk_sample.ps1 -Capture
powershell -NoProfile -ExecutionPolicy Bypass -File tools/tower_battle_sample.ps1 -Capture
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_progression_checks.ps1 -Mode rules -Label ammo_risk
```

무기·적·증원 규칙은 각 `tests/*_runner.gd`를 별도 격리 경로의 Godot headless로 실행했다. Godot MCP의 버전·프로젝트 조회 성공 후 기존 CLI 경로로 저장 격리 및 캡처를 수행했다. 변경으로 생긴 최종 스크립트 오류는 없다. 격리 Windows 실행에서 기존 `Failed to read the root certificate store` 환경 메시지는 남아 있으며 네트워크를 사용하지 않는 검사 결과와 구별했다.
