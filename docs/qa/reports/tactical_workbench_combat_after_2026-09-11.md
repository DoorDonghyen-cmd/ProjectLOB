# Tactical Workbench — CSV 준비 경로 수정 후 독립 전투 검증

작성일: 2026-09-11. 기준은 `3a116ad` 위 작업 트리의 `EnemyData.for_encounter()` 및 UI 호출 수정이다. 런타임 수정은 부모 작업에서 수행했고, 이 검증은 전용 프로브와 본 보고서만 수정/작성했다. 최초 보고서 `tactical_workbench_combat_2026-09-11.md`와 수정 전 JSON은 보존했다.

## 판정

**발견했던 CSV 불일치는 새 UI 준비 경로에서 해결되었다.** 돌격병·굴절병·방패병의 HP/DEF/EVA/SPD/넉백 저항/기준 거리가 원본 CSV 기반 인스턴스와 일치하며, 거리 비용은 그 다음 한 번 적용된다. 합성 적의 지정 스탯과 원본 리소스도 보존된다.

동일한 후반10사례·동일한193정책을 다시 실행한 결과, **10사례 모두 합법적인 승리 증거가 확보되었다.** 이전에 승리를 찾지 못했던 E관문 승천10도2후보에서 승리했다. 선정 증거는 각각 새 CombatManager에서 두 번 실행했고 초기 상태·장전·격발·리로드·최종 상태가 모두 같았다. 이 결과는 명시된 픽스처의 해법 존재 증거이며 캠페인 승률이나 난이도 적절성의 인증은 아니다.

## 변경한 검증 경로와 고정 조건

프로브의 조우 준비를 UI와 같은 `data.for_encounter(floor_delta)`로 변경했다. 기존 `duplicate()` 후 거리 직접 보정은 제거했다. 그 외 정책, 덱, 총기, 파츠, 시드, 한도는 최초 실행과 같다.

- 계층별 실제 관문 편성: C Ω, D 흡수 장갑 구체·돌격병·상위 신경 통제체, E 돌격병·굴절병·방패병·L.O.B 코어.
- 승천 조합: C 0/5/10, D 0/3/8, E 0/3/8/10.
- 전술 덱: 천공2·교란2·장약 증폭2·점착2·파쇄2. 파츠: 철갑 총열·인터럽터.
- C Stance Hunter(5발·리로드2턴), D Suppressor(5발 연발·리로드4턴), E Workhorse(5발·리로드1턴). 기본 보급5발, 리로드마다 상한까지 복구.
- 위험도1, 환기구 비용0. 마지막 층 거리 보정은 C +2, D 0, E −2m.
- 후보193개×최대5탄창. 전체1,930후보 및 선정 증거10개 재실행. 게임 RNG `6610911`, FX `991166`, 정책 RNG `6610911 + policy_id`.
- 추가 자원·소모품·강제 타깃·삽입·언로드 없음. 장전은 보유 재고와 기본 보급을 사용한다. 정의된 후반 빌드가 실제 런에서 생성되는 확률/경제 경로는 검사하지 않았다.

### 재현 가능한 발사 순서

아래는 **발사 순서**다. UI에는 역순으로 장전한다.

- C 정책44: **천공 → 장약 증폭 → 기본 소총 → 점착 → 천공**. 수정 전과 같은5발이며 리로드 없이 Ω를 처치한다.
- D 정책9: **파쇄 → 기본 소총 → 교란 → 장약 증폭 → 기본 소총**, 리로드4턴, **기본 소총5발**을 장전한다. 첫 버스트 뒤 구체·돌격병은 죽고 신경 통제체 HP3만 남는다. 두 번째 버스트 첫발에서 종료해 실제 발수6이다. 남은 적은 고정 차저이고 이동할 호위가 없어 이 리로드 구간의 적 전진 압박은 발생하지 않는다.
- E 정책40의 탄창1: **파쇄 → 장약 증폭 → 기본 경량 → 천공 → 점착**.
- 탄창2: **장약 증폭 → 천공 → 파쇄 → 교란 → 천공**.
- 탄창3: **기본 경량 → 천공 → 장약 증폭 → 교란 → 장약 증폭**.
- 탄창4: **천공 → 파쇄 → 기본 경량 → 기본 경량 → 점착**. 첫2발까지 발사해 총17발에서 코어 페이즈2를 처치한다.

각 탄창 사이 실제 리로드1턴을 소모한다. E0/3/8/10의 정책40은 같은 장전 순서를 사용하며, E10 초기 대열은 돌격병 HP6/거리5, 굴절병 HP8/거리6, 방패병 HP12/거리11, 코어 배리어5/거리16이다. 수정 전 E10의 돌격병 HP8/거리3 및 굴절병 HP6/거리7과 다른 **정본 상태**에서 검증했다.

## 데이터 계약과 거리 적용 순서 재검증

두 번 실행한 준비 경로 비교 JSON은 `identical=true`다.

| 적 | 원본 CSV 인스턴스와 `for_encounter(0)` | `for_encounter(-2)` |
|---|---|---|
| 돌격병 | HP6, 거리10, DEF0, EVA2, SPD3, 저항0 | 같은 스탯, 거리8 |
| 굴절병 | HP8, 거리9, DEF0, EVA7, SPD2, 저항0 | 같은 스탯, 거리7 |
| 방패병 | HP12, 거리12, DEF3, EVA1, SPD1, 저항2 | 같은 스탯, 거리10 |

옛 `.duplicate()` 단독 경로는 여전히 오래된 `.tres` 값을 읽지만, 수정된 UI는 해당 경로 대신 `for_encounter()`를 호출한다. 비교에서 남아 있는 옛 경로 차이를 수정 실패로 분류하지 않았다.

경로 없는 합성 적 HP17·DEF2·EVA4·SPD2·거리3에 `for_encounter(-2)`를 적용했을 때 HP/DEF/EVA/SPD를 유지했고 원본 거리3도 변하지 않았다. 준비본 거리는 기존 UI 계약인 최소4로 제한되었다. 따라서 "합성 적 보존"은 조우 거리 비용까지 무시한다는 의미가 아니다.

거리 순서는 **CSV 기준 → 조우 비용 및 최소4 → 침투 위험도 → 승천 및 최소1 → 대열 간격**으로 확인했다.

| 경계 조건 | 준비본 거리 | CombatManager 최종 거리(첫 적/둘째 적) | 기대값 |
|---|---:|---:|---:|
| 돌격병, 조우−4, 위험도3, 승천10 | 6 | 2 / 4 | 2 / 4 |
| 돌격병, 조우−20, 위험도3, 승천10 | 4 | 1 / 3 | 1 / 3 |

승천 보정이 두 번 적용되거나 대열 간격이 사라지는 회귀는 이 경계 검사에서 발견하지 못했다. 최소4는 준비 단계의 한계이지 최종 배치 최소거리가 아니다. 높은 승천에서 최종 거리가1~3이 되는 것은 기존 처리 순서와 일치한다. 준비함수만 고치면서 승천/대열 규칙을 바꿀 이유는 발견하지 못했다.
