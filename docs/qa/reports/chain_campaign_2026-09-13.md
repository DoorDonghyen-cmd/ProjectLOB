## 탐색 및 재생 방식

beam 폭 5, 최대 6탄창 단계, 시나리오 150초 제한. 현재 사용 가능한 기본/전술탄 순열을 1~`capacity()`발까지 열거하고 실제 `load_round → confirm → fire`로 평가한다. 각 단발 발사 중간에 멈추고 재장전하는 후보도 보존한다. 적 HP 감소·처치·남은 거리·균열에 가중치를 주는 제한 탐색이므로 최적해가 아니다.

교환 정책은 `off`, `optional`, `force`. 교환 후보는 공개 패 중 유도→충격→점착→도약→수확→파쇄→균열→축전→연속 순으로 1종을 고르는 고정 휴리스틱이다. 특히 유도·충격 사용 빈도는 이 편향의 영향을 받는다.

찾은 경로는 탐색 복제본이 아닌 실제 모델 인스턴스에 명령을 보내 다시 실행한다. 거절된 명령을 따로 기록하며, 전술 탐색에서 경로를 못 찾으면 `path_not_found_within_bounds`로 기록한다. 이를 불가능한 교전으로 해석하지 않는다. 이번 표본에서는 미발견이 없었다.

기본탄 정책은 탐색 없이 기본탄을 최대치까지 채우고, 탄창이 빌 때까지 발사한 뒤 재장전한다. `lost`가 실제로 발생하면 `defeated_by_simple_policy`로 기록한다. 치명적인 재장전도 실제 명령으로 실행한다.

## 기본탄 단순 정책 대조

seed 0~7을 순서대로 나열한 **패배한 교전 번호(1부터 시작)**다.

| 보상 정책 / 스냅샷 | 단발 | 일제 | 완주 |
|---|---|---|---:|
| 전부 skip / 수정 전 | 5, 6, 5, 5, 5, 5, 5, 5 | 4, 6, 3, 3, 5, 2, 2, 3 | 0 / 16 |
| 전술 정책과 같은 확장 우선 / 최종 수정 후 | 5, 6, 5, 5, 5, 5, 5, 5 | 5, 6, 4, 3, 6, 2, 2, 6 | 0 / 16 |

양 정책 모두 모든 발사가 실제 기본탄이었고 명령 거절은 0이다. 최종 수정 전 확장 우선 대조 16런도 같은 교전 번호에서 패배했으며 원본을 보존했다. skip 정책은 파츠를 장착하지 않으므로 현재 파츠 제외 수정의 영향을 받지 않는다.

관찰의 의미는 **단순 기본탄 반복만으로 표본 전체를 통과하지 못했고, 같은 seed에서 전술탄을 쓰는 실제 완주 경로가 존재한다**는 것이다. 기본탄만 쓰는 모든 가능한 전략의 불가능성이나 전술탄 각각의 필수성을 증명한 것은 아니다.

## UI 재생 입력 및 원본 경로

모든 경로는 worktree 기준이다.

- **최종 우선 UI 경로**: `qa_runtime/chain_campaign/primary_final/campaign_report.json`.
- 최종 나머지 16런: `qa_runtime/chain_campaign/seeds_final/campaign_report.json`.
- 최종 기본탄 대조: `qa_runtime/chain_campaign/basic_supply_final/campaign_report.json`.

UI는 `reports[].gun/seed`로 시작하고 `reports[].commands`를 순서대로 실행하면 된다. action은 `load(id)`, `confirm`, `fire`, `reload`, `exchange(id)`, `reward(id, remove_id)`이며 각 명령에 `accepted`, `phase_after`, `floor_after`, `turn_after`를 기록했다. `paths`에는 교전별 탄창 단위 경로, `history`에는 실제 결과, `encountered`에는 교전 진입 당시 적/파츠/용량을 보존했다.
