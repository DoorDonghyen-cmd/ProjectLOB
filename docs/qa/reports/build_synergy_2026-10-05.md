# 탄창·파츠·총기 연결 검증

2026-10-05 · Godot4.7 stable · Windows Compatibility renderer · 작업 트리 v12. [규칙](../../direction/build-synergy.md), [플레이](../../../PLAY.cmd).

## 변경과 검증 범위

사용자가 탄종 확장을 승인하고 탄창 크기·파츠·총기가 맞물려야 한다고 요청했다. 예약/차단/확산/연계탄과 냉각 약실/연쇄 방열기/예약 급탄기를 추가했다. 시작 덱, 기존 탄의 기본 화력, 무기 기본값, LIFO, 패 순환/잔열은 유지한다. 이번 변경은 전술 보급18종·수집 파츠26종이다.

실제 Model로 새 효과/발열/재장전/압축/저장/산개 예측을 검증했다. UI는 격리 런을 만들고 실제 버튼 입력으로 장전·사격·재장전·상점 구매·장비 교체를 실행했다. 사용자 저장은 사용하지 않았다. [소스 해시](build_synergy_2026-10-05_assets/source_hashes.json)는 이번 작업 전 스냅숏과 최종 소스를 구분한다. 기존 미커밋 변경을 보존했다.

전체 등반은 시드731042·난도0·탐색기 정책이다. 명령 예산 안에서 완주 가능한 경로와 저장 정합성을 확인한 것이며 사람 승률이나 최적 밸런스가 아니다. 초기 캠페인 검사의 탄창 기대식이 새 냉각 약실−1을 누락해 실패했다. 기대식을 갱신한 뒤 새 전체 등반을 통과했다.

예약 검사는 강제 재장전, 중복 소유 탄, 연속 예약의 상한, 영구 압축 보존, 현장 압축 제외, 종결 시 예약 제거를 포함한다. 차단은 한 적당1회·행동 재개·이동 지속을 확인했다. 산개에서 두 표적 중 하나만 차단 가능하면 첫 탄 발동50%, 재차 차단은25%; 화상을 옮길 표적이 하나인 두 연속 확산은50%→75%로 계산된다. 실제 무작위 결과를 공개 HP/압력탄 범위와 대조했다.

Godot 스크립트/파싱 오류와 새 UI 경고는0. 알려진 실행 환경의 root certificate store 메시지1종은 별도이며 오프라인 게임 기능 실패로 집계하지 않았다. 런처 경로 검사도 통과했다.

## 선택 비용 비교

[원자료](build_synergy_2026-10-05_assets/build_synergy_audit.json.gz)는 고정 장전 한 탄창과 가능한 경우 재장전 한 번을 실행한다. 짧은 정책은 소이→확산, 긴 정책은 탄창에 맞춰 예약/소이/확산/냉각/전격/철갑/회수를 넣고 연계로 마무리한다. 무기별로 최적화하지 않았고 실제 랜덤 손패 선택도 아니다. 열/칸/시간 비용이 발생하는지 확인하는 통제 실험이다.

예: 산개·성장0·시드731042·저체력3적·고열 시작에서 다음 차이가 생겼다. ‘피해’는 직접/전이/화상 실제 HP 감소의 합이고 턴은 사격+재장전이다. 고열 시작은 각 구성의 열 한계 절반이므로 마지막 구성은 시작 열도 다르다.

| 구성 | 탄창 | 피해 | 턴 | 강제 재장전 |
| --- | --- | --- | --- | --- |
| 기본 | 5 | 13 | 3 | 0 |
| 확장 탄창 | 6 | 18 | 4 | 1 |
| 확장+예약+연쇄 냉각+방열판+삼중 시퀀서 | 6 | 20 | 3 | 0 |

칸 하나의 추가가 화력과 과열 시간 모두를 늘릴 수 있고, 여러 파츠의 연결이 그 비용을 바꾼다. 다섯 파츠의 결과를 단일 파츠의 성능 우위로 비교하지 않는다. 증강 기본3칸에서는 예약 강도2가 이미 뒤의 두 칸을 채우므로 예약 급탄기만 더해도 예약량이 늘지 않았다. 이 파츠를 활용하려면 탄창 확장이 함께 필요하다.

최종 튜닝은 보류한다. 특히 긴 탄창의 다섯 파츠 조합, 예약 반복에 의한 선택 고정, 보행자의 무조건부 화력, 작은 탄창의 냉각 약실 가치와 사용자의 실제 건너뛰기 빈도를 추가 플레이로 확인한다.

## 실제 화면

- [새 탄환4종](build_synergy_2026-10-05_assets/new_roles_1008.png): 기존 카드 스타일과 구분되는 실루엣, 짧은 역할 문구. 3해상도 카드 효과 문구 폭을 검사했다.
- [예약 획득 후](build_synergy_2026-10-05_assets/reservation_earned_1008.png): 탄환 선택란에 다음 패의 실제 이름이 남는다. 처음에는 텍스트만 갱신한 숨겨진 노드라 보이지 않는 결함이 있었다. 캡처 검토로 발견해 표시 위치를 바꾸고 테스트도 `is_visible_in_tree`와 화면 경계를 확인하도록 고쳤다.
- [상점 냉각 약실](build_synergy_2026-10-05_assets/shop_cooling_breech.png): 탄창4→3, 패6→5, 쇄도 재장전 냉각9→13과 구매 결과를 표시한다.
- [장비 교체](build_synergy_2026-10-05_assets/equipment_tradeoff.png): 현재 장착 상태를 기준으로 해제/교체 후 실제 수치를 표시한다.
- [산개8칸](build_synergy_2026-10-05_assets/scatter_eight_slots.png): 정확 예측을 별도 스레드로 처리하고 확률을 유지한다. 이 두 적 사례의 최종 UI 대기80ms. 별도로4적·8칸·신규4탄/4파츠의 정확 예측을 측정했다. 장갑벽641.2ms/1,904분기, 원거리929.0ms/2,560분기, 충전924.3ms/2,560분기였다. 계산 중 UI를 막지 않는 기존 스레드 경로를 사용한다. 모든 편성의 최대치나 Galaxy 측정값이 아니다.

캡처는 실제 Godot 화면이다. 보정하거나 합성하지 않았다. PC 기능/화면 검증이며 사람의 최초 이해도, Galaxy 성능·터치, 장기 빌드 다양성은 미검증이다. 이번 요청에는 APK/커밋/푸시를 수행하지 않았다.

## 재현

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_build_synergy_checks.ps1 -Mode rules
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_build_synergy_checks.ps1 -Mode ui
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_build_synergy_checks.ps1 -Mode audit
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_progression_checks.ps1 -Mode campaign -Label synergy_final
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_ammo_expansion_checks.ps1 -Mode replay -CampaignSource qa_runtime/progression/campaign_synergy_final/city_campaign_report.json -Label build_synergy
```

결과는 `qa_runtime/build_synergy/` 및 해당 runner의 격리 경로에 생성한다. 보관된 로그/원자료는 이 보고서의 `_assets/`에 있다.
