- Godot MCP 프로젝트 정보 조회 성공: Godot4.7.stable. 실제 씬/입력/렌더링 검증은 기존 로컬 실행 경로로 수행했다.

## 검증

`powershell -NoProfile -ExecutionPolicy Bypass -File tools/open_ammo_upgrade.ps1 -Check -Label final`

- **236검사, 실패0**. [결과](result.json) · [stdout](stdout.log) · [stderr](stderr.log) · [소스 해시](source_manifest.json).
- 실제 Campaign의 압축/화력/방열 명령을 복제 상태에 실행해 미리보기와 확정 상태의 완전 일치를 확인했다. 결과 탄약19/20/20발, 무료 정비1회 사용, 금액/프로필 유지.
- 창 열기/닫기/취소/방식·대상 선택에 게임 상태 변화 없음. 부족한 재료, 최소 보유량, 이미 압축/개조한 탄, 방열 최저값, 미소유 탄, 창을 연 후 소유가 바뀐 상태, 중복 확정을 거절한다.
- PC 마우스와2340×1080의 합성 터치, 스크롤 밖 특수탄 접근, 닫기/ESC의 포커스 복귀, Enter 확정, F2 등급 창, F1 새 픽스처 재실행을 확인했다.
- 시작/끝에 격리 캠페인 저장이 생성되지 않음을 검사했다. 실제 사용자 저장 복원/자동 저장 본편 통합 검사는 수행 대상이 아니다.
- 신규 씬은 실행 전 대표 대상/결과/확정 버튼이 직렬화돼 있다. 엔진 파싱/최종 실행 오류 없음. 초기 비격리 headless 실행은 네이티브 크래시가 있었고 원인을 확정하지 않았다. 격리 경로 headless 및 실제 렌더러 재실행은 통과했다. 중간 입력 검사의 화면 배치 대기와 SceneTree 참조 오류를 고쳐 최종 결과에 반영했다.

## 제작자 화면 검토와 한계

1280×800과 S26비율의 실제 캡처를 확인했다. 긴 검정 면을 줄여 비교 창 높이를 고정하고, 원래 작업대 장면을 유지하면서 불투명한 따뜻한 작업 패널에 전후 수치를 모았다. 발당 값임을 표시해2발 재료의 합계와 혼동을 줄였다. 재료 목록의 부분 가림은 앞뒤 버튼으로 접근한다.

정식 전투/상점/정비소 씬과 계산/가격/저장 형식은 수정하지 않았다. 기존 HUD/정비소 회귀 검사를 이번 변경의 통과 수에 합산하지 않는다. 실제 희귀 등급은 기존 일반/고급만 연결하며 레어·에픽은 프레임 연구다. 사용자 미감/선택 이해도, Android 실기기·지속 성능과 본편 저장 통합은 확인 전이다.
