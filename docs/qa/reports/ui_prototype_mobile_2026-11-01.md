# HTML 목업 작은 화면 입력·읽기 검증 — 2026-11-01

## 범위와 판단

사용자의 다음 단계 진행 요청으로 HTML 검토판의 모바일 크기를 보완했다. 이전 화면 전체 축소 방식은 844×390에서 상세/빼내기 높이 약16.5px, 냉각/교체19.6px, 사격22.8px까지 작아졌다. 이제 UI는 CSS 픽셀 크기를 유지하며 화면 폭에 따라 배치를 바꾼다. 현재 아트와 자동 탄창 규칙은 유지한다.

- 작은 창의 검토 도구를 화면 선택 목록 하나로 정리했다. 데스크톱의 화면 맞춤/20:9/16:10 전환은 유지한다.
- 전투 상세/빼내기/취소와 냉각/교체 높이44px, 사격50px, 세로 화면 행동 버튼56px. 카드 최소 폭76px·높이92px, 이름/열14px, 주 수치22px.
- 부족한 탄창 폭은 가로 스크롤로 처리하고 선택/예측 갱신 후 위치를 보존한다. 이동한 포인터는 카드 선택·길게 누르기에서 제외한다.
- 낮은 전장의 적 정보는 짧은 한 줄, 세로 화면은 번호 대응 두 열로 배치한다. 거리 숫자는 추가하지 않았다.
- 상세창은 테두리 안쪽 내용만 스크롤하며 닫기 접근과 초점 잠금을 유지한다. 지도는 선택 장소 근처로 스크롤하고 상점은 상품/설명 영역의 크기를 확보한다.

본편 UI·캠페인 저장·전투 모델·APK·외부 게시를 바꾸는 단계는 아니다. 현행 모델 연결은 [직전 보고서](ui_prototype_magazine_2026-11-01.md)를 따른다.

## 실제 브라우저 결과

별도 검증 탭에서 공개 조작으로 확인했다. CSS 화면 크기이며 Android 실기기 측정이 아니다.

| 화면 | 전투 버튼 최소 높이 | 카드 이름 | 탄창 표시 |
|---|---:|---:|---|
| 740×360 | 44px | 14px | 가로 스크롤 |
| 844×390 | 44px | 14px | 7칸 동시 표시 |
| 1008×454 | 44px | 14px | 7칸 동시 표시 |
| 390×844 | 44px | 14px | 가로 스크롤, 행동 버튼56px |
| 1280×800 | 44px | 14px | 7칸 동시 표시 |

모든 크기의 변환 행렬 배율은1이었다. 데스크톱20:9/16:10도 글자를 축소하지 않고 외곽 영역만 조정했다.

- 중간2발 선택 → 상세 → Escape 후 선택 유지 → 즉시 빼내기: 7→5발, 빼내기 사용 완료. 사격 후3발/열5, 냉각 후3발/열0, 교체 후6발/한도2 회복 확인.
- 화면 크기 변경 시 전투 상태 유지. 세로 화면 마지막 카드 선택 후 예측 갱신에도 스크롤196px 유지.
- 도움말의 긴 본문과 닫기 접근, 빌드 서랍 스크롤, 지도 선택/이동, 공방 작업 후 복귀 확인.
- 가로 상점 구매75→63 Cr·덱10→11장, 세로 파츠 장착63→33 Cr·파츠2→3개, 구매 완료 비활성/지도 복귀 확인.
- 최종 상태 회귀 `node tools/test_ui_prototype.mjs`: 10개 통과. 검증 탭 콘솔 오류0건. 입력 전환 잠금이 끝나기 전 연속 입력은 기존대로 무시됨을 확인했다.

검수 중 세로 적 정보 겹침, 상품명 잘림, 도움말 스크롤 배경 이탈을 발견해 수정했다. 특히 낮은 상점의 내부 패널이 축소돼 구매와 복귀 버튼이 겹쳐 잘못 복귀하던 문제는 내용 높이를 보장해 수정하고 실제 구매로 재검증했다. 자동 상태 검사만으로는 잡히지 않은 배치 결함이다.
