# 화면 조작과 흐름 검토 — 2026-10-03

## 판단

현재 UI는 탄환 조합의 재료와 결과를 함께 보여 주는 틀을 갖췄다. 그러나 **반복해서 조합을 수정하는 조작, 다음 행동의 결과 설명, 파츠 교체 비교는 아직 충분히 직관적이지 않다.** 전투의 세로 순서를 통째로 바꾸기보다 이 세 가지를 중심으로 화면의 역할과 입력 규칙을 다듬는 것이 적합하다.

전투는 손패 → 순서 → 결과를 여러 번 오가는 게임이다. 전장·순서·손패를 동시에 볼 수 있는 현재 구성을 유지하고, 선택 위치와 행동의 의미를 안정시키는 것을 우선 권고한다. 상점과 파츠는 고정된 비교 영역을 유지하되, 선택 전후의 차이가 그 안에서 완결되어야 한다.

이 문서는 검토 결과와 후속 설계 권고다. 게임 구현·규칙·방향 원본을 변경하지 않았다. 사용자가 제시한 3초·30% 확대·민트색·다섯 단계 세로 배치는 참고 의견이며 확정 기준으로 취급하지 않는다. 승인된 탄환 카드 디자인을 유지하고 캐릭터·적·배경 재제작은 세계관·레퍼런스 작업 이후로 보류한다.

## 방법과 한계

- 활성 작업 위치: `worktrees/core-redesign`, `prototype/core-redesign`.
- 실제 Godot 4.7 OpenGL, 출력 1008×630, 기준 캔버스 1280×800. 두 번의 별도 실행에서 23개 상태 캡처와 버튼·레이블·모델 상태를 기록했다.
- 메인 → 새 등반 준비 → 지도 → 첫 전투는 실제 흐름으로 진입했다. 장전·계산 보기·회수·확정·발사·구매·작업실은 `InputEventScreenTouch`를 엔진에 전달해 조작했다. 입력 좌표는 컨트롤 위치에서 구했다.
- 상점·가득 찬 파츠·증강·보상·보급·관문은 기존 개발자 시나리오로 상태를 준비했다. 일반 등반 전체를 이 실행에서 완료한 것은 아니다. 증강 시나리오의 미리 장전된 탄창은 실제 확정·발사 버튼으로 진행했다.
- `APPDATA`/`LOCALAPPDATA`를 `qa_runtime/ux_flow_review_2026-10-03/` 아래로 분리하고 `save_enabled=false`로 실행했다. 기존 사용자 저장을 사용하지 않았다.
- 소스를 알고 수행한 검토다. 독립적인 사람의 첫 플레이·3초 이해도·오탭률·실제 Galaxy에서의 손가락 접근성을 측정한 결과가 아니다. 스크립트 오류는 없었으며 실행 환경의 루트 인증서 경고가 남았다.
- A는 독립적인 화면 비평, B는 정적 입력·표시 경로 확인을 담당했다. A 완료 후 B 결과를 종합했다. 두 평가가 슬롯 조작·파츠 비교·상점 행동 문제에 일치했고, 부모의 신규 실행에서 손패 이동과 증강 예측 범위 문제를 추가 확인했다.
- 웹 UI 탐지기는 `.gd`를 지원하지 않는다. 1회 실행 결과 `[]`/종료 0은 Godot UI 품질 통과가 아니다. 브라우저/DOM 검증으로 대체하지 않았다.

원본 입력 스크립트, 23개 PNG, 관찰 JSON, A/B 전문은 `qa_runtime/ux_flow_review_2026-10-03/`에 있다. 주요 근거는 아래 자산 폴더에 보존했다.

## 유지할 강점

1. 탄환 실루엣, 큰 피해 값, 별도 고유 효과가 카드의 성격을 구별한다. 새 카드 체계를 만들 이유가 없다.
2. 발사 순서와 전장의 예상 HP를 동시에 보여 줘 조합의 의미를 확인할 기반이 있다. 전체 탄창의 연계 예측은 유지할 가치가 있다.
3. 무기 5종 비교, 상점의 고정 상세 영역, 파츠 장착 5칸·보관함·선택 상세가 이미 연결돼 있다. 파츠 교체는 한 번에 적용되고 기존 파츠가 보관된다.

## 우선 개선 사항

### P1-1. 다음 발사와 전체 탄창 예측의 범위를 구분한다

**실행에서 확인:** 증강의 준비 화면은 `발사 · 3발`, A의 HP `30→10`을 표시했다. 한 번 발사한 뒤 실제 A의 HP는 29이고 탄창에는 2발이 남았다. 이는 피해 계산 오류가 아니라 **여러 번 계속 발사한 결과를 다음 행동의 결과처럼 읽게 하는 표시**다.

- [발사 전](interaction_flow_review_2026-10-03_assets/18_amplifier_before_fire.png)
- [한 번 발사 후](interaction_flow_review_2026-10-03_assets/19_amplifier_after_one_fire.png)
- 근거: `forecast.gd:9`는 복사 상태에 `fire()`를 반복 호출한다. `model.gd:126`의 증강은 주 표적이 살아 있으면 그 발사에서 멈추고, 처치하면 다음 탄환으로 이어진다. `screen.gd:846`의 버튼 수량은 탄창 전체다. 예측의 시간 범위와 처치 연쇄 조건은 툴팁에 있다.

**권고:** 발사 버튼과 전장의 기본 예측은 이번 발사 1회의 결과에 맞춘다. 증강은 `1발 발사`와 처치 시 이어지는 조건을 눈에 보이게 표시한다. 탄창 전체의 조합 결과도 제공하되 `계속 발사 시 · N턴`이라는 별도 범위를 붙인다. 레일에는 이번에 실행되는 구간과 이후 남는 구간을 구별한다. 전체 예측을 없애서 순서 설계의 정보를 잃지 않는다.

### P1-2. 조합을 시험하는 동안 카드 위치와 터치 의미를 안정시킨다

**실행에서 확인:** 처음 연발탄 두 사본 중 한 장을 넣으면 뒤의 철갑·소이·충격 카드가 한 자리씩 당겨진다. 두 번째 장전에서도 다시 이동한다. 표시 폭도 카드 수에 따라 약간 변한다. 카드가 많다는 사실보다 반복 조작 중 위치를 다시 찾게 되는 것이 문제다.

- [처음 손패](interaction_flow_review_2026-10-03_assets/05_battle_open.png)
- [두 발 장전 뒤](interaction_flow_review_2026-10-03_assets/06_load_2.png)

**실행에서 확인:** `계산 보기`를 켜면 슬롯 터치는 계산 확인이고, 끄면 같은 슬롯 터치가 회수다. 계산 상세는 손패 아래에 나타나 화면에 세로 스크롤을 만든다. 토글을 끈 채 확정하면 슬롯 터치가 계산 텍스트를 갱신하지만 상세 레이블은 계속 숨겨진다. 확정 전후의 무료 편집 경계도 버튼 본문에서 설명되지 않는다.

- [계산 확인 상태](interaction_flow_review_2026-10-03_assets/07_slot_inspection.png)
- [확정 후 슬롯 터치](interaction_flow_review_2026-10-03_assets/11_tap_locked_slot.png)
- 근거: `screen.gd:721–747`, `771–777`, `1430–1436`; `model.gd:102–120`; `magazine_view.gd:30–54`.

**권고:** 한 번 받은 손패의 카드 자리는 유지하고 장전된 사본은 사용 상태로 남긴다. 재장전·패 교환처럼 새 구성이 생기는 시점에 재배치한다. 탄창 탭은 일관되게 선택·간단 상세로 쓰고, 선택 탄 회수와 끝 탄 되돌리기를 명시적으로 제공한다. 레일 안 순서 변경은 직접 드래그에 더해 탭으로 선택 후 이동할 수 있어야 한다. 기존 같은 탄환끼리의 압축 드래그는 유지한다.

상세는 선택한 탄과 가까운 고정 영역이나 작은 팝오버에 둬 전체 화면의 높이를 늘리지 않는다. 길게 누르기는 보조 단축으로만 사용한다. 확정 버튼 곁에는 실제 무기에 따른 변경 비용을 표시한다.

**규칙 경계:** 현재 확정은 0턴이지만 이후 순서 변경은 남은 탄을 버리고 재장전 턴을 쓴다. 확정을 없애거나 발사와 합치는 것은 게임 규칙의 경계도 바꾼다. 이번 검토에서는 제거를 확정하지 않으며, 우선 비용과 상태를 공개한다.

### P1-3. 파츠 교체는 들어오는 효과와 사라지는 효과를 함께 보여 준다

**실행에서 확인:** 장착 5칸이 찬 상태에서 `야전 압축기 → 과구경 총열` 교체를 선택하면 새 파츠의 피해·관통 +2, 탄창 −1이 설명되지만 비교 결과는 `탄창 2→3칸`이다. 기존 파츠의 압축 기회가 사라진다는 설명은 비교 영역에 없다. 숫자는 정확하지만 변화의 원인을 플레이어가 기억하고 계산해야 한다.

- [교체 비교](interaction_flow_review_2026-10-03_assets/17_core_comparison.png)
- 근거: `campaign_ui.gd:674–714`는 유효한 교체 후보를 만들고 탄창·재장전만 전후 비교한다. `content.gd`의 야전 압축기는 교전 압축 +1회와 탄창 −2칸이다.

**권고:** 같은 영역에서 `해제할 파츠 / 장착할 파츠`, `사라지는 규칙 / 얻는 규칙`, `최종 탄창·재장전 변화`를 연결한다. 수치가 바뀌지 않아도 압축·전이·순서 조건 같은 빌드 효과를 누락하지 않는다. 장착 슬롯의 교체 예정 대상도 함께 표시한다. 자동 장착되는 구매는 지출 전에 이 결과를 보여 준다.

### P2-1. 상점은 선택 → 비교 → 구매로 중심 행동을 모은다

**실행에서 확인:** 상품 카드 밑 구매 버튼과 오른쪽 비교 영역 구매 버튼이 같은 구매를 실행한다. `맵으로 계속`도 구매와 함께 금색으로 강조된다. 구매 후 잔액·장착 표시·탄환 수치가 갱신되는 것은 확인했다.

- [현재 상점](interaction_flow_review_2026-10-03_assets/13_shop.png)
- 근거: `campaign_ui.gd:323–340`, `435–437`.

**권고:** 상품 카드는 선택, 카드 하단은 가격·재고 표시, 오른쪽 비교 영역은 주 구매 행동으로 정한다. 이동은 찾기 쉬운 고정 출구로 두되 구매와 같은 강조를 주지 않는다. 새 진열·압축 충전은 유료 서비스로 묶는다. 불필요한 구매 확인창을 더하는 것은 권고하지 않는다.

### P2-2. 출격 준비의 기본 흐름에서 고급 설정을 접는다

**화면·소스 확인:** 무기·시작 보급·난도·시드·새 시드가 같은 출격 준비에 노출된다. 기본 난도가 잠겨도 입력 형태가 남는다. 시작 보급의 각 탄환 효과는 툴팁에 있다.

**권고:** `무기 → 시작 보급 → 출격`을 기본 흐름으로 유지한다. 시드·재현 설정은 등반 설정에 넣고, 잠긴 난도는 상태로 표시한다. 시작 보급은 효과를 터치로 확인할 수 있게 한다. 무기 5종은 핵심 비교 대상이므로 단순히 개수가 많다는 이유로 숨기지 않는다.

| Primary / Secondary / Tertiary | 결과·주 행동, 비교 정보, 보조 정보를 구분하는 위계로 활용. 명칭이나 숫자 배율을 구현 규칙으로 고정하지 않음 |
| Primary 최소 30% 확대 | 일괄 적용 근거 부족. 작은 화면에서 핵심 값·비용·행동부터 선별하고 실제 줄바꿈과 전체 높이로 검증 |
| 민트색 사용처 제한 | 선택/행동의 강조 일관성은 활용. 이미 탄환 속성과 장치 분류에 쓰이는 색 의미를 무조건 바꾸지 않음. 색 외 표식도 함께 사용 |
| 전장 → 손패 → 순서 → 결과 → 발사 세로 배치 | 사고 과정 설명으로 유효. 물리적 세로 배치의 의무로 적용하지 않음. 이 게임의 반복 비교에는 세 영역의 동시 노출과 고정 위치가 더 중요 |

## 사용자 관점의 위험과 남은 관찰

- 처음 플레이하는 사람: 확정의 의미, 증강의 한 번 발사 범위, 파츠 교체의 손실을 행동 전에 설명할 수 있는지 확인해야 한다.
- 반복 플레이하는 사람: 순서 교체·되돌리기에 드는 입력 수와 움직이는 카드 때문에 다시 찾는 횟수를 관찰해야 한다.
- 휴대전화 사용자: 같은 자리 반복 터치, 상세를 열고 닫은 후의 위치, 중단 후 현재 단계 파악을 실제 기기에서 확인해야 한다. 툴팁의 존재만으로 핵심 정보가 전달된다고 보지 않는다.
- 보상·관문 캡처는 선택 내용을 비교할 기반이 있다. 이를 이유 없이 큰 메뉴 구조로 확장하지 않는다. 배경·배우의 임시 아트 품질은 이번 조작 권고의 근거로 섞지 않았다.

후속 검증은 증강의 **다음 1회/전체 탄창** 예측 구분, 장전·회수 후 카드 위치, 모든 단계에서 동일한 슬롯 선택 의미, 다섯 무기의 확정·재장전 비용, 조건부 파츠 효과의 교체 비교, 상점 지출 전 결과 인지를 포함해야 한다. 기능 확인과 사람의 이해도 관찰은 별도로 기록한다.

## 휴리스틱 평가 보조

아래 0–4 평가는 검토자의 주관적인 설계 평가다. 기능 통과율·출시 완성도·사람의 이해도 점수가 아니다. A의 독립 평가 24/40에서 신규 실행으로 확인한 예측 범위 문제를 상태 전달에 반영해 통합 평가를 23/40으로 기록했다. 두 평가는 서로 다른 시점의 개선 추세가 아니다.

| 항목 | 점수 | 근거 |
| --- | ---: | --- |
| 상태 전달 | 2 | 예측 시간 범위·확정 경계가 본문에서 불명확 |
| 플레이어 언어와 과업 일치 | 3 | 장전·발사·교체 장착 등 주요 용어는 명확 |
| 제어와 되돌리기 | 2 | 무료 편집과 비용 발생 경계의 노출 부족 |
| 일관성 | 2 | 슬롯 탭 의미가 모드에 따라 바뀜 |
| 오류 예방 | 3 | 유효 교체·구매 가능 조건·일부 파괴 행동 확인 존재 |
| 기억 부담 | 2 | 교체로 사라지는 조건부 효과를 기억해야 함 |
| 효율 | 2 | 손패 위치 변경·순서 변경의 간접 조작 |
| 정보 위계 | 2 | 상점 주 행동 중복, 출격 고급 설정 기본 노출 |
| 오류 회복 | 2 | 일부 제한 안내 존재, 실패 상태 전체 검토는 아님 |
| 도움말 | 3 | 도움말·상세는 있지만 중요한 규칙을 툴팁에 의존 |
| 합계 | **23/40** | 개선 필요라는 검토 판단. 적용 제외 항목 없음 |

P0 0건, P1 3건, P2 2건으로 묶었다. 자동 탐지 결과는 이 점수 산정에 사용하지 않았다. 추가 선호 질문 없이 사용자가 위임한 범위에서 권고를 정했다. 현재 결론은 **조합 편집과 결과 전달 → 파츠 비교 → 상점 행동 → 출격 준비** 순으로 개선하는 것이다.
