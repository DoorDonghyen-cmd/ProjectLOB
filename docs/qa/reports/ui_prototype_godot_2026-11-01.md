# HTML 검토안의 Godot 전투 HUD·저장 연결

2026-11-01. 사용자 ‘진행해 줘’ 요청에 따라 모바일 크기 검토 뒤의 Godot 통합 단계를 수행했다. 대상은 기존 탄창 여정과 독립 전투 비교다. HTML의 지도·크레딧·상점 모사를 본편 규칙으로 옮긴 작업은 아니다.

## 기준과 적용 범위

- 기준: [검토 HTML](ui_prototype_2026-10-31/index.html), [작은 화면 검토](ui_prototype_mobile_2026-11-01.md), 그 보고서의 844×390 화면. 검토용 상단 도구막대는 게임에 넣지 않았다.
- 하단 작은 탄창, 탄창 위 선택·빼내기와 발열, 오른쪽 냉각/교체/사격 배치를 적용했다. ‘이번 사격 / 탄을 눌러 장전하세요’ 안내 카드는 없다.
- 카드 76×96 논리 단위, 그림 18×30, 이름·열 14, 일반 입력 높이44/사격50. 넓은 화면에서도 카드를 늘리지 않는다. 부족한 탄창 폭은 가로 스크롤이며 키보드 초점도 마지막 탄까지 이동한다.
- 모든 장전 탄의 기본 성능·개별 열을 표시한다. 주황 테두리/순서 번호는 이번에 발사할 탄, 붉은 테두리/‘제외’는 빼낼 탄이다. 빈 소켓은 어둡게 남긴다. 카드 값은 최종 적중 피해가 아니다.
- `탄환 선택 → 빼내기`와 기존 한도/소모/시간 비용을 유지한다. 상세 버튼은 기본적으로 첫 탄을 가리키며 선택 시 해당 탄을 가리킨다. 빼내기 한도 소진 뒤 카드 탭은 상세를 바로 연다.
- 상세·메뉴·보상/정비는 각 독립 씬에 구성을 저장했다. 런타임은 기존 Model/Forecast/Campaign/Journey의 값, 선택, 사용 가능 여부만 연결한다.
- 작은 전장의 배우 크기·접지·HP/행동 예고를 표시 어댑터에서 조절했다. 보스 의도는 별도 윗줄에 둔다. 적 거리/체력/전투 계산은 바꾸지 않았다.

## 변경 파일과 자산

- `redesign/samples/hud/combat_hud.tscn`, `combat_journey_hud.tscn`: 공통 전투 구성과 여정 연결.
- 같은 폴더의 `combat_menu.tscn`, `combat_detail.tscn`, `journey_flow.tscn`: 독립적으로 열리는 공통 창과 보상/정비 구성.
- `combat_hud_presenter.gd`, `combat_hud_theme.tres`, `prototype_round_icon.gd`, `prototype_battle_view.gd`: 기존 명령 연결, 테마, 탄환 그림, 낮은 전장 표시.
- `redesign/battle_view.gd`: 기존 최소 전장 높이264를 기본값이 같은 내보내기 속성으로 만들었다. 새 HUD에서만80으로 지정한다.
- [자산 출처·SHA-256](../../../새-게임-프로젝트/assets/ui/prototype_20261101/provenance.json): 사용자 HTML 자산28개를 그대로 복사했다. 배경·배우·글꼴 원본은 수정하지 않았다.
- 기존 NeoDunggeunmoPro 글꼴을 재사용했다. 이전 Galmuri 비트맵 HUD 자산은 보존했다. 누락된 수학용 마이너스 글리프는 UI에서 지원되는 하이픈으로 표기한다.

Godot MCP의 프로젝트 조회는 성공했다. 씬/테마 일괄 작성은 로컬 리소스로 수행했고, 격리 저장 및 자동 입력·캡처는 Godot 4.7 CLI를 사용했다. `project.godot`의 기본 진입/전역 스트레치 설정과 저장 형식은 변경하지 않았다. 이 HUD가 열릴 때만 논리 배율을 적용하고 닫힐 때 원래 창 설정으로 복원한다. 2016×908 창의2배/1008×454 논리 크기도 확인했다.

최종 에디터 임포트는 종료 코드0, 스크립트/리소스 오류0이었다. Android `build-tools` 디렉터리를 열 수 없다는 환경 경고가 남았으며 이번 PC 검증에는 APK 내보내기가 포함되지 않는다.

연속 흐름은 정상 연출 속도에서4,010검사 실패0으로 완료했다. 최종 씬 분리 후에는 테스트 전용 연출 배속으로 다시 검사해4,217검사 실패0을 확인했다. 게임 연출 속도는 바꾸지 않았다. 일반 캠페인 저장이 생기지 않았음을 별도로 확인했다.

실행 명령은 `tools/run_prototype_hud.ps1 -Mode ui|flow|visual|direct|scroll|probe|import`, 별도 프로세스 검사는 `-Mode restart -Stage write` 후 `-Stage read`다. 최종 흐름 재검사는 `-Mode flow -Fast`를 사용한다. 로그·JSON·캡처는 모드별 하위 폴더에 있다.

## 시각 확인과 수정

- 짧은 화면에서 이전 전장 최소 높이가 하단 UI를 밀어내는 현상, 캐릭터 위쪽 잘림을 수정했다.
- 초기 배치 시 버튼 그림에 남던 오른쪽 여백 때문에 배경 그림이 입력 영역 밖으로 돌출되던 문제를 수정했다.
- 탄창 카드가 스와이프 입력을 가로채던 문제를 `mouse_filter=PASS`로 수정했다. PC의 터치 모사로 확인했으며 실기기 손가락 체감을 의미하지 않는다. [Godot ScrollContainer 문서](https://docs.godotengine.org/en/stable/classes/class_scrollcontainer.html).
- 보상 아이콘의 실제 그리기가 노드 크기보다 커 이름과 닿는 문제를 작은 아이콘 모드로 수정했다.
- 전투, 선택/소진, 메뉴·상세, 코어/탄 보상, 정비, 관문, 완료 화면을 직접 이미지로 검토했다. 에디터 구성을 확인하는 캡처는 씬의 컨트롤러를 제거한 상태이며 에디터 프로그램 자체의 스크린샷은 아니다.

## 실행과 남은 범위

`OPEN_COMBAT_UI_STUDY.cmd`는 새 HUD의 기존 탄창 여정으로, `OPEN_MAGAZINE_COMPARISON.cmd`는 독립 총기 비교로 연다. 실행기의 사용자 비교 저장은 QA 저장과 분리한다.

HTML과의 차이는 검토 도구막대/목업 지도·경제를 제외한 점, 실제 Godot 전장 연출/획득 화면을 쓴 점, 탄환을 고정된 작은 폭으로 유지한 점이다. HTML 전체 화면의 정밀 복제라고 주장하지 않는다.

본편 기본 진입 전환, APK 제작/게시, HTML의 상점·지도 전체 이식은 수행하지 않았다. 네이티브는 현행 게임의 가로 화면을 대상으로 하며 HTML의 세로 화면 대응과 구분한다. Android 안전 영역 코드는 연결했으나 실기기 안전 영역·스와이프·발열·지속 FPS, 사람의 미감·선택 이해도는 미검증이다.

다음은 이 실행본으로 화면과 연속 선택 체감을 확인하고, 본편 통합 조건에 따라 지도·획득·정비 화면의 적용 범위를 정하는 단계다.
