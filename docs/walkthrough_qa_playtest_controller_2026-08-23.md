# QA 실제 플레이테스트 컨트롤러 완료 워크스루

## 구현 결과

HTML 대시보드에서 로컬 QA를 시작·취소하고 진행률을 확인할 수 있다. 실행기는 전용 사용자
데이터 폴더에서 전체 회귀를 먼저 수행한 뒤, 초보·공격·보수·실험 성향이 실제 메인 씬과
`CombatManager`를 독립적으로 플레이한다. 브라우저는 seed와 목표 교전 수만 전달할 수 있고
임의 명령이나 경로는 실행할 수 없다.

전투 행동은 실제 UI 브리지의 합법 행동으로만 수행한다. 경험 테스터에게는 적의 숨은 상태나
미래 RNG 같은 oracle 정보가 전달되지 않는다. 각 행동의 기대 결과·이유·대안을 결과 전에
기록하며, 선택 집중·탄약 미사용·중단 지점 같은 관찰을 경험 신호로 남긴다.

## 버그와 재미의 분리

- 실제 제품 런타임의 동일 결함 지문이 2회 중 2회 재현된 경우만 확정 버그다.
- 일회성 이상은 버그 후보로 유지한다.
- seeded/synthetic 결함은 QA 탐지기의 오탐·미탐 확인용이며 제품 결함과 별도 집계한다.
- 재미·UX·밸런스는 단일 재미 점수 대신 축별 행동 증거와 신호 강도로 보고한다.
- 타격감, 오디오, 손 피로처럼 자동화가 직접 느낄 수 없는 항목은 사람 확인으로 남긴다.

초보·공격·보수 프로필은 승리했고 실험 프로필은 패배까지 정상 결과로 기록했다. 현재 REVIEW는
기능 실패가 아니라 여러 프로필에서 반복된 선택 집중 및 전술탄 사용 패턴을 향후 재미 논의
대상으로 남긴 것이다.

## 실행 방법

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\qa_dashboard_controller.ps1
```

이후 `http://127.0.0.1:8765/`에서 `QA 테스트 시작`을 누른다. HTML 파일을 직접 열면 기존
결과 조회만 가능하다.
