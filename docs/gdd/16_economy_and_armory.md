# 💰 경제 시스템 보충안 — 기업 크레딧과 무기고 상점

> **문서 경로**: `docs/gdd/16_economy_and_armory.md`  
> **상위 문서**: [마스터 GDD](file:///d:/ProjectLoB/docs/game_design_document.md)  
> **본 문서는 'Last on Board'의 재화·상점 경제에 대한 의도 보충(Addendum) 문서입니다.**  
> **기존에 구현이 완료된 '탄약 자원 시스템'의 전용/호환 구조 위에 얹히며, 두 경제가 상호 충돌하지 않고 효율성을 가리키도록 강제합니다.**

---

## 0. 지배 원칙 — 경제는 "탄 경제"와 충돌하지 않아야

- **상충 방지**: 이미 존재하는 핵심 경제는 **"탄 경제"**(유효 적중 환급, "효율적으로 쏘면 유지")입니다.
- **방향의 일치**: 재화 경제를 추가할 때의 핵심 원칙은 **두 경제가 같은 방향(효율성)을 가리켜 서로를 강화하게 만드는 것**입니다. 돈으로 탄 부족을 손쉽게 해결하는 방식의 충돌은 금지합니다.
- **핵심 방어선**: 플레이어가 크레딧으로 구매할 수 있는 것은 **"효율화 사치품"**이지 **"생존 필수품"**이 아닙니다. 돈으로 즉각적인 생존을 살 수 없게 제한함으로써, 탄 경제가 유발하는 생사의 긴장감(Tactical Horror)을 유지합니다.

---

## 1. 재화 = 기업 크레딧 (Corporate Credits)

### ① 컨셉: 세계관이 곧 시스템
- 시설 시스템이 플레이어의 전투 효율(탄약 소모율)을 **실시간으로 평가해 배급**합니다.
- **"효율 보상"**은 게임 시스템의 편의적 규칙이 아니라 세계관 내부의 행위(Diegetic Action)입니다. 시설의 AI 시스템이 플레이어(요원)를 끊임없이 감시·평가하고 배급 권한을 결정하는 서늘한 톤앤매너를 가집니다.
- **무기고의 정체성**: 단순한 정비실이 아니라, 아직 작동 중인 **"기업의 자동 보급 단말(Corporate Supply Terminal)"**입니다.

### ② 서사적 확장성 (추후 단계)
- 전투 종료 시 "탄약 효율 87%. 배급 등급 A 승인"과 같은 평가 메시지를 띄워 세계관 파편 및 로어(Lore)와 엮어냅니다.
- 후반부 서사 진행에 따라 시설이 플레이어를 인식하는 태도가 변화하고, 배급 단말의 대사가 달라지는 등의 시스템-서사 결합 확장이 가능합니다.

---

## 2. 획득 = 전투 종료 드래프트 "탄환 vs 크레딧" (B안)

- **전투 정산 자동 지급 배제**: 전투 종료 후 크레딧이 자동으로 인벤토리에 들어오지 않습니다. 대신 전투 종료 드래프트에서 **"탄환 vs 크레딧" 중 하나를 선택**해야 합니다.
- **효율 연동 크레딧**: 효율적으로 싸워 높은 등급을 받을수록 드래프트 선택지에 나타나는 크레딧의 액수가 많아져 크레딧 선택의 매력이 커집니다. 못 싸웠을 경우 크레딧 액수가 쥐꼬리가 되므로 당장의 탄환 보급을 선택하는 것이 강제됩니다.
- **선택의 본질**: **"확정된 지금(당장의 생존을 위한 호환 탄) vs 유연한 나중(크레딧 저축 → 무기고에서 원하는 것 구매)"** 사이에서 저축 여부를 판단하는 딜레마입니다.
- **드래프트 3택의 전제**: 선택지 3개 중 때로는 **"모두 내 덱(탄창 빌드)에 맞지 않아 쓸모없는"** 상황이 연출되어야 크레딧 선택지가 가치를 발휘합니다. 항상 쓸만한 탄환만 나온다면 크레딧 저축은 죽은 선택지가 됩니다.

### 화면 설계 — 결과창 + 드래프트 단일 오버레이
```
=========================================
               [ 전 투 종 료 ]
   
   탄약 소모율: 82% | 평가 등급: A
   "자원 통제 적정선 확인. 배급 등급이 상향 조정되었습니다."
-----------------------------------------
   [보상 드래프트]
   [탄환 A (경량탄)]   [탄환 B (소총탄)]   [기업 크레딧 +35]
=========================================
```
- 결과창(피드백)을 상단에, 드래프트(선택)를 하단에 배치하여 단일 화면에서 정산과 선택을 한 번에 끝냅니다. 클릭 피로도를 최소화하여 짧은 템포의 전투 반복 피로를 줄입니다.
- 드래프트에서는 **호환 탄**만 등장합니다. (전용 탄은 매 전투가 끝나면 리셋되므로 보상으로 선택할 필요가 없음)

## 3. 사용 = 무기고 상점 (Corporate Terminal)

- **노드 통합**: 맵 노드를 추가로 늘리지 않고, 기존 **"무기고(Armory)"** 노드 내부로 기능을 통합합니다.
- **기능의 구분**: 단말기 UI 내에서 무료 영역과 유료 영역의 성격을 명확히 구분합니다.
  - **파츠 교체 = 무료 정비**: 요원이 가진 장비를 직접 손봅니다. (소지 파츠 교체)
  - **크레딧 구매 = 유료 배급**: 단말기로부터 기업 크레딧을 지불하고 물자를 인계받습니다.
- **기본 진열 3장**: 호환/특수 탄환 1장 + 총기 개조 파츠 2장.
  - 파츠 두 장은 **하나만 살 수 있는 빌드 분기**다. 첫 계층은 역할 유지/역할 교대를, 이후 계층은 기존 빌드 후속/총기 친화를 대비시킨다.
  - 각 카드에 분기 유형과 선택 이유를 표시한다. 구매 버튼은 `1개 한정`을 미리 알리고, 구매 후 선택한 카드는 `선택 완료`, 다른 카드는 `반대 분기 폐쇄`로 구분한다.
  - 장착·가방·Hold에 이미 있는 파츠는 진열하지 않는다. 첫 계층 파츠는 30Cr, 이후 계층은 30~45Cr이다.
  - 소모품은 파츠 선택 밀도를 보장하기 위해 표준 진열에서 제외한다. 재도입 시 상점 파츠 슬롯을 대체하지 않는 별도 획득 경로를 먼저 검증한다.
- **판매 금지 품목 (핵심 방어선)**:
  - **전용 기본 탄**: 총기 고유 스펙이자 매 전투 리셋 대상이므로 상점 판매 불필요.
  - **탄창 확장**: 플레이어의 영구적/성장 핵심 축이므로 크레딧 상점에 넣지 않습니다. 상점에 넣을 경우 다른 모든 상품이 묻히고 '돈 모아서 탄창만 늘리기'가 최적 전략이 되어 기형화됩니다. (탄창 확장은 보스 처치나 특수 보안 구역 보상으로만 제한)

---

## 4. 레벨 디자인 저울추 — 무기고 등장 빈도

- **무기고가 너무 드문 경우**: 크레딧을 쓸 곳이 없어 가치가 폭락하고, 드래프트에서 무조건 당장 쓸 탄환만 고르게 되어 크레딧 경제가 고사합니다.
- **무기고가 너무 잦은 경우**: 크레딧을 즉각 물자로 치환할 수 있어 고민 없이 크레딧만 고르게 되고, 드래프트의 선택 딜레마가 붕괴합니다.
- **이상적인 조율**: 플레이어가 **"다음 무기고 노드까지 몇 층이 남았는가? 현재 탄약으로 버틸 수 있는가?"**를 머릿속으로 계산하며 저축 계획을 세우게 만듭니다. 이를 위해 **미리 맵 전체의 경로와 무기고 위치가 공개(슬더스식 맵 구조)**되어 있어야 합니다.

## 🧠 CD(Creative Director) 검토 의견 및 보완점

### 1. 코어 비전(LIFO Tactical Horror)과의 정합성 평가
- **매우 훌륭함 (Pass)**: 재화 추가 시 발생할 수 있는 가장 큰 리스크인 '생존 난이도 희석'을 철저히 차단했습니다. 탄을 돈으로 사서 생존을 메우는 것이 아니라, "내가 가진 탄창 빌드를 정교하게 다듬기 위한 윤활유(파츠, 특수탄)"로 크레딧 사용처를 좁혀 LIFO 덱빌딩의 긴장감을 유지합니다.
- "탄환 vs 크레딧" 드래프트는 **'즉시 장전하여 사용 가능한 실탄'**과 **'장기 투자를 위한 재화'** 사이의 전술적 딜레마를 만들어 LIFO 장전 계획에 깊은 고민을 유도합니다.

### 2. 감시 AI의 냉소적 피드백 시스템 구체화 (세계관 결합)
단순한 텍스트 출력을 넘어, 전투 종료 시 효율 등급에 따른 단말기의 피드백 대사를 세분화하여 디스토피아적 무드를 강화합니다.
- **A등급 이상 (효율 90%+)**: `"자원 통제 수준 우수. 배급 한도가 임시 증액되었습니다. 귀하의 생존 효율은 자산 가치에 부합합니다."` (크레딧 보너스 지급)
- **B~C등급 (효율 60%~90%)**: `"표준 작전 범주 내 소비율 감지. 기본 배급 절차를 진행합니다."`
- **D등급 이하 (효율 60% 미만)**: `"주의: 극심한 탄약 남용이 감지되었습니다. 시설 보급 한계치 임박. 탄약 절약이 강제 권고됩니다."` (크레딧 보상 극도로 축소)

### 3. 드래프트의 "오염 요소(Trash Option)" 설계 의도 명시
- 크레딧 선택의 가치가 살려면, 드래프트에 나오는 호환 탄이 내 현재 무기 아키타입이나 스택 순서에 방해가 되는 "꽝" 역할이어야 합니다.
- 예를 들어, 샷건(Scatter) 빌드를 가는데 DMR용 장거리 정밀 탄환(시너지가 전혀 나지 않음)이 드래프트 목록에 떴을 때, 플레이어는 고민 없이 크레딧을 선택할 수 있습니다.
- 따라서 드래프트 생성 로직 상에 **'현재 장착 무기와 무관하거나, 빌드를 꼬이게 만드는 특수/호환 탄환'**이 일정 확률로 섞이도록 설계의 빈틈을 보존해야 합니다.

### 4. 무기고 상점 단말의 "리롤(Reroll)" 시스템 제안
- 무기고에서 원하는 파츠나 탄이 확정적으로 나온다면 빌드의 고착화가 빨라집니다.
- 단말 상점은 3장으로 제한하고, 소량의 크레딧을 소모하여 품목을 갱신하는 **"단말기 주파수 재요청 (Reroll)"** 기믹을 사용합니다. 첫 진열은 학습을 위해 고정하되 리롤부터 역할 유지/전환 후보군 안에서 바뀌며, 이후 계층은 시너지/총기 친화 구조를 유지한 채 후보만 갱신됩니다.
- **UI 및 텍스트 톤**: `"단말기 데이터 수신 상태 불량. 추가 주파수를 대역해 보급품 목록을 갱신합니다. (비용: 3 Credit)"`

### 5. UI 개발 및 디버그 연동 규칙 (SOP) 환기
- 해당 UI 화면(결과창 + 드래프트 한 화면, 무기고 배급 UI)을 구현할 때는 룰북에 근거하여 소스 코드를 건드리기 전에 반드시 **UI 요청 제작 기획서(`ui_request_*.md`)**를 작성하여 승인을 받아야 합니다.
- 구현 완료 후에는 메인 메뉴의 **`🛠️ 개발자 테스트`** 팝업을 통해 직접 테스트할 수 있도록 연동 숏컷 버튼을 확보해야 합니다.

## 📅 미결 사항 및 다음 단계 태스크

| 항목 | 담당 / 방향성 | 비고 |
|---|---|---|
| **효율 N% ↔ 크레딧 양 매핑 수식** | 밸런스 디자이너 (Balance Designer) | 등급별/효율%별 상세 수식 설계 필요 |
| **무기고 상품 기본 가격 책정** | 밸런스 디자이너 (Balance Designer) | 호환 탄/특수 탄/파츠/리롤 기본 비용 설정 |
| **무기고 배치 알고리즘** | 레벨 디자인 / 프로그램 | 구역별 맵 제너레이터(`map_generator.gd`) 내 무기고 노드 배치 빈도 및 규칙 설계 |
| **드래프트 확률 풀 정립** | 프로그램 / 기획 | 무기 연동 및 확률 보정 규칙 정의 |
| **소모품(휴대용 배터리, 소형 치료제 등) 기획** | CD / 밸런스 디자이너 | 생존에 직접적 영향을 주지 않는 범위 내의 유틸리티 템 정의 |
