# UI·UX 선택 흐름 전면 개편 계획

상태: 구현·자동 검증 완료  
승인 근거: 2026-09-24 사용자가 UI·UX 중심 게임임을 전제로 개편을 승인  
정본 검토: `docs/qa/reports/uiux_intuitiveness_review_2026-09-24.md`

## 목표

플레이어가 규칙표를 해석한 뒤 행동하는 구조를 `선택 이유 → 선택 결과 → 확정 행동`이 화면에서 이어지는 구조로 바꾼다. 전투 계산, 경제, 저장 형식은 유지하고 정보 우선순위와 입력 경로를 개편한다.

## 1. 전투 결정 흐름

- 각 후보 탄환 아래에 현재 전열 기준 예상 결과를 직접 표시한다.
  - 표적, 피해, 처치, 도탄, 전이, 화상, 거리 변화 중 가장 중요한 결과
- 탄환 추가 전후의 처치 수, 접촉 위험, 최근접 거리를 비교해 좋아진 변화만 강조한다.
- 전투 단계 안내를 행동 문장으로 바꾼다.
  - `탄을 고르세요` → `순서와 결과를 확인하세요` → `발사할 준비가 됐습니다`
- `장전 확정`, `발사`만 현재 단계의 채운 주 버튼으로 표시한다.
- 압축 가능한 동일 탄환은 드래그 외에 명시적인 `두 발 합치기` 버튼을 제공한다.
- 기존 드래그, 장전, 회수, 계산, 확정, 발사 입력 식별자를 유지한다.

## 2. 지도 선택과 확정

- 지도 노드 첫 탭은 목적지만 선택한다.
- 하단 선택 카드에 시설 종류, 경로 비용, 다음 전투 영향을 보여 주고 `이 경로로 이동`으로 확정한다.
- 이동 가능한 노드를 눌렀다고 즉시 진입하지 않는다.
- 기존 `city_enter_*` 확정 버튼은 유지한다.

## 3. 상점 비교

- 상품 카드를 누르면 화면 안 비교 패널을 갱신한다.
- 탄환은 현재 수량과 구매 후 수량, 파츠는 즉시 장착 여부와 이득·대가를 표시한다.
- 전체 규칙은 비교 패널의 상세 버튼에서 연다.
- 구매와 상세 입력 식별자는 유지한다.

## 4. 덱·장비 작업 분리

- 한 긴 모달을 `장착 파츠`, `보관함`, `탄환 덱` 탭으로 분리한다.
- 첫 탭은 5칸 현재 빌드, 두 번째 탭은 장착·해제, 세 번째 탭은 탄환 종류와 수량만 보여 준다.
- 장착 뒤 현재 탭과 스크롤 맥락을 가능한 범위에서 유지한다.

## 5. 공통 문법

- 채운 민트 버튼은 화면당 현재 주 행동 하나에만 사용한다.
- 시안은 압축·전기, 노랑은 성장·보상, 주황은 위험·대가로 제한한다.
- 설명은 행동 순간에 한 문장으로 제공하고 상세 규칙은 탭 또는 상세창으로 보낸다.
- 1280×800, 1008×630, 840px 접힘을 검증한다.

## 완료 조건

- 처음 보는 플레이어가 전투에서 후보 탄환마다 이번 상황의 결과를 읽을 수 있다.
- 장전 후 변화와 다음 주 행동이 한 화면에서 강조된다.
- 압축을 드래그 지식 없이 버튼으로 실행할 수 있다.
- 지도 노드 탭과 실제 이동이 분리된다.
- 상점 상품 선택 시 구매 전후가 화면 안에 표시된다.
- 덱·장비 세 작업이 탭으로 분리된다.
- 전체 자동 검증과 실제 OpenGL UI 재생이 통과한다.

## 구현 결과

- 전투 후보 카드가 현재 전열 기준 결과를 카드 하단에 표시하고, 단계 안내와 장전 확정·발사 버튼의 주 행동 위계를 분리했다.
- 같은 탄환 두 발은 드래그하거나 `2발 합치기` 버튼을 눌러 압축할 수 있다.
- 지도는 노드를 눌러 경로를 고른 뒤 하단의 민트색 이동 버튼으로 진입한다.
- 상점은 진열 두 칸과 구매 전후 비교 한 칸을 같은 작업대에 배치했다. 파츠는 이득·대가·빌드 변화를 먼저 보여 주고 전체 규칙은 별도 상세창에서 연다.
- 덱·장비는 `착용 중`, `보관함`, `탄환 덱` 세 탭으로 분리했다.
- 전체 자동 검증 3,730/0, 실제 OpenGL UI 3,675/0·버튼 입력 1,179회·보행자/쇄도 35층 재생을 통과했다.

사람의 첫 플레이 이해 속도와 선택 피로는 자동 검증으로 확정하지 않는다. 이번 결과물을 다음 사용자 플레이테스트 기준으로 사용한다.
