# QA 실제 플레이테스트 컨트롤러 구현 계획

## 목표

HTML 대시보드의 시작 버튼으로 동일 빌드를 실제 플레이하고, 재미·UX·밸런스 신호와 기능
버그를 서로 오염시키지 않은 보고서로 남긴다. 자동화가 볼 수 없는 타격감·오디오·피로도는
사람 확인 대상으로 명시한다.

## 핵심 원칙

- fixture 전투가 아니라 실제 메인 씬과 `CombatManager`를 사용한다.
- 테스터는 `player_view`에 공개된 정보와 합법 행동만 사용하며 oracle 상태를 보지 않는다.
- 초보·공격·보수·실험 4개 성향은 동일 seed에서 독립 실행한다.
- 모든 선택은 실행 전에 기대 결과, 선택 이유, 고려한 대안을 기록한다.
- 재미는 단일 점수로 환산하지 않고 7개 경험 축과 행동 근거로 보고한다.
- 기능 버그는 제품 런타임에서 동일 지문이 2/2 재현되어야 확정한다.
- seeded/synthetic 결함은 검출기 자체 점검 결과로 분리한다.
- QA 전용 사용자 데이터 폴더를 사용해 실제 플레이 세이브를 보호한다.

## 구조

1. `qa_dashboard_controller.ps1`이 루프백 HTTP와 고정 API를 제공한다.
2. `qa_run_playtest.ps1`이 회귀, 4개 프로필, 비교, 통합, 이력 갱신 단계를 격리 실행한다.
3. `qa_autonomous_playtest_runner.gd`가 실제 UI/전투 경로를 의미 단위 행동으로 플레이한다.
4. QA 역할별 원본 보고서는 서로 공유하지 않고 마지막 통합 단계에서만 합쳐진다.
5. exporter가 PASS/FAIL/REVIEW/BLOCKED와 원본 증거를 HTML 데이터로 변환한다.

## 판정 계약

| 판정 | 의미 |
|---|---|
| PASS | 회귀 실패, 확정 버그, 강한 경험 검토 신호가 없음 |
| FAIL | 실제 제품 기능 버그가 재현 기준을 충족함 |
| REVIEW | 재미·UX·밸런스 신호 또는 미확정 버그 후보가 있어 사람이 논의해야 함 |
| BLOCKED | 실행 인프라나 필수 산출물 문제로 검증을 완료하지 못함 |

## 완료 조건

- 대시보드 시작·취소·진행률·중복 실행 차단이 동작한다.
- 4개 프로필이 실제 메인 씬에서 최소 한 전투 결과를 만든다.
- 실행별 로그와 필수 JSON이 생성되고 대시보드 이력에 보존된다.
- 전체 자동 회귀와 JavaScript/PowerShell 정적 검사를 통과한다.
- 사람이 직접 확인해야 할 감각 항목이 자동 PASS에 섞이지 않는다.
