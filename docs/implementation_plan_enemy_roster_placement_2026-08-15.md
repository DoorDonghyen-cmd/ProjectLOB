# 몬스터 13종 계층 배치·표기명 정합 구현 계획

> 상태: 사용자 승인 후 구현·자동 검증 완료 (2026-08-15)
> 범위: 일반·변종 9종의 계층별 일반전 편성, 관문 보스 4종 도달성, 현행 적 표기명 정합
> 비범위: 적 스탯·기믹·아이콘·스프라이트·보스 관문 편성·난이도 수치 변경

## 1. 목표

- 13종 적 리소스가 개발자 메뉴에만 존재하지 않고 실제 35층 캠페인에서 모두 도달 가능하게 한다.
- 일반전 편성을 `combat_scene.gd`의 분산된 조건문에서 계층별 콘텐츠 정본으로 분리한다.
- 관리 계층과 정점이 같은 스폰 분기를 공유하는 구조를 해소하고, 상층일수록 비인간형 자물쇠 비중이 높아지게 한다.
- 구 감염·나노 실험체 문맥이 남은 표기명을 기계화=계급 세계관과 아키타입 실루엣 언어에 맞춘다.

## 2. 계층별 도입 규칙

| 계층 | 신규 노출 | 전술 학습 |
| :--- | :--- | :--- |
| 침전 거주구 | 돌격병·방패병·회피병 | 거리·관통·명중 기본 게이트 |
| 공역 | 순찰 드론·술사 | 넉백 저항·차징 우선순위 |
| 정비 계층 | 흡수체 | 유효타 수와 관통 스침 |
| 관리 계층 | 태세 교란 드론·광학 추적체·상위 신경 통제체 | 역할 교대·고명중·강제전진 종합 |
| 정점 | 신규 일반 적 없음, 상위 자물쇠 고밀도 재조합 | 최종 관문 전 종합 복습 |

각 계층은 초·중·종반 3티어에 2~3개의 결정형 편성 후보를 가진다. 무작위는 후보 선택에만 사용하며, 선택된 편성의 적 종류·수치는 고정한다.

## 3. 구현 구조

- 신규 `scripts/core/enemy_roster.gd`
  - 계층×티어별 일반전 편성 ID 정본
  - 계층별 증원 후보와 목표 밀도
  - 실제 리소스 로드 및 계층별 도달 ID 조회
- `scripts/ui/combat_scene.gd`
  - 인라인 스폰 분기를 제거하고 `EnemyRoster`를 호출
  - 기존 첫 구역 온보딩·3~4체 상한·관문 `CampaignContent` 분리는 유지
- 적 CSV·`.tres`·현행 GDD
  - 표시명만 동기화하고 ID와 스탯은 유지

## 4. 표기명 원칙

- 하층의 인간형 통제 병력은 직무명으로 유지한다.
- 상층 변종은 개인·감염·실험실 잔재 대신 기능과 실루엣을 나타내는 명칭을 사용한다.
- UI 코드에 이름을 하드코딩하지 않고 CSV와 `.tres`의 표시명을 일치시킨다.
- 최종 제목과 `L.O.B 코어` 재명명은 별도 제목 확정 작업까지 보류한다.

## 5. 검증

- 일반·변종 9종이 일반전 편성 정본에서 모두 한 번 이상 도달한다.
- 보스 4종이 기존 A/B/C/E 관문에 그대로 연결된다.
- 캠페인 도달 ID의 합집합이 적 리소스 13종과 정확히 일치한다.
- 기본 3종은 침전에서, 중급 3종은 공역·정비에서, 응용 변종 3종은 관리에서 처음 등장한다.
- 일반전은 최대 4체이고 고속 적(`SPD >= 3`)이 한 편성에 둘 이상 겹치지 않는다.
- `enemy_stats.csv`와 13개 `.tres`의 표시명이 일치하고 폐기 명칭이 남지 않는다.
- 전체 Godot 헤드리스 테스트 실패 0을 유지한다.

## 6. 구현 결과

- `EnemyRoster`를 일반·변종 9종의 계층별 편성 정본으로 추가하고 `combat_scene.gd`의 하드코딩 분기를 교체했다.
- 관리 계층과 정점 계층의 편성을 분리했다. 정점은 신규 일반 적을 추가하지 않고 관리 계층까지 학습한 상위 자물쇠를 3~4체로 재조합한다.
- 9종 일반·변종과 4종 관문 보스가 35층 캠페인에서 모두 도달 가능하도록 고정했다.
- CSV와 적 리소스의 표시명을 현행 세계관에 맞춰 동기화했다. 리소스 ID·스탯·기믹·보스 관문은 변경하지 않았다.
- 전용 회귀 스위트를 추가해 최초 등장 계층, 편성 상한, 고속 적 중첩 제한, 13종 전체 도달성, CSV↔리소스 표시명 일치를 검증한다.
- 최종 검증: 스크립트 85개 컴파일, 씬 4개 로드, 3,297 통과 / 0 실패 / 기존 경보 3.
