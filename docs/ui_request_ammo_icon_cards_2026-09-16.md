# 탄환 카드 아이콘 정보 체계

상태: 구현·자동 검증·Windows 검토 빌드 완료. 사람의 첫인상 가독성 확인만 남음. 기준 브랜치 `prototype/core-redesign`, 기준 커밋 `06ac0cb`.

## 목표

카드마다 반복되는 `위력·관통·명중` 문장을 작은 픽셀 아이콘과 숫자로 바꿔, 여러 탄환을 한눈에 비교하게 한다. 아이콘만으로 세부 규칙을 숨기지 않으며 선택 탄의 문장 설명과 실제 피해 계산은 기존 공용 영역에 유지한다.

## 카드 와이어프레임

```text
┌─────────────────────┐
│  ◇ 탄환 아이콘  조준탄 ×1 │
│                     │
│  [충격] 2 [관통] 0 [조준] 10 │  ← 기본 수치, 고정 순서
│  [조준+] +4  × 다음 2발     │  ← 효과 한 줄
└─────────────────────┘
```

- 카드 전체는 기존처럼 한 번 눌러 즉시 장전한다. 별도 확인 단계를 추가하지 않는다.
- 탄환 외형 아이콘은 좌상단에 유지한다. 이름·보유량은 첫 줄에서 가장 크게 읽힌다.
- 수치 행은 `위력 → 관통 → 명중` 고정 순서다. 아직 배우지 않은 축은 빈칸을 남기지 않고 행을 균등 재배치한다.
- 기본 수치는 부호 없이 `8`, 다른 발이나 상태를 변화시키는 효과는 반드시 `+8` 또는 `−2m`처럼 부호를 붙인다.
- 효과 행은 효과 아이콘과 최소한의 수치/범위만 표시한다. 정확한 조건과 문장은 카드 선택 시 공용 설명 영역에서 제공한다.
- 비활성 카드도 수치 비교가 가능하도록 아이콘과 숫자의 대비를 유지한다.

## 공용 픽셀 아이콘

| 의미 | 실루엣 | 카드 예시 |
| --- | --- | --- |
| 위력 | 사방으로 튀는 탄착 충격 | `5`, 연속탄은 `2×2` |
| 관통 | 방패를 통과하는 오른쪽 화살 | `2` |
| 명중 | 네 방향 조준점 | `8` |
| 균열 | 갈라진 방패 | `+2` |
| 강화 | 탄착 충격과 작은 `+` | `+2 · 2발` |
| 조준 보조 | 조준점과 작은 `+` | `+4 · 2발` |
| 2회 공격 | 겹친 탄환/타격 | `×2` |
| 밀기 | 오른쪽 화살 | `2m` |
| 둔화 | 아래 화살 | `−2m · 1회` |
| 도약 | 두 갈래 화살 | `1 / 균열 3` |
| 마무리 | 절반 HP 표시와 충격 | `HP≤½ · +4` |
| 회수 | 순환 화살 | 재장전 공급량 |

아이콘은 Godot `CanvasItem`의 정수 좌표 선·사각형·다각형으로 그린다. 별도 PNG와 필터링을 사용하지 않아 화면 배율에서 흐려지는 문제를 피한다. 제한된 뮤트 팔레트와 1px 또는 2px 단위의 공통 선 굵기를 사용한다.

## 상세·보상·학습 흐름

- 카드 아래 공용 영역에는 `위력 → HP`, `관통 → 장갑`, `명중 → 회피` 범례와 선택 탄의 정확한 문장을 유지한다.
- 실제 장전 슬롯을 선택하면 기존처럼 최종 피해와 강화·장갑·스침·HP 상한의 계산 근거를 표시한다.
- 보상 카드에도 같은 수치 아이콘을 사용해 전투 카드와 학습한 시각 언어를 재사용한다.
- 첫 학습 교전은 위력 아이콘만, 장갑 학습부터 관통, 회피 학습부터 명중 아이콘을 공개한다. 전체 정보창은 세 축을 항상 제공한다.
- 메인 메뉴 `개발자 테스트`에 아이콘 카드 전체 조합을 즉시 확인하는 숏컷을 추가한다.

## 완료 조건

1. 일반 3열 카드와 5칸 확장 전투에서 이름·3개 수치·효과가 겹치거나 잘리지 않는다.
2. `명중 8`과 `명중 +8`이 시각적으로 구분된다.
3. 단계별 미도입 축이 카드에 나타나지 않고, 전체 정보/툴팁에는 누락되지 않는다.
4. 마우스·터치 장전, 비활성 상태, 선택 탄 계산, 보상 선택이 기존과 동일하게 작동한다.
5. 1280×800과 1920×864에서 버튼과 카드가 화면 안에 유지된다.
6. 기존 전투 수치·저장·캠페인 규칙은 변경하지 않는다.

APK는 사용자가 명시적으로 요청할 때까지 제작하거나 갱신하지 않는다.
