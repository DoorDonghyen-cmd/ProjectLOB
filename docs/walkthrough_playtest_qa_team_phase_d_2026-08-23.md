# 전용 플레이 QA 팀 Phase D 워크스루

> 완료일: 2026-08-23
> 세션 ID: `codex0823-qa-team-rng`
> 범위: 재현 가능한 1~2구역 런과 게임플레이/FX RNG 분리

## 결과

QA 캠페인 실행기가 실제 메인 씬을 전용 세이브 경로에서 시작해 타이틀, 구역 선택,
준비실, 지도, 전투 결과, 보상, 상점, 다음 구역 전환을 의미 행동으로 진행한다.
고정 seed `424242`로 두 번 독립 실행한 결과 모두 46개 행동과 13개 노드를 지나
`section_c` 지도에 도달했다.

두 실행의 행동열, 완료 노드, 크레딧·HP·현재 구역, 6개 게임플레이 RNG 스트림 상태는
완전히 같았고 FX seed만 달랐다. 초기 구현에서 QA seed가 준비실 완료 콜백으로 전달되지
않던 결함도 산출물 대조로 발견해 수정했다.

## 구현

- `RandomStreams`: `map`, `encounter`, `reward`, `shop`, `event`, `combat`과 FX 스트림 분리
- 맵 생성, 적 편성, 보상, 상점, 이벤트, 전투 셔플의 전역 난수 호출을 명시적 스트림으로 이관
- manifest 스키마 v2와 `PlaytestLogger` 스키마 v3에 `gameplay_seed`, `session_id` 기록
- `choose_reward`, `buy`, `use_maintenance`, `continue_section` 의미 행동 추가
- 매 행동 뒤 `progress.json`에 단계, 마지막 행동, 진행 상태, 전체 RNG 상태 저장
- `qa_campaign_replay_runner.gd`로 깨끗한 세이브의 1~2구역 재생 지원

## 검증

- 첫 실행: `passed`, 46행동, 13노드, `section_c` 도달
- 동일 seed 독립 재실행: 행동열·진행 상태·게임플레이 스트림 일치, FX seed만 상이
- 저널: 마지막 단계 46, 마지막 완료 행동 보존, 실제 RNG seed `424242` 확인
- 플레이테스트 로그: 스키마 v3, QA 세션 ID·seed·11개 전투 문맥 기록
- 전체 회귀: **3,515 통과 / 0 실패 / 기존 경보 3**
