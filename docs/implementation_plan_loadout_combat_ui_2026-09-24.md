# 덱·장비 통합과 전투 작업대 장면화 계획

상태: 구현·검증 완료  
승인 근거: 2026-09-24 사용자가 다음 단계 진행을 승인  
기준 화면: 1280×800, 저해상도 1008×630, 가로 화면

## 목표

무기고에서 확정한 장면 기반 UI 기준을 덱·장비와 전투에 적용한다. 파츠 화면의 동작과 표기를 한 구현으로 통일하고, 전투의 `탄환 선택 → 순서 설계 → 발사` 흐름을 편집기에서 보이는 고정 구조로 분리한다. 전투 규칙, 탄환 계산, 저장 형식은 변경하지 않는다.

## 덱·장비 와이어프레임

```text
덱·장비
[덱 장수 | 탄창 | 재장전 | 압축 코어]

현재 빌드                        파츠 n/5 · 코어 n/1
[01] [02] [03] [04] [05]

보관함                          전투 사이 무료 교체
[파츠 카드 + 장착/해제] [파츠 카드 + 장착/해제]

전술 덱 구성
[탄환 카드 + 보유 수] [탄환 카드 + 보유 수]
```

- 무기고와 같은 상태 문구, 5칸 장착 표시, 파츠 카드와 장착 제한을 쓴다.
- 전투 중에는 장착 버튼을 비활성화하고 `교전 종료 후 교체`를 표시한다.
- 덱·장비에서는 파츠 분해를 제공하지 않는다.
- 900px 미만의 매우 좁은 창에서는 보관함과 덱을 1열로 전환한다. 1008×630 가로 화면에서는 두 열을 유지해 한 화면 비교를 우선한다.

## 전투 와이어프레임

```text
[거리 전장 · 전열/증원/접근 상태]
[1 탄 선택] [2 순서 확인] [3 발사]

┌ 보유 탄환 ───────────┬ 발사 순서 n/m칸 ───────┐
│ 압축 코어 / 패 교환   │ 탄창 슬롯·결과           │
│ 탄환 카드 3열         │ 계산 보기 / 끝 탄 회수   │
│ 선택 탄 상세          │ 예상 처치·안전 거리      │
│ 다음2 / 대기 / 사용   │ 확정 또는 발사·재장전    │
└───────────────────────┴────────────────────────┘
```

- `combat_workbench.tscn`이 전장, 단계 표시, 탄환 영역, 탄창 영역의 고정 구조를 가진다.
- 스크립트는 적·탄환·탄창·예측·행동 상태만 바인딩한다.
- 현재 단계는 번호, 문구, 색을 함께 사용한다.
- 1008×630 모바일 가로 화면에서는 탄환과 탄창을 나란히 유지해 선택과 결과를 함께 본다. 900px 미만에서는 두 영역을 세로로 쌓고 탄환 카드를 2열로 줄인다.
- 기존 `BattleView`, `CombatSteps`, `ReserveAmmo`, `MagazineView`, `load_*`, `confirm`, `fire`, `reload` 입력 식별자를 유지한다.

## 구현 순서

1. `deck_loadout.tscn`과 `combat_workbench.tscn`을 작성한다.
2. 파츠 보관함 렌더러에 화면별 버튼 접두사, 편집 가능 여부, 분해 표시 여부를 주입한다.
3. `deck()`을 새 장면에 바인딩한다.
4. `_combat()`을 새 장면의 고정 호스트에 바인딩한다.
5. 기존 개발자 `덱·장비`, `압축탄 장전 UI`, `전투 중 임시 압축 UI`, `상층 적 3규칙` 경로를 그대로 사용한다.
6. 장면 존재, 반응형 열 수, 단계 상태, 실제 구매·장착·장전·발사 입력을 자동 검사한다.

## 완료 조건

- 두 장면이 `_ready()` 전에도 주요 구역과 대표 문구를 보여 준다.
- Godot 4.7 편집기 로드와 파싱 오류가 없다.
- 1280×800과 1008×630에서 가로 넘침 없이 모든 행동에 접근한다.
- 실제 UI 35층 재생과 덱·장비·전투 개발자 경로가 통과한다.
- 무기 규칙과 전투 계산 회귀가 유지된다.

## 완료 결과

- `deck_loadout.tscn`, `combat_workbench.tscn`과 각 반응형 스크립트를 추가했다.
- 무기고와 덱·장비가 같은 파츠 카드, 5칸 장착 상태, 코어 제한, 장착 가능 판정을 사용한다.
- 전투의 전장, 단계 표시, 보유 탄환, 발사 순서, 예측, 행동 영역을 편집 가능한 장면 구조로 분리했다.
- Godot 전체 자동 검증 3,730/0, 실제 OpenGL UI 재생 3,438/0, 실제 입력 1,103회를 통과했다.
- 보행자·쇄도 35층 UI 경로, 1280×800·1008×630·840px 반응형 규칙을 검증했다.
