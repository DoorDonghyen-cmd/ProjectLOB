# 전용 플레이 QA 팀 Phase C 워크스루

> 완료일: 2026-08-23
> 세션 ID: `codex0823-qa-team-ui`
> 범위: 실제 씬 의미 행동, 공개 UI 상태, 체크포인트 캡처

## 1. 구현 결과

기존 UI를 복제하지 않고 `combat_scene.tscn`을 실제로 인스턴스화해 다음 흐름을
프레임별로 재생한다.

```text
타이틀 → 구역 선택 → 준비실 → 지도 → 전투 장전 → 전투 보상
       → 보상 뒤 지도 → 상점 최초 진열 → 주파수 재요청 뒤 상점
```

`qa_ui_action_executor.gd`는 픽셀 좌표 대신 기존 버튼이 연결된 실제 콜백을 호출한다.
화면이 다른 행동, 존재하지 않는 노드, 비활성 버튼은 상태를 바꾸지 않고 거절한다.
전투 승리와 4층 상점 진입만 빠른 체크포인트를 위한 명시적 QA fixture를 사용한다.

## 2. 공개 UI 상태

`qa_ui_state_serializer.gd`는 현재 화면과 보이는 `Control`을 다음 필드로 기록한다.

- 안정적인 루트 기준 경로, 노드 이름과 타입
- `visible`, `disabled`, `text`
- 전역 `rect`의 x/y/width/height
- 현재 화면에서 허용되는 의미 단위 행동
- 보상 카드의 공개 텍스트와 선택 상태
- 상점 슬롯별 아이템 ID·표시명·가격·선택·품절·설명·실제 렌더 텍스트

상점은 데이터 슬롯 수와 렌더 카드 수를 대조하고, 각 파츠의 선택 이유와 설명이 같은
슬롯에 실제로 존재하는지 검사한다. 따라서 주파수 재요청 뒤 가운데 파츠만 바뀌고 이전
설명이 남는 문제와 삭제 대기 중인 구 카드가 한 프레임 겹치는 문제를 모두 검출한다.

## 3. 캡처와 실행기

`qa_capture.gd`는 렌더 가능한 Viewport를 PNG로 저장한다. headless dummy renderer에서는
엔진 오류를 내지 않고 `classification: qa_infrastructure`와 사유를 JSON에 남긴 뒤 의미
단위 검증을 계속한다.

`qa_ui_session_runner.gd`를 실행한 결과 9개 체크포인트 JSON이 생성됐으며 화면별 공개
Control 수는 19~286개였다. 현재 검증 환경은 headless라 PNG 9장은 정상적으로 인프라
생략 처리됐다. 렌더 가능한 실행 환경에서는 같은 경로의 `screenshots/`에 PNG가 저장된다.

## 4. 자동 회귀

`suite_qa_ui_checkpoints.gd`가 다음을 고정한다.

- 실제 메인 씬의 7개 화면 전환과 보상 뒤 지도 복귀
- 다른 화면 행동의 거절과 무상태변경
- 화면별 공개 컨트롤과 합법 행동 직렬화
- 실제 보상 카드 상태
- 상점 최초 진열과 리롤 뒤 데이터↔렌더 설명 일치
- 가운데 카드 교체 시 이전 파츠 설명 제거
- 의도적으로 삽입한 잔존 카드 fixture 검출
- PNG 불가 환경의 QA 인프라 분류

최종 전체 Godot 회귀 결과:

- 통과: **3,502**
- 실패: **0**
- 기존 경보: **3**
- 스크립트 컴파일: **98개 성공**
- 씬 로드: **4개 성공**

Windows 인증서 저장소 읽기 오류는 기존 Godot 실행 환경 메시지이며 테스트 결과에는
영향을 주지 않았다.

## 5. 다음 단계

Phase D에서 맵·적 편성·보상·상점의 게임플레이 RNG와 연출 RNG를 분리하고, manifest에
seed를 기록해 동일 행동열로 1~2구역을 재현한다. Phase C의 UI 브리지는 그 런의 화면
행동과 체크포인트 증거 계층으로 재사용한다.
