# 아트 이전 개발 · 기능 검토 빌드

## 판정

아트 이전 기능 검토 빌드를 구현하고 Windows 실행 파일을 제공한다. **게임 전체의 재미 검증 및 아트 착수 승인은 아직 완료가 아니다.** B안의 정식 채택, 실제 사람의 장전 피로/성공감, 후반 전투 경험과 모바일 실기 확인은 남아 있다.

사용자의 개발 위임에 따라 구현·QA·문서 정리를 진행했다. 기본 게임은 A안 전체 전술탄 선택을 유지한다. 정식 규칙으로 승격하기에 사람 근거가 없는 B안과, 보류 중인 컨버전 킷/덱 정제를 임의로 채택하지 않았다.

## 구현

- 실제 장전 순간의 공개 후보·보급량·장전/발사 순서·적 상태를 기록한다. 실제 발사 수와 장전 결정을 분리하여 적이 먼저 죽었을 때도 시퀀스 집계가 잘리지 않는다.
- `tools/analyze_ammo_hand.py`가 같은 seed/적/총기/파츠/덱/정책인 A/B 한 쌍만 비교한다. 누락·중복 쌍은 거절하며 과거 로그에 장전 기록이 없으면 미측정으로 남긴다.
- 적 아트의 투명 여백을 표시 단계에서 정규화하고 동거리 4체를 같은 바닥선의 수평 슬롯으로 배치한다. HP·배지·선택 영역은 숨쉬기 변형에서 분리했다.
- 연발 넉백 예산을 선제 효과·파츠 증폭·확산 전파에 공통 적용한다. 기존 2칸 계약을 우회해 4칸 밀던 결함을 수정했다.
- 최종 관문 뒤 층 번호가 9가 되어도 누적 진행은 실제 35층으로 제한한다. 36층/590Cr 오정산을 35층/575Cr로 복구했다.
- 선택형 세계관 로어20개와 수집 기록 열람, 타이틀 장전 안내를 구현했다. 파편은 수집 즉시 저장하며 미수집 본문을 숨긴다.
- 암시장 커넥션의 실제 효과를 분해 환급+50%로 표시하고, 처음 장전 중에는 비활성 리로드 대신 가방 사용을 안내한다.
- 경험 QA에 다음 프레임의 공개 행동 결과와 종료 화면을 기록한다. 구매한 방문을 미구매 퇴장으로 잘못 분류하던 기록을 바로잡았다.

## 자동 검증

최종 전체 회귀는 **3,690 통과/0실패/기존 경보3**이며 `qa_runtime/preart_20260911/regression/final/summary.json`에 기록했다. 최초 기준은 3,655 통과/0실패/기존 경보3이었다. 경보는 기존 `sentry_drone` HP 및 `nano_stalker` HP/EVA 데이터 밴드 점검이다. Python 비교 집계 검증5개는 통과했다.

독립 기능 QA는 실제 UI 경로로 5계층35노드·122행동·24검증을 수행했다. 35층/+575Cr 정산, 메타 저장/reload, 5계층 및 승천1 해금, 디브리핑→타이틀→새 런1층 지도 진입을 통과했다. **이 흐름 검증의 전투는 명시적 승리 fixture이므로 실제 전투 승률 증거가 아니다.**

독립 시뮬레이터의 집중 회귀185개와 넉백6사례를 통과했다. 실제 함수로 메타9회 구매 총385Cr 및 완주 정산575Cr를 확인했다. 기존 단일 탄창 검사에서 적 상태 변화가 생겼다는 사실을 생존·완주 해법 보장으로 확대 해석하지 않는다.

실제 렌더러로 타이틀, 장전 안내, 로어, 관리4체, 동거리4체, 랜덤 공개 패를 캡처했다. 최종 화면 원본은 `qa_runtime/preart_20260911/visual/final/artifacts/`이다.

## A/B 결과와 한계

고정 공개정보 정책으로 4시드×3총기×3적×2안=72전투, 36쌍을 비교했다.

| 지표 | A 전체 선택 | B 공개7발 |
|---|---:|---:|
| 고유 조합 수 | 11 | 22 |
| 반복 장전 비율 | 75.0% | 47.6% |
| 실제 발사 중 기본탄 비율 | 62.2% | 73.6% |
| 독립 전투 승리 | 24/36 | 26/36 |

B안은 이 정책에서 반복을 줄였지만 기본탄 사용도 늘었다. 표본은 실제 적을 사용한 독립 전투이며 캠페인 승률·사람의 재미 점수가 아니다. 제공되는 기본탄이 합법 장전을 가능하게 한다는 사실도 모든 전투에 해법이 있다는 증명은 아니다. 집계기는 `HUMAN_PLAY_REQUIRED`를 유지한다.

## 실제 경로 정책 플레이

3시드×4성향 정책으로 12개 런, 765행동, 33전투를 기록했다. 대부분 초반에 종료하여 후반 경험 판단에는 부족하다. 원본 기록의 행동 결과가 비어 있던 문제를 발견한 뒤 결과 연결을 구현했고, 별도 새 실행은 **92행동/92결과**, 잘못된 미구매 퇴장0건을 확인했다. 원본12개 보고서를 소급하여 새 결과인 것처럼 바꾸지 않았다.

패배한 두 표본은 별도로 초기 공개 대열·실제 탄환 수량을 복원해 원본 패배를 재현했다. 유한 탐색에서는 다음 합법 승리 반례를 확보했다.

- `902113-experimental`: 50후보 중12승. 원본10발/리로드2회 사망에서9발/리로드1회 승리로 개선.
- `731042-beginner`: 100후보 중27승. 원본11발/리로드2회 사망에서6발/리로드1회 승리로 개선.

이 두 사례는 봇 선택 한계의 근거다. 모든 패배를 봇 탓으로 돌리거나 사람의 승률로 일반화하지 않는다. 수치 밸런스를 임의로 낮추지 않았다.

## 실행과 인계

`builds/preart-windows/Play-Preart.cmd`를 실행한다. 같은 폴더의 QA 프로필을 사용해 기존 개발용 저장과 분리한다. 실행 파일, README, SHA256을 포함한 빌드 명세를 함께 생성했다. 최종 소스에서 Windows 내보내기 및 헤드리스 시작 검증을 통과했다. 빌드 크기126,610,928바이트, SHA256 `21EDBB40E1CD85E13B7D79B738890EF28946F11ED0B38DA3325FFA451155F837`이다. [보존된 검증 명세](qa/reports/preart_validation_2026-09-11.json)에 회귀 결과와 빌드 정보를 함께 기록했다.

재현 명령:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_preart_checks.ps1 -Mode regression -RunLabel review
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_preart_checks.ps1 -Mode ammo -RunLabel review
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_preart_checks.ps1 -Mode campaign -RunLabel review
powershell -NoProfile -ExecutionPolicy Bypass -File tools/export_windows_preart.ps1
python -m unittest discover -s tools -p test_analyze_ammo_hand.py
```

아트 교체 규격은 [아트 인계](preart_art_handoff_2026-09-11.md)에 기록했다. 설치된 Windows 템플릿으로 내보냈으며 Android SDK build-tools는 현재 구성되지 않아 APK 실기 검증 완료로 표기하지 않는다. 최종 그림·음악·브랜딩은 이 작업에서 제작하지 않았다.

현재 환경의 Windows 기동 stderr에는 시스템 루트 인증서 저장소 읽기 오류가 남는다. 프로세스는 종료 코드0으로 시작 검증을 통과했고 스크립트·리소스 로드 오류는 없었다. 온라인 기능의 정상 동작을 검증한 결과로는 사용하지 않는다.

## 남은 승인·검증

1. 사람이 A/B를 플레이해 조합 고민·성공감·반복감·장전 피로를 비교한다. 기존 가이드대로 각3회와 1~5점 기록을 권장한다.
2. B안 정식 채택 여부에 따라 시작 덱·보상·덱 희석 비용을 확정한다. 채택 전 덱 정제는 보류한다.
3. 후반 및 승천0/3/5/8/10의 실제 플레이 결과로 최종 밸런스를 확정한다.
4. Android 실행 환경을 구성한 뒤 모바일 실기 사용성을 확인한다.

이 네 항목을 기능 테스트 통과만으로 완료 처리하지 않았다.
