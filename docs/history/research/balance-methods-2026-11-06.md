# 밸런스 설계 학습 자료와 LoB 적용

2026-11-06 · 사용자 요청에 따른 외부 원문 조사. 기능 구현·수치 조정·도구 설치 이전의 자료 검토다. 게임 결정 원본은 `docs/direction/`이며 이 문서는 출처와 적용 근거를 보존한다.

## 우선 추천

### 1. Slay the Spire — Metrics Driven Design and Balance

- Anthony Giovannetti / Mega Crit, GDC2019. [공식 영상](https://www.youtube.com/watch?v=7rqfbvnO_H0) · [공식 슬라이드 PDF](https://gdcvault.com/play/mediaProxy.php?sid=1026309) · [발표 개요](https://www.gdcvault.com/play/1025731/-Slay-the-Spire-Metrics).
- 핵심은 각 카드가 쓰일 자리를 갖도록 반복 수정하고, 지표를 사람 피드백·플레이 관찰과 함께 해석하는 것이다. 숙련도 차이를 분리하는 난도 계층도 설명한다. 슬라이드 텍스트를 읽었으며 차트 OCR 수치나 영상 전체 시청을 근거로 하지 않는다.
- [개발자 직접 인터뷰 전사](https://maintainersanonymous.com/games/#t=19:44)의19:44~26:35도 확인했다. 보유 카드의 승률만으로 평가하면 함께 가진 카드/유물과 당시 해결할 문제를 놓치며, 강한 완성 조합에 도달하기까지의 획득·판단도 설계 대상이라고 설명한다.
- **LoB 적용 판단:** 제시 대비 선택, 획득 구역, 총기/복장/코어/지원 파츠, 현재 탄 구성과 다음 조우를 함께 기록한다. 수치를 먼저 정해 사용률을 맞추는 목표로 바꾸지 않는다. 자동 정책과 사람의 숙련도는 구분한다.

### 2. Ian Schreiber — Game Balance Concepts

- [Level3: 비용과 효용 곡선](https://gamebalanceconcepts.wordpress.com/2010/07/21/level-3-transitive-mechanics-and-cost-curves/) · [Level6: 상황별 가치](https://gamebalanceconcepts.wordpress.com/2010/08/11/level-6-situational-balance/).2010년 공개 강의 원문.
- 가격 외에 사용 조건·제약도 비용으로 평가하고, 비슷한 효과의 기준점을 만든다. 광역 효과의 가치는 적 수/배치, 회복의 가치는 현재 상태, 도구의 가치는 교체 비용에 따라 달라진다는 접근이다.
- **LoB 적용 판단:** 비용을 피해 한 숫자에 억지로 환산하지 않고 탄 수·발열·점유·행동·무료 정비 기회로 분해한다. 소이/전이의 효율은 군집·단일 보스·장갑·증원·접촉 시한을 나누어 비교한다. 곡선은 초안이며 실제 전투 결과로 보정한다.

### 3. LocalThunk — Balatro 제작자 인터뷰

- [Game Informer의2024-03-21 직접 인터뷰](https://gameinformer.com/interview/2024/03/21/balatro-was-almost-called-joker-poker-and-other-details-from-its-creator). 조커 채택/삭제와 과도하게 강한 조합에 대한 문답을 확인했다.
- 개발자는 뜻밖의 강한 조합을 발견하는 재미를 인정하면서도, 쉽게 반복할 수 있어 다른 조합을 탐색할 이유를 없애는 상태를 구분한다. 효과 자체가 재미없으면 수치 수정만 반복하지 않고 제거하는 판단도 설명한다.
- **LoB 적용 판단:** 큰 피해를 내는 완성 빌드는 유지할 수 있다. 리액터·소이가 문제인지 판단할 때 피해 상한뿐 아니라 조립 난도·획득 경로·준비 비용·대응 가능한 적의 범위·사격/냉각 판단이 남는지를 확인한다. 발라트로의 점수/경제 수치를 직접 이식하지 않는다.

### 4. Machinations — 자원 흐름과 반복 실험

- [공식 Balancing difficulty and score 튜토리얼](https://machinations.io/docs/balancing-difficulty-score). 문서의 자원 노드, 누적/소모/종료 조건, 반복 실행과 서로 다른 플레이어 가정의 비교를 확인했다.
- **LoB 적용 판단:** 전투의 탄약→사격→발열→냉각/교체→적 접근과, 여정의 획득→강화→탄약 소모→상점/정비를 연결해서 본다. 단일 전투의 효율 개선이 여러 전투 뒤 탄 부족으로 바뀌는지 확인한다.
- 문서는 공개지만 모델 편집/서버 예측에는 계정 및 기능별 이용 조건이 있다. 이번에는 설계 방법을 참고하며 서비스 가입/업로드를 하지 않았다. 예제의 임의 성공 확률을 LoB 사람 실력으로 간주하지 않는다.

## GitHub 학습 후보

### 5. gamerpuppy/sts_lightspeed

- [저장소/README](https://github.com/gamerpuppy/sts_lightspeed). 비공식 Slay the Spire용 C++ 시뮬레이터. 페이지에서MIT 표시와 Ironclad 카드/난수 상태를 아는 트리 탐색 중심의 지원 범위를 확인했다.
- **배울 부분:** 상태 복제, 난수 재현, 실행기와 행동 선택 정책의 분리, 많은 분기 비교를 위한 구조다.
- **적용 범위:** README 기준 참고이며 로컬 빌드·속도·원작 완전 재현을 검증하지 않았다. 난수를 아는 탐색의 좋은 결과는 일반 플레이어의 성과가 아니다. 이미 있는 LoB Campaign/Model 위에 검증 정책을 보완하는 쪽이 우선이며, 슬더스용 계산기를 본편에 연결할 이유는 없다.

### 6. HighDiceRoller/icepool

- [저장소/README](https://github.com/HighDiceRoller/icepool) · [작성자의 튜토리얼](https://highdiceroller.github.io/icepool/notebooks/lab?path=tutorial%2Fc00_introduction.ipynb). 순수 Python의 확률 분포 계산 도구이며 정확한 분수 확률과 일부 비복원 추출 지원을 명시한다. 페이지에서MIT 표시를 확인했다.
- **배울 부분:** 평균 외에 결과 분포와 특정 조합의 발생 확률을 계산하는 접근이다. LoB에서는 연계 탄이 함께 장전될 가능성 등을 따로 분석할 때 유용할 수 있다.
- **적용 범위:** 보조 분석 후보이며 설치/실행하지 않았다. 발사 순서·열·처치 후 표적 변화는 실제 Model이 담당해야 한다. 도입한다면 README의 호환성 주의에 따라 버전을 고정하고 작은 사례로 대조한다.

## 학습 내용을 강화 통합에 적용하는 방법

사용자가 승인한 단일 강화는 [현행 강화 방향](../../direction/ammo-upgrade.md)에 기록했다. 아래는 이번 조사에서 도출한 LoB 검증 계획이며 외부 저자가 LoB에 대해 직접 내린 결론이 아니다.

### 비용과 효과를 같은 기준으로 비교

현행 `ammo_variants.gd`의 기본탄 위력3 프로필을 예로 들면 다음과 같다. 장비 보정·연속 사격 추가 열·장갑·표적 전이를 제외한 **원본 데이터 예시**다.

| 항목 | 원본2발 | 압축 결과1발 |
|---|---:|---:|
| 원본 피해 합계 | 3×2 = 6 | 7 |
| 기본 발열 합계 | 3×2 = 6 | 5 |
| 탄창 점유 합계 | 1×2 = 2칸 | 2칸 |
| 탄 수/발사 횟수 | 2 | 1 |

발당3→7만 보고 성장률을 평가하면 원본 두 발의 가치를 빠뜨린다. 실제로는 처치선·오버킬·다음 표적·한 번의 사격에 선택할 발수·세 번째 발 파츠·화상 지속 시간·이후 전투의 탄 부족이 결과를 바꾼다. 두 발이 한 사격에 함께 나갈 수 있으므로 강화가 항상 적 행동1회를 절약한다고 가정하지 않는다. 이 표는 전체 밸런스 검증 결과가 아니다.

### 실제 획득 상태에서 분기

- 같은 정비 진입 상태를 복제해 **원본 유지 / 강화 / 다른 정비**를 비교한다. 무료 강화도 다른 정비를 포기하는 기회비용이 있다.
- 원본과 강화 결과의 단독 성능, 실제 보유 빌드와 결합한 성능, 다음 전투뿐 아니라 뒤의 보급/상점까지의 자원을 본다. 자연 획득 검증과 대표 픽스처 검증을 분리한다.
- 단일/무리/장갑/증원/지속 압박과 초반/후반을 나눈다. 모든 조우에서 모든 탄이 같은 효율을 내는 목표는 두지 않는다.

### 관측과 판단의 분리

- 관측: 처치까지 필요한 발수/행동, 접촉까지 남은 적 행동, 강제 중단·냉각·교체, 남은 탄약·비상 보급, 파츠 발동, 제시/선택/거절 이유.
- 정책: 단순 전탄 사격, 보이는 열/거리로 판단하는 운용, 보이는 조합으로 판단하는 운용, 미래 드로/난수를 아는 상한 탐색을 각각 표기한다. 앞의 세 정책도 스크립트이면 사람의 숙련도라고 부르지 않는다.
- 기존16완주470전투는 이전 규칙의 검증이다. 새 단일 강화 비용과 사람의 선택 가치를 입증한 결과로 재사용하지 않는다.
- 유지 근거: 강화 전후의 처치/운용 차이가 읽히고, 강화하지 않을 합리적 상황도 남는다. 수정 근거: 항상 강화/항상 보류, 준비 없는 자동 승리, 짝이 없어 반복적으로 강화 불가, 탄 소모만 늘고 체감이 없음.

## 이번 작업 범위

외부 원문/발표 자료/README를 대조하고 설계 방법과 승인 방향을 문서화했다. GitHub 코드 이식·패키지 설치·게임 수치/씬/저장 변경은 하지 않았다. 다음 단계는 위 기준으로 단일 강화 규칙과 비교 창을 수정하고 실제 Model/획득 여정으로 검증하는 것이다. 자료는 밸런스의 정답이나 자동 최적화 보증이 아니다.
