# 2026-11-08 플레이 피드백과 후속 우선순위

플레이에서 확인한 증상과 현재 소스·이전 검수의 범위를 대조했다. 아래 표는 피드백 접수 당시의 작업 기준이다.

## 1차 적용과 검증

- 캐릭터 7복장의 색면 처리에서 밝은 장비색이 어두운 재질 경계로 넘어가는 부분을 확인했다. PixelOE 색 차이가 큰 재질 경계는 원래 색을 유지하도록 수정했다. 21장 원본 알파는 동일하다. Godot에서 권총·장총 조준 및 장총 재장전 21컷을 비교했고, 장총 자세 343개와 스파이크 실전 사격·재장전·냉각 119개 검사가 통과했다. [수정 전](../../qa/reports/combat_outfit_blocks_2026-11-07/outfits.png) · [수정 후](../../qa/reports/actor_edges_2026-11-08/outfits.png)
- 본편 상점의 고정 최소 높이 434로 844×390에서 단말기 하단과 행동줄이 잘렸다. 최소 높이를 풀고 짧은 화면의 내부 간격과 물리 키·단말기 외곽을 함께 조정했다. 5크기에서 318검사 통과. 844×390에서 장착 화면 진입, 판매 복귀와 실제 구매를 터치로 확인했다. PC 창과 모의 터치 검증이며 Android 실기기 확인은 남아 있다. [수정 전](../../qa/reports/mobile_shop_2026-11-08_before/stock_844x390.png) · [수정 후](../../qa/reports/mobile_shop_2026-11-08_after/stock_844x390.png)
- [빌드 역할과 성장 순서](../../direction/build-synergy.md)를 현행 탄환·파츠·강화·총기와 대조해 정리했다. 핵심 탄 643개·파츠 역할 3,048개 검사 통과. 현재 플레이가 선택을 만드는지 확인할 비교 기준이며 보상·수치 변경은 별도다.

| 우선순위 | 플레이 피드백 | 작업과 완료 기준 |
|---|---|---|
| P0 · 시각 결함 재현 | 캐릭터 그래픽이 일부 깨져 보인다 | 이전 몸체와 E안 적용 몸체를 같은 조준·사격·재장전 프레임에 놓고 비교한다. 원본 도트, 화면 배율, 총과 손 합성 중 원인을 분리한다. PC 기본 크기, 모바일 가로 크기와 사용자 기기에서 본 화면을 구분한다. |

| P1 · 버튼 규격 | 화면마다 버튼 디자인이 다르다 | 공통 역할별 크기·여백·글자·상태·터치 영역을 정리하고 전투·장비·상점·지도·팝업에 대조한다. 상점의 물리 키 같은 세계관 표현에는 같은 역할과 상태 규칙을 적용한다. |
| P1 · 전투 연출 | 피격·경직 반응과 감속 상태가 약하다 | 보통 피격은 짧은 몸 반응, 강한 적중에는 짧은 히트스톱, 경직에는 분명한 자세 변화가 읽히는지 비교한다. 접근 감속 중 발밑 표식은 실제 상태를 따라 대상과 함께 이동하고 해제·처치 시 사라지게 검증한다. 연사·다수 적·동작 축소·모바일에서 FX가 판독과 입력을 가리지 않는지도 확인한다. |

## 기존 검증에서 확인한 범위

- 운반복 E안과 7복장 검수는 원본 알파와 파지 등록, 조준·재장전 등의 동작, PC 가로 캡처를 확인했다. 이번에 보고된 깨짐의 원인은 아직 확인 전이다. [기존 복장 비교](../../qa/reports/combat_outfit_blocks_2026-11-07/outfits.png)
- 장비 선택의 기존 검사는 주요 버튼의 노출과 클릭, 장비 조합 적용을 확인했다. 카드 그림·여백·비중의 시각 판단은 다시 확인한다. [장비 선택 검수](../../qa/reports/equipment_live_2026-11-06/README.md)
- 상점은 PC의 S26 비율에서 구매·장착 물리 키와 판매 복귀를 검사했다. Android 실기기 안전 영역과 손가락 입력은 별도 확인이 남는다. [상점 조작 검수](../../qa/reports/shop_actions_2026-11-05/README.md)
- 접근 감속은 전투 상태와 피해 문구에 이미 전달된다. 발밑 표식은 이 상태에 연결하는 후보이고, 기존 막타 슬로우와 일반 적중의 반응은 다른 사례로 검수한다. [현행 전투 피드백](../../direction/presentation-feedback.md)

## 빌드 역할 가설

| 수단 | 플레이어가 하는 선택 |
|---|---|
| 탄환 | 이번 탄창에서 무엇을 준비하고 어떤 순서로 터뜨릴지 정한다. 준비탄·결정타·대응탄처럼 발사에서 맡는 역할이 드러나야 한다. |
| 코어 | 이번 등반에서 반복할 승리 방식 하나를 고른다. 발사 순서, 상태 연계, 화력 성장 등 사격 선택을 바꾼다. |
| 일반 파츠 | 코어 조건을 더 안정적으로 만들거나 약점을 보완한다. |
| 강화·압축 | 이미 모은 탄 중 어느 역할에 계속 투자할지 정한다. |
| 총기 | 발수·급탄·발열이 빌드를 굴리는 방식과 제약을 바꾼다. |

기존 [탄환 역할](../../direction/ammo-build-roles.md)과 [파츠 구조](../../direction/parts-builds.md)에 대입해 역할 중복과 빠진 선택을 찾는다. 우선 순서·결정타형과 상태 제어·연계형을 같은 조건에서 비교한다. 플레이어가 초반에 모을 대상을 알고, 중반 보상에서 다른 선택을 하며, 후반에 사격 순서와 결과가 달라지는지가 첫 판단 기준이다. 새 수단 추가와 수치 변경은 이 비교 이후 결정한다.

검수는 개발자가 정상 진행 경로로 먼저 수행한다. 클릭과 경계 검사에 더해 화면 비율·텍스트·겹침·선택 및 비활성 상태·동작 시작과 복귀를 실제 화면에서 확인한다. 사용자 확인이 필요한 경우에도 재현 절차와 비교 화면을 먼저 준비한다.
