# 2026-11-05 최신 플레이 후기 접수·구현 대조

이번 기록은 사용자의 최신 빌드 후기와 현재 소스를 대조한 진단·작업 순서다. 수치 변경, 신규 등급·적 패턴·지형의 채택, 본편 적용이나 재현 테스트를 완료한 기록이 아니다. 사용자가 플레이한 실행 파일·저장 사본은 전달받지 않았으므로 새 도전과 이전 저장의 규칙 차이를 실제 재현에서 확인해야 한다.

## 접수한 내용

| 사용자 후기·요청 | 작업에 반영할 요구 |
|---|---|
| 빈 탄창이면 재장전 버튼에 불이 들어오면 좋겠다 | 전투 중 장전 가능 상태의 빈 탄창에서 재장전 필요를 바로 알 수 있게 표시 |
| 리액터·소이탄 조합이 지나치게 강하다 | 총기 고유 효과·지속 피해·성장·발열·적 행동 비용을 함께 재검토 |
| 파츠·총기·탄환 전체 밸런스 재조정 | 개별 피해량뿐 아니라 빌드 간 선택 가치와 획득 전후 운용을 비교 |
| 일반·고급·레어·에픽 등급마다 카드 디자인 차이 | 등급 데이터의 의미를 정리하고 카드 외형·문양·명암으로 식별 |
| ‘탄환 압축’을 ‘압축 강화’처럼 직관적으로 | 실제 행동과 강화 결과가 읽히는 용어로 통일 |
| 일반탄 강화와 압축이 분리돼 있어 통합 필요 | 탄환 선택→재료/비용→결과 비교→확정의 한 성장 흐름으로 구성 |
| 압축 시 별도 UI 창 필요 | 소모할 탄과 결과 탄, 피해/발열/점유/보유량 변화 및 취소를 한 창에 표시 |
| 상점 버튼 배열이 맞지 않음 | 기존 단말기 구도에서 상품 상세·결제 정보·행동의 정렬 검토 |
| 남은 금액 같은 중요한 값이 잘 보여야 함 | 보유액·선택 가격·결제 후 잔액의 정보 위계 강화 |
| 구매 버튼은 오른쪽에 | 결제 영역 우측의 일관된 확정 위치로 정리 |
| 탄약고가 현재 필요한지 의문 | 다른 보상/상점/정비와의 중복 및 실제 보충 가치를 비교 |
| 난도가 높을수록 더 많은 적이 접근했으면 함 | 적 수·증원 간격·전열 보충·속도를 통한 접근 압박 검토 |
| 지도/전장에 기믹, 예를 들어 공격을 가리는 벽 | 특정 교전에 전장 조건을 부여해 탄종·발사량·대기 선택 변화 검토 |
| 정예·보스가 체력만 많고 존재감이 약함 | 고유 행동의 실제 발동, 대응 필요성, 반격 기회와 성장 덱 상대 영향 검토 |

## 현재 소스에서 확인한 것

- **재장전 표시:** `redesign/samples/hud/combat_hud_presenter.gd`의 `render()`는 빈 탄창의 사격 문구와 교체 비용/접촉 위험을 표시한다. 빈 탄창 때문에 재장전 버튼을 별도로 점등하는 분기는 확인되지 않았다. 새 표시는 실제 재장전 가능 여부·입력 잠금·전투 종료와 함께 판정해야 한다. 전투 전체 탄약 소진/비상 보급은 빈 탄창과 구분한다.
- **소이 피해:** `redesign/model.gd::_advance()`에서 화상과 지역 불길 중 큰 피해를 적 이동 전에 적용한다. 합산 중첩은 이미 막혀 있다. 재장전·냉각처럼 여러 적 행동을 보내는 명령에서도 피해가 진행되고 장갑·배리어를 통과한다. `combat_roles.gd`의 불길 범위/기간, 코일·성장 코어의 피해 보정이 영향을 준다.
- **리액터:** `content.gd::weapon_spec()`과 `model.gd::fire()/finish_fire()`에 강행·추가 냉각/재장전 경로가 있다. 긴 재장전의 비용이 지속 피해 덱에서는 피해를 주는 시간이 된다는 상호작용이 주요 검토 가설이다. 이것만으로 과성능의 원인을 확정하지 않았다. 이전 무기 규칙의 리액터는 화상 기본값도 다르므로 저장 버전을 나눠 확인한다.
- **등급/강화 분리:** `content.gd::grade()`는 기본/일반/고급을 압축 상태와 연결하고, `ammo_visual.gd::grade_mark()`는 작은 표식 위주다. `ammo_variants.gd`에는 위력·개조·압축별 개별 탄 프로필이 있고, `focus_build.gd::upgrade()`는 주력 탄의 화력 개조/압축 후보를 제시한다. 현재 `grade`를 네 단계 희귀도로 바로 바꾸면 기존 압축 판정과 보상에 영향을 준다.
- **정비소:** `workbench/screen.gd`의 ‘탄환 압축’과 ‘탄환 개조’ 탭, 관문 강화/보상 후보가 서로 다른 진입점이다. 통합은 용어만 바꾸는 작업보다 넓다. 승인된 작업대 외형과 기존 카드 크기를 유지하면서 성장 흐름을 묶는 설계가 필요하다.
- **상점:** 실제 `shop_terminal_live.gd`는 승인된 단말기 시안을 상속한다. `samples/shop_terminal_review/preview.tscn`의 결제 HBox에 Buy→Replace 순서가 직렬 배치되어 있다. 잔액은 단말기 지갑 및 결제 결과 줄에 표시된다. 이 구조를 확인했으며 사용자 환경의 어긋남은 실제 PC 창/S26 비율 화면에서 재현할 대상이다.
- **난이도/적:** `campaign_content.gd::encounter_pack()`의 난이도 보정은 시작 거리 단축이고 활성 전열은 최대4기다. 지역별 편성·후속 증원은 별도로 있다. 물량 압박이 난도와 함께 증가하는지는 별도 검증이 필요하다.
- **정예/보스:** 기존 구역별 적에 장갑 개폐·발사 준비·지휘 등 패턴이 이미 있다(`residential_challenges.gd`, `central_guard.gd` 및 구역별 전용 로스터). 새로 패턴이 있는지보다 실제 성장 덱을 상대로 행동이 발동하고 대응을 요구하는지가 문제다. 고유 규칙이 없는 일부 정예의 생성 경로에는 체력 배율도 남아 있다.
- **탄약고:** `campaign.gd::_supply_options()`와 `focus_build.gd::rewards()`에 주력 탄·연계 탄·강화 후보 제공이 연결된다. 단순 휴식 외에 획득 경제에 영향을 주므로 삭제 전에 전투 보상과 강화 통합 후의 역할을 비교한다.

## 다음 작업 순서 — 제안

| 순서 | 작업 | 확인할 결과 |
|---|---|---|
| 1 | 빈 탄창 재장전 점등, 상점 보유액/잔액 강조·결제 정렬·구매 우측 배치 | 전투/거래 계산과 기존 구도를 유지하면서 다음 행동과 구매 가능 여부가 읽히는지 |
| 2 | 리액터·소이의 과성능 재현부터 전체 총기·탄환·파츠 비교 | 어느 덱에서도 같은 운용만으로 진행되는지, 열/재장전/제어/단일·다수 처리의 선택이 남는지 |
| 3 | 압축 강화·기본탄 강화의 통합 흐름과 별도 비교 창, 등급 의미·카드 외형 정리 | 성장 이유와 재료 소모/화력/발열/칸수 변화가 같은 방식으로 이해되는지 |
| 4 | 난도별 접근 압박, 정예/보스 패턴의 효력, 전장 기믹 | 공격/냉각/재장전/제어 판단을 실제로 바꾸고 공정한 대응·반격 기회를 주는지 |
| 5 | 탄약고 유지/재구성/통합 판단과 전체 경로 재검증 | 다른 장소와 구분되는 방문 이유, 성장 재료/탄약 경제 및 전투-정비 간격이 유지되는지 |

2번은 작은 피해 감소치를 임의 확정하는 작업이 아니다. 현재 큰 피해를 만드는 빌드 재미를 유지 기준으로 두고, 동일한 획득·시드·구역/편성에서 5총기의 직접 화력·연타/배리어·지속 피해·제어 빌드를 비교한다. 초중후반의 실제 보유 상태를 사용하고 복장별 탄 소진·정비 비용을 포함한다. 처치까지 행동 수, 적 접촉 여유, 강제 냉각/재장전, 남은 탄, 첫 고유 패턴의 발동 여부와 대응 필요성을 기록한다. 기존 `run_late_balance.ps1`, `run_build_roles.ps1`, `run_core_choice.ps1`의 실제 모델/획득 경로를 재사용하되 최신 질문에 필요한 비교만 보완한다. 자동 결과를 사람의 승률이나 재미 검증으로 취급하지 않는다.

3번의 우선 설계는 하나의 ‘탄환 강화’ 진입점에서 탄을 선택하고, 강화 방법·재료·결과를 비교한 뒤 명시적으로 확정하는 방식이다. ‘압축 강화’는 같은 탄을 합쳐 어떤 효과가 강화되는지 보여 준다. 개조의 방열 선택도 같은 비교 규칙을 사용한다. 등급은 일반/고급/레어/에픽 구분을 시안으로 검토하되, 희귀도·위력·압축의 관계와 획득/승급 규칙은 아직 미확정이다. 색 외에 테두리 구조·등급 문양·탄체 차이를 쓰며 전투 카드 크기·클릭 위치·선택 표시와 승인한 라인+도트/장소별 아트 방향을 유지한다.

4번의 벽은 지도 장식이 아닌 교전의 전장 조건 후보로 다룬다. 막는 공격·피해/파괴 조건·보호 구간·남은 시간을 공개하고 기본탄으로도 합법적인 해결 경로를 남긴다. 필수 탄종을 갖추지 못하면 막히거나 이미 강한 소이 우회만 정답이 되는지 함께 확인한다. 정예·보스는 예고→대응 창→행동 결과→반격 기회를 중심으로 설계하며 체력 증가만으로 완료하지 않는다. 구체 패턴·수치는 아직 채택 전이다.

## 진행 범위와 남은 확인

이번 차수는 후기 전항목 접수와 소스 대조, 우선순위 갱신이다. 제품 코드·전투 수치·배치·저장 형식은 변경하지 않았다. 기능 테스트나 신규 화면 캡처는 실행하지 않았다. 리액터·소이 과성능과 상점 정렬의 실행 재현, 실제 폰/S26 화면과 재미 확인이 남는다. 이전에 승인된 관문 시안과 암전 연출은 보존하며 본편 연결을 완료로 바꾸지 않는다.
