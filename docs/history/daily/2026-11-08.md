- 리벳·운반복·같은 시드의 실제 첫 전투에서 성장 코어 또는 일반 파츠 하나를 골라 시작한다. 별도 저장 영역으로 실행하고, 둘 다 기존 주력탄 보상과 다음 교전에 연결했다.

## 빌드 작업실 통일

사용자가 빌드 작업실을 이미 개편했는지 물어, 11월3일 글자 점검 외에는 개편한 적이 없고 상점 단말의 파츠 장착(11-04)이 비슷한 기능이라고 답했다. 사용자 진행 지시로 새 디자인 없이 승인 구성을 가져왔다.

- `campaign_ui.gd::deck()`이 `build/workshop.gd`를 열고 화면의 작업 창으로 등록(닫기·Esc·포커스 복귀 유지). 파츠 탭은 상점의 `part_mount.tscn`을 `build/part_mount_view.gd`로 확장(규칙·분해·전체 규칙 문장·열람 전용), 탄환 덱 탭은 탄약고의 휴대 칸과 탄 묶음.
- 파츠 변경은 `_campaign_action`(자동 저장)으로 작업실을 닫지 않고 처리.
- 화면 확인 중 `제3 격발기`(11-06 추가 파츠)의 아이콘 누락을 발견해 `part_icon_art.gd`에 추가.
- 실수와 정정: 전투 상태 검사에서 지도 화면을 거치지 않아 표시 연결이 비어 있던 것을 검사 쪽에서 연결. 처음 검사 프로세스가 멈췄을 때 Godot 전체 종료 명령은 다른 작업자 프로세스를 건드릴 수 있어 거절되었고, 내 검사 프로세스만 골라 정리했다. 규칙 문장 라벨이 이름 없는 노드를 찾다 오류를 낸 것을 고쳤다(검사는 통과로 보였으나 오류 로그로 발견).
- 검증: 105검사, 관문·탄약고·조우 본편 검사 재통과. [보고서](../../qa/reports/build_live_2026-11-08/README.md).

## 공통 창 개편

사용자 진행 지시로 남은 개편 대상인 공통 창(설정·조작 안내·게임 규칙)을 진행했다. 새 메뉴에서 여는 기록실도 이전 청록 화면이라 함께 다뤘다.

- 새 공통 창 틀 `common/window.tscn`은 기존 대화창 동작(`console_dialog.gd`)을 상속하고 정비소 테마만 입혔다. 확인 창 등 다른 대화창은 그대로 둔다.
- 설정은 드롭다운 대신 선택지를 모두 버튼으로 펼쳤다. 조작 안내는 카드 3장, 게임 규칙은 머리말 있는 줄, 문장은 그대로(조작 안내의 장소 이름만 현재 지도에 맞춤).
- 기록실은 빌드 작업실과 같은 전체 화면: 구역별 4칸 × 5줄, 못 찾은 기록에 출처 표시, 오른쪽 읽기 판, 보급 선호 탭.
- 검사 중 발견: 844×390에서 저장이 있으면 타이틀 `설정`이 화면 밖(y=410)이라 그 자리를 누르면 기록실이 열렸다. 낮은 화면에서만 타이틀 묶음을 줄여 고쳤다.
- 확인 중 발견(고치지 않음, 결정 필요): 보급 선호 해금은 현재 탄창 등반의 첫 보상 후보에 쓰이지 않는다. 글자 크기 설정은 16단위 맞춤 때문에 본문이 바뀌지 않는다.
- 실수와 정정: 창 내용 열 이름을 바꾸는 바람에 고유 이름 조회가 실패해 창 높이 맞춤이 오류를 냈다(참조를 보관해 수정). 회귀 스크립트를 BOM 없이 저장해 PowerShell이 한글 경로를 깨뜨려 처음 실행이 모두 비었다(BOM 추가 후 재실행). 보급 선호 카드에 이전 시작 덱을 적었다가 현재 등반과 맞지 않아 뺐다.
- 검증: 128검사. 관문·탄약고·조우·빌드·장비 회귀 통과. 타이틀 검사의 2개 실패는 변경 전 파일로도 같아 무관. [보고서](../../qa/reports/common_windows_2026-11-08/README.md).

## 다음 진행 1~3: 결정 2건·검사 정리·이야기 장면

사용자에게 다음 진행 사항(1 결정, 2 오래된 검사 정리, 3 남은 이전 화면, 4 실기기)을 정리해 보고했고, 사용자가 "1~3까지 진행해 줘"라고 했다.

1. 디렉터 결정(사용자 확정 아님, 되돌리기 쉬움)
   - 보급 선호: 현재 탄창 등반은 첫 보상에서 다섯 계열을 모두 보여 줘 선호가 아무것도 바꾸지 못한다(11-06 비교와 같은 결론). `SUPPLY_PREFERENCE_VISIBLE=false`로 기록실 탭·등반 설정·무기 상세에서 숨겼다. 데이터·해금 기록은 보존.
   - 글자 크기: 정수 배율 화면과 16 단위 픽셀 글꼴에서는 90/110%가 효과가 없거나 흐려진다. 설정에서 빼고 저장값을 100%로 읽는다.
2. 오래된 검사 33개를 격리 폴더에서 다시 돌렸다(오류 뒤 멈추는 검사를 감지해 해당 프로세스만 종료). 지금도 있는 화면을 보는 6개는 고쳐 통과시켰고, 없어진 화면을 누르던 27개는 파일 맨 위에 은퇴 사유·대체 검사를 적어 실행 대상에서 뺐다. 현재 검사 18종을 `tools/run_current_ui_checks.ps1`로 묶었다. [UI 검사 목록](../../qa/ui-test-suites.md).
   - 검사 중 발견해 고친 것: 공통 창 닫기 버튼이 터치 기준(48)보다 작은 44였다.
3. 출발·공급 복구·귀환을 조우와 같은 전체 그림 + 이야기 판으로, 파츠 분해 확인·파츠 상세를 공통 창으로 옮겼다. [보고서](../../qa/reports/story_scenes_2026-11-08/README.md).
   - 기초 훈련은 유지·재제작·삭제 결정이 필요해 손대지 않았다.
- 실수와 정정: 첫 기준 실행은 오류 뒤 멈추는 검사가 15분씩 기다려 중단하고 감지 방식으로 다시 돌렸다. 일부 검사는 출력 폴더 끝 `/`를 요구하고 하나는 반대로 요구해 실행기를 나눴다. 보급 선호 해금이 만들던 저장에 기대던 내 검사 1곳을 명시적 저장으로 고쳤다.

## 빌드·성장 분석과 빌드 엔진 시험

사용자가 빌드·성장의 재미와 방향(총기·탄환·파츠, 발라트로식 파츠 교체)에 대한 의견을 물었다. 코드·자동 등반 기록으로 판단해 '종류와 뼈대는 충분하지만 파츠 효과가 작고(가산 위주), 제시 빈도가 낮고, 탄창 통제 폭이 좁고, 큰 숫자가 보이지 않는다'고 보고했다. 사용자가 동의하고 진행을 지시했다.

- 정정: 분석 답변에서 '성장형 파츠가 없다'고 했으나 코어 3종은 승리마다 성장한다(`damage_engines.gd`). 일반 파츠에 성장형이 없다는 뜻으로 문서에 정정했다.
- 설계: [빌드 엔진](../../direction/build-engine.md) — 빌드 3종, 파츠 세 종류(가산·배율·규칙)와 성장형.
- 시험 적용(새 등반만): 연타 공명기·타격 기록기, 연타 등반의 상점·정예 보상 제시, 아이콘, 파츠 상세의 기록 표시, 전투 계산 줄.
- 수치: 통제 계산에서 같은 준비의 연타 한 발이 84 → 210(공명기) → 390(기록기 +6). 실제 래칫 전투 6건에서 전투가 짧아지고, 순서를 맞춘 플레이와 계속 사격의 차이가 생겼다(3구역 17/17 → 8/12).
- 실수와 정정: 처음에는 계산 줄 자료를 발사 결과에 새로 저장해 이전 규칙 비교 검사(`build_roles_rules`) 24개가 깨졌다. 저장에는 아무것도 남기지 않고 기존 계산 기록으로 표시하도록 바꿔 3048검사를 다시 통과시켰다. 줄이 작고 흐려(14) 16으로 키우고 합계를 붙였다. 기록기 상세에 '특정 탄종 없이 적용'이라는 기본 문구가 나와 연결 문구를 넣었다.
- 무관한 기존 실패: `magazine_build_rules`의 후미 점화기 1건(변경 전 파일로도 실패).
