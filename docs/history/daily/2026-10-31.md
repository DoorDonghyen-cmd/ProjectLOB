# 2026-10-31 작업 기록

## 플레이 후기 — 접근 압박과 탄창 구조

사용자 후기 원문:

> 몬스터가 내 앞 직전까지 오는 경우가 거의 전무해서 긴장감이 떨어짐
> 이 게임은 적이 도달하는 즉시 죽는 구조이기에 이 구조가 보다 긴장감으로 작용하면 좋겠음
> 적이 더 압박적으로 다가와야 할 것 같음
>
> 장전 발사의 단계를 장전 시 바로 발사하는 구조는 어떨까 고민
>
> 적의 압축탄과 같은 발사체도 체력이나 타격 스택을 갖는건 어떨지 고민
>
> 총기마다 시작 시 발열 상한이 높은 거 같음
>
> 탄환을 삽입 교체 하는 방식이 아닌 하나의 탄창을 교체하는 식은 어떨까?
> 재장전 시 새로운 탄창을 갈아 끼우는 식
> 탄창의 탄환은 자신의 덱에서 섞인 형태
>
> 현재 게임이 쉽게 느껴지는 게 탄환이 전부 공격 형태이고 모두 적중하는 형태라 생각이 듦

- 사용자 확인: 적의 근접 위협과 시작 발열 제약이 약하게 체감되며, 전투가 쉽게 느껴진다. 즉사 규칙을 긴장감으로 작동시키길 원한다.
- 비교 제안: 장전 즉시 발사, 발사체 HP/타격 수, 덱에서 섞인 탄창 단위 교체. 이 제안들을 채택한 확정 규칙으로 기록하지 않는다.
- 미확인: 테스트 빌드와 새 등반/이어하기 여부, ‘장전 즉시 발사’가 탄 한 발 삽입마다 발사인지 탄창 장착 후 자동 사격인지. 두 항목을 사용자에게 확인 중이다. 답변 없이 특정 빌드의 결과로 간주하지 않는다.
- 코드 확인: 장전 삽입과 확정에는 턴 비용이 없다. 다수 무기는 여러 탄을 한 사격 입력으로 처리한 뒤 적이 1행동 진행하며, 마지막 적을 제거하면 접근 행동 없이 승리한다. 재장전에는 무기/발열/파츠 비용만큼 적 행동이 발생한다. 현재 압력탄은 HP 1이다. 증폭·냉각 등 직접 피해가 없는 지원탄도 존재한다.
- 해석: 전탄 사격의 행동 효율과 낮은 처치선이 접근 전에 전투를 끝내는 원인일 수 있다. ‘모두 공격형’이라는 표현은 실제 탄종 정의와 구별해 역할·위험 차이의 체감 문제로 추적한다. 원인 확정이나 새 체감 검증을 수행한 것은 아니다.
- 우선순위를 접근 압박/행동 비용 비교 → 탄창·입력 흐름 비교 → 발사체 대응/열 관리 조정으로 갱신했다. 짧은 돌파의 만족감과 긴장 구간의 대비를 유지하고, 자동 완주보다 근접 위험과 대응 가능성을 관찰하기로 했다.
- 이번 작업은 피드백·설계 검토 기록이다. 본편 규칙·수치·저장과 APK는 변경하지 않았다.

## UI 완성도 검토와 전투 통합 개편 계획

- 사용자는 다른 AI 게임의 UI에 비해 프로젝트 비주얼이 계속 아쉽게 느껴지는 이유를 물었고, 화면 전체 완성도와 제작/검수 방식에 대한 검토 후 앞선 전투 피드백을 포함한 개편 계획을 요청했다.
- 검토 근거: 10월30일 전투·10월25일 상점의 실제 캡처와 아트 방향/검증 기록. 통합 아트 방향은 이미 있으나 기존 레이아웃 안의 부품 개선이 반복됐고, 전장·물건·핵심 행동·보조 정보의 시각적 비중과 UI 재질의 연결이 약하다는 디렉터 판단이다. 다른 AI 작품의 제작 방식이나 품질 원인은 확인하지 않았다.
- [전투와 UI 통합 개편 계획](../../direction/combat-ui-rework.md)을 작성했다. 사용자 체감/제안, 디렉터 권고, 기존 구현과 미검증 가설을 분리하고 과거 피드백을 단계별 작업과 연결했다.
- 순서: 기준선·행동·화면 공동 설계 → 탄창/발사/접근 압박 비교 → 발열/발사체/탄 역할 → 대표 전투 화면 완성 → 연속 전투/성장 → 다른 화면/후반 확장. 모바일 지속 성능은 전 단계에서 추적한다.
- 탄창 단위 교체는 우선 비교 후보이며 확정 규칙이 아니다. 즉시 발사의 두 의미를 구분하고, 확률 고장/빗나감·슬롯 확대·관문 연출 등은 후순위로 남겼다. 실제 획득 덱, 유한 탄약·기존 저장, 행동 비용·예측·모바일 성능을 비교 조건에 포함했다.
- 현재 방향·통합 우선순위·아트 기준·tracker를 계획으로 연결했다. 본편 규칙·수치·저장·UI 코드는 변경하지 않았으며 APK·커밋·푸시·외부 게시는 수행하지 않았다.
- 문서 검증: 새 계획의 로컬 링크 3개와 현재 문서 4곳의 계획 연결을 확인했다. 기존 방향 문서 내용과 이전 일지 보존을 검사했고 대상 문서의 `git diff --check`를 통과했다. 실제 구현/시각/사람 체감/모바일 검증은 향후 단계의 완료 조건이며 이번 계획 작성에서 수행한 것으로 표시하지 않는다.

## 통합 개편 실행 — 1단계 행동·화면 공동 설계

- 사용자 실행 요청에 따라 [1단계 설계 결과](../../direction/combat-ui-stage1.md)를 작성하고 독립 Godot 구성 시안 A/B, 격리 실행 파일, 진단/화면 검사를 추가했다. 기존 프로젝트 코드/씬/리소스 270파일의 해시가 작업 전과 같다.
- 현행 획득 경로 25전투를 재생해 이전 턴/소모 탄 결과 일치를 확인했다. 12건이 적 행동 없이 종료했고, 무리전/성장 확인전 각 5총기는 모두 해당했다. 방패전은 적 행동이 있어도 접근 여유가 컸지만 일부 총기의 첫 보스는 이미 가까워졌다. 자동 경로의 결과이며 사람 난이도로 일반화하지 않는다.
- 전체 화면 A 하단 탄창형과 B 측면 탄창형을 같은 실제 상태로 비교했다. 위협·탄창·주요 행동의 크기/배치를 바꾸고 증폭·코어·전이가 반영된 탄별 총 피해와 최고 열을 연결했다. 디렉터는 일렬 전장과 가로 탄 순서를 읽기 좋은 A를 다음 비교의 기본안으로 권고한다.
- 3비율 UI 335검사와 전환/종료 4검사 실패 0, GPU 캡처 21장. 근접 시안은 빈 재장전 13회로 합법적으로 만든 표시 검수 상태이며 압박 개편 성과가 아니다. 실행기 한글 경로, 터치 주입 경로, 큐 해제 시점의 검사 문제를 고쳐 최종 재검증했다.
- [검증 보고서와 캡처](../../qa/reports/combat_ui_stage1_2026-10-31.md). 실제 미감/이해도·모바일 지속 성능/발열·큰 글씨·다른 탄창 용량·새 규칙은 미검증이다. 시안은 본편을 대체하지 않으며 탄창 전체 추첨과 새 압박 수치는 아직 구현하지 않았다.
- 다음은 **2단계 탄창·발사·접근 압박 비교**다. 모바일 측정 조건과 사수 분기 등 다음 비교의 대표 상황을 함께 기록했다. APK·커밋·푸시·외부 게시는 수행하지 않았다.

## A안 선택과 탄환 수 확대 후속

- 사용자 원문: “A안 기반으로 하고 탄환도 더 많이 들어가야 할 것 같아”. A안 채택은 확정했다. 실제 용량 확대/동시 표시 확대의 의미를 확인하는 질문은 아직 답변이 없으며, 우선 실제 용량 확대를 가정한 독립 비교를 진행한다고 알렸다.
- [6칸 후속 비교](../../direction/combat-magazine-capacity.md)를 작성하고 A안의 탄환 영역을 가로 전체로 넓혔다. 행동/발열은 아래로 이동, 3/6칸 전환과 기본/강적 상황을 연결했다. 숫자 6은 사용자 확정값이 아니다.
- 리벳 실제 획득 손패로 3/4/6칸 × 3전투를 비교했다. 짧은 전투는 처치로 조기 종료하고, 강적전 6칸은 4발째 과열되어 2발을 미발사 배출한다. 더 큰 용량의 활용 가치를 냉각·사격 단위·잔탄 정책과 공동 검토해야 한다는 근거다.
- 규칙 105검사, 3비율 UI 141검사 실패 0. 생성한 실제 GPU 캡처는 9장. 초기 파싱의 추론 불가 변수는 타입을 명시해 수정했고, 보스 제목/이중 결과 표기 겹침과 카드 그림 범위를 실제 화면에서 교정했다.
- 기존 저장의 보너스 상한 때문에 6칸 비교 후보는 현행 저장 복원에서 거부된다. 이 검증을 완화하지 않고 본편 적용에 새 규칙 버전이 필요함을 기록했다. 비교 상태는 저장하지 않는다.
- 기존 소스·씬·리소스/JSON 274개 해시 보존. 본편·기존 A/B 씬은 유지했고 기본 시안 실행 파일을 새 6칸 비교로 연결했다. 모바일 지속 성능·사람 미감·전 총기/전체 등반 균형은 미검증이다.


## A안 탄창 운용 비교 플레이 구현·검증

사용자의 후속 진행 지시에 따라 [2단계 첫 운용 후보](../../direction/combat-magazine-loop.md)를 구현했다. 리벳+돌파 코어 6칸에서 두 발 사격, 잔탄을 보존하는 냉각/과열 처리, 자기 덱에서 전체 탄창 교체, 미사용 탄 예비 복귀, 별도 자동 저장/재개를 일반전과 보스전 승패까지 연결했다. A 배치와 기존 실제 사격·적 이동 연출을 사용한다. 공통 모델에 명시적인 비교 버전 분기를 추가했으며 본편 신규 등반은 미활성, 이전 저장 규칙을 유지한다.

같은 보스 6발 비교에서 기존 4발 사격/2발 배출 → 6발 활용으로 바뀌었다. 강제 냉각을 감수하면 적 5행동, 사전 냉각 한 번은 적 4행동이었다. 일반전은 적이 여전히 19~21 거리에서 정리되어 접근 압박 해결로 판정하지 않았다. 압력탄 피격/몸체 접촉 안내를 구분했고, 실제 근접 캡처의 HP·안내 겹침은 전장 위 별도 안내 줄로 교정했다.

검증: 신규 기능 797, 3비율 화면/터치/저장 재개 422 검사 실패 0, 실제 캡처 18장. 기존 25전투 재생 보고서 전후 동일, 연속 발열 1,087검사/80조건 및 유한 탄약 683검사 실패 0. 기존 스크립트/씬/리소스/JSON 283개 중 공통 모델/콘텐츠/예측 3개만 변경했고 나머지 280개 해시 동일. 저장 재개 검사에서 JSON 정수/실수 표현 차이를 확인해 양쪽을 동일 JSON 경계로 비교했다. [증거와 한계](../../qa/reports/combat_magazine_loop_2026-10-31.md).

남은 일: 자연 플레이 접근 압박, 다른 총기/복장, 신규 규칙으로 실제 초반 연속 획득 경로, 본편 새 등반 연결 여부, 전체 경제, 모바일 지속 성능·기기 발열, 사람의 재미와 이해도. APK·커밋·푸시·외부 게시 없음. 기본 `OPEN_COMBAT_UI_STUDY.cmd`는 새 반복 플레이로 연결한다.


## A안 탄창·접근 압박 비교 후속

사용자의 다음 스텝 진행 지시에 따라 [방패 진지/보스 이동 적 접근 후보](../../direction/combat-approach.md)를 구현했다. 거리×0.5 올림·이동+1로 조정하되 정지 보스/사수와 HP·장갑·적 수·공격 시계는 유지한다. 무리전/성장 확인전/사수 매복을 포함한 다섯 실제 획득 전투를 이전 거리와 동일 탄창으로 비교할 수 있게 연결했다. 기존 A안·실제 연출·일렬 접지·별도 저장을 유지하며 기본 실행 파일을 새 비교로 연결했다. 본편 새 등반은 미활성이다.

600조건 후보 비교 후 0.5/+1을 첫 적용값으로 선택했다. 기존/새 60조건에서 냉각 정책의 방패전 최소 접촉 여유11~12→2~3행동, 보스6~9→1~2행동, 전투 턴은 각각3~4유지/10~15→8~14였다. 기본 방패전 사격2회 뒤 강행하면 과열 냉각 중 접촉 패배, 먼저 냉각하면 잔탄으로 승리한다. 냉각 직후 교체는 다시 접촉 패배한다. 추가80순서 중 동일 정책 실패5건은 다른 합법 승리 경로를 탐색·재생했다. 인간 승률·재미나 모든 순서의 해결 가능성으로 해석하지 않는다.

## 전투 화면 배치·디자인 정리

## 전체 UI 레이아웃 검토

- 사용자 요청으로 게임 전체 화면의 레이아웃을 검토했다. 현재 작업 트리로 전체 화면 캡처 실행기를 격리 저장에서 돌려 65장(검사 436개 통과)을 새로 찍고, 최신 여정 HUD·보상·가방 캡처와 함께 비교했다.
- 디렉터 판단: 전투 HUD 안의 통일감은 개선됐으나 화면 사이의 UI 계열(급탄 장비 / 평면 청록 / 일반 글꼴), 상단바, 주 행동 색, 선택 표시가 서로 다르다. 본편 전투의 하단 3단 구조, 적 명찰의 겹침·잘림, 조우·지도·탄약고의 빈 공간을 우선 문제로 정리했다.
- 권고: 공통 화면 틀 정의 → 본편 전투 HUD 방향 결정 → 적 명찰 재배치 → 빈 공간 화면 재배치. 최신 재질을 전체로 확장하는 것은 사용자 미감 확인이 필요하다.
- [검토 보고서](../../qa/reports/ui_layout_review_2026-10-31.md). 게임 코드·저장·APK·커밋 없음. 사람의 이해도와 실기기 확인은 하지 않았다.

## 공통 화면 틀 목업

- 사용자 요청으로 레이아웃 검토의 권고 순서대로 목업을 만들었다: 공통 틀 → 본편 전투(적 명찰 포함) → 지도 → 장소 틀(조우·탄약고) → 상점. 1440×630과 1008×630에서 캡처했다.
- 최신 급탄 장비 원화와 도트 글꼴만 사용했다. 전투는 실제 전장 뷰·장전 입력·예상 계산을 격리 저장에서 그대로 썼다(94개 검사 통과).
- 디렉터 제안:
  - 상단바 하나, 붉은 주 행동 하나, 상아색 선택 면 하나.
  - 전투 하단 2단(전장 약 30% → 약 70%), 장전 순서를 칩 줄로, 잠긴 칸 대신 '이번 사격' 예상.
  - 적 명찰은 머리 위에 붙이고, 겹치면 쌓고, 번호 배지로 연결.
  - 지도는 한 화면에 전체 구역, 조우·탄약고는 장소 틀, 상점은 보조 버튼을 묶음.
- 재질의 전체 확장과 주 행동 색은 사용자 확인 전이다. 게임 화면·규칙·저장·APK 변경 없음, 커밋 없음.

## 동작하는 HTML UI 프로토타입

- 사용자가 원한 목업은 버튼과 UI가 실제로 동작하는 것이었다. 이에 맞춰 [HTML 프로토타입](../../qa/reports/ui_prototype_2026-10-31/index.html)을 만들었다.
- 흐름: 지도 → 전투·조우·탄약고·공방·상점 → 보상 → 지도. 전투에는 장전·빼기·사격 연출·재장전·과열·비상 보급·증원·승패가 있고, 빌드 서랍·메뉴·탄 상세·적 정보·화면 비율 전환을 넣었다.
- 그림과 수치는 Godot 격리 저장에서 추출한 실제 게임 자료를 쓴다(`tests/ui_prototype_export_runner.gd`, `tools/build_ui_prototype_assets.py`). 전투 계산은 단순화했다고 화면에 표시했다.
- Edge 헤드리스로 화면별 캡처와 실제 클릭 자동 진행(지도 3칸, 전투 2승, 조우 1회)을 확인했다. 휴대폰 실기기 터치와 사람의 이해도는 확인 전이다. 게임 코드·저장·APK 변경 없음, 커밋 없음.
