# 2026-11-01 작업 기록

## HTML UI 프로토타입 화면 탭

- 사용자 요청으로 [HTML 프로토타입](../../qa/reports/ui_prototype_2026-10-31/index.html) 위쪽에 화면 탭을 추가했다. 그룹은 흐름 · 전투 · 장소 · 공통이고, 숫자키 1~9와 `#tab=` 주소로도 연다. 탭으로 들어간 화면도 그대로 조작할 수 있다.
- 탭을 바꾸면 진행 중인 사격·재장전 연출을 멈추도록 했다. Edge 헤드리스로 확인한 것:
  - 탭으로 직접 열기: 정예전, 관문전, 탄 상세, 승리, 공방, 메뉴
  - 연출 중 상점 탭 전환: 오류 없이 상점으로 넘어가고 전투 상태가 정리됨
  - 처음부터 이어 하는 자동 진행: 지도 3칸 완료
- 게임 코드·저장·APK 변경 없음, 커밋 없음.

## 전투 UI 네이티브 픽셀 목업

- 사용자 “다음 스텝” 요청으로 외부 UI 비평 검토 후의 목업 단계를 진행했다. [결과·상태별 화면·검증](../../qa/reports/combat_pixel_study_2026-11-01.md).
- 실제 여정 사격과 비교 전투에서 장전/부분 소진/빼내기/과열/9칸 상태를 격리 저장으로 새로 캡처했다. LibreSprite에서640×400 픽셀 원본과2배 PNG, 편집 가능한 ASE5개를 작성했다.
- 비트맵 한글·전장 기반19색·어두운 소켓·빈자리·분할 발열·실제 발사 순서 표시. 상시 피해 요약 문장을 추가하지 않았다. 폰트 원본/OFL과 캡처/상태/재제작 스크립트를 보존했다.
- 5상태의 정수2배, 제한된 UI 색, 전장 보존, ASE 재출력 일치, 실제 모델 값 대응과 글자 경계 확인.1280표시 이미지5장 직접 검수. 새 UI의 플레이/다른 비율/모바일/사용자 미감은 미검증.
- 게임 코드·기존 리소스·프로젝트 해상도 변경 없음. 현행 실행본과 새 정지 시안을 방향 문서에서 구분했다. 다음은 부품 분리와 Godot 연결이다.

## 픽셀 전투 HUD 실제 연결

- 사용자 다음 스텝 요청으로 목업의 소켓/발열/탄환/글꼴을 탄창 여정과 전투 비교에 연결했다. [실제 화면과 검증](../../qa/reports/combat_pixel_live_2026-11-01.md).
- TSCN에 콘솔/대표 카드 상태를 저장하고 기존 명령·예측·저장 흐름을 재사용했다. 동적 수치는 Godot 노드, 발열은 상태 변경 시 그리는 분할Control이다.
- LibreSprite로 작은 프레임/탄환20종과 Galmuri 두 비트맵 글꼴을 내보냈다. 글꼴은1024×2048의 두 페이지씩이며 원본41,676글리프의 비트 일치를 확인했다.
- 초기 한글 누락/흰 아이콘/사격 비용 대비를 수정했다. 최종 UI13,436·연속흐름4,816·집중1,779검사 실패0. 실제 작은 화면/9칸/빼내기/과열/메뉴/상세와 에디터 구성을 검수했다.
- 전투 규칙·저장 형식·본편 기본 진입·전역 해상도는 유지했다. APK/커밋/게시 없음. Android 지속 성능과 사용자 미감/이해도는 후속이다.

## 탄환 선택 후 즉시 빼내기

- 사용자 제안과 진행 승인으로 현재 픽셀 HUD의 여정/총기 비교를 `탄환 선택 → 위쪽 빼내기 버튼`으로 단축했다. [실제 화면·검증](../../qa/reports/direct_ejection_2026-11-01.md).
- 같은 탄/빈 곳/빈 소켓/Escape 취소, 한도 내 두 발 선택, 제거 후 선택 초기화를 연결했다. 상세는 선택 시 `N번 상세`로 열며 창을 닫아도 선택을 유지하고 한도 소진 뒤에도 읽을 수 있다.
- 기존 모델·예측·저장을 재사용하고 소모/한도/시간 비용을 유지했다. 선택 중 사격 버튼을 다른 버튼으로 바꾸지 않으며, 비활성 사격을 누른 입력이 취소 후 발사로 이어지는 것을 막았다. 완전 소진 패배는 실행 버튼에서 경고한다.
- 최종 집중 검사2,431·공통 HUD13,536·연속 여정4,836검사 실패0. PC 터치/마우스/키보드와 실제 화면을 검수했다. 초기 검사 비교의 숫자형/이력 범위 차이는 보고서에 기록했다.
- Android 실기기 조작 체감/지속 성능과 사람 이해도는 후속. APK 생성·커밋·게시 없음.

## HTML 목업 전체 조작 검토

- 사용자 요청으로 별도 브라우저 탭에서 지도→실제 일반 전투 두 회→보상·조우, 상점·탄약고·공방, 관문전 과열·탄약 소진·비상 보급·패배·재시도와 공통 창/화면 탭을 조작했다. [결과와 재현 증거](../../qa/reports/ui_prototype_interaction_2026-11-01.md).
- 승리 후 크레딧 중복 지급, 보상 더블클릭의 다음 전투 진입, 메뉴 뒤 키보드 이동, 두 번째 비상 보급 비용 오표시, 사격 중 재시작 오류, 대상 없는 공방 작업을 재현했다. 과열 시 미발사 탄 소실 안내와 구매 후 예측 표시도 기록했다.
- 1280×800/1008×630/1008×454와 목업 비율 전환을 확인했다. 작은 화면 버튼 실측을 남겼으며 Android 실기기 조작·길게 누르기·지속 성능은 미검증이다.
- HTML과 Godot 소스는 수정하지 않았다. HTML 해시 동일 확인, 브라우저 임시 화면 크기 복원. 현재 Godot 탄창/즉시 빼내기와 HTML의 이전 LIFO 조작을 구분했다. 보고서·검토 증거·이력만 추가했다.

## HTML 목업 조작 안정화 1·2단계

- 사용자 진행 승인으로 승패 종료 상태/단일 지급, 화면 전환 연속 입력 차단, 모달 초점·배경 입력 차단, 사격 일시 정지/재시작 취소를 적용했다. [변경·검증·남은 단계](../../qa/reports/ui_prototype_stabilization_2026-11-01.md).
- 비상 보급 표시와 실행 비용을 통합하고, 공방 실제 대상·최소 덱/가방/파츠 제한, 구매 완료 표시를 보강했다. 현재 탄창 규칙의 미발사 탄 보존을 목업 과열 처리에도 적용해 실제 발수와 잔탄을 맞췄다.
- 실제 인라인 스크립트의 상태 회귀 10개 통과. 별도 브라우저에서 자연 승리·보상 더블클릭, 메뉴 Shift+Tab/재시작/재개, 무효 공방, 구매·교체, 과열·탄약 소진·비상 보급 두 차례, 상세·빌드·재시도를 재검증했고 콘솔 오류 0건.
- Godot 코드·저장·아트·APK는 변경하지 않았다. 다음은 현행 탄창/빼내기 UX 정렬과 모바일 크기 조정, 이후 Godot 연결이다. Android 실기기·길게 누르기·지속 성능·사람 이해도는 후속이다.

- 다음은 실행본의 미감·연속 선택 체감과 본편 통합 조건 확인. Android 실제 손가락/안전 영역·지속 성능·발열과 사람 이해도는 미검증이다.

## UI 라인 시안 — 산나비·데이브 더 다이버 레퍼런스

- 사용자 목표(UI의 AI 슬롭 제거·게임다운 퀄리티)에 따라, 사용자 제공 화면 4장을 [레퍼런스](../../art/references/2026-11-01-user/README.md)로 보관했다. 함께 받은 산나비풍 마인크래프트 리소스 팩(팬 제작)은 지시대로 참고만 하고 저장소에 복사하지 않았다.
- 분석: 두 레퍼런스 모두 짙은 청록 3~4단계 + 강조색 하나, 1px 선·구분선 행, 선택과 주 행동에만 채운 면을 쓴다. 현재 강철 틀은 같은 두꺼운 재질을 모든 요소에 반복해 템플릿처럼 보인다.
- HTML 프로토타입에 `assets/theme_line.css`와 도구 줄 **스타일: 현재 강철 / 라인 시안** 전환을 추가했다(`#theme=line`). 기존 강철 화면·전투 연결·작은 화면 CSS는 그대로다.
