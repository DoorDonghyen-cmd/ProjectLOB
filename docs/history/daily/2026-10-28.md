# 2026-10-28

## 최신 빌드 플레이 후기 접수

사용자가10월27일 최신 작업 빌드로 진행한 후기를 전달했다. 관문 재정비, 후반 모바일 프레임 저하/기기 발열, 상시 몬스터 거리 숫자 제거, 화력/배율 성장 재미, 파츠의 시각적 체감, 발열 수치/연속 사격 조건 변경, 탄환 불량 또는 총기 고장, 장비 캐릭터 접지를 접수했다. 추가 질문에서 프레임 저하 환경이 모바일임을 확인했다.

현행 관문 전환/파츠 관리, 발열 계산, 발동 표시, 장비 배경/발 기준점과 이전 성능 보고서를 대조했다. 성능1차는 PC 입력 처리 측정이었으며 모바일 지속 성능/기기 열은 미검증이었다. 사용자의 최신 관찰을 이전 빌드 문제로 넘기지 않고 모바일 성능·강화/파츠 체감을 미해결로 추적한다.

[상세 피드백·현행 근거·개선안·우선순위](../design/playtest-review-2026-10-28.md). 우선순위는 모바일 성능/접지 → 관문 재정비 → 강화·파츠 체감 → 이동·위협/거리 숫자 축소 → 연속 사격 부담/고장 비교. 고장·불량 확률은 미확정 아이디어이며 사용자 확정 규칙으로 기록하지 않았다. 게임 코드·수치·저장·APK·외부 게시를 변경하거나 신규 성능/시각 검증을 수행하지 않았다.

## 어제 진행 사항을 포함한 전체 우선순위 통합

사용자 요청으로10월26일 원문12항목,27일 단계별 구현·검증,28일 후기를 대조해 [통합 계획](../../direction/playtest-priorities.md)을 현행 기준으로 만들었다. 어제 마지막으로 비상 보급까지 구현됐고 다음 예정이 적 이동/거리 표시였음을 확인했다. 기존 성능·전투·휴대 개편은 기준선으로 유지하면서 모바일 지속 성능과 성장/파츠 체감을 미해결로 구분했다.

모바일 성능/접지 → 관문 재정비 → 성장·파츠/장갑·강적 → 이동·위협 → 발열·고장 비교 → 전체 성장·탄약 경제 → 선택적 확장 → 관문 연출로 통합했다. 각 단계에서 회귀를 확인하고 마지막에 전체 균형을 판단한다. current/tracker에 최신 계획을 연결해 이전 기록의 다음 작업과 구분했다. 게임 구현이나 신규 실행 검증은 수행하지 않았다.

## 순차 실행 — 성능2차·장비 캐릭터 접지

사용자의 “진행해 줘”에 따라 첫 작업을 실행했다. 후반 전장 좌표/체력 표시의 반복 배치를 재사용하고, 잔열 증기와 정지 무기의 불필요한 렌더링을 줄였다. 전체 기록을 보존하는 저장 인코딩 캐시와 모바일60FPS 상한을 적용했다. 장비 화면은 실제 발 기준점을 바닥에 맞추고 그림자를 추가했다.

PC 동일 후반 상태에서 화면 갱신 약70→47ms, 반복 저장 약32→13ms. 첫 후반 저장 약35ms와 캐시 정적 메모리 약7MB 증가가 남는다. 기능·저장·배치·전투/장비 화면 최종5,000검사 실패0,7복장 대표 화면 직접 확인. 테스트의 잘못된 fixture/API·숫자 타입·오래된 노드 참조·뷰포트 휴지 판정은 교정 후 최종 결과로 집계했다. [측정·명령·검증·화면·제한](../../qa/reports/mobile_revision_2026-10-28.md).

ADB 연결 기기가 없어 모바일 지속 FPS·온도는 미검증으로 유지한다. 사용자 저장과 격리해 검사했고 전투 수치·APK·커밋·푸시·외부 게시를 변경하지 않았다. 다음 독립 구현은 관문 재정비와 출발 단계다.

## 순차 실행 — 관문 재정비·출발

사용자의 후속 “진행해 줘”에 따라 관문 개조 후 재정비 화면에 머물고 직접 출발하도록 변경했다. 다음 구역과 현재 무기·복장·탄약/휴대량·개조·파츠를 보여주며 기존 작업실에서 소유 파츠를 무료 장착·해제·교체하고 탄약을 열람한다. 개조/교체/출발 자동 저장과 재개, 중복 개조/보상/출발 방지, 기존 관문 저장과 마지막 보스 엔딩을 유지했다. 작은 화면에서 보스 전리품 건너뛰기 버튼이 밀리는 문제와 빠른 다시 그리기 중 포커스 오류도 수정했다.

규칙835/실제 UI·터치151/전체 등반4,293검사 실패0. 연사 시드731042는 실제27전투·4관문 후 엔딩까지 도달했다. 별도3무기 관문 경로4,561검사에서는 리액터 주조장 보스 탐색 실패/관문 미도달2건이 남았다. 즉시 이동 대조군1,711검사도 같은2건 실패이며7전투 상태/결과가 일치했다. 다섯 무기의 다음 전투 상태·프로필도 이전 이동 방식과 일치한다. 숫자형 정규화가 필요한 비교 검사 자체를 교정했고 실패를 전체 통과로 합산하지 않았다.

[규칙](../../direction/gate-rewards.md) · [명령·실제 화면·검증 데이터·한계](../../qa/reports/gate_reorganization_2026-10-28.md). 현대 관문은 `resolved`로 선택/재정비를 구분하며 옛 버전 없는 관문은 즉시 이동을 유지한다. 모바일 실기기와 사람의 이해도·재미는 후속이다. APK·커밋·푸시·외부 게시 없이 로컬 구현/검증을 마쳤으며 다음은 성장·파츠 발동 체감과 강적 대응이다.

## 순차 실행 — 성장·파츠 발동 체감1차

후속 요청으로 연쇄/복열·돌파/후미·열압의 실제 발동별 궤적/적중을 구별하고 사격 피해·처치·발동 파츠를 사격 후에도 표시했다. 지원·차폐 실패·투사체·중복 처치와 연출 축소/생략을 구분한다. 코어 선택 화면의 옛 성장 문구(매번 타격+1/배율+0.25)가 현행 계산과 달랐던 결함을 고치고, 성장 축적과 실제 수치 상승 전후를 표시했다.

현행162조건을 변경 전후 비교해 결과가 동일함을 확인했다. 실제 HP·처치선·턴 비용에서 성장 이득을 확인하고 이번에는 전투 수치를 추가 조정하지 않았다. 발동/문구223, 실제UI445, 비교756, 강적449, 기존규칙273, 성장657, 실제획득상태UI113, 저장/대기142검사 총3,058건 실패0. UI 검사 확장 정책/타입 오류와 옛 성장 검사의 불완전한 승리 fixture를 교정한 후 최종 결과다. 새 전체 등반을 실행한 것으로 집계하지 않았다.

PC 대기 프레임 중앙값 약6.06ms·후반 잔열 그리기 약19~21회/초는 이전 수준이다. 전체 화면 재생성은 후반 약52.7~57.2ms로 이전 약47~50ms보다 높았고, 실행 시점/변경 비용의 원인 분리와 모바일 지속 성능은 남는다. [구현·실제 화면·비교·명령·한계](../../qa/reports/build_feedback_2026-10-28.md). 다음 독립 구현은 적 이동·겹침·위협 표시이며 사람의 체감과 성장/강적·탄약 경제의 장기 판단은 후속이다. APK·커밋·푸시·외부 게시 없음.

## 순차 실행 — 적 이동·겹침·위협 표시

사용자의 다음 스텝 요청으로 거리 순서 뒤 강제 간격/우측 밀어넣기를 제거하고 개체의 실제 거리로 몸체 위치를 정했다. 얕은 깊이의 겹침은 허용하되 HP·상태·상세 버튼을 분리하고 연결선/포커스 강조로 대응했다. 식별 문자 시안은 기존 제거 결정에 따라 제외했다. 상시 거리 숫자는 상세로 옮기고 실제 다음 적 행동의 접촉·발사·돌진·지휘를 복사 상태의 전투 계산으로 표시한다. HP·피해·압력탄을 몸체 위에 표시한다.

기능/실제 UI/이동/저장 최종7,542검사 실패0, 연출141프레임 거리 역전0.5지역 보스와 특수 행동 직전,3화면 크기, 같은 거리/근접/밀기/처치/증원·실제 터치를 검사했다. 옛 거리 영역/동일 좌표 가정과 손패에 없는 기본탄을 누르는 fixture를 교정했다. eavesback 실행기의 인증서 경고 오판도 stdout/stderr 분리 후 정상 실행했다. [현행 결정](../../direction/enemy-readability.md) · [실제 화면·명령·실패 원인·검증 자료](../../qa/reports/enemy_readability_2026-10-28.md).

PC 후반 대기 프레임 중앙값 약6.063ms·잔열 다시 그리기18~21회/초·렌더 호출232~233으로 이전 수준이다. 전체 화면 재생성 후반 약48~56ms는 여전히 남는 비용이다. 모바일 지속 FPS·기기 발열·사람의 식별/위험 이해도는 미검증이며 자동 검사를 재미 완성으로 보지 않는다. 전투 수치·저장 규칙은 유지했고 새 전체 등반·APK·커밋·푸시·외부 게시 없음. 다음 독립 작업은 발열·연속 사격·고장 방식 비교이며 확률 고장은 미확정이다.
