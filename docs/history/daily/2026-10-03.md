# 2026-10-03 — PixelLab 연결과 첫 도트 전투 화면

활성 프로젝트: `worktrees/core-redesign/새-게임-프로젝트`, Godot 4.7, `prototype/core-redesign`.

PixelLab 연결의 Windows CRLF 활성화 오류와 앱 환경 변수 전달 의존성을 수정했다. 재시작 후 네이티브 도구 97개와 계정 조회를 확인했다. 키는 채팅·파일·검증 보고서에 기록하지 않았다.

## 구현

- Pixen으로 배경·회수자·적 6종 총 8개를 생성하고 전투에 적용했다. 생성 후 trial 32회 잔여, $20 크레딧 유지. [원본·프롬프트·작업 ID](../../../새-게임-프로젝트/assets/art/pixel_20261003/provenance.json), [자산 검사](../../../새-게임-프로젝트/assets/art/pixel_20261003/asset_report.json).
- 바닥을 원경과 분리하고 실제 발 픽셀에서 기준점을 정했다. 네 적의 전열 오프셋은 고정하고, 접근 거리만 해당 적의 가로 이동에 반영한다. 같은 거리의 적도 서로 가리지 않게 배치했다. 부유 적은 접지 그림자와 높이 차로 구분한다.
- 적 명찰은 HP·예상 HP·거리·장갑·상태 순으로 구성했다. 근접한 명찰의 겹침을 방지하며 터치 상세와 산개의 HP 범위를 유지한다.
- 탄종별로 다른 도트 실루엣을 만들었다. 피해를 크게, 유효 관통과 고유 효과를 짧게 표시한다. 연발 배수와 카드별 예측 문장의 중복을 제거했다. 압축 슬롯 제약과 드래그/버튼 입력은 유지한다.
- 발사 레일을 낮추고 각진 프레임을 적용했다. 짧은 보상 카드도 같은 정보를 높이에 맞게 표현한다. 게임 계산·RNG·저장 형식은 변경하지 않았다.

메인을 주 행동 중심으로 재배치하고, 출격 준비의 다섯 무기·실제 시작 탄환·출격 버튼을 한 화면으로 구성했다. 상점 비교는 위치와 높이를 유지한다. 파츠는 장착·보관함·상세를 함께 표시하며 실제 모델에 원자적 교체 명령을 추가했다. 코어 제한·교체 수치·보관함 스크롤·전투 중 잠금·분해 확인·키보드 초점 복원을 연결했다. 승인된 탄환 카드는 그대로 사용하고 파츠의 픽셀 장치 실루엣을 제작했다.

## 외출 중 요청 — 4번까지 구현과 검증

앞서 파츠·조합 피드백에 이어 빌드 선택, 첫 지역 도입, 맵·상점·경제 흐름을 진행했다. 720사례의 실제 모델 비교에서 기존 예비 급탄기의 보급 효과가 결과를 바꾸지 않는 점을 확인해 탄창당 패 교환+1회를 더했다. 상점은 역할·보유 탄과의 연결·구매 후 잔액을 표시한다. 첫 지역은 소유 덱의 조합 예시를 첫 패에 제공하고 장갑·전기 약점·다수·파츠·증원을 차례로 안내한다.

새 런 자금30Cr, 다른 역할의 첫 일반 파츠 두 개, 미등장 우선 진열, 한 상점의 교체 비용3→5→7→9Cr, 환기구 전투의 크레딧 보상+6Cr를 적용했다. 기존 저장의 자금·진열을 다시 생성하지 않는다. 탄환 카드와 임시 배우·환경 아트를 유지했다.

## 세계관 초안 착수

사용자가 현행 플레이를 긍정적으로 검토하고 다음 단계인 세계관 정리를 요청했다. 정서 선택 질문에 ‘위험한 탐험 + 사람 사는 온기’를 답해 사용자 확정 사항으로 기록했다. 기상탑·탄환 기술자라는 구체적인 설정은 디렉터 제안으로 구분했다.

[세계관 초안](../../direction/worldbuilding.md)에 주인공의 직업/목표, 일상과 위험의 대비, 탄환·파츠·압축의 연결, 인물 세 역할, 기존 적 여섯 역할에 맞춘 생물/설비 외형 후보, 다섯 공간, 짧은 서사 전달과 반복 런의 해석을 정리했다. 현재 기록/지역/결말의 적용 경계도 명시했다. SANABI·Arcane Trigger 공식 소개를 확인했으며 고유 인물·서사·설정을 그대로 계승하지 않는다.

현재 방향·아트 기준·진행 문서를 연결하고 상태 구분과 문서 링크를 확인했다. 세계관·아트 초안 작업이므로 게임 실행 코드·수치·저장·이미지는 변경하지 않았고 기능 검사는 다시 실행하지 않았다. 새 시각 레퍼런스 보드·통합 시안·실제 자산 교체는 후속 범위다. 이전 종료 요청은 앞선 작업 완료에 대한 요청이며 이번 세계관 작업에서 다시 종료를 예약하지 않았다.

## 세계관 피드백 — 생존자와 복구 엔딩

사용자가 기상탑 방향을 긍정적으로 평가하고, 폭주로 통제를 벗어난 생물·상점에서 버티는 생존자의 이야기·은근한 디스토피아적 어두움을 요청했다. 이 방향을 현행 문서에 반영했다. 기존의 공통 NPC 두 명 제한을 갱신하고 현행 다섯 지역의 상점에 각기 다른 생존자를 배치하는 초안을 작성했다. 거래는 짧은 인사 뒤 이용하고 추가 이야기는 선택해서 읽도록 제안했다.

‘최상층에서 탑을 복구하는가’라는 질문에는 폭주 중단/기상 기능 복구를 최종 목표로 제안했다. 재난 전의 공급 우선순위와 현장 생존자를 연결해, 구역별 비상 제어권을 여는 결말을 v0.2에 기록했다. 생물의 과거 용도, 상점 인물의 개별 사연, 복구 방식과 최후 교전은 디렉터 제안이며 사용자 확정/구현으로 취급하지 않는다. 다중 엔딩·호감도·숨은 대화 정답은 도입 범위로 잡지 않았다.

문서 상태와 연결을 확인했다. 게임 코드·아트·규칙·저장은 변경하지 않았고 기능 테스트는 재실행하지 않았다.

## 세계관 채택 — 아이템과 쪽지의 간접 서사

사용자가 현재 세계관에 만족한다고 답하고 아이템·쪽지 등으로 세계의 깊이를 간접적으로 발견하는 방식을 요청했다. 기상탑·탄환 기술자·복구 엔딩의 큰 방향을 채택 상태로 갱신하고 개별 원고/연출의 제작 상태와 구분했다. [간접 서사 설계](../../direction/narrative-delivery.md)에 효과 우선/선택 열람, 서로 연결되는 출처, 상점 거래의 독립성을 정리했다.

실제 아이템 키에 맞춘 서사 6개와 기존 기록 ID 1~20에 대응하는 쪽지/관리 기록 초안을 작성했다. ‘명단에 없는 집’, ‘우리 밖의 생물’, ‘고쳐 쓰는 사람들’ 세 이야기의 단서를 아이템·문서·상점·환경에 나눴다. 현재 수집 경로를 확인해 우회/기록 이벤트/보급/관문과 맞췄으며, 상점 진입을 기존 기록 획득 경로로 잘못 간주하지 않았다. 랜덤 분기에서 못 읽은 기록이 있어도 목표·기본 엔딩은 이해할 수 있도록 설계했다.

현행 문서 연결, UTF-8, 20개 ID의 누락/중복을 확인했다. 게임 표시 문구와 UI에는 아직 반영하지 않은 원고이며 코드·저장·수치는 바꾸지 않았다. 기능/시각 검사는 이번 문서 작업에서 새로 실행하지 않았다.

## 사용자 이미지로 도트 방향 재정립

사용자가 바탕화면 `reference` 폴더에 캐릭터5장·배경5장을 제공하고, 전체적으로 가장 가까운 느낌은 산나비이며 배경에는 강한 디스토피아 분위기를 원한다고 밝혔다. 원본을 보존하며 `docs/art/references/2026-10-03-user/`로 복사했다. 파일명/바이트를 유지했고 SHA-256 10건의 일치를 확인했으며 크기와 용도를 manifest에 기록했다.

전 이미지 10개를 직접 열어 검토했다. 캐릭터는 성인 비율·큰 형태·비대칭 무기/장비·접지, 배경은 거대 건축·차가운 명암층·깊이·작은 인물의 대비를 공통 방향으로 정리했다. 배경03/04의 분위기/구도와 배경02/05의 도트 처리/깊이를 구별했다. 현재 QA 전투 캡처와 비교해 작은 장비 묘사의 밀도와 수평 배경의 깊이 부족을 개선 대상으로 기록했다.

[원본/검토 보드](../../art/references/2026-10-03-user/README.md)와 [제작 기준](../../direction/pixel-style.md)을 추가하고 현재 방향·아트 기준·자산 목록·세계관·진행 기록에 연결했다. 보드는 원본 이미지를 사용하는 로컬 HTML 검토 문서다. 게임의 웹 빌드가 아니며 네트워크 리소스나 이미지 변환은 사용하지 않는다.

원본 해시, 이미지 10개 열람, 문서/보드의 로컬 연결을 확인했다. 보드의 브라우저 렌더나 새 Godot 통합 화면을 검증한 것은 아니다. 새 캐릭터·적·배경 시안, 게임 코드·규칙·저장·APK·커밋·푸시는 이번 작업에서 변경하지 않았다. 다음은 승인된 카드와 함께 보는 첫 통합 시안이다.

## 캐릭터·배경 레퍼런스 이미지 제작

사용자가 개별 캐릭터와 배경 이미지 각 1장을 요청했다. 내장 image_gen으로 초안을 만든 뒤 사용자 캐릭터01/02, 배경02/05를 입력해 잔묘사를 줄이고 큰 도트 덩어리로 수정했다. 캐릭터는 겹치는 손/총 형태를 줄이기 위해 가방 끈을 잡고 한 손으로 총을 내린 자세로 추가 수정했다. 최종 2장을 `docs/art/concepts/2026-10-03-pixel-reference/`에 저장했다.

캐릭터 1254×1254 알파 PNG, 배경 1672×941 RGB PNG. 시각 검토, 원본/사본 SHA-256 일치와 이미지 크기를 확인했다. 프롬프트와 출처는 provenance.json에 기록했다. 엄격한 픽셀 격자/팔레트 정리와 게임 크기 검수는 후속이며 현재 결과는 화풍 검토용 컨셉이다. 게임 코드·저장·실행 자산은 바꾸지 않았다.

## 주인공 헬멧 수정안

사용자는 리로딩 후 이미지가 정상 표시된다고 답하고 도트풍을 긍정적으로 확인했다. 주인공에게 헬멧이나 모자를 요청해 기존 캐릭터를 입력으로 짧은 챙의 청록 정비용 헬멧, 황토색 띠와 작은 점검등을 추가했다. 내장 image_gen 편집으로 제작했고 `character-reference-v2-helmet.png`로 보존했다. 시각 검토와 복사 SHA-256을 확인하고 별도 provenance에 프롬프트/파일 정보를 기록했다. 구체적인 헬멧 디자인은 검토안이며 게임 적용은 하지 않았다.

## 시작 외형 채택과 복장·헬멧 후속 수집

사용자가 현재 헬멧 캐릭터로 시작하길 확정하고 추후 인게임 복장·헬멧 획득/교체 구조를 요청했다. 시작 외형 채택 상태를 현행 방향·아트 기준·자산 목록·시안 설명·작업 목록에 반영했다. `appearance.md`에 독립 두 슬롯, 프로필 영구 수집, 획득 알림/선택 미리보기/명시적 착용을 디렉터 설계로 기록했다. 능력치 효과는 미정으로 남겼다.

현재 전투가 reclaimer 단일 이미지를, 메인은 별도 world_art 이미지를 사용하고 프로필은 campaign.gd에 런/전투와 함께 저장되는 구조임을 확인했다. 후속 아트의 몸/복장·머리·헬멧·무기 분리, 공통 프레임/기준점·머리카락 마스크·표시 상태 통일과 저장 마이그레이션 기준을 정리했다. 게임 코드·저장·아트를 이번에 변경하지 않았고 기능 테스트는 재실행하지 않았다. 문서 링크와 결정 상태를 확인했다.

## 주인공 추가 외형 후보

사용자가 더 많은 시안을 요청해 기존 헬멧 v2를 기반으로 같은 도트풍의 후보 3종을 제작했다. A는 작업모·짧은 황토색 재킷·옆가방, B는 방한모·회녹색 방한복·배낭, C는 각진 헬멧·긴 청회색 외투·붉은 어깨 덮개다. 내장 image_gen의 개별 편집 요청 3건으로 제작했고 동일한 방향/비슷한 크기에서 비교하도록 했다.

`docs/art/concepts/2026-10-03-character-variants/`에 PNG 3장과 원본 경로·프롬프트·SHA-256·크기를 보존했다. 출력 이미지의 시각 차이와 알파 형식, 복사 해시를 확인했다. 개별 이미지 시안 검토이며 게임 크기/애니메이션 검증은 아니다. 기존 시작 외형 채택은 유지하고 새 후보는 검토 전으로 기록했다. 게임 코드·저장·런타임 이미지는 바꾸지 않았다.

## C 복장과 B 방한모 조합

사용자가 C에 B의 모자를 씌우고 복장에 맞춰 색상을 조정하길 요청했다. C를 편집 대상으로, B를 모자 형태 참고로 입력해 내장 image_gen으로 조합했다. C의 긴 외투·붉은 어깨 덮개를 유지하며 방한모는 청회색 가죽·적갈색 띠로 변경했다. `character-c-expedition-cap-v2.png`와 별도 provenance로 보존했고 원본/사본 SHA-256 일치·알파 형식·이미지 크기 및 결과 외형을 확인했다. 실제 게임 자산은 교체하지 않았다.

## 선택한 캐릭터·배경의 실제 전투 샘플

사용자가 선택 조합과 제작한 배경으로 샘플 전투 화면을 요청했다. Godot MCP로 엔진/프로젝트를 확인하고 샘플 씬을 만들었다. 원본 PNG 두 장을 해시 일치로 복사하고 기존 화면/전투 모델을 상속해 별도 샘플을 구현했다. 배경 비율과 발판 위치, 캐릭터 발/총구 기준점, 적의 같은 접지를 맞췄다. 승인된 카드6장·순서·예측과 실제 확정/발사를 재사용했다.

첫 렌더의 세로 넘침을 전장 높이 조정으로 해결했다. 1280×900·1280×800·1008×630·1440×630와 확정/발사 후 캡처를 직접 검토했다. 샘플68/0, 기존 pixel 전투 회귀79/0, 런처 경로와 변경 코드 공백 검사를 통과했다. 격리 저장 사용, 기본 캠페인 저장/아트는 유지. `PLAY_TOWER_SAMPLE.cmd`와 [검수 보고서](../../qa/reports/tower_art_sample_2026-10-03.md)를 제공한다. 기존 적과 캐릭터 단일 포즈의 한계를 기록했다. APK·커밋·푸시는 하지 않았다.
