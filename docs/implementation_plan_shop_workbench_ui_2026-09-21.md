# 무기고·파츠 작업대 UI 적용 계획

상태: 구현 및 검증 완료  
승인 근거: 사용자가 외부 UI 워크플로 검토 뒤 현재 프로젝트에 적용하도록 요청  
대상 화면: 도시 무기고 `shop`, 장착 파츠와 보관함  
진입/종료: 지도에서 무기고 진입 → 구매·장착 → `맵으로 계속`

## 문제

기존 무기고는 현재 빌드, 세 상품, 압축 코어, 장착 슬롯, 보관함이 모두 같은 절차식 세로 패널로 생성됐다. 파츠 카드 자체는 아이콘 중심이지만 카드 아래에 같은 효과 설명이 반복됐고, 구매와 장착 결과가 여러 문장 사이에 묻혔다. 고정 화면 구조가 전부 코드에 있어 최종 아트를 적용할 때 편집기에서 전체 구도를 확인하기 어려웠다.

## 목표 구조

```text
무기고 / 진열을 비교하고 바로 아래에서 빌드를 완성
[새 진열] [맵으로 계속]

[현재 빌드: 장착 수 | 무기·탄창·재장전 | 덱 요약]
[01] [02] [03] [04] [05]

진열                                      75 Cr
[탄환] [신규 파츠] [신규 파츠]

[압축 코어 충전] [전투 중 결합 규칙]

장착 작업대                      파츠 0/5 · 코어 0/1
[장착 슬롯 1..5]
보관함
[파츠 카드 + 장착/해제 + 분해]
```

## 구현

1. `shop_workbench.tscn`에 고정 구역과 대표 상태를 작성한다.
2. `campaign_ui.gd`는 장면을 인스턴스화하고 실제 빌드·가격·상품·파츠만 채운다.
3. 상품 카드 아래의 효과 중복 문장을 제거하고 `즉시 장착` 또는 `보관함으로 이동` 결과만 남긴다.
4. 1280px에서는 상품 3열·보관함 2열, 1120px 미만에서는 2열·1열로 전환한다.
5. 기존 자동화가 사용하는 노드와 버튼 이름은 유지한다.
6. 메인 메뉴의 기존 `개발자 테스트 → 무기고` 바로가기로 대표 상태에 진입한다.

## 검증

- 편집기 파싱과 장면 로드
- 실제 OpenGL 1280×800 및 1008×630 캡처
- 구매, 파츠 상세, 장착, 리롤, 압축 코어 충전, 맵 복귀
- `ShopWorkbench`, 세 구역, 모바일 열 수 자동 검사
- 기존 두 무기 35층 UI 재생과 1,100회 이상 입력 회귀

## 범위

이번 단계는 무기고·파츠 화면을 첫 장면 기반 기준으로 만든다. 전투, 지도, 보상 등 나머지 정식 화면은 같은 기준으로 순차 전환한다. 최종 그림과 사운드, APK 생성은 포함하지 않는다.
