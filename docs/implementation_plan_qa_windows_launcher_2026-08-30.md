# QA 대시보드 Windows 실행 파일 런처 구현 계획

## 목표

기존 PowerShell QA 컨트롤러를 명령어 입력 없이 시작할 수 있도록 프로젝트 루트에
더블클릭 가능한 Windows 실행 파일을 제공한다. QA의 실제 실행 계약과 보안 경계는 기존
컨트롤러에 유지하고, EXE는 경로 탐색·프로세스 실행·브라우저 열기만 담당한다.

## 설계

- Windows 기본 .NET Framework로 동작하는 작은 콘솔 런처로 만든다.
- EXE 위치에서 상위 디렉터리를 탐색해 `tools/qa_dashboard_controller.ps1`을 찾는다.
- 컨트롤러, 실행기, HTML 대시보드가 모두 존재할 때만 실행한다.
- PowerShell은 `-NoProfile -ExecutionPolicy Bypass`와 고정 스크립트 경로로 호출한다.
- `127.0.0.1` 포트 응답을 확인한 뒤 기본 브라우저를 연다.
- 콘솔의 `Ctrl+C`를 컨트롤러 종료로 전달한다.
- `--check`는 서버 없이 필수 파일을 검사하고, `--probe`는 실제 컨트롤러를 잠시 기동해
  localhost 응답과 종료 정리를 검증한다.
- `--port`와 `--godot`만 선택 인자로 노출한다.

## 배포 범위

`ProjectLoB-QA.exe`는 게임과 QA 스크립트를 내장한 독립 패키지가 아니다. 실제 프로젝트와
Godot를 사용해 테스트해야 하므로 저장소 루트에 두는 개발·QA용 런처다. 배포 파일은
`tools/build_qa_launcher.ps1`로 동일 소스에서 다시 생성할 수 있다.

## 완료 조건

- 프로젝트 루트와 다른 현재 작업 폴더 모두에서 필수 파일을 찾는다.
- Godot 자동 탐지 후 컨트롤러가 지정한 localhost 포트에 응답한다.
- probe 종료 후 테스트 포트와 컨트롤러 프로세스가 남지 않는다.
- 빌드 스크립트가 EXE 생성 직후 자체 점검을 수행한다.
- 사용법과 독립 배포본이 아니라는 제한을 문서화한다.
