# 개편·검증 작업 기준

2026-10-31 사용자 승인으로 Claude Code Game Studios의 유용한 절차를 기존 LoB 역할에 선별 반영했다. 게임 결정 원본은 이 폴더의 현행 설계이며, 새 조직·자동 에이전트·별도 GDD를 설치하지 않는다. [출처와 적용 범위](../../.agents/skills/THIRD_PARTY_NOTICES.md).

## 재미 가설에서 다음 결정까지

선택 구조나 전투 흐름을 바꾸는 작업은 해당 기능 문서에 다음을 짧게 남긴다. 문구·배치의 작은 수정마다 별도 실험 문서를 만들 필요는 없다.

| 항목 | 기록할 내용 |
| --- | --- |
| 질문 | 이번 변경으로 확인할 플레이 경험 한 가지 |
| 현재 근거 | 사용자 발언, 실제 화면/행동, 측정 결과와 해석을 구분 |
| 비교 조건 | 실제 빌드/저장, 총기·덱·시드·적 구성, 바꾸는 변수와 유지하는 변수 |
| 유지할 근거 | 어떤 선택 이유나 결과가 관찰되면 효과가 있다고 볼지 |
| 수정할 근거 | 반복 클릭, 하나의 정답, 이해 불가, 보상 무의미 등 반대 증거 |
| 다음 결정 | 유지 / 수정 / 보류, 남은 불확실성, 다음에 확인할 한 가지 |

- 프로토타입도 실제 Campaign/Model과 획득 상태를 재사용한다. 제작 시간을 미리 제한할 수 있지만 고정 시간·반복 횟수 때문에 유효한 작업을 폐기하거나 검증된 계산을 다시 쓰지 않는다.
- 기능 실행 성공은 재미 근거가 아니다. 사람이 하지 않은 플레이는 `사람 확인 대기`, 관측 장치가 없는 지표는 `미측정`으로 둔다. 기존 긍정 후기는 그 사람이 플레이한 빌드와 범위에만 연결한다.
- 사용률을 올리는 것을 목표로 삼지 않는다. 행동을 **하지 않을 합리적 이유**도 선택 가치다. 승률·횟수와 함께 당시 공개 정보, 선택 이유, 탄약·시간·위험의 대가를 기록한다.
- 새 비교판은 기존 판이 답하지 못하는 질문이 있을 때 만든다. 질문이 해결되면 실제 구현·검증 기록을 본편 통합에 활용하고 불필요한 변형 확장을 멈춘다.
- 현재 첫 적용은 [탄창 여정의 판단·통합 조건](magazine-journey.md#본편-연결-판단-조건)과 [플레이 기록지](../qa/protocols/magazine-journey-playtest.md)다.

## 변경 영향과 검사 선택

작업 전에 아래 연결 중 영향을 받는 곳을 찾고, 기존 검사 또는 실제 확인 방법을 붙인다. 모든 작업에 모든 검사를 수행하지 않는다. 영향이 없는 곳은 이유를 한 줄 남기면 된다. 실제 호출·데이터 흐름을 따라가며 파일 이름만으로 연결을 추정하지 않는다.

| 변경 | 함께 확인할 실제 연결 | 대표 근거 |
| --- | --- | --- |
| 탄창·발사·열·빼내기 | 명령 비용/난수 → 예측 → 적 행동/승패 → 상태 표시 → 저장/복원 | `model.gd`, `forecast.gd`, `combat_magazine_loop_rules.gd`, `magazine_ejection_rules.gd` |
| 적·조우 구성 | 배치/접근 시한 → 합법 대응 → 탄 소모 → 다음 보상/전투 | `campaign_content.gd`, `combat_approach_trial.gd`, `weapon_magazine_rules.gd` |
| 보상·성장·경제 | 실제 획득 → 다음 탄창/성장 → 가격/구매 대안 → 보유/저장 | `campaign.gd`, `content.gd`, `magazine_journey_rules.gd`, `economy_campaign_runner.gd` |
| 표현·사운드·문구 | 실제 결과 이벤트 → 표시/소리 → 상세/접근성 → 작은 화면/동시 효과/성능 | `presentation_feedback.gd`, `combat_hud_presenter.gd`, `presentation_feedback_runner.gd`, `combat_hud_ui.gd` |
| 기본 진입·배포 | 실행 모드 → 새 출발/이어하기 → 구버전 저장 → 실제 포함 리소스/패키지 | `project.godot`, `suite_save_load.gd`, `tools/mobile_release.py` |

위 파일은 `새-게임-프로젝트/redesign/`, `redesign/samples/hud/`, `tests/` 또는 표의 명시 경로에서 찾는다. 이름이 바뀌면 실제 참조를 찾아 표를 갱신한다. 과거 문서의 수치·저장 버전을 새 요구로 되살리지 않는다.

증거에는 **요구/위험 → 시나리오 → 해당 코드 상태 → 결과 → 남은 범위**를 연결한다. 미커밋 작업이 많으면 커밋 번호만으로 빌드를 특정하지 말고 관련 파일 해시나 빌드 manifest를 함께 사용한다. 이후 관련 코드·자산이 바뀌면 해당 증거만 재확인한다. 실패를 검출하는 의미가 중요하며 assert 수나 문서 수를 통과 조건으로 삼지 않는다.

## 전투 구성·성장·경제

### 밸런스 판단과 비교 단위

[개발자 발표·비용/상황 이론·시뮬레이션 참고 자료와 LoB 적용 근거](../history/research/balance-methods-2026-11-06.md). 이 자료들은 수치의 원본이나 자동 균형 보증이 아니다.

- 비용을 탄약·발열·탄창 점유·행동·다른 정비 기회로 분해한다. 두 탄을 한 탄으로 바꾸는 성장은 원본 두 발과 결과 한 발을 같은 조건으로 비교한다. 단독 결과와 실제 획득/빌드 결합 결과를 구분한다.
- 대표 적 구성·접촉 시한·발사 위치/파츠 조건별로 가치가 달라지는지 본다. 피해 합계뿐 아니라 처치선·오버킬·접촉 여유·강제 중단·남은 탄약/비상 보급·파츠 발동을 관측한다.
- 카드 선택 지표는 제시 횟수/선택/거절을 나누고 획득 시점·총기/복장/빌드·다음 조우를 함께 남긴다. 보유 카드의 승률만으로 해당 카드의 인과적 강함을 판단하지 않는다. 작은 표본은 사례 수와 범위를 함께 기록한다.
- 단순 운용, 공개 열/거리 기반 운용, 공개 조합 기반 운용, 미래 드로/난수를 아는 상한 탐색을 분리한다. 자동 정책에 초보/숙련 사람의 성과라는 이름을 붙이지 않는다. 시드 수를 늘려도 잘못된 플레이어/자원 가정은 해소되지 않는다.
- 큰 피해를 만드는 완성 조합과 준비 없이 모든 문제를 해결하는 조합을 구분한다. 조립/획득 비용과 다른 선택이 남는지를 함께 검토하며 사용률·승률을 모두 같게 맞추는 목표를 두지 않는다. 효과의 역할이 없으면 수치 조정 외에 역할 변경/제거도 검토한다.

- 적 수나 체력만 늘리기 전에 각 전투가 요구하는 판단을 적는다. 짧은 무리 처리, 사수 대응, 방패 뒤 표적, 성장 보상의 효율 확인처럼 선택의 초점과 휴식 구간이 달라지는지 본다. 현행 일렬 전장 배치와 [전투 호흡](combat-rhythm.md)을 따른다.
- 획득 전후에 같은 행동이 얼마나 달라지는지 실제 덱으로 비교한다. 피해뿐 아니라 처치까지 필요한 행동, 접촉 여유, 냉각/교체 비용, 남은 탄과 다음 전투의 선택을 본다.
- 경제 변경은 획득량·소비처·가격·반복 구매·보상 건너뛰기를 연결한다. 구매할 이유가 없는 항목, 누적되기만 하는 재화, 한 번의 강한 선택 뒤 사라지는 대안을 찾는다. 장기 등반과 상점이 없는 비교 모드는 전체 경제 검증에서 제외한다.
- 고정 시드는 재현에 쓰고 다양한 조건은 편향 확인에 쓴다. 숨은 난수를 활용한 탐색 결과를 사람의 승률이나 자연스러운 선택이라고 부르지 않는다.

## 사운드·전투 피드백

기존 `presentation_feedback.gd`의 효과음과 `game-feel` 제작 절차를 재사용한다. 추가 도구나 오디오 미들웨어 도입을 전제하지 않는다.

- 작업 대상 이벤트마다 전달할 의미, 실제 발생 조건, 들릴 시점, 시각 대체, 동시 재생 우선순위를 정한다. 일반 사격·강화 사격·장갑 반응·과열·장전 완료·보상을 구분하되 실제 존재하는 결과와 연결한다.
- 중요한 경고나 결정적 타격이 반복 클릭/사격음에 묻히는지 실제 재생으로 확인한다. 필요할 때만 동시 음 제한, 약한 소리 중단, 일시 음량 조절을 적용한다. 크게 만들거나 효과 수를 늘리는 것을 품질 기준으로 삼지 않는다.
- 효과음 끄기·동작 축소/즉시 처리, 연속 입력, 장면 이탈에서 잔여 소리·애니메이션·입력 잠금이 남는지 확인한다. 이벤트 기록 성공과 실제 청취·사람의 타격감 평가는 별도다.
- 현재 음량/재생 경로의 제약은 조사 결과로 남긴다. 새 음향 계층이나 경고음이 이미 구현됐다고 기록하지 않는다.

## 통합·성능·전달

- 한 구간에서 전투 → 보상 → 정비 → 다음 전투 → 종료/재개를 연결해 기능 누락과 제작 비용을 확인한다. 모든 프로젝트에 동일한 분량·기간을 강제하지 않는다. 현재 범위는 [탄창 여정](magazine-journey.md)이다.
- 본편 전환은 해당 기능의 미해결 조건을 보고 결정한다. 비교 화면 완성이나 테스트 통과만으로 기본 진입을 바꾸지 않는다. 새 규칙의 적용 범위와 기존 저장 처리, 되돌릴 경로를 먼저 정한다.
- 모바일 후반 저하·발열은 [지속 플레이 절차](../qa/protocols/mobile-sustained.md)에 따라 같은 기기의 초기/후반을 측정한다. PC 짧은 검사와 모바일 UI 크기 검사는 대체 증거가 아니다.
- APK 요청은 [기존 전달 절차](../mobile-delivery.md)를 따른다. 내부 테스트에 필요한 무결성·저장/실행 모드·미검증 범위만 명확히 하고 정식 출시 절차 전체를 붙이지 않는다.
- 작업 현황은 짧게 갱신하고 상세 변경·판단·미검증은 `docs/history/`와 기존 QA 보고서에 둔다. 외부 분석 수집이나 별도 기획 원본은 이번 절차 적용에 포함하지 않는다.
