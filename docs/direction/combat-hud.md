# 전투 화면 — 탄창 중심 배치와 디자인

**현행 — 중립 재질 통일 본편 반영(2026-11-06):** 사용자 승인한 [화면 간 정합성 검토](../qa/reports/ui_cohesion_2026-11-06/README.md)에 따라 기본 패널·카드 받침·일반 버튼을 지도/장비의 먹색·철제·아이보리로 연결했다. 청록 반복 무늬/점선 레일은 제거하고 절제된 모서리·이음선·빛/그림자를 사용한다. 다음 발사 탄의 청록/상승·순서 번호, 제외·열/냉각/사격·피해 효과 등 기능색은 유지한다. 기존 배치·크기·글꼴·입력/전투/저장은 바꾸지 않았다. [전후/실제5구역·검증과 한계](../qa/reports/hud_material_2026-11-06/README.md). 아래 과거 청록 기본 프레임/디더 묘사보다 이번 중립 재질이 우선하며 Android/사람 미감 확인은 남는다.

**사용자 확정 — 적 HP 하단 문구 제거(2026-11-03):** HP 카드 아래의 `다음 접근/접촉`, 예상 피해 `−N`, `처치` 보조 줄을 표시하지 않는다. 문구가 차지하던 높이도 제거하되 최소44px 상세 터치 영역과 겹침 시 높이 분리는 유지한다. HP·상태 아이콘·게이지 예측 색·정예/관문 위쪽 행동 설명과 적 상세는 그대로이며 전투 계산·저장은 바꾸지 않는다.

**현행 보완 — 발사/교체 시점과 화면 배율(2026-11-02):** 다음 발사 탄을8px 올리고, 실제 `shot_started`마다 해당 탄과 잔탄 수를 갱신한다. 행동 종료 전에는 다른 탄 위치를 유지한다. 탄창 교체는 분리→빈 소켓→새 탄창 묶음 삽입, 냉각은 잔탄 보존/열 영역 반응이다. 즉시 설정은 움직임을 생략한다. 카드 그림76×96과 기존 하단 영역을 유지하며 슬롯 높이104 안에서8px 여유를 사용한다. 순서·개별 열·행동 비용은16px. 전투 이탈 시 배율 복원 재진입 오류도 수정했다. [화면·상태/RNG·크기 회귀](../qa/reports/playtest_presentation_2026-11-02.md). 규칙·입력 의미·저장은 유지하고 Android 실기기와 사용자 체감은 후속이다.

**최신 — 전투 중 피드백(2026-11-01):** 기존 배치와 라인 테마를 유지하며 각 사격/명중/냉각 이벤트의 실제 열을 분할 게이지에 표시하고, 종료 후 다음 사격 예측을 복원한다. 새 HUD의 기존 효과음 연결과 메뉴 음량/연출 설정을 추가했다. 과열의 추가 적 접근 재생 누락과 냉각 중 교체 동작도 수정했다. [근거·검사·화면](../qa/reports/journey_feedback_2026-11-01.md). 계산/전투 저장은 유지하며 청취 품질과 긴장감의 사람 평가는 별도다.

**최신 — 라인 + 도트 테마 Godot 적용(2026-11-01):** 사용자 확정 [테마](ui-line-theme.md)를 전투 HUD·메뉴/상세·보상/정비·여정 경로와 본편 지도/장소/상점에 적용했다. 카드76×96·버튼44/50·입력·계산·저장·기본 진입을 유지했다. [같은 크기 비교·검사·남은 확인](../qa/reports/ui_line_godot_2026-11-01.md). 기존 HUD 검사와 현행 지도/장소·상점 검사를 통과했다. 실기기 선명도/지속 성능과 사용자 미감 확인은 남는다.

**전투 외 연결(2026-11-01 후속):** 보상/정비는 왼쪽 후보와 오른쪽 상세/실제 변화로 분리했다. 여정 메뉴와 이동 화면에 현재/다음 구간·현재 준비를 연결하고 창 안의 초점/빠른 재입력을 보완했다. [실제 화면·검증](../qa/reports/journey_flow_ui_2026-11-01.md). 전투 하단 배치와 규칙은 유지한다.

**최신 — HTML 검토안 Godot 적용(2026-11-01):** 작은 탄창과 우측 행동 배치, 목업의 프레임·탄환·글꼴을 실제 탄창 여정/독립 비교에 연결했다. 선택 후 즉시 빼내기, 실제 보상·정비·관문과 저장/재개를 유지한다. 아래 이전 픽셀 목업/직접 빼내기 기록보다 이 구성과 본문의 기준이 우선한다. [적용 범위·실제 화면·검증](../qa/reports/ui_prototype_godot_2026-11-01.md).

**최신 조작 — 선택 후 바로 빼내기(2026-11-01):** 사용자 승인으로 카드 탭을 탄 선택으로 바꾸고 탄창 위 빼내기 버튼을 즉시 실행에 사용한다. 선택 시에만 `N번 상세`를 표시하며, 한도 소진 뒤에도 상세 확인은 가능하다. 선택 취소·제거 후 초기화·예측과 실행의 일치를 유지한다. [조작 규칙](magazine-ejection.md#조작과-예측) · [실제 화면·검증](../qa/reports/direct_ejection_2026-11-01.md).

**최신 적용 — 픽셀 목업을 실제 전투에 연결(2026-11-01):** 사용자 “좋아 다음 스텝” 요청으로 아래 시안의 어두운 소켓·빈칸·발사 순서·분할 발열·비트맵 글꼴을 탄창 여정/전투 비교의 공통 HUD에 적용했다. 실제 사격·냉각·교체·빼내기와 연속 보상/정비·저장 재개를 검증했다. **최신 시안 — 고정 격자·어두운 소켓(2026-11-01):** 사용자 승인으로 외부 UI 비평을 검토한 뒤 실제 캡처 위의 픽셀 목업5상태를 제작했다. 640×400 원본을2배 표시하고, 비트맵 한글·전장 기반 팔레트·빈 탄창 홈·분할 발열·따뜻한 발사 순서 테두리를 사용한다. 이는 이번 비교안이며 프로젝트 전역 해상도나 사용자 미감 확정이 아니다. [실제 화면·검증](../qa/reports/combat_pixelcraft_2026-10-31.md).

[실제 화면·검증](../qa/reports/combat_focus_2026-10-31.md).

## 화면의 우선순위

전장의 위협 → 발사 순서/탄환 선택 → 실행 순서로 읽는다. 사용자 선택 A안의 하단 가로 탄창을 유지하며 상시 사격 안내 카드는 표시하지 않는다.

- 상단: 진행·장소, 총기, 남은 탄약, 빌드, 메뉴. 재도전·새 출발·도움말은 메뉴 안에 둔다.
- 전장: 같은 바닥선, 실제 HP·다음 적 행동·겹침을 표시한다. 짧은 가로 화면은 배우와 정보 크기를 조절하고 관문 의도를 윗줄에 분리한다. 거리 숫자를 복원하지 않는다.
- 탄창 위: 왼쪽 탄창/선택 수·상세·빼내기·선택 취소, 오른쪽 실제 상한별 분할 발열과 수치다. 선택 전 빼내기는 비활성, 선택 후 `1발 빼내기` 또는 `2발 빼내기`가 된다.
- 탄창: 작은 그림·이름·기본 성능·개별 열. 다음 발사 탄은8px 상승·청록 테두리와 순서 번호, 제외할 탄은 붉은 테두리와 `제외`, 빈 용량은 어두운 외피로 남긴다. 수치는 최종 적중 피해가 아니며 상세에서도 이 차이를 설명한다.
- 오른쪽: 위에 냉각/탄창 교체, 아래에 사격. 행동 비용과 과열/접촉 위험은 해당 버튼의 짧은 보조 줄로 보인다.

발열은 실제 상한만큼 나누며 현재 열/예상 증가/위험을 구분한다.12칸이나 마지막3칸 위험으로 고정하지 않는다. 빼내기 선택은 남은 탄의 실제 Forecast를 사용한다. 무작위 사격의 최대 열·행동 수·패배 확률을 유지한다.

## 시각과 조작 기준

사용자 HTML 검토안의 강철 외피·작은 황동 탄환·주황 발사 순서·녹슨 사격 버튼을 사용한다. 새 원화를 생성하지 않고 기존 PNG28개를 복사했다. [출처와 해시](../../새-게임-프로젝트/assets/ui/prototype_20261101/provenance.json). 이전 Galmuri 비트맵/픽셀 시안 자산은 이력으로 보존한다.

카드는76×96, 탄환 그림18×30 논리 단위다. 이름/열14, 일반 버튼 최소 높이44, 사격50이며 넓은 화면에서도 카드 폭을 늘리지 않는다. 좁은 화면에서는 탄창만 가로로 넘긴다. 기존 NeoDunggeunmoPro 글꼴과 nearest 텍스처를 재사용한다. UI 배율은 이 HUD의 창에 한해 정수로 적용하고 종료 시 이전 설정으로 돌린다. 프로젝트 전역 픽셀 해상도를 확정한 것은 아니다.

카드 탭은 선택/해제, 같은 탄·빈 곳·취소·Escape는 선택 취소다. 선택 중 사격·냉각·교체를 막고 빼내기는 위쪽 같은 자리에서 즉시 실행한다. 상세창을 닫아도 선택은 유지한다. 제거 후에는 선택을 비워 밀려온 탄이 연달아 제거되지 않게 한다. 빼내기 한도 소진 뒤에는 카드 탭으로 상세를 바로 연다. 상세 버튼은 선택이 없을 때 첫 탄, 선택 중에는 해당 탄을 가리킨다.

가로 스와이프는 선택을 실행하지 않으며 카드의 입력을 상위 스크롤로 전달한다. 비활성 사격을 누른 한 번의 입력이 선택 해제와 사격으로 연달아 처리되지 않게 한다. 저장 실패는 상단 경고에 남긴다.

## 구성과 실제 데이터

전투·메뉴·상세·보상/정비는 각각 TSCN에서 열 수 있다. 주 배치와 대표 상태는 씬에 저장하며 런타임에서 새로 배치하지 않는다. 실제 수치·텍스트·선택·사용 가능 여부와 짧은 누름 효과만 연결한다.

- 여정: `redesign/samples/hud/combat_journey_hud.tscn`
- 독립 비교/공통 배치: `redesign/samples/hud/combat_hud.tscn`
- 공통 창: `combat_menu.tscn`, `combat_detail.tscn`, `journey_flow.tscn`
- 표시 연결: `combat_hud_presenter.gd`, `prototype_round_icon.gd`, `prototype_battle_view.gd`, `combat_hud_theme.tres`

기존 Model/Forecast/Campaign/Journey를 사용한다. 실제5전투, 코어/탄 보상, 무료 정비, 관문, 현재 전투 재도전, 별도 자동 저장을 이어 간다. HTML 지도·크레딧·상점 모사를 이 여정의 규칙으로 옮기지 않는다. 전투 계산과 저장 형식은 유지한다.

## 실행·검증 경계

`OPEN_COMBAT_UI_STUDY.cmd`와 `OPEN_MAGAZINE_COMPARISON.cmd`는 최신 HUD로 열린다. 기존 비교 저장을 이어 쓰며 QA는 별도 저장에서 실행한다. 본편 기본 진입과 이전 APK는 이 변경을 포함하지 않는다.

740×360부터1280×800의 가로 화면 조작/배치,5총기, 부분 사격·빼내기·한도·메뉴 입력 차단,5전투 연속 보상/정비, 새 프로세스 저장 재개를 검사했다.2016×908에서 정수2배/1008×454 논리 크기도 확인했다. 상세 증거와 초기 결함 수정은 [보고서](../qa/reports/ui_prototype_godot_2026-11-01.md)에 둔다.
