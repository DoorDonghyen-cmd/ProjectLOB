# UI 공통 규격과 정비소 적용

## 본편 행동 버튼 공통 틀

2026-11-11. 전투의 냉각·탄창 교체에서 쓰는 금속 틀을 본편 행동 버튼의 기준으로 삼았다. 일반 상태의 테두리는 윗면과 옆면 1픽셀, 하단 2픽셀이고 모서리는 4픽셀로 처리한다. 키보드 포커스는 안쪽을 채우지 않는 2픽셀 테두리로 표시한다. 클릭과 누름 반응은 기존 공통 입력 효과를 사용한다.

타이틀·장비·지도·정비소·관문·보급소·조우·상점·보상·결과와 주요 확인창에 적용한다. 테마에서 지정한 글자와 내부 여백을 사용한다. 상점의 구매 키, 전투의 냉각·교체·사격, 결과 제목에는 각 화면의 기능 색을 쓴다. 탭·상품 행·지도 노드는 각 화면의 선택 표시로 읽힌다. [실제 화면과 검증](../qa/reports/button_frames_2026-11-11/README.md)

황동 행동 버튼의 윗면과 왼쪽에는 밝은 픽셀 단을, 오른쪽과 아랫면에는 어두운 픽셀 단을 그린다. 글자 뒤는 기존 황동 면을 쓰고, 버튼을 누르면 윗면 반사광이 어두워진다. [황동 표면 전후](../qa/reports/button_frames_2026-11-11/README.md#황동-표면-후속)

타이틀은 사용자가 고른 어두운 철제 시안을 적용했다. 저장이 있으면 ‘등반 계속’, 없으면 ‘새 등반’이 어두운 철제 면 `#252B23`과 아이보리 글자를 사용한다. 윗면의 얇은 황동 반사광과 포커스 테두리가 주 행동을 표시한다. [타이틀 실제 화면](../qa/reports/button_frames_2026-11-11/README.md#타이틀-시안-적용)

같은 테마를 장비 선택 ‘등반 시작’, 결과 ‘새 도전’, 지도 ‘이동’과 전투 건너뛰기, 보상의 ‘이 탄으로 교체’, 정비소의 작업 실행과 ‘강화 확정’에 사용한다. 보상 교체와 정비 실행은 선택 조건을 충족하면 황동 반사광이 보이고, 비활성일 때는 어두운 면과 낮은 밝기의 글자로 표시한다. [적용 화면](../qa/reports/button_frames_2026-11-11/README.md#시작-이동-확정-버튼-적용)

**장비 선택 버튼 역할(2026-11-08)** — 한 화면의 주 행동은 황동 채움과 어두운 글자로, 보조 행동은 먹색·철제 면과 아이보리 글자로 구분한다. 장비 선택의 주 행동 높이는 54, 보조 행동은 48 논리 픽셀이다. 선택 카드에는 황동 표시를 유지하고 일반 호버는 중립색, 키보드 포커스는 별도 선, 비활성 카드는 채도를 낮춘 글자·그림과 잠금 기호로 읽힌다. 다른 화면은 이 역할 구분을 참조하며 실제 크기는 각 화면에서 검수한다. [장비 선택 적용](equipment-ui.md)

**장비 선택 팝업(2026-11-06):** [정식 상속 씬과 실제 검증](../qa/reports/equipment_dialog_2026-11-06/README.md). 기존 공용 ConsoleDialog의 배치·입력·여백/폰트 크기를 보존하고 장비 문맥에서만 철제/먹색·아이보리·황동과 같은 형상의 체크 표시/드롭다운으로 연결한다. 다른 페이지 Theme나 공용 씬을 덮어쓰지 않는다.

**장비 정보 그룹(2026-11-06):** [실제 전후/검증](../qa/reports/equipment_information_2026-11-06/README.md). 총기명 바로 아래 고유 효과, 그림 아래 기존6px 간격의 발사/수치 그룹을 TSCN에 저작한다. 복장은 최대 보유 탄약을 우선 표시하고 최소 유지/정비 확장 설명은 기존 상세에 둔다. 이 변경으로 화면·배우·버튼 크기/위치나 글꼴 크기를 늘리지 않는다. 공용 팝업의 이전 청록 재질까지 정리됐다는 뜻은 아니다.

**전투·지도 재질 연결(2026-11-06):** [본편/전후·검증](../qa/reports/hud_material_2026-11-06/README.md). 전투 기본 패널·탄환 받침/일반 조작부는 철제·먹색/아이보리로 연결하고 다음 발사·제외·열/냉각/사격·효과별 색은 보존한다. 지도7버튼은 장비 선택의 장식 코드를 공유하되 위치·최소 크기·여백은 그대로다. 통일 대상은 중립 재질/마감이며 상점 CRT·정비소 조명·결과 상태색이나 화면별 레이아웃까지 동일화하지 않는다. 장식은 입력과 최소 크기 계산에 참여하지 않는다.

**지도 재질/정보 역할(2026-11-06):** [실제 본편/검증](../qa/reports/map_material_2026-11-06/README.md). `pipe_map/theme.tres`와 지도 전용 StyleBox/팔레트로 기존12/8 내용 여백과44px 이상 터치·배관도 배치를 유지한다. 현재 구역/소지금32, 보유 탄약/난도·범례·선택16을 사용하며, 현재·방문·선택·이동 가능은 선/모서리/체크/전체 테두리로 함께 구분한다. 상태 견본은 기존 오른쪽 Spacer 안에서만 표시하고 크기 계산에 참여하지 않는다. 상세/범례의 재질 적용은 기존 여백·입력/포커스를 유지한다. 이 값들을 다른 화면의 일괄 크기 규칙으로 확대하지 않는다.

**장비 선택 본편(2026-11-06):** [현행 기준](equipment-ui.md) · [실제 화면/입력 검증](../qa/reports/equipment_live_2026-11-06/README.md). 이 화면은 정식 `equipment/theme.tres`의 철제·아이보리·황동과 원래 버튼/총기 카드 크기를 사용한다. 상단과 하단 행동 줄은 중간 선택 스크롤 밖에 있고 짧은 창의 여백/간격은 상속 씬에 저작했다. **입력/처리 반응1차(2026-11-06):** [현재 반응과 실제 검증](../qa/reports/interaction_fx_2026-11-06/README.md). 테마/버튼·카드 크기/클릭 영역·포커스를 유지하고 그리기 전용 장식으로 눌림/복귀와 처리 확인선을 보완한다. 실제 명령 성공 뒤 현재 결과 위치만 반응하며 취소/거절·페이지 이동은 성공으로 표시하지 않는다. 즉시는 움직임 없이 정적인 확인선, 기본/빠르게는 짧은 반응을 사용한다. 컨테이너 최소 크기/간격에 장식이 참여하지 않도록 검증했다.

## 정비소 현행 구현

- 사용자 후속 지시로 작업대 중앙 좌측의 선택 탄환 그림/수량 문구를 제거했다. 작업 대상은 하단 선택 표시와 우측 변화 정보로 읽는다. [제거 후 PC 화면](../qa/reports/workbench_remove_display_2026-11-04/compression.png).
- 씬: `redesign/workbench/screen.tscn`, 반복 탄 항목: `item.tscn` / `candidate.tscn`, 표현: `theme.tres`. 동작: `screen.gd`. 기본 구도는 실행 전 에디터에서도 보인다.
- 제목32 / 본문·수치·행동16. 기존 공통 픽셀 글꼴과 native/정수 배율·안전 영역 적용. 먹색 반투명 면, 아이보리 글자, 황동 선택/확정, 2px 포커스 선. 모든 글자·수치는 엔진 노드다.
- 상단 장소/무료 횟수/소지금·나가기·보조 메뉴, 5개 작업 탭. 우측336×256 정보창(오른쪽24, 위128), 하단152 탄 목록. 이는 승인된 정비소의 현재 구성 수치이며 다른 화면의 영구 해상도 규칙이 아니다.
- 행동은 높이44·내용 폭. 보유 탄 항목128×96, 교체 후보128×72. 같은 이름도 성능 ID가 다르면 합치지 않으며 대표 성능/수량으로 구분한다. 목록은 가로 스크롤, 정보는 내부 세로 스크롤을 사용하고 실행 버튼은 정보 스크롤 밖에 둔다.
- 정비소의 현재 최소 논리 높이는540. S26 기본형 비율1170×540에서는 전체가 보이며, 더 짧은 창에서는 native 글자/구도를 보존하고 기존 바깥 세로 스크롤을 허용한다. 전역 Canvas를 축소해 맞추지 않는다.
- 탭/탄/받을 탄 선택과 선택 취소는 게임/저장에 변화를 주지 않는다. 화력·방열 개조 모두 기존 명령을 사용한다. 미리보기는 메모리 복제에 실제 Campaign 명령을 실행하고 확정만 현재 Campaign에 연결한다. 입력마다 한 번의 미리보기를 만들며 매 프레임 재계산하지 않는다.
- 무료 정비는 다섯 작업 중 한 번. 완료 뒤 같은 작업대에 결과·업데이트된 보유 탄·나가기를 표시한다. 저장 오류도 기존 메시지를 유지한다. 창 크기 변경은 작업 탭과 양쪽 교체 대상을 보존한다. 메뉴에서 기존 빌드·기록·설정·타이틀에 접근한다.

## 아래는 규격 v1 도입 기록

**최신 사용자 정비소 방향 — 2026-11-04:** 청록 중심 인상과 기능 목록 구성을 지적하고 작업대 장면/작업별 탭을 요청했다. [별도 시안과 범위](../qa/reports/workbench_theme_2026-11-04.md). 아래2열/팔레트는 현재 본편v1의 기록이며 새 정비소의 탭 전환을 막는 영구 규칙이 아니다. 사용자는 새 시안을 가장 좋은 결과로 긍정 평가했다. 글꼴·터치·내용 폭 등 역할 원칙을 유지하며 작업 장면/탭과 새 배색을 정비소의 후속 시각 기준으로 반영한다. 실제 정비 기능 연결은 다음 단계다.

2026-11-04. 사용자 ‘규격표 + 공통 컴포넌트 + 기존 배치의 정비소 전후 비교’ 실행 승인에 따라 정리했다. 라인+도트와 기존 인게임 배치가 기준이다. 현재 적용 범위는 **현행 정비소 기본 화면**이며 결과·상점·선택·기존 전투 HUD에 이 값을 일괄 적용하지 않는다.

## 원본과 적용 방법

- 역할별 글자·색·간격·상태·버튼 폭 상한의 구현 원본: `redesign/ui/standard_theme.tres`.
- 버튼: `redesign/ui/action_button.tscn/gd`. 패널 안의 남는 폭을 채우지 않고 문구와 스타일 여백으로 폭을 계산한다.
- 작업 영역: `redesign/ui/operation_card.tscn`. 제목/설명/행동은 별도 노드이며 화면은 값·활성 여부·콜백을 연결한다.
- 화면: `redesign/workshop_screen.tscn/gd`. 장소·2열·5개 작업·계속 버튼의 배치는 씬에 저장한다. 기존 `modern_workshop()`은 이 씬을 불러와 현재 모델에 연결한다.
- 문서 표는 역할의 의미와 적용 범위를 설명한다. 코드에서는 역할 이름을 사용하며 각 화면에서 같은 숫자를 다시 지정하지 않는다.

| IconButton | 44 | 44 고정 | 도구/기호, 실제 적용은 후속 |

숫자는 논리 UI 단위이며 기존1/2배 표시 체계와 구분한다. 정비소는 동등한 작업 선택이므로 ActionButton만 사용하고 주황 버튼을 다섯 개 만들지 않는다. 선택창을 여는 행동은 ‘압축할 탄 선택’처럼 다음 동작을 드러낸다. 즉시 적용되는 가방은 ‘확장’, 조건과 증가량은 설명에 한 번만 표시한다. 긴 문구는216 내에서 줄바꿈하며 높이는 필요한 만큼 늘어날 수 있다. 정상 문구에서 최소44를 확보하고 버튼을 부모 너비로 늘리지 않는다.

## 유지하는 화면별 예외

- 정비소 중앙 열900, 작은 화면의 기존 열 폭 계산·2열 작업 순서는 유지한다. 4개 작업인 저장은 교체 항목을 숨기는 기존 조건을 따른다.
- 작업 행 최소124, 계속 버튼 행 최소52는 이전 구성의 위치/기준선을 유지하기 위한 화면 규격이다. 그 안의 버튼 터치 높이는44다.
- 기존 장소 그림/캐릭터, 그림과 설명의24 간격, 바깥 화면 여백20, 안전 영역·정수 배율과 정상 페이지 스크롤을 유지한다.
- 전투44/50·선택 화면·상점 등 과거 규격은 아직 이전 구현을 사용한다. v1을 적용하지 않은 화면을 규격 통합 완료로 표시하지 않는다.

## 문구

- 행동·조건·비용·결과를 추가하는 문구를 남긴다. 같은 정보를 제목/설명/버튼에서 불필요하게 반복하지 않는다.
- 정비소 소개는 ‘무료 작업 1회’만 남긴다. 각 작업 설명이 선택지를 설명하므로 ‘탄환을 다듬거나 가방을 확장하세요’는 덜었다.
- 가방 증가량과 탄약 지급 없음/구역 한도는 실제 모델의 `bag_growth_hint()`를 표시한다. 버튼에는 증가량을 다시 쓰지 않는다.
- ‘다음 설계’와 결과창 조언은 후속 적용 범위다. 이번 작업에서 다른 화면의 문구를 일괄 삭제하지 않는다.
