# 탄환·파츠 효과 확장 기준

2026-10-11 · 디렉터 검토. 현행 규칙을 변경하지 않고 확장 경계를 정리한다.

## 판단과 적용 범위

[Slay The Robot README](https://github.com/DesirePathGames/Slay-The-Robot#-action-system)의 재사용 액션, 조건 검사, 예측과 실제 처리 공유를 참고했다. 해당 프로젝트의 전체 내부 동작을 검증하거나 프레임워크를 이식한 것은 아니다. LoB도 이미 `forecast.gd`에서 상태를 깊은 복사한 Model로 예측한다. 따라서 새 프레임워크 전환보다 기존 단일 계산 경로를 유지하는 것이 우선이다.

**이번 구현:** `combat_vfx.gd`로 장갑 조각·전격선·냉각 증기의 표현을 분리하고 실제 결과만 전달한다. 주인공 등록 좌표도 편집 원본과 함께 내보내는 데이터로 분리했다. **검토만 완료:** Model의 효과별 함수 분해, 데이터 스키마 전환, 범용 이벤트 버스는 아직 구현하지 않았다.

## 현재 발사 처리 순서

| 단계 | 현재 코드와 책임 | 확장 시 지킬 조건 |
|---|---|---|
| 장전 검증·순서 | Model의 can_load/load_block_reason/confirm | 마지막 장전이 먼저 발사되는 확정 순서를 UI에서 별도 계산하지 않음 |
| 대상·프로필 | Model._shot, Model.shot_profile | 유효 대상과 파츠 적용 프로필은 예측·실전에서 공유 |
| 사격 전 열 | 냉각/열 소모·추가 발열·고열 조건 | 냉각량은 실제 감소분, 고열 조건의 참조 시점은 heat_before |
| 직접 피해 | 증폭/조건부 파츠·장갑/관통·연타·배리어·쇄도 집중 | 1발 전체와 각 명중을 구별. 관통과 영구 장갑 감소를 혼동하지 않음 |
| 후속 효과 | 기폭·장갑 감소·증폭 소비/부여·화상·밀기·차단·전이 | 현행 순서를 유지. 장갑 파쇄는 같은 발의 직접 피해 이후 적용 |
| 처치·발사 후 열 | 처치 냉각·세 번째 발 냉각·과열 결과 | 열 한계 판단은 해당 발의 후속 냉각까지 반영한 상태 |
| 행동 종료 | Model.finish_fire, _advance, reload_magazine | 적 행동·증원·승패·필요한 강제 재장전. 마지막 적 처치 시 불필요한 재장전 없음 |
| 표현 | result/secondary/part_effects → 전투 뷰·수치·VFX | 표현 코드는 HP/열/RNG를 변경하거나 다음 표적을 다시 추첨하지 않음 |

## 확인한 확장 부담

- `_shot`에 서로 다른 시점의 조건이 모여 있어, 새 파츠가 어느 단계에 끼어드는지 실수하기 쉽다. 후속 기능 추가 때는 먼저 ‘사격 전 열 / 직접 피해 보정 / 명중 후 상태 / 처치 후 보정’ 중 위치를 선언하고 해당 단계만 추출한다. 한 번에 전부 재작성하지 않는다.
- `part_feedback.gd`에는 실제 수치 변경과 별도로 발동 문구 조건이 있다. 새 파츠는 계산 시 확정된 발동 기록을 결과에 남기는 방식을 우선하며, UI에서 같은 조건식을 다시 만들지 않는다. 기존 모든 문구의 정합성을 이번 작업에서 전수 검증한 것은 아니다.
- 산개 예측은 최소 결과(`forecast_minimal`) 경로를 사용한다. 새 효과가 열·생존·다음 표적에 영향을 주면 일반 결과뿐 아니라 최소 결과와 분기 합산도 함께 검증해야 한다.
- 모델은 덱과 표적용 RNG 상태를 이미 구별한다. 이번 VFX는 난수를 사용하지 않으므로 같은 입력·시드의 전투 결과를 바꾸지 않는다.

## 새 효과의 완료 조건

한 효과당 발동/불발 예, 발동 시점, 실제 결과 필드, 손패·탄창 설명, 예측 반영을 함께 작성한다. 관통/파쇄, 차단/피해, 열 감소/과열 종료처럼 혼동할 수 있는 반례도 포함한다. 연출 유무·즉시 연출·건너뛰기가 Model 상태와 RNG를 바꾸지 않는지 검증한다. 임의의 효과 발동 순서를 변경하는 범용 인터셉터는 필요성이 생길 때 별도 설계한다.

## 외부 VFX 검토와 실제 도입

[Godot VFX Library](https://github.com/haowg/GODOT-VFX-LIBRARY)의 `shield_break.tscn`, `lightning_chain.tscn`, `steam.tscn`을 확인했다. 짧은 일회성 파편·상승 증기의 구성을 참고했으나 해당 씬/코드/이미지를 복사하지 않았다. 특히 라이브러리 전격은 여러 방향으로 퍼지는 입자라 LoB의 실제 대상 간 전이와 다르다. 현재 Control 기반 전장과 도트 크기에 맞춰 작은 사각 조각과 실제 대상 연결선을 자체 구현했다. 외부 플러그인·셰이더·렌더러 변경은 없다.
