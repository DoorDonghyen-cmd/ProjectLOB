# ORVASK — 현재 방향과 결정 상태

**최신 — 빌드 엔진 시험(2026-11-08):** 사용자가 빌드·성장 분석에 동의하고 진행을 지시했다. [빌드 엔진](build-engine.md)에 빌드 3종(연타·결정타, 소이·확산, 감속·후속타)을 설계하고 연타·결정타를 새 등반에 시험 적용했다. 신규 파츠 연타 공명기(n번째 타격 ×n)·타격 기록기(연타 처치로 성장)와 전투 피해 숫자 아래 계산 줄(`기본+가산 ×배율 = 합계`). 파츠·수치는 디렉터 결정이고 사람 체감 확인 전이다. 실제 전투 비교에서 순서를 맞춘 플레이와 계속 사격의 차이가 새로 생겼다. [보고서](../qa/reports/build_engine_2026-11-08/README.md).

**최신 — 디렉터 결정 2건·이야기 장면(2026-11-08):** 사용자 "1~3까지 진행해 줘". 아래 두 결정은 사용자 확정이 아닌 **디렉터 결정**이며 되돌리기 쉽다.
- **보급 선호 숨김**: 현재 탄창 등반은 첫 보상에서 다섯 계열을 모두 보여 줘 선호가 후보를 바꾸지 못한다(11-06 비교에서도 4선호 결과 동일). 기록실 탭·등반 설정·무기 상세에서 숨겼다(`campaign_content.gd::SUPPLY_PREFERENCE_VISIBLE`). 전술 데이터·해금 기록은 저장에 남는다. 정식 해금 재설계는 [플레이 점검 44번](playtest-priorities.md)에서 다룬다.
- **글자 크기 설정 제거**: 화면은 정수 배율, 픽셀 글꼴은 16 단위라 90/110%가 바뀌지 않거나 흐려진다. 설정에서 빼고 저장값을 100%로 읽는다(`preferences.gd`). 큰 글자가 필요하면 별도 '큰 글자 모드' 설계가 필요하다.
- 출발·공급 복구·귀환을 조우와 같은 장면 구성으로, 파츠 분해 확인·파츠 상세를 공통 창으로 옮겼다. [이야기 장면](../qa/reports/story_scenes_2026-11-08/README.md).

**최신 — 공통 창(2026-11-08):** 사용자 진행 지시로 설정·조작 안내·게임 규칙·기록실을 정비소 테마로 옮겼다. 가로 휴대폰에서 저장이 있으면 타이틀 설정 버튼이 화면 밖으로 나가던 문제도 고쳤다. **결정 필요**: 보급 선호 해금은 현재 탄창 등반의 첫 보상 후보에 쓰이지 않는다(30데이터를 써도 효과 없음). 글자 크기 설정은 픽셀 글꼴 16단위 맞춤 때문에 거의 바뀌지 않는다. [본편·검증](../qa/reports/common_windows_2026-11-08/README.md).

**최신 — 빌드 작업실 통일(2026-11-08):** 사용자 진행 지시로 빌드 작업실을 상점의 파츠 장착 구성(장착대·보관함·얻음/잃음)과 탄약고의 휴대 칸·탄 묶음으로 바꾸고 정비소 테마로 맞췄다. 파츠 `제3 격발기` 아이콘 누락도 보완. [본편·검증](../qa/reports/build_live_2026-11-08/README.md). 이전 빌드 작업실 버튼을 누르던 오래된 검사15개 갱신 필요.

**최신 — 조우 본편 연결(2026-11-08):** 사용자 승인으로 사건·조우 시안을 `PLAY.cmd`에 연결했다. 구역 전투 배경 위 이야기 창, 선택 뒤 결과와 행동 하나, 매복은 같은 자리 전투, 탄 발견 추가/교체, 자동 저장. [본편·검증](../qa/reports/event_live_2026-11-08/README.md). 이전 사건 버튼을 누르던 오래된 검사는 갱신 필요.

**직전 규칙 수정:** 사용자 원래 의도에 맞춰 **마지막 장전 탄부터 발사**한다. 새 탄은 레일 맨 앞에 들어가고 화면은 실제 발사 순서인 왼쪽→오른쪽을 보여 준다. 예측·압축·위치 제약·회수·샘플과 안내를 함께 수정했다. 기존 저장의 이미 배치된 발사 순서는 보존한다. [검증과 화면](../qa/reports/lifo_2026-10-04.md). 탄환 선택 가치와 밸런스 문제는 별도 후속이며 이번에 수치를 바꾸지 않았다.

**이전 후속 작업:** [발열 빌드 비교·결과 피드백](../qa/reports/heat_polish_2026-10-04.md)을 적용했다. 당시 2,400 독립 전투에서 냉각형과 고열형의 차이를 확인하고 수치는 유지했다. 보상·엔딩에 열 운용 요약, 게임 내부 교전 기록, 실제 실패 원인과 파츠 수치/상호작용 안내를 추가했다. 당시 비교를 새 장전 조작의 사람 플레이 검증으로 취급하지 않는다.

**이전 구현:** [발열 빌드 확장](heat-builds.md)의 파츠3종·탄환2종과 화면/응답성 개선을 본편에 적용했다. [최신 검증과 화면](../qa/reports/heat_builds_2026-10-04.md). 기존 탄환별 발열·무기별 한계·상시 게이지를 유지한다. 한계 도달 탄까지 발사하고 뒤는 중단하며 전투가 계속되면 기본 재장전+1턴을 자동 처리한다. 냉각은 현재 열을 낮춘다. [발열 설계](heat-system.md)의 수치는 디렉터 첫 구현값이며 최종 재미 검증과 구별한다.

[이전 감사](../qa/reports/ammo_choice_2026-10-04.md)의 무작위1,080/1,080승 문제를 반영해 보조탄 피해와 적 접근 시한도 조정했다. 같은 조건의 새 비교는 무작위1,025/1,080승, 회수탄 반복625/1,080승이다. 결과 차이는 생겼으나 압쇄의 무작위216/216승 등 추가 밸런스 판단은 남는다. 독립 전투 비교이며 사람 승률은 아니다.

## 사용자에게 확인된 핵심

- 탄종 확장을 승인하면서 **탄창 크기·파츠·총기의 연결**을 강조했다. 개별 신규 효과와 수치는 디렉터 구현값이다.

- 마지막에 넣은 탄환이 가장 먼저 발사되는 구조가 원래 의도다. 장전 입력과 발사 순서를 구분한다. LIFO 수정 당시에는 아무 탄을 넣어도 효율이 좋다는 체감이 남았고, 이후 패·순환·잔열 개편 후에는 긴장감과 선택의 재미가 개선됐다는 사용자 평가를 받았다. 모든 탄환의 역할/밸런스 문제가 해결됐다는 평가로 확대하지 않는다.
- 쇄도 테스트 후 현재 발열·재장전 메커니즘을 긍정 평가했다. 이 구조를 바탕으로 폴리싱하고 탄종·과열 제어 파츠를 확장하는 방향이다. [발열 빌드 확장](heat-builds.md)의 파츠3종·탄환2종은 구현했으며 개별 수치는 디렉터 첫 밸런스다.
- 탄환을 조합하고 순서를 설계해 피해를 증폭하고 여러 적을 처치한다. 탄환은 카드, 무기는 캐릭터, 여러 파츠는 조커처럼 개인 빌드를 만든다.
- 강력한 파츠·압축에는 의미 있는 대가가 필요하다. 모든 선택에 일률적 패널티를 붙이지 않는다.
- 최근 사용자는 발열에 따른 재장전 비용을 긍정적으로 평가했고, 적 특성의 의미가 약하며 탄종과 조합이 반복된다고 피드백했다. 이 세 가지를 종합한 개발을 승인했다.
- 후속으로 발열을 일부 변형탄만의 대가가 아닌 전투 전반의 핵심으로 두고, 탄환마다 발열 수치와 과열 시 강제 재장전 같은 결과를 제안했다. 구체 한계·자동 처리 순서·냉각 턴까지 사용자 확정으로 확대하지 않는다.
- 기본 정보는 단순하게, 선택과 상호작용은 깊게. 화염은 지속 피해이며 기폭은 별도 탄환이다. 명중·회피 수치를 되살리지 않는다.
- 전투뿐 아니라 메인·무기 선택·맵·보상·상점·장비의 조작과 정보 위계가 중요하다. 작은 글자로 내용을 밀어 넣지 않는다.
- 게임 전체와 UI는 도트 아트풍. 가장 가까운 참고는 산나비이며 ARCANE TRIGGER와 사용자 제공 이미지도 참고한다. [레퍼런스](../art/references/2026-10-03-user/README.md), [제작 기준](pixel-style.md).
- C 복장+B 방한모 주인공과 제작한 배경, 주인공을 35% 축소한 크기를 사용자가 확인했다. 기존 탄환 카드 디자인을 유지한다. 몬스터 최종 외형과 캐릭터 동작은 미확정이다.
- 세계관은 폭주한 기상탑을 오르는 탄환 기술자. 위험한 탐험, 생존자의 온기, 은근한 디스토피아와 복구 엔딩의 큰 방향을 채택했다. 아이템·쪽지로 간접 전달한다. 개별 원고·연출까지 확정한 것은 아니다.
- 현재 전체 진행 방향에 긍정 답변을 받았다. 발사·과열 반응의 추가 재정비와 폴리싱은 향후 진행한다. 수치·재미·최종 아트 완료로 확대 해석하지 않는다.
- UI·규칙·아트 판단은 위임받은 범위 안에서 진행한다. APK·커밋·푸시·외부 게시는 해당 요청 범위에 따른다.

## 현재 디렉터 결정과 구현

핵심 문장: **손패로 한 번의 사격을 설계하고, 파츠로 나만의 연쇄를 만든다.**

- 다섯 무기, 파츠 5칸, 압축 코어 경제를 유지한다. 새 등반은 [생성형45방 맵](route-map.md), 기존 저장은35방 맵을 사용한다. 이 수치는 영구 규칙이 아니다.
- 시작 덱은 무기별 3~4종 10장. 전술 보급은18종이며 기본탄/압축 변형은 별도로 센다. 보상은 연계 후보와 미보유 탄을 제안하고 상점은 미진열 탄부터 보여 준다.
- 파츠28종(빈 슬롯 제외). [파츠 빌드 역할](parts-builds.md)을 따른다. 냉각 약실은 재장전 냉각+4/탄창−1, 연쇄 방열기는 세 번째 발 냉각3/한계−1, 예약 급탄기는 예약+1장이다. 방열판은 한계+3, 순환펌프는 처치한 탄 열−2, 잔열 노심은 발사 전 고열 화력+2/한계−2. 방출은 마지막 위치에서 열→피해, 과급은 발사 전 고열 조건의 공격탄이다. 상점·장비에 열 한계/고열 조건 변화가 보인다.
- 산개5발 이상은 별도 스레드의 정확 예측을 사용한다. 편집 중 이전 계산 취소·최신 결과만 반영, 계산 중 조작 유지·확정/발사는 완료 후 활성화한다.
- 파쇄는 후속 장갑을 낮추고, 기폭은 남은 화상 피해를 소모하며, 추격은 직전 탄의 처치에 연결된다. 우회는 앞 적을 넘기고 냉각은 현재 열을 낮추며 과열 중단 전에 발사해야 한다. 현재17계열의 영구/임시 압축 변형을 지원한다. [등급 설계](ammo-grades.md)를 따른다.
- 모든 탄에 발열 변화량을 표시한다. 무기 한계는 보행자12/쇄도14/산개16/압쇄13/증강10. 과열 중단·강제 재장전과 총 경과 턴을 예측하며 보조탄의 직접 피해·초반 적 처치선·접근 거리를 함께 조정했다.
- 초반 세 교전 이후 일반 편성은 장갑 전열·배리어 전열·장갑 뒤 원거리를 순환한다. 보조 적은 낮은 HP를 유지한다. 한 탄종만 요구하는 잠금식 적은 지향하지 않는다.
- 압력두꺼비는 2턴 준비, 압력탄 HP 1·6m/턴, 생성 턴 이동 없음. 최근접 압력탄은 산개도 자동 요격한다. 이미 날아온 탄은 본체 처치 후에도 남고 0m에 도달하면 패배한다.
- 본편 전투에도 승인된 주거구 배경·주인공 크기와 과열/원거리 표시를 적용했다. 지역별 배경 세트와 적의 최종 아트는 후속이다.
- 새 탄환 실루엣·한 줄 효과, 순서별 파쇄/기폭/추격/냉각 결과, 사격 후 재장전 비용과 상점/보상 획득 흐름을 연결했다. 산개는 범위와 확률로 표시한다.
- 전투 저장v12는 예약과 적 차단 상태를 저장하며 v11 이하의 편집 중/확정/부분 발사 배열과 기존 손패를 그대로 보존한다. 새 손패 크기는 다음 재장전부터 적용하며 잔열이 남은 장전 단계도 저장한다. v8의 추가 재장전 부채를 한 번 보존·소진하고 열0으로 옮기는 기존 경로도 유지한다.

## 남은 판단과 작업

- [새 빌드 연결](build-synergy.md)의 실제 선택/건너뛰기 빈도와 작은 탄창·긴 탄창·무기별 조합을 사람 플레이로 확인한다. 기능 통과와2,520개 짧은 통제 사례를 최적 밸런스나 사람 승률로 확대하지 않는다.

- 손패·탄창과 잔열은 1차 개편했다. 다음은 [검토의 남은 항목](../qa/reports/decision_revision_2026-10-04.md), 특히 보행자의 무조건부 화력·조건부 탄의 실패 비용과 첫 지역3편성의 공개 행동 시한이다. 최소 두 대응과 실수 후 회복, 성장 후 남길 탄을 확인한다. 자동 완주/효과 계산 통과만으로 핵심 재미를 완료 처리하지 않는다.
- [발열 빌드 확장](heat-builds.md)의 실제 선택 빈도와 비용을 플레이로 확인한다. 새 일반 파츠가 모든 빌드의 필수품이 되는지, 고열 유지와 냉각 운영이 모두 유효한지 검토한다.
- 구현된 [발열 규칙](heat-system.md)으로 과열 직전 냉각·저발열 혼합·위험을 감수한 마무리의 체감을 확인한다. 기능/통제 비교 결과와 사람의 재미를 구분하며 무기별 안전성과 냉각 의존도를 조정한다.
- 압력두꺼비는 시험용 도형, 기존 적 여섯 종은 임시 자산이다. [몬스터 제작안](monster-roster.md), 무기별 동작, 지역 배경, 사운드와 최종 폴리싱은 후속이다.
- [간접 서사](narrative-delivery.md)의 원고/상세 연결과 [복장·헬멧 수집·교체](appearance.md)는 설계 단계다. 능력치 효과는 미정이다.
- 실제 Galaxy 성능·터치 피로도, 여러 시드·난도에서의 장기 빌드 다양성은 추가 플레이가 필요하다.
