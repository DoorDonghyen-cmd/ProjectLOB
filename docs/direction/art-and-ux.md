**전투 효과·주인공 원본 경로:** 실제 장갑 감소에는 금속 파편, 전이에는 실제 표적 사이의 짧은 계단형 전격선, 실제 열 감소에는 총구 주변 냉각 증기를 사용한다. 단순 관통·열0에서는 해당 특수 효과가 발생하지 않는다. 감소된 연출/건너뛰기에서 잔상을 정리하며 전투 계산은 그대로 유지한다. 승인 주인공4자세를 LibreSprite 편집 원본으로 보존하고 발·총구 좌표까지 게임에 내보내는 경로를 연결했다. [제작 경로](../../art_source/hero/README.md) · [효과 구조 검토](effect-pipeline.md) · [검증](../qa/reports/combat_vfx_pipeline_2026-10-11.md). 새 효과의 강도·체감에 대한 사용자 확인은 후속이다.

**전투 패널 정렬:** 헤더 배경 띠는 고정 장식 높이 대신 실제 헤더/편집 버튼의 영역과 여백을 따른다. 탄환 판과 장전 확정·발사 버튼은 상하 기준선을 공유한다. 과열 경고는 기존 결과 행 오른쪽에 공간을 예약해, 경고 표시 여부가 주 행동 정렬을 바꾸지 않는다. [검증](../qa/reports/combat_alignment_2026-10-10.md).

**장전 중 발열 판독:** 큰 수치는 `발열 0 → 예상 8 / 12`처럼 현재 열과 사격 중 예상 최고치를 함께 표시한다. 탄환 추가·회수·순서 변경과 장전 확정에 맞춰 예측을 갱신한다. 실제 열은 발사 시 누적하며, 발사 중에는 현재치로 돌아간다. 냉각 후 0을 사격 최고치로 표시하지 않는다. 무작위 분기는 최고치 범위를 표시한다. 게이지의 실선/윤곽 구분과 강제 냉각 결과 기록은 유지한다.

**사용자 채택과 후속 디테일:** 사용자는 아래 공통 도트 UI가 이전보다 월등히 좋아졌다고 평가했다. 이를 기준으로 유지하며 추가 참조에 따라 카드 이음·이름 띠 단차·장전 판 안착부·버튼 어깨/받침/눌림 깊이를 보강했다. 새 세부는 디렉터 구현 후 사용자 확인 전이다. [참조](../art/style-reference/detail-ui-study.md) · [화면·검증](../qa/reports/console_detail_2026-10-10.md).

**현행 공통 도트 UI — 참조 적용:** 카드의 밝은 데이터 면/어두운 이름·효과 띠, 탄창의 홈/장전 판, 계기 채널, 두께 있는 행동 키를 공용 SVG/StyleBoxTexture 리소스로 연결했다. 가방/상점 카드와 파츠 프레임, 메인·무기·맵 공통 버튼에도 적용했다. 새 외형은 디렉터 구현안이며 사용자 미감 확인 전이다. 아래 참조 검토의 ‘미구현’ 및 이전 얇은 판형 설명보다 이 구현 상태가 우선한다. [화면·검증·범위](../qa/reports/console_ui_2026-10-10.md).

**사용자 제공 상점 카드 참조:** 카드 섹션·개별 카드·버튼을 함께 설계하고, 반복되는 정보 위치와 카드 하단의 비용/상태 표현으로 물건과 행동의 관계를 드러낸다. 색상/구매 조작의 직접 채택은 아니며 실제 클릭 동작은 참고 이미지에서 확인할 수 없다. [이미지와 검토](../art/style-reference/shop-card-ui-study.md). 현재는 다음 제작 기준이며 새 UI 미구현.

**Pinterest 추가 참조 — 장비/가방 화면:** 사용자 제공 보드의 공개 미리보기에서 빈 슬롯의 낮은 대비, 물건 중심 선택, 선택 대상과 행동의 국소 강조를 검토했다. 탄환 가방/파츠의 표현 후보이며 전투에 조밀한 능력치 격자를 추가하는 근거로 쓰지 않는다. 고해상도·상태 동작은 미확인이고 새 화면은 미구현이다. [관찰과 적용 후보](../art/style-reference/pinterest-ui-study.md).

**CraftPix 참고 검토 — 다음 제작 제안:** 공개 사이버펑크·현대 장비·RPG UI 이미지를 비교했다. 현재 정보 위계와 절제된 색은 유지하면서 부품의 단면/홈/눌림 깊이, 역할별 형태, 일관된 도트 덩어리로 조형성을 보강하는 방향을 검토한다. 프레임 장식을 모든 면에 늘리거나 철회한 정비함 외피를 복원하지 않는다. 새 외형은 미구현·사용자 확인 전이며 [관찰 근거와 적용 후보](../art/style-reference/craftpix-ui-study.md)에 구분해 기록한다.

**현행 시각 폴리싱:** 획일적인 두꺼운 윗선/계단 모서리를 줄였다. 카드의 얇은 판형, 탄창의 어두운 홈, 주 행동의 밝은 눌림면, 보조 버튼의 낮은 대비 바닥선으로 역할을 나눈다. 탁한 회녹색 카드와 어두운 청회색 주변 면, 제한된 강조색을 유지한다. 이는 디렉터 구현안으로 사용자의 미감 확인 전이다. 아래 초기 공통 프레임의 구체적인 모서리/윗선 설명보다 우선한다. [비교·검증](../qa/reports/combat_visual_polish_2026-10-10.md).

**조작 상태의 현행 규칙:** 손패 hover/focus는 합법적인 탄창 삽입 위치·점유 폭을 모서리로 보여 준다. 재장전 hover/focus는 현재 열을 바꾸지 않고 제거 예정 셀을 청회색 빈 윤곽/빼기 기호로 표시한다. 모바일의 냉각 전후와 적 턴은 버튼에서 상시 판독 가능해야 한다. 보조 조작은 중립색, 선택·주 행동은 민트, 냉각은 청회색, 접촉 위험은 주황을 사용하며 누름 반응도 따른다. 비활성 카드는 이유를 짧게 밝힌다. 컨테이너 크기·입력 영역을 움직이지 않는다. [구현·검증](../qa/reports/combat_affordance_2026-10-10.md).

**현행 전투 UI — 일관된 도트 조작부:** 정비함의 금속/가죽 PNG 외피는 사용자 부적합 의견에 따라 철회했다. 청회색 3단계 색면, 2px 계단 모서리, 같은 한글 도트 글꼴을 손패·장전 카드·발열계·발사/재장전에 적용한다. 실행은 밝은 회녹색, 냉각은 청회색, 실제 위험은 주황으로 기능을 구분한다. 발사/재장전은 같은 폭의 오른쪽 조작 열에 정렬한다. 수치 뒤 잔묘사·얼룩·가짜 재질 없음. 사용자가 후속 발전의 기준으로 선택한 도트 UI다. [통합 화면·검증](../qa/reports/combat_pixel_ui_2026-10-09.md).

**전투 피드백:** 현재 피해 숫자를 36px/강화44px 중심으로 표시하고 짧은 정수 크기 변화·상승·끝 페이드로 구분한다. 효과/처치는 16px 꼬리표로 분리한다. 전이 피해는 각 피해 대상에 표시하며, 확정 모델의 합계/실제 타격 횟수를 사용하고 가짜 치명타·개별 피해를 만들지 않는다. 머리 위 HP·거리·다른 숫자와 겹치지 않는 범위를 우선한다. UI 반응은 컨테이너 대신 내부 0.22~0.24초 선/모서리를 움직인다. 즉시 연출에서는 해당 동작을 생략한다. [실제 검증](../qa/reports/combat_feedback_2026-10-09.md).

**이전 1차 제작 이력 — 외피는 위 현행 기준으로 대체:** 낡은 강철 면·계단 모서리·짧은 활성 가장자리로 공용 프레임을 정리하고, 빈 탄창 홈/장전 면을 구분한다. 발열은 현재의 채워진 셀·예상 최고 열의 빈 윤곽 셀·한계 끝 표시, 냉각은 짧은 푸른 잔상. 기존 승인 PNG를 유지하며 접지 그림자·낮은 대비 환경 입자·국소 사격/냉각 반응을 더한다. 연출 중에도 고정 배치와 실제 모델 결과를 유지하고 즉시 연출 설정에서는 잔상/환경 동작을 생략한다. 디렉터 첫 제작안이며 최종 사용자 스타일 승인은 후속. [화면·검증](../qa/reports/combat_finish_2026-10-09.md).

## 전투 정보 위계 · 발열과 냉각

사용자 승인 방향: 상시 정보량을 줄이고 발열·재장전 냉각을 핵심 판단 정보로 올린다. 아래 배치와 수치는 디렉터 구현안이며 사람의 이해도 검증은 후속이다.

- 항상 표시: 전장과 적의 현재 상태, 탄환 선택, 발사 순서, 큰 현재 열/한계 게이지, 재장전 행동. 탄환별 발열은 카드에 유지한다.
- 장전 후 표시: 순서 편집과 예상 결과. 편집·예측·과열 경고 영역의 높이는 빈 상태에도 확보하여 정보 노출만으로 전장/손패가 움직이지 않게 한다. 확정 후에는 편집 버튼을 숨기고 발사할 탄 수를 주 행동에 표시한다. 탄을 누르면 상세 열람은 유지한다.
- 열 게이지는 68px 높이 영역, 현재값28px·사격 중 최고값21px와 예측 구간을 사용한다. 강제 냉각 뒤의 0만 보여 주지 않고 과열에 닿는 최고 열을 읽게 한다.
- 재장전 버튼에 냉각량·현재→재장전 후 열·적 경과 턴을 함께 둔다. 현재 재장전 시 접촉으로 패배하면 버튼에 위험을 표시한다.
- 과열 시 주 행동 옆에 사격 중단·강제 재장전 턴·열0을 표시한다. 산개의 확률적 과열과 마지막 적 처치로 재장전이 없는 결과를 구분한다. 증강의 이번 발사/전체 사격 예측 범위를 따르며 규칙은 변경하지 않는다.
- 전장 상시 접근 설명·반복 조합 수업·빈 선택 결과 박스를 제거한다. 무기 이름을 누르면 특성 열람, 턴/적/재화는 빌드 상세, 다음 추첨2장과 덱 순환은 탄환 가방으로 모은다. 다음2장은 종전 전투 화면에서 공개하던 정보이며 나머지 더미는 탄종순 정렬을 유지한다.
- 별도 하단 예비탄 행을 제거한다. 고정된 조작 영역과 창 크기에 맞춰 전장 최소 높이를210px까지 조절하되 선호 높이와 배우 크기는 유지해 카드/행동이 화면 밖으로 밀리지 않게 한다. 모든 상태에서210px로 고정하는 방식은 아니다.

[실제 화면·기능/시각 검증](../qa/reports/combat_hierarchy_2026-10-09.md). 아래 초기 상시 문구/패널 배치보다 이 기준을 우선한다.


**탄환 등급 표시:** 카드의 속성색과 선택 테두리를 유지하고 일반1개/고급2개의 짧은 막대로 구분한다. 임시 압축은 금색 점을 더한다. 등급·영구/임시 설명은 상세와 획득 화면에, 압축 전후 효과/열/점유/위치 제약은 확정 전에 둔다. [현행 설계](ammo-grades.md).

**현행 전투 탄환 카드:** 상단 이름/발열18px, 가운데 승인 도트 탄환/피해30px/관통18px, 하단 효과17px 한 줄. 고유 효과는 의미가 읽히는 짧은 문구를 유지한다. 발열 기호 확대/양수는 따뜻한색·냉각은 푸른색과 부호, 일반 피해는 밝은 중립색. 효과 내부 박스는 선으로 축약, 압축 가능 여부는 그림 옆 연결 기호와 모서리로 표시하며 전체 테두리는 호버/초점에 사용한다. 카드 크기/전장 비율 유지. [현재 화면·검증](../qa/reports/ammo_card_cleanup_2026-10-09.md).

**현행 정보 배치:** 체력 바 위 왼쪽은 HP, 위 오른쪽 끝은 약점·장갑·상태 아이콘이다. 전기 약점을 우선하고 오른쪽 정렬로 확장하되 HP 숫자 공간이 부족하면 추가 상태를 위쪽 줄에 배치한다. HP26px·기호21px와 박스 없는 표현은 유지한다. 거리20px는 발밑 같은 지면 기준 높이에 둔다. 아래 과거 배치보다 이 기준이 우선한다. [현재 화면](../qa/reports/enemy_hud_2026-10-09_assets/upper_idle_1008.png).

**현행 몬스터 정보 위계:** A/B/C/D는 제거했다. HP 숫자와 거리를 같은 줄에 크게 표시하고 아래에 현재 체력 바, 그 아래 큰 상태 아이콘을 배치한다. 전기 약점은 번개+`약점`, 장갑/화상은 기호+수치. 탄창의 식별 문자 대신 피해량을 표시하며 터치/호버 표적 강조로 연결한다. 상세·사격 문구는 이름 사용. 아래 식별 문자 강조 방식보다 이 기준이 우선한다. [현재 화면](../qa/reports/enemy_hud_2026-10-09_assets/readable_idle_1008.png).

**현행 몬스터 HUD의 면 처리:** 사각형 배경과 프레임은 사용자의 후속 피드백으로 제거했다. 문자·체력 바·거리·기호만 배우 위에 표시하며 읽기 대비는 글자의 좁은 외곽선/그림자와 아이콘 그림자로 보완한다. 터치 영역은 눈에 보이는 박스와 분리한다. 아래 초기 설명의 투명한 면보다 이 결정이 우선한다. [현재 실제 화면](../qa/reports/enemy_hud_2026-10-09_assets/open_idle_1008.png).

**최신 몬스터 HUD:** 사용자 요청에 따라 머리 위 현재 HP/거리/식별 문자와 상태 아이콘으로 정리했다. 예상 HP와 손실 색상, 상시 접근 문구, 발밑 중복 식별 표시는 제거했다. 장갑·전기 약점·화상·특수 행동은 도트 형태+필요 수치, 의미는 터치 상세에서 확인한다. 최대160px 폭으로 실제 배우의 머리 위에 배치하며 현재 체력만 실제 행동 후 갱신한다. [화면과 검증](../qa/reports/enemy_hud_2026-10-09.md).

**최신 전투 배분:** 사용자 요청에 따라 전장 높이를 확대하고 탄환 선택 영역을 압축했다. 작은 가로 화면의 전장240→280, 기본 탄환 패널256→232, 카드154→140 논리 px. 실제 조작부 높이에 따라 전장 가용 높이를 조절하며 주인공 크기는 기존과 분리해 유지한다. 탄환의 형태·글자 크기는 보존하고 밝은 전체 테두리를 청회색 프레임과 국소 속성 표시로 정리했다. 제작자 화풍 검토상 적합하며 사용자 선호/실기기 확인은 후속이다. [화면과 검증](../qa/reports/combat_layout_2026-10-09.md).

**아트 제작 절차:** [도트 제작 기준](pixel-production.md)의 용도별 승인 원본과 실제 화면을 첫 입력부터 사용한다. 캐릭터·배경·지도 기호의 표현을 구분하고, 화풍이 맞지 않는 후보는 전달 전에 내부 수정한다. 기술 검사와 화풍 검수/사람의 체감은 따로 기록한다.

**사용자 채택·본편 적용 — 탑 탐사도:** 중앙은 기호와 연결선을 읽는 지도 면, 가장자리는 탑 배경으로 구분한다. 역할 표식8종과 상단 범례를 공통 사용하며, 현재 선택 가능 장소는 높은 대비, 이후 경로는 낮은 대비의 점선, 방문 경로는 실선으로 나눈다. [실제 화면·검증](../qa/reports/map_chart_adoption_2026-10-09.md).

지도는 헤더/하단 조작을 제외한 가용 높이를 채운다. 개별 기호에는 상시 박스를 두지 않고 선택 모서리·현재 점·방문 체크·위험 `+`만 표시한다. 하단 장소명/이동과 선택형 상세, 전체 터치 영역을 유지한다.

5구역은 청회색·갈색·녹색·청색·보랏빛 지도 바탕/가장자리 배경 색조로 구분한다. 동일 승강 통로 배경을 사용하며 전용 지역 환경 아트는 후속이다. 선택 표식의 짧은 밝기 반응과 이동 확정 선은 입력/저장을 지연시키지 않는다. 즉시 연출 설정에서는 모두 생략한다.

시설 미니어처 v1/v2는 이전 제작 이력으로 보존한다. 이후 지도 아이콘의 현행 기준은 사용자 채택 탐사도 기호이며 미니어처 표현을 되살리지 않는다.

## 확정 방향과 참고작

최신 전투 샘플: 추가 후보 비교 후 C의 긴 외투+B의 방한모 조합을 선택했다. 제작한 주거구 배경·기존 탄환 카드와 [실제 Godot 샘플](../qa/reports/tower_art_sample_2026-10-03.md)을 만들었다. 4개 비율·실제 확정/발사 검수 완료. 적은 기존 임시 자산이고 정식 캠페인 교체/배우 애니메이션은 후속이다. 아래 초기 헬멧 채택은 이전 결정 이력으로 읽는다.

2026-10-03 최신 사용자 결정: **탄환 카드 디자인을 유지하고, 새 도트풍과 정비용 헬멧 주인공을 채택한다.** 기존 게임 안의 캐릭터·적·배경은 임시 자산이며 [새 시작 외형](../art/concepts/2026-10-03-pixel-reference/character-reference-v2-helmet.png)으로 교체할 제작 기준이 마련됐다. 추후 복장·헬멧 획득/교체를 위해 [분리 제작과 후속 흐름](appearance.md)을 따른다. 컨셉 채택을 실제 게임 적용 완료로 취급하지 않는다.

배우·환경 아트의 재개 선행 작업: (1) 플레이어의 정체·목적·적대 관계 등 세계관 핵심 정리, (2) 캐릭터 비율/복장·적 형태·공간/색감별 레퍼런스 수집과 비교, (3) 캐릭터·적·배경을 함께 배치한 소수의 통합 시안 비교. 산업도시·기계형 적은 디렉터의 임시 해석이며 사용자 확정 세계관으로 취급하지 않는다.

현재 [세계관 기준](worldbuilding.md) v0.3의 큰 방향을 사용자가 채택했다. 정서는 **위험한 탐험 + 사람 사는 온기 + 은근한 디스토피아적 어두움**이다. 풀려난 생물과 상점별 생존자의 생활 흔적을 아트에 연결한다. 주전자 옆의 배급 중단 통지, 판매대 뒤의 임시 잠자리처럼 온기와 결핍을 한 공간에서 보여 주는 안을 제안한다. 개별 인물·공간·엔딩 연출은 제작안이다. 사용자 제공 캐릭터/배경 10장으로 [레퍼런스 보드](../art/references/2026-10-03-user/reference-board.html)를 구성하고 [도트 제작 방향](pixel-style.md)을 재정립했다. 새 배우·배경의 통합 시안은 아직 제작하지 않았고 기존 게임 자산은 여전히 임시 적용이다.

간접 서사는 아이템·쪽지·환경 흔적으로 전달한다. 탄환/파츠 카드에는 기능 정보가 먼저 보이고 상세의 `물건의 흔적`을 선택해 읽는 안을 사용한다. 기록은 획득 때 전투를 막지 않고 보관함에서 다시 읽게 한다. 인물 대사는 거래 진입을 막지 않는다. [노출 위치와 원고 기준](narrative-delivery.md)은 설계 상태이며 현재 UI에 이미 적용된 동작으로 취급하지 않는다.

## 시각 언어

캐릭터·적·바닥·배경·아이콘·버튼에 공통 픽셀 밀도와 명암 단계를 적용한다. UI는 도트 금속 프레임, 명확한 모서리와 눌림 상태, 제한된 강조색으로 구성한다. 원경의 세부와 대비는 전투 대상보다 약하게 유지한다. 스캔라인·격자·발광 테두리를 모든 영역에 반복하지 않는다.

- 바탕 `#101820`, 패널 `#1a2833`, 밝은 글자 `#f2eee3`, 보조 글자 `#acbbc1`.
- 행동·선택 `#edc47a`, 위험 `#ee8777`, 전기 `#78c9ed`, 화염 `#ef9967`.
- 상태는 색 외에 형태·문구·위치로 구별한다. 전기와 압축, 선택과 피해 예측이 같은 의미처럼 보이지 않게 한다.
- 제목·수치·버튼은 판독 가능한 픽셀 글꼴을 우선 검토한다. 한글 설명은 충분한 글자 크기·자간·대비를 먼저 확보한다. 필요할 때 선명한 한글 본문 글꼴을 함께 비교하며, 낮은 해상도로 모든 텍스트를 일괄 축소하지 않는다. 현행 Noto Sans KR은 전환 중 유지 자산이며 최종 글꼴 확정은 아니다.
- 버튼은 '전/규/설/메'로 줄이지 않는다. 작은 보조 기능은 메뉴로 합치거나 이해되는 짧은 이름을 쓴다.

## 공간과 픽셀 기준

- 실제 전투 바닥을 원경 이미지와 분리해 구성한다. 배경의 화면 채우기 크롭에 따라 배우의 발이 바닥에서 떨어져 보이지 않아야 한다.
- 발 위치를 배치 기준으로 삼고 접지 그림자·캐릭터 크기·시점·광원을 맞춘다. 부유형 적은 지면 그림자와 부유 동작으로 의도를 전달한다.
- 접근 거리는 가로 위치와 연결한다. 다수 적의 얕은 깊이 배치는 식별을 위한 표현이며 새로운 다중 레인 규칙이 아니다. 증원·이동 때 기존 적의 전열을 재정렬하지 않는다.
- 캐릭터와 적은 동일한 픽셀 밀도·외곽선·명암으로 제작한다. 탄환과 파츠도 같은 계열의 픽셀 물건으로 읽혀야 한다.
- 월드의 기준 해상도와 UI의 읽기 크기를 구분해 검토한다. 텍스처 보간·정수 배율·좌표 정렬은 실제 출력에서 흐림과 픽셀 두께 변동이 없도록 설정한다. 특정 해상도를 영구 규칙으로 확정하지 않는다. [Godot 다중 해상도 기준](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)

## 전투 와이어프레임

```text
층/무기/현재 턴                                      전투 정보 · 메뉴
┌──────────────────────────────────────────────────────────────┐
│                        전장                                  │
│ 회수자  ← 접근 거리 / 고정 전열 / 적의 HP·장갑·핵심 상태       │
│             선택한 탄창의 피해 변화와 처치 표시                 │
└──────────────────────────────────────────────────────────────┘
발사 순서  [1 탄] → [2 탄] → [3 탄] → [4 탄]    [확정 / 발사]
예상 결과                                       [회수/재장전]
손패      [회수탄] [전술탄] [전술탄] [전술탄] [전술탄] [전술탄]
예비 탄환 / 압축과 교환 도구        선택 상세는 별도 창
```

이 와이어프레임은 동선 기준이며 현재 패널 높이를 고정하지 않는다. 전장·발사 순서·손패가 전체 폭을 공유한다. 빈 장전 레일의 높이를 줄이고 손패 6장의 그림·수치와 전장의 바닥에 공간을 배분한다. 낮은 높이에서는 정보의 노출 단계를 바꾸며 모든 글자를 함께 줄이지 않는다. 비정상적으로 좁은 창은 필요한 곳의 스크롤을 허용한다.

## 정보 공개

적: 큰 HP와 장갑, 접근 시간/거리, 전술적으로 중요한 상태. 이동량·정확한 조건은 상세로 이어진다.

탄환: 큰 물건 실루엣과 이름 → 직접 피해·관통 → 고유 효과 한 줄. 피해를 명중처럼 보이는 조준점으로 표현하지 않는다. 고유 효과는 `매 턴 1 · 3턴`, `다음 2발 +2`처럼 짧은 문구와 수치를 결합한다. 이는 표기 예시이며 수치 원본을 바꾸는 지시가 아니다. `2×2`와 `×2` 같은 타격 횟수의 중복을 없앤다. 장전 결과는 선택한 탄·적의 변화·레일에 연결하고 모든 카드에 작은 결과 문장을 반복하지 않는다.

파츠: 실루엣과 이름, 핵심 이득, 대가. 장착 전후 비교는 선택한 한 부품에 집중한다.

각 화면의 주 행동은 한 곳이다. 툴팁만 있어야 이해되는 기능은 터치 상세도 제공한다. 선택·잠금·부족·위험·사용 완료 상태를 구분한다.

현재 조작 기준: 전장의 기본 예측은 다음 발사 1회이며 여러 턴에 걸친 전체 탄창 결과는 범위를 명시해 전환한다. 장전한 탄은 손패의 같은 자리에 사용 상태로 남긴다. 슬롯 탭은 선택, 이동·회수는 명시적 행동이며 확정 전 순서 이동은 드래그도 지원한다. 계산 상세로 전체 화면의 높이를 늘리지 않는다. 장전 확정의 변경 비용은 버튼 곁에 노출한다. 파츠 교체는 얻는 규칙과 잃는 규칙, 새 대가와 해제되는 대가를 함께 비교한다. ## 제작 방식

### 현재 비전투 UI

- 메인: 왼쪽은 게임 이름과 실제 탄환 카드 조합, 오른쪽은 이어하기/새 등반과 훈련. 미확정 캐릭터 원화를 화면의 주인공으로 고정하지 않는다. 기록·규칙·설정은 보조 영역으로 분리한다.
- 출격 준비: 다섯 무기 전체 카드가 선택 영역이다. 선택한 무기의 고유 규칙·탄창·재장전과 실제 무기별 시작 보급을 보여 준다. 시작 탄환은 전체 영역을 눌러 효과를 확인한다. 난도 입력과 시드는 등반 설정에 접으며 현재 난도와 출격 버튼은 기본 화면에 남긴다.
- 상점: 세 상품과 고정 비교 영역을 나란히 배치한다. 상품은 선택과 가격/재고 표시, 비교 영역은 구매를 담당한다. 선택해도 높이와 스크롤이 갑자기 바뀌지 않는다. 파츠 카드에 이득·대가를 보여 주고 비교 영역에서 장착/보관 위치와 구매 결과를 확인한다.
- 파츠: 장착 5칸·보관함·선택 상세를 함께 보여 준다. 보관함만 내부 스크롤하며 끝의 파츠도 선택 가능하다. 슬롯이나 코어 제한에 걸리면 유효한 교체 후보를 고르고, 탄창·재장전 변화 확인 후 한 번에 교체한다. 전투 중에는 열람만 가능하며 분해에는 게임 안의 확인 절차가 있다.
- 파츠 실루엣은 엔진 픽셀 도형으로 구별하며 승인된 탄환 카드와 각진 프레임을 공유한다. 탄환 카드 디자인과 배우·환경 자산은 이번 범위에서 변경하지 않았다.

[실제 화면과 검사](../qa/reports/navigation_ui_2026-10-03.md). 화면·입력 검사를 사람의 이해도 확정으로 해석하지 않는다.

먼저 첫 지역의 통합 전투 화면을 제작한다. 적 4마리, 손패 6장, 발사 순서, HUD를 함께 검토해 공통 팔레트·픽셀 밀도·시점·그림 크기를 정하고 나머지 화면으로 확장한다. 에셋 단독 미리보기로 화풍의 통일을 판정하지 않는다.

생성 도구는 컨셉과 스프라이트 후보 제작에 활용한다. 생성 결과는 픽셀 밀도·팔레트·투명 경계·발 기준점·프레임 일관성을 검수한다. 활자·수치·슬롯·버튼의 동작은 엔진에서 구성한다. 코드로 그리는 공통 아이콘도 최종 출력의 도트 규칙을 따른다. 적은 장갑판·충전 코어·다리·흡수 셀처럼 역할을 전달하는 형태를 가진다. 원본을 지우지 않고 교체 자산은 새 이름으로 저장한다.

[자산 목록](art-assets.md)에 파일·용도·도구·프롬프트·적용 상태를 남긴다. 원화 완성과 스프라이트/애니메이션 적용을 구분한다.

## 세계관을 연결하는 UI 제작 기준

사용자는 외부 디자인 스킬 검토 후 활용 가능한 원칙의 반영을 승인했다. 아래 원칙을 기존 Godot·도트 작업에 적용하며, 구체적인 새 화면의 미감은 실제 플레이 검수로 판단한다.

- 작업 전에 현재 화면을 실행해 행동의 순서, 첫 화면에서 보이는 버튼, 선택 전후의 변화를 확인한다. 독립된 카드만이 아니라 같은 해상도의 전체 화면을 전후 비교한다.
- 재질과 장식은 게임의 물건·사용 방식에서 정한다. 탄약 받침, 파츠 장착대, 정비한 성능표는 현재 구현의 예다. 모든 화면에 같은 비유나 장식을 강제하지 않는다.
- 핵심 성능, 비용·패널티, 행동 결과를 분리한다. 상점은 구매 후 장착/보관/탄환 교체를, 파츠는 들어오는 효과와 빠지는 효과 및 실제 성능 변화를 보여 준다. 긴 규칙은 상세에서 열어 본다.
- 비교 대상은 같은 크기와 같은 정보 위치를 유지한다. 웹 포트폴리오식 비대칭, 유행 글꼴, 장식용 통계, 무작위 질감, 강한 CRT 효과를 기본값으로 채택하지 않는다. 도트풍은 프레임·활자·수치·조작 상태가 함께 맞아야 한다.
- 색은 선택, 실행, 비용, 발열/냉각 등의 기능을 따른다. 문구·아이콘·형태를 함께 사용하며 한 가지 강조색으로 모든 의미를 합치지 않는다.
- 작은 화면과 긴 화면에서 기본/선택/보유/품절/재화 부족/교체/빈 보관함/전투 중 열람/포커스 상태를 확인한다. 자동 기능 통과와 디렉터 시각 검토, 사람의 직관성·미감 확인은 별개다.

[사용자 제공 글](https://leevigong.tistory.com/50)과 [taste-skill 공식 저장소](https://github.com/Leonxlnx/taste-skill)에서 게임에 맞는 검토 관점을 선별한 기준이다. 외부 스킬 전체를 설치하거나 별도의 기획 원본을 만들지 않는다. 기존 Impeccable의 검토 절차와 Godot의 씬·입력·실제 렌더 검증을 계속 사용한다.

## 통과 기준

### 2026-10-03 첫 통합 화면의 구현

- 새 자산은 `assets/art/pixel_20261003/`에 저장했다. 원본 80×80 회수자, 64×64 적, 512×192 배경을 다시 그리거나 리샘플링하지 않고 투명 여백만 잘랐다. 팔레트는 자산별 18~63색, 스프라이트 알파는 0/255다. 실제 발의 아래쪽 픽셀에서 기준점을 계산하고 `.tres`로 보존했다.
- 월드 텍스처는 nearest, 배우는 원본의 2배로 그린다. 바닥은 배경 크롭과 무관한 별도 픽셀 금속판이다. 부유형은 바닥 그림자와 18px 높이 차로 구별한다. 화면 전체의 한글은 읽기 크기를 유지하며 Noto Sans KR을 계속 사용한다.
- 같은 거리에 모인 네 적을 구분하기 위해 고정 전열별 가로 간격 96px와 얕은 깊이 12px를 둔다. 거리 감소는 각 적을 왼쪽으로 이동시키며 정확한 거리는 명찰로 표시한다. 이는 배치 오프셋이며 실제 표적·거리 계산이나 다중 레인 규칙을 추가하지 않는다. 사망·증원으로 생존 적을 재정렬하지 않는다.
- 명찰은 적의 가로 위치에 따라 배치하고 이웃끼리 겹치지 않도록 밀어낸다. HP/예상 HP·거리/접근·장갑/상태를 구분한다. 산개의 HP는 범위로 표시한다. 터치 상세를 유지한다.
- 손패는 큰 탄종 실루엣·피해·유효 관통·효과 한 줄이다. 모든 카드의 결과 문장을 없애고 예측을 발사 순서와 전장에 모았다. 연발의 배수 중복을 없앴다. 압축의 두 칸/첫 발/끝 발 표시는 유지한다.
- 현재 전투 전체는 첫 공업 지대 배경을 공유한다. 지역별 도트 환경, 지도와 배우 최종 아트, 전용 보행/대기 프레임은 아직 후속 제작이다. 메인·무기 선택·상점·파츠의 후속 UI 개편은 위의 현재 비전투 UI 항목에 반영했다. 전체 아트 완료 상태는 아니다.
- 실제 렌더 1280×800, 1008×630, 1440×630에서 기본/장전/발사와 네 적 밀집을 검토했다. 자세한 증거와 한계는 [작업 기록](../history/daily/2026-10-03.md)에 남긴다.

- 실제 렌더에서 적·탄환·주 행동의 시선 순서가 구분된다.
- 캐릭터·적이 같은 바닥과 공간에 속해 보이며 증원·이동·피격 전후에도 발 위치와 그림자가 어긋나지 않는다.
- 모든 화면에서 픽셀 밀도·외곽선·프레임·아이콘의 제작 규칙이 일관된다. 화면 전체의 픽셀 필터를 검수의 대체물로 사용하지 않는다.
- 1280×800, 1008×630과 갤럭시형 긴 가로 비율에서 핵심 조작과 정보가 겹치지 않는다.
- 위험·파츠 패널티·압축 비용을 작은 기호만 보고 추측할 필요가 없다.
- 손패 6개, 탄창 최대, 장갑/화상/배리어/증원, 산개 확률을 확인한다.
- 기능 자동 검사, 시각 검토, 실제 사람의 이해도는 각각 기록한다.


## 제목 검토와 메인 화면 설계안

2026-10-11 사용자 지시로 ORVASK 단일 제목을 채택하고 아래 구도를 실제 메인 화면에 구현했다. 화면의 개별 미감은 디렉터 제작안이며 사용자 확인 전이다. 명칭의 결정 원본은 [세계관의 최신 제목 검토](worldbuilding.md#최신-검토--추천-순서-실행-후-보정)다.

- 화면의 약속: 작은 정비소에서 거대한 탑으로 올라가 동네의 공급을 되살리는 탄환 기술자. 기존 도트풍의 큰 색면과 탁한 청회색/작은 주황빛을 유지한다.
- 구도: 가로 화면 중앙~오른쪽에는 화면 밖까지 솟은 탑 하부와 승강 구조, 아래에는 승인 주인공과 열린 정비소. 왼쪽은 어두운 여백 위 제목·주 행동 영역. 탑을 작게 전경에 모두 보여 주기보다 가장자리와 상단을 잘라 규모를 전달한다. 지하로 내려가는 입구나 왕좌는 두지 않는다.
- 로고 설계: `ORVASK` 단일 영문 로고와 작은 한글 이름. 굵은 픽셀 획과 적은 절개, 밝은 낡은 강철색. 작은 따뜻한 틈새빛만 허용하며 획을 관/총알 장식으로 잘게 부수지 않는다. 정상부를 왕관이라 부르는 설정은 아직 채택하지 않는다.
- 메뉴 위계: 유효한 진행 저장이 있으면 `등반 계속`을 주 행동, 없으면 `새 등반`을 주 행동으로 둔다. `새 등반`과 `설정`을 근처에 두고 훈련·기록실·안내·개발은 보조 영역에 묶는다. 새 등반의 기존 저장 보호/확인 흐름 유지. 기존 기능을 폐기하는 설계가 아니다.
- 정보량: 저장이 있으면 현재 구역 한 줄만 주 행동 옆에 표시. 처음 화면에는 무기/탄환 도감이나 긴 규칙 설명을 펼치지 않는다. 카피 후보는 `돌아갈 곳의 불을 켜기 위해.` 한 줄.
- 게임 규칙의 시각 단서: 정비대의 탄환 몇 발과 식어가는 총열, 증기가 흐르는 생활 배관. 발열/냉각/탄환이라는 연결을 암시하되 가짜 조작 버튼이나 의미 없는 계기 수치를 추가하지 않는다.
- 미세 동작: 느린 배관 증기와 희미한 정비소 불빛, 소규모 배경 움직임. 버튼 영역을 가로지르지 않고 즉시/축소 연출 옵션에 반응한다.
- 후속 구현 검수: 현재 1008×630 등 가로 모바일 화면에서 제목 글자와 버튼을 먼저 확인. 이어하기/새 등반/무기 선택/설정 왕복, 저장 보호, 터치 영역, 포커스와 뒤로 이동을 실제 Godot에서 검사한다. 웹 레이아웃 검증으로 대체하지 않는다.


### ORVASK 타이틀 본편 구현

- `redesign/title_screen.tscn`에 배경·승인 주인공·로고·주 행동/하단 보조 메뉴를 직렬화했다. `main.tscn`도 에디터에서 같은 장면을 미리 보여 준다. 런타임은 저장과 콜백을 바인딩한다.
- 새 배경은 기존 주거구 원화를 참조해 built-in image_gen으로 제작. 로고/아이콘은 직접 작성한 격자 SVG, 버튼은 기존 공통 도트 스킨. [원본 프롬프트·출처](../art/title-20261011.json).
- 메뉴 뒤 어두운 큰 면, 오른쪽 열린 정비소와 거대한 승강축. 승인 주인공은 같은 배경 프레임 안에서 발 위치를 유지해 긴 화면 크롭에도 떠오르지 않는다. 따뜻한 조명에만 ±1.8%의 느린 밝기 변화, 즉시 연출에서는 정지.
- 유효한 진행이 있으면 등반 계속을 기본 포커스/강조, 없으면 새 등반을 강조. 현재 구역/무기 한 줄 외에는 수치나 탄환 카드가 없다. 기초 훈련·기록실·조작 안내·규칙·개발과 별도 훈련 저장 복구를 유지한다.
- 기본1280×800, 작은1008×630, 긴1440×630 및110% 글자 확인. 진행 저장/마지막 복구 직전 저장 교체는 확인 후 실행한다. [검증](../qa/reports/title_2026-10-11.md).
