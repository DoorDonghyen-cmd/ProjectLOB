# UI 라인 + 도트 테마 — 본편 적용 기준

**정비소 현행 — 작업 장면/탭(2026-11-04):** 사용자가 가장 좋다고 평가한 시안을 본편에 연결했다. `redesign/workbench/screen.tscn`·`theme.tres`가 이 장소의 구성/외형 원본이며 기존2열·청록 중심 정비소는 대체한다. [화면·실제 기능/저장·검증](../qa/reports/workbench_live_2026-11-04.md). 기존 글꼴/터치/배율 원칙은 유지하며 다른 화면의 배치를 이번에 변경하지 않았다.

**정비소 역할 규격 후속 — 2026-11-04:** 기존 라인+도트와 배치를 유지하며 [UI 공통 규격 v1](ui-standards.md)을 정비소 기본 화면에 먼저 적용했다. 정비소의 글자·버튼·작업 면은 해당 규격과 [실제 전후/검증](../qa/reports/ui_standard_workshop_2026-11-04.md)을 따른다. 나머지 화면에는 일괄 적용하지 않았다.

2026-11-01 작성. Godot 본편 UI에 이 테마를 적용하는 작업자를 위한 기준과 인계 문서다.

**적용 완료:** 기존 Godot 전투 HUD → 메뉴/상세/보상/정비 → 지도/장소/상점 외형에 연결했다. 기본 진입·카드/버튼 배치·입력·전투 계산·저장은 유지한다. [실제 화면 비교·검사·비정수 배율 한계](../qa/reports/ui_line_godot_2026-11-01.md). 사람·Android 실기기 확인은 별도다.

**사용자 후기(2026-11-01):** 적용 결과에 “좋은 거 같아”라고 평가하고 다음 연속 플레이 점검 진행을 승인했다. 현재 외형을 유지한다. 이 평가는 연속 전투의 재미·모바일 선명도/성능 확인을 뜻하지 않는다.

## 결정 상태

**최신 — PC·Galaxy S26 기준 공통 가독성 수정(2026-11-03):** 사용자 실행 승인으로 상점 전체 Canvas 축소와 비전투 viewport 축소를 제거하고 native/정수 배율·최소16px 글자·반응형/세로 스크롤을 연결했다. 지도·장소·작업실·장비/설정·보상/관문을 함께 수정하고 미지원 기호를 자체 도트 보조 글꼴로 동봉했다. 작은 상세 창의 닫기 버튼은 고정한다. 기존 라이브 전투 HUD 크기와 전투/저장 규칙은 유지한다. S26 기본형2340×1080 및 감소 가용 영역을 PC에서 렌더/입력 검사했다. [화면·검사·남은 범위](../qa/reports/ui_readability_2026-11-03.md). Android 실기기·OS 배율/안전 영역·사람 체감은 미검증이다. 아래 과거 작은 상점 글자/비전투 축소 상태는 이 구현으로 대체한다.

**2026-11-01 배관도 그래픽 후속:** 사용자 승인으로 지도 기호·구역 문양·관문 손잡이를 실제 표시 크기의 도트 그림으로 교체했다. 지도 바탕만 반복 디더를 제거하고 낮은 대비 격자로 정리했다. 공통 테마·버튼·글꼴·기존 지도 배치는 유지한다. 따라서 지도 기호와 바탕은 초기 HTML 재사용 상태보다 이 [후속 결과](../qa/reports/pipe_map_art_2026-11-01.md)를 우선한다.

**2026-11-01 배관도 지도 통합:** 사용자가 개편한 지도 목업을 검토한 뒤 연속 실행을 승인했다. 지도는 이 문서의 초기 배치 유지 범위에서 별도로 개편하여 구역 진행표·고정 관문·스크롤 지도·오른쪽 선택 패널로 구성한다. HTML 배관도 기호와 기존 라인 테마를 재사용하고 실제 5구역/샛길·이전 저장에 연결했다. 전투 HUD·장소/상점 배치와 게임 규칙은 유지한다. [현행 지도 기준](route-map.md#사용자-채택--배관도-지도-본편-통합2026-11-01) · [화면·검증](../qa/reports/pipe_map_godot_2026-11-01.md).

**2026-11-01 HP 겹침 배치 보정:** 사용자 지적과 실행 승인에 따라 이전의 수평 밀기 중심 배치를 교체했다. 공간이 충분하면 몬스터 머리 위x를 유지하고, 카드/보스 안내가 겹치면 위로 쌓아 연결선으로 잇는다. 낮은 전장/수용 공간 부족 시 한 줄 전환한다. 카드와 터치 영역은 동일하게 갱신하고, 고정 우선순위·분리 여유·연출 중 높이 유지로 흔들림을 줄였다. [목업/본편·전후 화면과 검증](../qa/reports/hp_stack_2026-11-01.md). 아래 캐릭터·HP 보정의 수평 배치 유지 결정은 이 보정으로 대체한다.

**2026-11-01 캐릭터·HP 보정:** 사용자 크기 피드백으로 본편/공통 HUD의 플레이어를 HTML 기준 약96px(1280px 너비 기준)로 축소했다. HP16px·작은 상태 아이콘·분할 게이지·겹침 번호를5구역에 공통 적용했다. 일반 체력창128px/보스180px, 상세 터치 높이 최소44px. 이는 사용자 세부 미감 확인 전 구현이며 [전후 화면·회귀 결과](../qa/reports/actor_hp_2026-11-01.md)를 따른다. 전투 계산·저장·하단 카드/버튼 배치는 유지한다.

- HTML: `OPEN_UI_PROTOTYPE.cmd` → `http://127.0.0.1:8765/index.html#tab=elite&theme=line`. 탭으로 상점·보상·지도·탄 상세·메뉴를 본다.
- 비교·확대 이미지: [보고서](../qa/reports/ui_line_theme_2026-11-01.md). 특히 `pixel_zoom_3x.png`(도트 크기)와 `pixel_frames_8x.png`(틀 15종).
- 원본 코드: `docs/qa/reports/ui_prototype_2026-10-31/assets/theme_line.css`. 값이 이 문서와 다르면 CSS가 정답이다.

## 적용 범위

- **외형만 바꾼다.** 진행 중인 Godot HUD(`redesign/samples/hud/` — `combat_hud_theme.tres`, `combat_hud.tscn`, `combat_journey_hud.tscn`, 메뉴·상세·보상 씬)의 배치, 카드 크기(76×96), 입력 높이(44/50), 스크롤, 명령 연결, 전투 계산, 저장 형식은 그대로 둔다.
- 대상: 전투 HUD → 공통 창(메뉴·상세·보상·정비) → 지도·장소·상점 순서.
- 적·탄환 그림의 도트 크기 정리는 이 작업이 아니다(별도 아트 작업).
- 기본 진입 교체, APK, 커밋은 사용자 요청이 있을 때만 한다.

## 1. 틀(9분할 도트 그림)

`tools/build_line_theme_assets.py`가 그린다. 도트 하나가 논리 2×2로 보여야 한다. Godot `StyleBoxTexture`는 그림을 원래 크기로 그리므로 **2배 판을 만든다.**

```
python tools/build_line_theme_assets.py --scale 2 --out 새-게임-프로젝트/assets/ui/line_theme_20261101
```

- `StyleBoxTexture`: `texture_margin` 4방향 = **12**(큰 틀) / **8**(작은 틀: heat·chip·tag 계열), `axis_stretch_horizontal/vertical = TILE`(디더 무늬 보존), `draw_center = true`.
- 해당 Control(또는 상위)의 `texture_filter = NEAREST`.
- 안쪽 여백(content margin): 버튼 좌우 12, 카드 8·8·6·12(위·오른·아래·왼), 창 22·26, 패널 14·16. 강철 틀의 왼쪽 걸쇠용 넓은 여백은 없앤다.

| 틀 | 크기 | 쓰는 곳 |
| --- | --- | --- |
| `panel` | 큰 | 창·패널·상세·메뉴·장면 위 설명 |
| `standby` | 큰 | 선택 안 된 카드·선택지·상품 |
| `active` | 큰 | 선택한 것, 이번에 발사할 탄(왼쪽 청록 띠) |
| `danger` | 큰 | 빼낼 탄 |
| `slate` | 큰 | 보조 버튼 |
| `cool` | 큰 | 냉각 |
| `reload` | 큰 | 탄창 교체 |
| `fire` | 큰 | **화면당 하나뿐인 주 행동**(사격·구매·이동·확보) |
| `disabled` | 큰 | 비활성 버튼(글자 `#56777a`) |
| `heat` | 작은 | 발열 게이지 틀 |

## 3. 글자

- 현행 비전투 UI: NeoDunggeunmoPro의 원형은16단위다. 본문·버튼·작은 설명은 최소 **16**, 큰 제목/수치는 **32** 등16단위로 정리한다. 창 전체를 줄여 맞추지 않고 줄바꿈·재배치·세로 스크롤을 쓴다. `ui_readability.gd`가 native 크기와 정수 확대를 관리한다. 기존 라이브 전투 HUD의16/24/32 등 개별 크기는 이번 수정에서 유지했으므로 전투24px까지 도트가 균일하다고 간주하지 않는다. 과거12·24px을 동일하게 선명한 단계로 적은 설명은 폐기한다.
- 공통 `combat_pixel_font.tres`에 프로젝트 자체 `ORVASKPixelSymbols.ttf`를 명시적 fallback으로 연결한다. →←↔−‹›⌁↑↓…를 시스템 대체 글꼴에 맡기지 않는다.
- 제목·큰 숫자·적 HP 숫자: 그림자 `#01080a`, 오프셋 (0, 2), 흐림 없음.
- 글꼴 가져오기의 안티앨리어싱·서브픽셀 설정이 선명도를 해치면 끈다(실제 캡처로 판단).

## 4. 칸·점선·지도

- 발열 게이지: 열 한계 수만큼 칸으로 나눈다(칸 사이 2). 예상 열은 금색 반투명 칸.
- 적 HP 막대: 높이 4, 칸 4 + 틈 2. 남은 HP는 강조색, 예상 피해는 금색.
- 상단바 아래·하단 독 위: 2 두께 점선(선 4, 틈 4, `#2c7a80`). 목록 행 구분: 2 두께 점선(선 2, 틈 2, `#1d4f56`). 행에 상자를 두르지 않는다.
- 지도 경로선: 안티앨리어싱 끔(계단형 도트 선). 노드 표시: 선택 = 청록 면 + 2 선, 갈 수 있음 = 금색 2 선, 현재 = 흰 점선.

## 5. 선명도 주의

도트가 고르게 보이려면 화면의 논리 배율이 정수여야 유리하다(현재 HUD는 2016×908에서 2배). 정수가 아닌 기기에서 틀 도트 크기가 들쭉날쭉한지 캡처로 확인하고 결과를 기록한다. 특정 해상도를 영구 규칙으로 만들지는 않는다.

## 6. 검증

- 격리 저장(`qa_runtime/...` 아래 별도 APPDATA/LOCALAPPDATA)에서만 실행한다. 기존 `tools/run_prototype_hud.ps1`의 ui·flow·visual·direct·scroll 검사가 계속 통과해야 한다(외형만 바뀌므로 수치·흐름은 동일).
- 740×360, 844×390, 1008×454, 1280×800에서 Godot 캡처를 HTML(`#theme=line`) 같은 크기 캡처와 나란히 놓고 비교한다.
- 3배 확대로 확인: 틀 도트 하나 = 논리 2×2, 번진 틀 경계 없음, 비전투 글자는 최소16/32단계, 라이브 HUD의 개별 크기는 별도 확인, 채운 주 행동은 화면당 하나.
- 기능 통과, 시각 확인, 사람의 이해도를 따로 기록한다. 결과는 `docs/qa/reports/`, 작업 기록은 `docs/history/daily/`.
