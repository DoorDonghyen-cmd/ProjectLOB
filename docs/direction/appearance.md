# 주인공 시작 외형과 복장·헬멧 수집

**최신 가방 성장:** [현행 기준](outfit-bag.md)은 기본 작업복5장→정비/관문 투자→최대10장이다. 운반6/정찰4의 시작 차이를 유지한다. 직전6/7/5 구성은 이전 저장 호환용이다.

**2026-10-09 적용:** [복장·가방3종](outfit-bag.md)의 출격 선택/효과/저장을 구현했다. 작업복6장/1회, 운반복7장/0회, 정찰복5장/2회. 그림과 효과를 분리하며 UI에는 도트 복장 기호를 사용한다. 실제 복장별 캐릭터 동작 아트/획득/헬멧 교체는 아직 후속이다. 아래 초기 설계의 ‘능력치 미정/복장 데이터 없음’보다 이 상태가 우선한다.

2026-10-03 · 후속 기능 설계. 현재 게임에 획득·교체·저장을 구현한 문서가 아니다.

## 결정 상태

- **사용자 확정:** 초기 헬멧 캐릭터 채택 후 추가 후보 비교를 거쳐 [C 복장+B 방한모](../art/concepts/2026-10-03-character-variants/character-c-expedition-cap-v2.png)를 선택했다. 이 외형과 제작한 배경으로 전투 샘플을 요청했고 [실제 샘플](../qa/reports/tower_art_sample_2026-10-03.md)에 적용했다. 이후 인게임에서 복장과 헬멧을 획득하고 교체할 수 있는 구조를 원한다.
- **디렉터 설계:** 복장 1칸과 헬멧 1칸을 독립적으로 선택한다. 시작 복장과 정비용 헬멧은 기본 보유다. 획득한 외형은 프로필에 남겨 다음 등반에서도 사용할 수 있게 한다. 무기·파츠의 슬롯은 소모하지 않는다.
- **아직 미정:** 외형의 능력치 효과, 획득 조건·가격·종류 수. 첫 도입은 외형 수집 중심으로 설계하되 능력치가 영구 성장인지 런 중 선택인지까지 확정한 것으로 해석하지 않는다.
- **구현 상태:** 선택 외형을 별도 전투 샘플에 적용했다. 기본 캠페인은 이전 임시 캐릭터를 표시하며 복장/헬멧 데이터·획득·교체 UI가 없다. 분리 레이어/프레임 애니메이션 제작과 정식 적용, 수집 기능은 후속 범위다.

## 획득과 교체 흐름

첫 획득 후보는 지역 탐험·생존자 이야기·도전 달성이다. 해당 지역에서 사용하던 작업복과 보호구라는 맥락으로 아이템의 흔적을 연결한다. 첫 버전에서 탄환·파츠의 필수 보상 선택을 외형 보상으로 밀어내지 않는다. 상점 판매와 가격은 기존 경제 영향을 따로 확인한 뒤 정한다.

획득 시 작은 알림으로 보관함에 추가하고 자동으로 갈아입히지 않는다. 출격 준비 또는 비전투 보관함의 ‘외형’에서 복장/헬멧 탭 → 실제 캐릭터 미리보기 → ‘착용’으로 이어진다. 미리보기와 저장된 착용 상태를 구별하고, 뒤로 가면 미확정 선택을 취소한다. 전투 중에는 열람만 허용하는 안이다. 잠금 아이템은 얻는 방법을 짧게 표시한다. 긴 설명·별도 수치표를 기본 화면에 늘리지 않는다.

기본 복장/헬멧은 항상 복귀 가능하다. 획득은 한 번만 처리하고 중복 지급이 진행도나 재화를 의도치 않게 바꾸지 않게 한다. 영구 수집과 별개로 실제 런의 저장/이어서 하기와 모순되지 않도록 설계한다.

## 아트와 구현을 위한 준비 기준

현재 `redesign/battle_view.gd`는 `Pixel.sprite(..., "reclaimer", ...)` 한 장을 그리고, 메인은 `title_backdrop.gd`에서 별도 `world_art.gd` 이미지를 사용한다. 주인공 아트를 교체할 때 두 화면이 같은 착용 상태를 보도록 공통 외형 조회 경로를 만든다. 현재 코드가 이미 이런 구조라고 간주하지 않는다.

- 데이터: 안정적인 복장 ID·헬멧 ID와 각 보유 목록, 착용 ID를 분리한다. 저장에는 파일 경로보다 ID를 기록한다. 기본값 후보는 `technician_coat`와 `maintenance_helmet`이다.
- 아트 원본: 몸/복장, 머리/머리카락, 헬멧, 무기를 편집 가능한 레이어로 분리한다. 헬멧에 가려질 머리카락 마스크와 총/팔의 앞뒤 순서를 함께 설계한다. 기존 컨셉 PNG를 그대로 겹쳐 붙이면 된다고 가정하지 않는다.
- 동작: 대기·조준·반동·재장전·피격의 같은 프레임 수/타이밍과 발·머리·손 기준점을 사용한다. 모든 조합을 별개 캐릭터로 다시 그리는 방식은 피한다. 런타임 레이어 합성과 미리 조합한 시트 중 실제 정합성/성능으로 결정한다.
- 표시: 메인·출격·전투·외형 미리보기에서 같은 장착 선택을 사용한다. 머리 장식이 적의 표식이나 전투 UI를 가리지 않도록 게임 크기로 확인한다.
- 저장: 현행 `campaign.gd`는 런·전투·프로필을 하나로 저장/검증한다. 후속 구현에서 외형 필드의 기본값과 마이그레이션을 함께 추가한다. 외형 ID 누락/삭제는 기본 외형으로 복원하며 기존 정상 런을 외형 문제만으로 버리지 않는다. 캠페인 시작 전 프로필 저장 경로도 마련한다.

## 제작 순서와 완료 기준

1. 채택된 기본 캐릭터를 실제 게임 크기의 분리 가능한 스프라이트로 제작하고 배경·적·카드와 통합 검수한다.
2. 시험용 헬멧 1종·복장 1종을 추가해 교차 조합과 전 동작의 틈/머리카락 노출/가림을 검수한다.
3. 획득 → 보관함 → 미리보기 → 착용 → 재시작 복원 → 다음 등반 흐름과 기존 저장 호환을 구현/검증한다.
4. 탐험·생존자 이야기에 획득 경로를 연결하고 종류를 확장한다. 능력치 효과는 별도 빌드 설계와 함께 검토한다.

수집 기능 때문에 기본 캐릭터의 첫 게임 적용을 늦추지 않는다. 기능 자동 검사, 실제 도트/애니메이션 검수, 사람이 교체 흐름을 이해하는지 확인하는 검증은 구별한다.

## 현행 구현 — 장소 레이어 및 복장 연결

- work/carrier/scout 복장 선택·가방 규칙·저장은 기존대로 유지한다.
- **분리 완료:** 상점/압축 작업대/보급소의 인물 없는 실내와 투명 기본 작업복 3자세를 독립 리소스로 표시. 인물 숨김/교체 시 배경을 다시 만들 필요가 없다.
- **연결 완료:** 실제 campaign.outfit → service_location.configure → service_actor_catalog의 복장/장소별 자세 조회. 신규 자세의 투명 PNG·소스 영역·발 기준점을 프로필 리소스에 등록하면 같은 장소에서 교체된다. 현재 표시는 기본 작업복이며, carrier/scout 그림이 없으면 work로 대체한다.
- **미제작:** 운반복·정찰복 장소 3자세, 복장별 전투 전 동작, 헬멧, 작업 애니메이션. 그림 대체 준비가 완료된 것과 신규 복장 아트 완료를 구분한다.
- 기존 구도의 몸/손은 설비 앞에 있어 현재 별도 앞쪽 가림 그림은 없다. 미래 자세에서 손이 설비 뒤로 들어가면 앞쪽 가림 레이어를 추가하고 접점을 검수한다.
- [구조·실제 화면·검증517/0](../qa/reports/service_layers_2026-10-11.md). 분리 그림의 세부 픽셀은 기존 원본과 일부 다르며 사용자 선호 확인은 별도다.

## 무기 동작의 현행 구현

사용자 승인으로 권총/장총2계열을 본편에 연결했다. 몸체·총기·손가락의 런타임 합성, 총별 그립/총구/재장전 부품 등록은 `redesign/weapon_actor.gd`에서 관리한다. 보행자·증강은 권총, 쇄도·산개·압쇄는 장총 계열이다. 압쇄는 가슴 높이 사격을 사용한다. [화면·기술 검증](../qa/reports/weapon_motion_2026-10-11.md).

이 구현은 무기 레이어 분리 단계다. 기본 복장만 새 몸체를 사용하며, 머리·헬멧·복장까지 각각 교체하는 조합 제작은 아직 완료하지 않았다. 새 복장은 두 몸체 계열의 발·손 기준점과 전체 상태를 맞춰 제작해야 한다. 이전 고정 총기 ASE 내보내기 자료는 보존용이며 새 몸체를 덮어쓰지 않는다.
