# 전투와 UI 통합 개편 계획

작성: 2026-10-31. 현재 상태: **1단계 완료 / 2단계 탄창·접근·총기별 비교와 선택 빼내기 구현·검증**. [현재 총기별 후보](weapon-magazine.md) · [선택 빼내기·결과·남은 작업](magazine-ejection.md). 본편 새 등반에는 아직 활성화하지 않는다.

**현재 후속:** A안의5~9칸 탄창과 총기별 사격을 실제 획득한5총기×4전투에 연결하고, 중간에서도 탄창당2발을 빼내는 비교를 추가했다. 빼낸 탄은 이번 전투에서 소모하며 추가 적 행동·냉각·보충은 없다. 선택/미리보기/확정과 사용 한도 저장을 검증했고 스플린터 보스 순서17의 빼내기 후 승리 경로를 확인했다. 다음은 빼내기의 선택 가치, 남은 무작위·장기전 편차와 새 규칙의 실제 초반 연속 획득 경로·정예다. 사람의 긴장감·이해도와 모바일 실기기는 후속이다.

사용자가 전투 후기와 UI 완성도 검토를 합친 개편 계획을 요청했다. 이 문서가 다음 작업의 순서를 정한다. 기존 문서의 과거 ‘다음 작업’보다 우선하며, 현재 실행되는 게임 규칙을 바꾸었다는 의미는 아니다. 기존 구현은 [현재 방향](current.md)과 각 기능의 현행 문서를 따른다.

## 1. 목표와 결정 상태

**목표:** 다가오는 적을 보고 이번 탄창을 어떻게 쓸지 판단하고, 잘 만든 탄환·파츠 조합으로 위기를 돌파하며, 그 결과가 화면과 다음 보상에서 분명하게 느껴지도록 한다. 전투마다 압박과 빠른 처치의 리듬을 달리하고, 대표 전투 화면의 완성도를 다른 화면의 기준으로 삼는다.

| 구분 | 내용 |
| --- | --- |
| 사용자 확인 | 적이 가까이 오지 않아 즉사 규칙의 긴장감이 약함. 전투 반복감, 성장·파츠 체감, 시작 열 한계, UI 비주얼이 아쉬움. 모바일 후반 프레임 저하와 기기 발열이 발생함. |
| 사용자 제안·비교 대상 | 장전 즉시 발사, 자기 덱에서 섞인 탄창 전체 교체, 적 발사체의 HP/타격 수, 탄환·총기 고장. 구체 규칙 채택 승인은 아님. |
| 이번에 합의한 작업 방향 | 전투 피드백과 화면 전체의 완성도를 함께 다루는 개편 계획을 먼저 작성. 기존 틀 안의 부품 수정에 머물지 않고 대표 전투 화면을 완성해 확장. |
| 디렉터 권고 | 탄창 단위 교체를 우선 비교 후보로 삼고, 행동 비용과 적 압박을 함께 설계. 발사체는 HP 방식을 먼저 검토. 발열은 기존 연속 부담을 출발점으로 조정. 확률 빗나감·고장은 후순위. |
| 검증 전 가설 | 준비 비용과 사격 한 번의 처리량이 접근 전에 전투를 끝내고, UI의 비슷한 상자·명암·정보 크기가 위협과 조합의 매력을 약하게 보이게 할 수 있음. |

최신 후기의 정확한 빌드/새 등반 여부와 ‘장전 즉시 발사’의 의미는 아직 확인되지 않았다. 계획은 현행 새 등반을 기준으로 만들고 이전 저장을 별도로 비교한다. 답변이 없다는 이유로 특정 의미나 규칙을 확정하지 않는다. 한 발 삽입 즉시 발사와 탄창 장착 즉시 발사는 아래 비교에서 구분한다.

UI 설계는 1단계부터 전투 규칙과 함께 시작한다. 2~3단계는 범위를 좁힌 비교 플레이이며, 4단계는 모든 콘텐츠를 만들기 전에 대표 화면을 실제로 완성하는 단계다. 사람 테스트에서 핵심 문제가 남으면 해당 단계로 돌아가며, 단순한 기능 통과만으로 화면 수를 늘리지 않는다. 별도의 반복 승인 절차를 만들지 않고 결과와 판단 근거를 남긴다.

## 4. 핵심 규칙의 비교안

### 탄창과 발사

| 후보 | 비교할 흐름 | 주요 판단 |
| --- | --- | --- |
| A. 현행 조합 + 확정/발사 통합 | 손패에서 조합한 뒤 하나의 실행 입력으로 장전 확정과 발사 연결 | 입력을 줄이는 것만으로 충분한지 확인하는 대조군. 적 행동 비용은 별도 비교해야 함. |
| B. 자기 덱의 탄창 단위 교체 | 자기 덱에서 섞인 탄창을 제시하고 구성/순서를 읽은 뒤 사용·교체 판단. 장착과 첫 발사를 한 실행으로 묶는 안을 우선 검토 | 권고 후보. 덱 구성이 매번의 탄창 성격에 영향을 주는지, 자동으로 나온 탄을 누르기만 하는 반복이 되는지 확인. 기존 개별 삽입·순서 자유 편집을 자동으로 존치하지 않음. |
| C. 탄 한 발 삽입 즉시 발사 | 넣는 탄마다 실행 | 별도 의미의 제안으로 간단한 상태/행동 사례부터 비교. 조합 준비와 지원탄 사용이 유지되는 근거가 없으면 큰 프로토타입으로 확대하지 않음. |

탄창 전체 교체와 즉시 발사는 서로 다른 결정이다. B가 적합해도 자동 발사가 판단과 예고를 약화하면 분리 사격안을 선택할 수 있다. 이번 계획에서는 B를 채택한 것으로 기록하지 않는다.

비교 구현 전에 다음 항목을 하나의 표로 정한다.

- 탄창 용량과 여러 칸을 쓰는 탄, 남은 탄이 용량보다 적은 경우, 공격탄 없는 탄창의 처리.
- 조합/미리 보기 중 시간의 진행 여부, 교체·발사·냉각마다 적이 행동하는 시점과 횟수. 기존 행동 기반 진행을 기본으로 비교하며 실시간 제한을 자동 도입하지 않음.
- 발사 순서, 표적 규칙, 발사 중 적 전멸·과열·발사체 접촉의 해결 순서. 사용자가 볼 수 있는 정보와 실제 예측 범위.
- 교체로 배출한 잔탄·사용탄의 위치, 전투 중 재순환 여부, 다음 전투 복구, 비상 보급 조건. 기존 유한 탄약을 기본 대조군으로 유지.
- 재뽑기 비용과 무작위 상태의 저장. 무료 무한 교체나 이어하기를 통한 유리한 탄창 재추첨을 만들지 않음.
- 기존 손패/교환/용량 파츠·복장·총기 능력의 대응 관계. 이미 보유한 장비의 효과를 조용히 삭제하거나 무효화하지 않음.

### 적의 압박과 발사체

접근 압박은 초기 거리·이동량·공격 한 번의 처리량·재장전 비용을 함께 본다. 적의 몸체가 실제 위험과 맞게 가까워져야 하며, 모든 전투를 위기로 만들거나 성장에 맞춰 적을 몰래 가속하지 않는다. 근접전에는 밀치기·먼저 처치·열을 감수한 마무리 등 실제 덱으로 가능한 대응을 확인한다.

적 압력탄은 현재 HP 1이다. **일반 HP 방식**을 먼저 비교해 높은 단발 피해와 여러 약한 공격 모두 대응 수단이 되게 한다. **고정 타격 수 방식**은 특정 발사체의 특성 후보로 남긴다. 후자를 쓰면 큰 단발 피해가 손해 보는 이유가 외형과 표시에서 읽혀야 한다. 내구를 올릴 때는 생성 주기·접근 속도·자동 요격 순서·동시 발사체 수·남은 탄약을 함께 조정한다. 본체와 발사체를 연달아 처리해야 하는 불가피한 즉사가 생기는지도 확인한다.

### 발열과 탄환 역할

기존 연속 공격 부담 B1을 비교 기준으로 삼는다. 무기별 시작 한계를 낮추는 안과 탄별 열/냉각을 조정하는 안을 비교하고, 처음부터 매번 강제 과열되는 답답함과 전혀 신경 쓰지 않아도 되는 여유 사이를 찾는다. 클릭 횟수로 연속 여부를 판정하지 않으며, 탄창 구조가 바뀌면 연속 부담 초기화 조건도 함께 결정한다. 열압의 발동선·강행 보상·스플린터의 누적 부담을 따로 확인한다.

증폭·냉각 등 피해 없는 지원탄은 이미 있으므로 ‘모두 공격형으로 느껴진다’는 후기는 역할의 체감 문제로도 다룬다. 공격/준비/제어/냉각이 현재 위협에 따라 다른 가치가 있는지, 획득과 화면 표현에서 차이를 알 수 있는지 비교한다. 확률 빗나감은 기본 개편에 넣지 않는다.

탄환 불량과 총기 고장은 별개 후보로 보존한다. 도입을 재검토할 때는 발생 확률·누적 조건·고급 탄의 신뢰도/출력 부담·고장 탄과 미발사 잔탄의 처리·소실 기간·복구 비용을 먼저 명시한다. 지금은 발열 위에 또 다른 확률 제약을 겹치지 않는다.

## 5. 대표 화면의 완성도 기준

- **보는 순서:** 현재 가장 중요한 위협 → 이번 탄창/조합 → 실행 결과와 주요 행동 → 보조 정보. 전장과 탄환 판단의 크기는 함께 조정한다.
- **공간:** 큰 빈 슬롯과 반복 프레임의 면적을 줄인다. 탄환·총기·적은 역할을 식별할 크기로 보여 주고, 자세한 규칙은 필요한 순간 열어 본다. 상시 거리 숫자는 되살리지 않는다.
- **활자·명암·색:** 주 수치·행동·설명의 크기와 밝기를 구분한다. 선택·실행·위험·냉각은 색과 형태/문구를 함께 사용하고, 모든 패널을 같은 강조도로 그리지 않는다.
- **재질·세계:** 기존 도트풍과 산업 시설·탄약·정비의 분위기를 연결한다. 배경 그림, 실제 물건, 조작부가 한 화면에서 어울려야 한다. 장식만 금속으로 바꾸는 것을 전체 개편으로 보지 않는다.
- **결과의 체감:** 장착→발사→적중→처치의 흐름과 파츠 발동을 실제 영향을 받은 탄·적에 연결한다. 큰 한 발·연타·연쇄·과열의 차이를 읽을 수 있게 하고, 잦은 긴 연출로 조작을 지연하지 않는다.
- **통합 확인:** 현재 화면과 새 화면을 같은 전투 상태·해상도로 비교한다. 정지 화면과 움직이는 실제 플레이를 모두 보며, 작은 모바일 화면·넓은 화면·큰 글씨에서 검수한다. 보기 좋다는 판단을 잘림/기능 검사 통과로 대체하지 않는다.

1단계의 결과물은 **전체 화면 구성안 2개 + 상태별 행동 표 + 비교할 대표 전투 목록**이다. 4단계의 결과물은 같은 상태의 전후 캡처와 실제 조작 가능한 대표 화면이다. 정지 이미지에만 존재하는 버튼/수치를 구현 완료 화면처럼 제시하지 않는다.

## 6. 검증과 완료 판단

| 축 | 비교 방법 | 완료로 인정하지 않는 것 |
| --- | --- | --- |
| 압박·선택 | 동일한 실제 획득 조건에서 가장 가까운 적, 접촉까지 남은 행동, 재장전 위험, 사용 가능한 대응, 입력 수·전투 길이를 비교. 대표 압박전의 1~2행동 내 접촉 위기는 초기 목표이며 플레이로 조정. | 적 속도/HP 상승만 확인하거나 모든 전투의 강제 근접을 성공으로 간주 |
| 성장·다양성 | 무리/근접 압박/발사체/장갑 대응과 획득 직후 전투에서 실제 처치 방식·필요 탄·선택 변화를 비교. 보상으로 얻을 수 있는 장비 사용. | 완성 덱 시연, 승률·피해 숫자 상승만으로 재미 해결 선언 |

| UI·미감 | 동일 상태 전체 화면 비교, 주요 행동과 위험의 판독, 선택/실행/빈 탄창/위기/승리/상세 복귀, 실제 손가락 조작. | 개별 카드만 예뻐졌거나 잘림·정렬만 통과 |
| 모바일 지속 성능 | 같은 기기·설정·밝기·충전 조건에서 동일 경로를 20~30분 비교. 초반/후반 프레임 시간 중앙값·상위 지연, 멈춤·메모리 추이·기기 열 상태를 기록. 60FPS 상한을 초기 기준으로 사용하고 지속 가능한 목표는 측정 후 확정. | PC 수치만으로 모바일 해결 선언. 연결 기기가 없으면 실기기 확인은 미완료 유지 |
| 사람의 체감 | ‘위험을 언제 알았는지’, ‘전투별로 무엇을 달리했는지’, ‘어떤 탄/파츠로 좋아졌는지’, ‘화면에서 어디를 먼저 보았는지’를 플레이 후 확인. | 자동 탐색 완주·검사 횟수를 재미나 미감의 대체 지표로 사용 |

성능은 마지막 단계에 몰지 않는다. 1단계부터 기준선을 남기고 새 화면·연출을 넣을 때마다 후반 상태의 갱신 비용을 비교한다. 모바일 기기 발열과 전투 규칙의 발열을 분리하며, 실기기 미연결은 독립적인 설계·로컬 검증을 막지 않는다. QA는 격리 저장을 사용한다.

정찰 리액터 최종전의 탐색 미해결, 스플린터 연속 발열 부담, 후반 성장 속도·탄약 편차는 6단계의 기존 미해결 항목으로 이어간다. 새 개편의 회귀와 구분해 추적하며, 탐색 실패를 곧바로 불가능 판정으로 쓰지 않는다.

## 7. 이번 순서에서 뒤로 두는 작업

확률 고장·명중률 도입, 파츠 슬롯 확대, 소모형 특수탄, 복장 해금/교체 확장, 새 발사기구 파츠, 관문 통과 이벤트 연출은 대표 전투의 선택·완성도 검증 후 다시 판단한다. 새 적·지역·대량 에셋 추가보다 현재 자산으로 핵심 흐름을 먼저 검증한다. APK·커밋·푸시·외부 게시 단계는 이번 계획 작성에 포함하지 않는다.

2단계의 탄창 반복 플레이와 [접근 압박 비교](combat-approach.md)를 구현했다. 다음은 총기별 사격/용량 비교와 새로운 규칙으로 얻은 연속 전투 경로·정예다. 본편 연결 여부는 그 검증 결과로 판단하며 이전 등반은 기존 규칙을 유지한다.
