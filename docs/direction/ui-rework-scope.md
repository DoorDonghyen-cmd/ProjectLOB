# 정비소 이후 UI 개편 대상과 레퍼런스 수집 범위

**이야기 장면·확인 창(2026-11-08).** 출발·공급 복구·귀환을 조우·탄약고와 같은 전체 그림 + 이야기 판으로, 파츠 분해 확인과 파츠 상세를 공통 창으로 옮겼다. [본편·검증](../qa/reports/story_scenes_2026-11-08/README.md). 남은 이전 화면은 기초 훈련과 기타 대화창(탄환 상세·전투 정보).

**공통 창(2026-11-08).** 설정·조작 안내·게임 규칙·기록실을 정비소 테마로 옮겼다. 설정은 모든 선택지를 버튼으로 펼치고, 기록실은 구역별 칸과 읽기 판으로 바꿨다. 문장은 그대로. [본편·검증](../qa/reports/common_windows_2026-11-08/README.md). 남은 이전 화면은 출발·공급 복구·귀환 장면, 기초 훈련, 확인 창.

**빌드 작업실 통일(2026-11-08).** 새 디자인 없이 상점 단말의 파츠 장착 부품과 탄약고의 휴대 칸·탄 묶음을 정비소 테마로 묶어 빌드 작업실을 바꿨다. 파츠 변경은 작업실을 닫지 않고 자동 저장. [본편·검증](../qa/reports/build_live_2026-11-08/README.md). 남은 개편 대상은 공통 창(설정·조작 안내·게임 규칙).

**조우 본편 연결(2026-11-08).** 사용자 승인으로 사건·조우 시안을 본편에 연결했다. 매복은 같은 자리 전투로 이어지고, 탄 발견은 탄약고와 같은 추가/교체를 쓴다. [본편·검증](../qa/reports/event_live_2026-11-08/README.md). 개편 대상 7순위(빌드 작업실)와 공통 창이 남았다.

**탄약고 본편 연결·사건 시안(2026-11-08).** 보급소 3차(아래 선반) 시안을 본편 탄약고에 연결했다. 사건·조우는 레퍼런스3개(Slay the Spire·Citizen Sleeper)를 바탕으로 구역 전투 배경 위 이야기 창 시안을 만들었다. [탄약고 본편](../qa/reports/supply_live_2026-11-08/README.md) · [사건 시안](../qa/reports/event_review_2026-11-08/README.md) · [레퍼런스](../art/references/2026-11-08-event/README.md). 사건은 사용자 확인 뒤 본편 연결.

**관문 본편 연결·보급소 시안(2026-11-07).** 승인된 관문 표찰 시안을 본편에 연결했다(실제 등반·자동 저장·복장별 자세·정비소와 같은 메뉴·844×390 배치 보정). 보급소는 레퍼런스4개를 모아 탄약고 장면 시안을 만들었다(보급함 위 받을 탄, 아래 휴대 칸 게이지, 추가/교체 비교창). [관문 본편](../qa/reports/gate_live_2026-11-07/README.md) · [보급소 시안](../qa/reports/supply_review_2026-11-07/README.md) · [레퍼런스](../art/references/2026-11-07-supply/README.md). 보급소는 사용자 확인 뒤 본편 연결.

**현재 UI 목록(2026-11-07):** 본편에서 열리는 주 화면 14개와 창을 개편 반영/시안만/이전 화면으로 나눈 [UI 목록](ui-inventory.md).

**지도 UI 후속 본편(2026-11-06):** 사용자 실행 지시로 아래 ‘지도 부분 점검’을 진행했다. 기존 배관도/노드/주요 배치를 유지하고 승인된 철제·먹색·황동으로 재질/상태 위계를 맞췄다. 구역/잔액 강조, 상태 견본과 선택·이동/범례·상세를 연결했다. [실제 진행/전후/검증](../qa/reports/map_material_2026-11-06/README.md). 지도 생성/전투/저장은 수정하지 않았다. 외부 게임의 새 구도를 가져오거나 새 그래픽 생성 도구를 추가한 작업이 아니다.

**2026-11-06 선택 UI 본편 반영:** 아래 후순위였던 캐릭터/장비 선택을 새 총기2종보다 먼저 진행했다. 사용자 실행/캐릭터 축소 지시로 철제·황동 외형과 중앙0.85 표시, 고정 행동 줄/중간 스크롤을 적용했다. 실시간 착장과 큰 구도·기존 버튼/카드 크기는 유지한다. [현행 결정](equipment-ui.md) · [본편 화면/검증](../qa/reports/equipment_live_2026-11-06/README.md). S26 비율에서5총기/시작 동시 노출, 신규1,513·HUD11,558 실패0. 사람/Android 실제 지속 확인은 후속이며 이전 시안 대기는 해소됐다.

**상점 주요 행동 후속(2026-11-05).** 구매/파츠 장착을 오른쪽 물리 키로, 현장 기록을 하단 보조 행동으로 옮겼다. 기본 재고 탭은 숨기고 기록/장착 중에만 판매 물품 복귀를 표시한다. [본편·시안 화면과 검증](../qa/reports/shop_actions_2026-11-05/README.md). 직전 결제 행 내부의 구매 우측 정렬보다 이 사용자 지시가 우선한다.

**플레이 후기1차 반영(2026-11-05).** 상점의 단말기 색을 본편과 맞추고 금액 위계·구매 우측 정렬을 정리했다. 전투 HUD에는 빈 탄창 재장전 표시를 적용했다. [상점](../qa/reports/shop_feedback_2026-11-05/README.md) · [재장전](../qa/reports/hud_reload_2026-11-05/README.md). 다음은 전투 밸런스이며 승인 관문 시안의 본편 연결과 강화 창/등급 카드 등은 계속 남아 있다.

**관문 출발 피드백 반영(2026-11-05).** 출발을 목적지 표찰에 옮겼다. 출발 시 문과 캐릭터 자세를 유지하고, 경보등과 개방 신호를 표시한 뒤 암전한다. 다음 구역 변경은 완전 암전 뒤 실행한다. [수정 시안과 검증](../qa/reports/gate_threshold_2026-11-05/README.md)

**관문 출발 연출 시안(2026-11-05).** 작업 중에는 캐릭터와 조작대에 시선을 모으고, 문 옆에서 출발하면 비교창이 물러나며 목적지 표찰과 열린 통로가 남도록 구성했다. [실행·캡처·검증](../qa/reports/gate_threshold_2026-11-05/README.md)

**관문 레퍼런스 후속(2026-11-05).** 실제 게임 네 편의 작업대·승강기·환승장·출구 캡처를 본편 정비소와 관문 시안에 대조했다. 작업 중에는 조작대에, 출발할 때는 문과 다음 구역에 시선을 모으는 안을 검토한다. [캡처와 출처](../art/references/2026-11-05-gate/index.html)

**관문 구도 비교(2026-11-05).** 사용자 피드백에 따라 정비소의 장면 중심 배치와 테마를 관문에 적용한 비교 시안을 추가했다. 차단문·캐릭터·조작대를 한 장면에 놓고 개조 후보는 하단, 적용 전후는 오른쪽에 배치했다. [정비소·관문 비교와 실행](../qa/reports/gate_workstation_2026-11-05/README.md)

**관문 시안(2026-11-05).** 실제 차단문 옆에서 무료 개조의 전후 수치와 유료 재정비 비용을 확인하고, 출발 시 문이 열리는 Godot 시안을 만들었다. 전용 탄약 생산과 기본탄 3장 선택도 조작할 수 있다. [시안 실행·캡처·검증](../qa/reports/gate_review_2026-11-05/README.md)

**전투 보상 본편 적용(2026-11-05).** 정예 파츠·탄환 교체·첫 성장 코어의 시안을 현행 지도 보상에 연결했다. 보스 보상과 관문 또는 정상 진입, 상세·교전 기록, 자동 저장을 확인했다. 다음 개편 대상은 관문이다. [본편 화면·검증](../qa/reports/reward_live_2026-11-05/README.md)

**전투 보상 시안 피드백(2026-11-05).** 사용자는 F1 정예 파츠와 F3 성장 코어의 구도를 긍정 평가했다. F2 교체 화면은 같은 전장과 패널 비율을 적용하고, 후보를 세 장씩 표시하며 받을 탄과 내보낼 탄의 변화량을 두 줄에 정렬했다. [수정 화면·검증](../qa/reports/reward_review_2026-11-04/README.md)

**전투 보상 시안(2026-11-04).** 전투 장소 위에 전리품과 현재 빌드에 대한 효과를 함께 보여 주는 Godot 시안을 만들었다. 정예 파츠, 가방이 찬 상태의 탄환 교체, 첫 성장 코어에서 주력 탄 묶음으로 이어지는 흐름을 검토할 수 있다. 본편 연결 전 시안이다. [실행·캡처·검증](../qa/reports/reward_review_2026-11-04/README.md)

**상점 본편 적용(2026-11-04).** 사용자가 확정한 옆 조작기와 CRT 모니터를 본편에 연결했다. 같은 단말에서 재고와 현장 기록을 열고, 장착대와 보관함의 파츠를 고른 뒤 얻는 효과와 잃는 효과를 확인한다. 구매·장착·해제·교체는 진행 중인 도전에 자동 저장된다. 구버전 지도에서 이어가는 저장은 해당 상점의 전용 서비스를 제공한다. [본편 캡처와 검증](../qa/reports/shop_terminal_live_2026-11-04/README.md)

**옆 조작기 단말의 CRT 시안:** 왼쪽 모니터에 주사선·유리 음영과 짧은 화면 전환 효과를 적용했다. 사용자 요청에 따라 단말을 보는 동안 희미한 띠가 약 6초 주기로 천천히 내려간다. [움직임 캡처·실행·검증](../qa/reports/shop_console_crt_2026-11-04/README.md). 본편 채택 전 시안이다.

**모니터와 옆 조작기 상점 시안:** 사용자 요청으로 《Stories Untold》와 《Nauticrawl》을 참고한 비교안을 추가했다. 좌측 모니터는 재고 또는 기록을, 오른쪽 조작기는 실제 보유금과 모드 전환을 표시한다. [두 시안 비교와 개별 실행](../qa/reports/shop_console_2026-11-04/README.md). 본편 채택 전 시안이다.

**하단 조작부 단말 시안:** 사용자가 진행을 승인한 HP 2644A 참고안을 적용했다. 매립 화면 아래에 재고·기록 조작 키와 데이터 테이프 슬롯을 배치하고, 기록을 열면 슬롯 표시등이 켜진다. [실행·이전 외형 비교·검증](../qa/reports/shop_terminal_data_deck_2026-11-04/README.md). 본편 채택 전 시안이다.

**카세트 단말 외형 시안:** 매립 화면을 감싼 바랜 사출 케이스와 테이프 모듈을 추가했다. 기록 탭을 열면 릴과 상태등이 반응한다. [실행·이전 외형 비교·검증](../qa/reports/shop_terminal_cassette_2026-11-04/README.md). 본편 채택 전 시안이다.

**물자 거래 단말 2차 시안:** 상점 내부의 배관도 제거와 단말 확대 피드백을 반영했다. 사용자가 선호한 《Lethal Company》의 거래·기록 전환과 《Alien: Isolation》의 문서 구성을 적용했다. 구역별 원문에는 내용을 요약한 제목을 붙였다. [실행·화면·검증](../qa/reports/shop_terminal_v2_2026-11-04/README.md). 본편 채택 전 시안이다.

**물자 거래 단말 시안(2026-11-04):** 사용자가 상점 배경을 생략하고 기존 이야기도 단말로 전달하는 방향의 시안 제작을 요청했다. 실제 배관도 옆에 `재고`와 `현장 기록`을 둔 Godot 검토용 씬을 만들었다. 재고가 기본이며 기록 탭에서 현재 구역의 기존 원문을 읽는다. [실행·캡처·검증](../qa/reports/shop_terminal_review_2026-11-04/README.md) · [참조 게임](../art/references/2026-11-04-ui/shop-device-followup.md). 본편 채택 전 시안이다.

**상점 시안 검토 대기(2026-11-04):** [카운터 진열과 구매 시안](../qa/reports/shop_counter_review_2026-11-04/README.md). 실제 상점 기록으로 진열 3개와 가격표·선택 상세·구매 결과를 확인했다. 사용자 피드백을 반영해 상인 그림과 이름을 제거했다. PC/S26 가로 크기에서 349개 검사 통과. 구도 검토 후 본편 거래와 기존 보조 화면을 연결한다.

**상점 레퍼런스 후속(2026-11-04):** [게임 화면 4종과 시안 적용안](../art/references/2026-11-04-ui/shop-followup.md). Shogun Showdown의 상품·가격 위치와 Blasphemous의 조명·진열을 중심으로, 선택 상품의 실제 구매 결과를 한곳에 모으는 구도를 다음 시안으로 검토한다.

**결과창 본편 적용(2026-11-04):** [본편 캡처와 검증](../qa/reports/results_live_2026-11-04/README.md). 승인한 시안과 실제 결과창이 같은 씬을 사용한다. 같은 경로 재시작을 덜고 새 도전과 기록실을 연결했다. 다음 순서는 상점 시안이다.

**레퍼런스 수집 후속(2026-11-04):** 사용자 실행 지시로 상위4영역 각4개, 총16개의 실제 게임 UI를 수집·검토했다. [이미지 비교 보드](../art/references/2026-11-04-ui/index.html) · [화면별 관찰/참고/제외/출처](../art/references/2026-11-04-ui/README.md). 아래는 수집 전 작성한 범위이며, 후속 제안은 위 자료에 연결한다. 제품 파일은 그대로이고 다음은 결과창 통합 시안이다.

2026-11-04. 사용자는 정비소에서 효과가 있었던 과정을 나머지 UI에도 적용하되, 제작 전 레퍼런스부터 수집하고 먼저 개편 대상을 목록화하도록 요청했다. 이번 문서는 현재 UI·기존 실제 캡처·호출부를 대조한 **우선순위 제안**이다. 화면별 새 구도·팔레트·탭 구성은 아직 정하지 않았으며 제품 파일은 변경하지 않았다. 외부 레퍼런스 수집도 이 목록 다음 단계다.

## 적용할 과정

현재 화면의 목적/필수 정보와 조작 확인 → 실제 게임 레퍼런스 수집 → 가져올 원리/맞지 않는 점 비교 → 우리 배경·캐릭터를 넣은 통합 시안 → 시안 검토 → 실제 기능/저장 연결 → PC/S26비율·공개 조작 검증.

정비소에서 확인된 것은 ‘장소와 기능에 맞는 장면, 선별된 정보, 역할별 글자·내용 폭 버튼’의 가치다. 모든 화면을 작업대·황동색·5탭으로 만드는 기준이 아니다. 중앙 좌측의 탄환 소품/수량 표시는 중복이라는 사용자 후기로 제거했으므로 불필요한 장식을 다른 화면에 되살리지 않는다. 캐릭터 선택의 정상 스크롤은 유지하며 화면을 채우려는 확대/버튼 확장을 목표로 삼지 않는다.

## 우선 제작 대상

| 순서 | 화면과 포함 상태 | 현재 근거 / 개편할 초점 | 수집할 레퍼런스의 목적 |
|---|---|---|---|
| 1 | 등반 결과 — 승리·패배 | 사용자 지적과 실제 화면: 같은 무게의 통계5개·열 기록·파츠/덱·넓은 버튼이 병렬로 이어진다. 성취/실패 원인·대표 빌드·다음 행동의 위계, ‘다음 설계’ 같은 모호한 제목 정리가 필요하다. | 승리/실패의 정서, 핵심 성취와 상세 통계의 분리, 다시 시작 행동의 위계. |
| 2 | 상점 — 진열·선택·구매 완료·재화 부족·탄 교체/보관 | 사용자 지적과 실제 화면: 장소/인물은 위쪽 작은 그림에 머물고 아래 큰 상품/상세 패널이 화면을 지배한다. 물건·상인·거래가 한 공간에서 읽히게 구성하고 그림/빈 면/가격/행동 비중을 조정한다. | 상인/진열대/거래 공간, 상품 비교와 가격, 구매 후 장착/보관/교체 표시. |
| 3 | 전투 보상 — 코어·주력 묶음·탄환·파츠·보스 전리품·보유 한도 교체 | 캡처와 `reward()`: 여러 겹 프레임/재질·버튼이 경쟁한다. 획득물의 개성과 현재 빌드에서 얻는 이득·대가를 먼저 보이게 한다. | 전리품/카드 선택, 현재 빌드와의 비교, 후보 간 차이·선택 확신. |
| 4 | 관문 — 개조 선택·전용 탄 견본/교체·유료 재정비·출발 | 실제 화면과 `gate_reward_ui.gd`: 같은 큰 카드가 반복되고 선택→적용→정비→출발이 주로 문구로 안내된다. 관문이라는 전환점과 성장/지불 결과를 구분한다. | 구역 전환/성장 설비, 변경 전후, 선택 단계와 출발의 위계. |
| 5 | 보급소 — 탄 후보·추가/교체·보급 완료·보류 | 캡처와 `modern_supply()`: 작은 장소 그림 아래 탄 카드+같은 버튼이 반복된다. ‘보급받는다’는 행위와 소유/휴대 한도 정보를 연결한다. | 탄약고/보급 상자/배급대, 고를 물건과 수량/소유 관계. |
| 6 | 사건·조우 — 최초 선택·유료 선택·매복/전투·전리품·해결 | 실제 화면과 `encounter_service()`: 보급소와 동일 장소 자산/선택 패널 어휘를 공유한다. 사건의 상황·선택 비용·결과가 장소에 맞게 읽히도록 구성한다. | 사건 삽화와 선택지, 중요한 비용/위험, 선택 뒤 결과 전환. |
| 7 | 빌드/보관함 — 파츠 장착·교체·해제·탄환 덱·빈 상태·전투 중 열람 | 실제 화면과 `deck()`: 장착 카드/빈 슬롯/상세의 무게가 다르고 금속·크림색·청록 패널이 섞인다. 현재 조합과 교체로 얻고 잃는 점을 명료하게 보여 준다. | 실제 장비/보관함, 슬롯·목록·상세 관계, 비교와 성장/시너지 판독. |

위 순서는 기존 결과→상점 우선순위를 이어가는 작업 제안이다. 처음에는 **1~4의 레퍼런스를 함께 조사**해 공통 글자/재질과 화면별 역할을 비교하고, 통합 시안·본편 적용은 한 화면씩 진행한다.

## 위 화면과 함께 정리할 공통 UI

| 대상 | 포함 범위와 처리 |
|---|---|
| 탄환/파츠 상세·비교 창 | 상점/보상/빌드/전투의 실제 호출 경로를 구분한다. 핵심 효과·변경량·비용/불이익·긴 규칙을 나누고 닫기/복귀·긴 문구·작은 화면을 확인한다. 화면마다 별개로 고쳐 중복되지 않게 해당 화면과 연결해서 정리한다. |
| 공통 메뉴·설정·확인/취소 | 글자 역할, 패널/버튼 강도·크기, 선택/비활성/포커스를 정리한다. 특히 명령 확정 팝업은 무엇이 소모/변경되는지 명시한다. 설정 기능이나 기존 입력을 바꾸는 작업은 아니다. |
| 상단 상태줄·알림·툴팁 | 각 화면에서 실제 필요한 상태만 남기고 별도 공통 패널이 장소를 덮지 않도록 한다. 색만으로 의미를 전달하지 않고 수치·아이콘·문구를 함께 확인한다. |

공통 요소는 별도 전면 재배치 단계보다 우선 화면의 시안/구현에서 실제로 쓰이는 상태부터 정리한다. 전투 HUD의 경고/열/사격 색 의미를 정비소 팔레트로 일괄 치환하지 않는다.

## 후순위 검토 후보

- **출발·공급 복구·귀환:** `story_ui.gd`의 장면/서사/행동 구조를 확인했다. 감정과 장면을 보강할 후보지만 이번에 모든 상태의 최신 화면을 재검수하지는 않았다. 결과창과 귀환을 함께 볼 때 추가 범위를 정한다.
- **기록실·해금·도시 이야기:** `archive()`는 해금/진행 정보와 기록 열람을 함께 담는다. 실제 기록이 충분히 쌓인 상태를 추가로 확인한 뒤 열람·수집 화면 레퍼런스를 수집한다.

## 구조 유지와 부분 점검

- **캐릭터/무기/복장 선택:** 사용자가 상대적으로 좋게 평가한 장면 중심 기준 화면이다. 정상 스크롤/현재 배치를 유지하고 버튼·문구·표현 연결만 검토한다.
- **지도:** 현재 배관 경로·노드 구조를 유지한다. 범례·지나온 길·현재 위치·장소 상세의 읽기/배색은 부분 점검 대상으로 남긴다. 이번 UI 목록을 지도 경로나 노드 밸런스 변경으로 확대하지 않는다.
- **전투 HUD:** 선택/발사/빼내기/열의 현재 구조와 이미 연결한 피드백을 유지한다. 나중에 상세창·글자/프레임의 연결을 점검하며 이번 작업으로 배치를 새로 설계하지 않는다.
- **타이틀:** 즉시 전면 개편할 근거는 부족하다. 나머지 UI 정리 후 글자·버튼·이어하기 등 상태의 일관성을 확인한다.
- **정비소:** 새 기준 화면으로 유지한다. 남은 실기기/사용성 문제는 실제 후기에서 처리한다.

## 레퍼런스 수집 기준

- 각 화면별 실제 게임 전체 화면3~5개를 출처와 함께 고른다. 장식 카드만 잘라 모으지 않고 기본/선택/완료와 가능한 한 조작 흐름을 함께 확인한다.
- `화면 목적 / 참고할 배치·정보·장면 원리 / 가져오지 않을 점 / 우리 게임에 필요한 자산 / 모바일 제약`을 붙인다. 외부 이미지는 연구용 참조이며 게임 자산으로 복사하지 않는다.
- 도트 게임의 활자/픽셀·작은 화면 사례와, 다른 화풍 게임의 장면/기능 연결 사례를 구분해 비교한다. 유명 게임의 미감 전체를 우리 배경에 그대로 덮지 않는다.
- 최종 방향은 우리 실제 배경·배우·상품·수치를 넣은 통합 시안에서 판단한다. 색만 바꾼 공통 틀이나 불필요한 소품 추가로 결론내지 않는다.
