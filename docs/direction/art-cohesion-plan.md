# 무기 적용과 도트 화풍 통합 계획

2026-10-24 수립한 실행 계획. 후속 전체 실행 요청으로 구현/검증을 마쳤다. 아래는 판단 근거와 실행 순서를 보존한 것이며, 실제 결과와 한계는 [완료 보고](../qa/reports/art_cohesion_2026-10-24.md)를 따른다.

## 결정과 범위

- 사용자: 현재 다섯 총기 디자인을 따라 제작을 진행한다. 스플린터는 원통형v3를 긍정했으나 황토색을 바꾼다. 무기 작업 뒤 전체 도트의 외곽선/선명도 차이를 점검하고 현재 구역 배경에 어울리도록 맞춘다.
- 제안: 스플린터는 바랜 회녹색 도장, 짙은 회색 금속, 소량의 낡은 아이보리 표식. 청회색 리액터와는 색온도·형태로 구별한다. 구체적인 색은 아직 사용자 지정/완료 상태가 아니다.
- 유지: 리벳/스파이크 한손, 래칫/스플린터/리액터 양손 계열. 승인 실루엣과 리벳 축소 비율을 기준으로 손·몸체를 맞춘다. 다른 기능 개편을 화풍 통합에 묶어 변경하지 않는다.
- 새 해상도나 외곽선 픽셀 수를 모든 자산에 영구 강제하지 않는다. 배경·배우·UI의 역할 차이를 살리면서 화면상 도트 크기와 명암 관계를 맞춘다.

## 이번에 확인한 근거

최근 보관 캡처의 장비 선택, 주조장 중반, 정원 보스, 중앙 통제구, 새 무기 파지 비교를 직접 확인했다. 이번 요청에서는 새 플레이 캡처/기능 테스트를 수행하지 않았다.

- 주인공의 큰 색면에 비해 일부 기계 적에는 작은 부품별 어두운 선과 강조가 더 많다. 정원 생물의 넓은 음영 덩어리와도 묘사 밀도가 다르다. 소재 차이와 화풍 불일치를 나눠 조정해야 한다.
- 선택 화면에서는 확대된 캐릭터의 큰 도트와 무기 내부의 작은 경계가 한 화면에 보여 밀도 차이가 강조된다. 확대 원화와 전투용 축소 표시를 각각 검수해야 한다.
- `weapon_actor.gd`의 현재 저해상도 무기 레이어는 `coarse_burst && gun_id == "burst"`에만 적용된다. 총기별 표시 경로 차이가 실제로 존재한다. 이것이 모든 차이의 원인이라는 뜻은 아니며 원본·축척·회전·알파 컷아웃도 함께 비교한다.
- 배경은 이미 큰 구조와 전경/원경의 명암 관계를 갖췄다. 주조장·정원·중앙 통제구의 색은 다르므로 특정 구역의 색을 모든 자산에 고정하지 않는다.
- 현행 [제작 기준](pixel-production.md)에도 큰 색면/낮은 잔묘사 원칙이 있다. 고해상도 생성 PNG는 동일 픽셀 격자를 보장하지 않으므로 문구와 nearest 설정만으로 통일됐다고 판단하지 않는다.

## 실행 순서

### 1. 무기 적용 전에 비교 기준 확보

현재 배경의 가까운 난간·바닥·기둥과 승인 주인공을 같은 화면에 두고 기준 샷을 만든다. 원경 건물의 낮은 대비를 전투 캐릭터에 그대로 적용하지 않는다. 1~3구역을 주 검수 대상으로,4~5구역은 밝기·색조가 다른 환경의 호환 확인 대상으로 사용한다.

같은 자세/표시 크기/배경에서 기존과 신규를 나란히 비교하고, 원본 묘사·화면 축척·렌더 경로·동작에 따른 차이를 분리한다. 무기 완료 후 다시 전부 제작하는 낭비를 줄이는 최소 기준 확인이다.

### 2. 승인한 다섯 총기를 게임에 연결

스플린터 색을 먼저 변경한다. 다섯 원화의 손잡이/보조 손/총구/재장전 부품/발열 표면을 새로 등록해 기존 몸체·파지를 유지한다. 장비 선택 그림과 전투 표시에서 같은 무기라는 인상을 유지하되 전투에서는 작은 나사·흠집보다 실루엣이 먼저 읽히게 한다.

대기→조준→반동→장전 열기/닫기→냉각을 확인한다. 신규 무기명은 선택/전투/빌드/설명에 일관되게 연결하고 내부 ID·기존 저장 키는 보존한다. 리액터의 능력 변경은 [무기 설계](weapon-design.md)의 별도 규칙 검증과 예측 정합성을 거친다. 외형 적용만으로 능력 구현 완료라고 기록하지 않는다.

### 3. 무기 적용 후 전체 화풍 진단과 대표 보정

전체 자산을 바로 재생성하지 않는다. 주인공+신규 무기+기계 적1종+생물1종을 현행 배경에 놓아 대표 보정 화면을 만든다. 도트 크기/윤곽/내부 명암/포인트 색/재질 묘사를 함께 비교한다.

| 기준 | 목표 | 검수 방법 |
|---|---|---|
| 도트 크기 | 가까운 구조물·배우 사이에서 픽셀 덩어리 규모가 어울림 | 실제 전투 크기와 장비 확대 화면을 분리 비교 |
| 외곽선 | 주변색을 반영한 어두운 경계, 부위에 따른 선택적 강조 | 검은 띠·얇은 잔선·알파 가장자리의 튀는 지점 확인 |
| 내부 묘사 | 재질을 대표하는 큰 면, 제한된 부품선 | 원화에서만 보이는 나사·흠집·밝은 점이 작은 화면에서 노이즈가 되는지 확인 |
| 명암·색 | 배경과 같은 세계, 주체와 공격 신호는 구별됨 | 어두운 실내·밝은 외부·식물 배경에서 동일 자산 비교 |
| 동작 | 정지/회전/반동/피니시 확대에서도 도트 인상이 유지됨 | 윤곽 두께 변화, 깜빡임, 금속 표면 밖 발열 잔상 확인 |
| UI | 같은 금속/천/도장 재질감, 글자와 상태 기호의 판독 유지 | 카드/파츠/버튼의 작은 장식 밀도와 글자 대비를 별도 판정 |

흐림 필터로 덮거나 외곽선을 전부 없애는 방식은 사용하지 않는다. 먼저 표시 경로/축척 문제를 조정하고, 원화 묘사 자체가 다른 자산만 부분 편집 또는 재제작한다. 대표 보정 기준이 정리되면 캐릭터·복장/무기 → 일반·정예·보스 → 실내 소품 → 탄환·파츠·UI 장식 순으로 확장한다. 지도·타이틀도 마지막 통합 점검에 포함한다.

### 4. 실제 화면·동작 검수와 제작 기준 갱신

전투/장비 선택/상점·정비를1280×900,1008×630,1440×630에서 비교한다. 배경은1~5구역의 밝고 어두운 대표 장면, 배우는 전체 복장×5무기 조합의 파지/가림·총구를 확인한다. 대기/반동/장전/과열·냉각/25% 피니시 확대가 검수 대상이다.

저장은 격리한다. 자산 등록·모션 변경에 해당하는 기존 장비/배우/무기 열기 검사를 수행하고, 전투 규칙이 바뀌는 경우에만 규칙/예측 검사도 연결한다. 제작자 시각 검수, 기능 통과, 사용자 미감, Galaxy 실기 확인을 구분한다.

산출물: 배경을 포함한 전후 비교판, 수정 대상·이유 목록, 최신 참조 이미지와 원본/전체 프롬프트/등록 정보, 현행 `pixel-production.md`·참조 목록의 보완. 이후 새 자산도 같은 배경+배우 기준에서 출발하게 한다.

## 완료 판단

- 다섯 총기의 실루엣·손 위치·반동/재장전/열기와 UI 표시명이 연결된다.
- 특정 물체만 유독 검거나 촘촘하거나 밝게 보이는 차이가 대표 환경에서 해소된다.
- 캐릭터·적·탄환·공격 예고가 배경에 묻히지 않는다.
- 다른 구역으로 이동해도 동일한 아트 계열로 읽히고, 동작·확대 중에도 그 인상이 유지된다.
- 원화 승인, 본편 적용, 기능 검증, 사람의 화풍 승인 상태를 따로 기록한다.
