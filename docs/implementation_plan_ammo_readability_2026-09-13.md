# 탄환 정보와 초반 학습 흐름 개선 계획

상태: 계획 작성 완료, 구현 전. 기준 `4ec4283` 연계 개편판. 사용자 피드백은 '재미는 있으나 탄환 역할/정확한 스탯 전달이 약하고, HP·방어·회피가 처음부터 등장해 복잡하다'이다. 이번 작업에서는 제품 코드·수치·빌드를 변경하지 않는다.

**지속 작업 제약: APK 제작·갱신·서명·패키징은 사용자가 다시 명시적으로 요청할 때만 수행한다.** 일반 개발/계획/검증에 APK 생성을 자동으로 포함하지 않는다. 기존 APK는 보존한다.

## 진단과 방향

1. 카드에는 역할 문구만 있고 위력/관통/명중은 공용 정보줄·툴팁·정보창에 있다. 여러 탄을 동시에 비교하기 어렵고, 터치에서 상세 확인과 탄창 추가가 가까이 묶여 있다.
2. '파쇄/수확/축전' 같은 이름으로는 기본 공격 성능과 효과를 모두 추정하기 어렵다. 관통은 탄환의 수치, 회피는 적의 수치이며, 현재 화면은 둘 사이의 관계를 충분히 연결하지 않는다. 역할과 수치는 별도 층으로 구분해야 한다.
3. 현행 장갑과 회피는 모두 피해를 감산한다. 관통/균열 또는 명중으로 대응하는 수단은 다르지만, 결과가 같은 '피해 감소'라 초심자가 중복 규칙으로 느낄 수 있다. '회피'가 확률 회피나 완전 빗나감처럼 읽히는 용어 문제도 있다.
4. 시작부터 전술탄9종을 가진 덱10장에서 패5장을 받고, 첫 적부터 시드에 따라 장갑 또는 회피를 만난다. HP 외에도 거리/행동 시간, 관통/명중, 균열/강화, 표적 전환을 배워야 한다. 설명 가독성과 실제 학습량을 함께 줄인다.

권장: HP·거리와 순서 연계를 중심으로 정보 표현/도입 순서를 먼저 개선한다. 장갑은 균열 연계의 주요 기반이므로 유지한다. 회피는 뒤에 도입하며 별도 전략으로 기능하는지 검증한다. 회피 삭제나 피해 공식 재개편을 이번 1차 작업의 전제로 삼지 않는다.

## 1단계 — 탄환끼리 바로 비교하기

- 모든 보유 카드의 같은 위치에 **이름 / 기본 전투 수치 / 한 줄 효과**를 배치한다. 다른 카드에 대한 장문 설명은 동시에 펼치지 않는다.
- 수치는 `위력 5 · 관통 2 · 명중 6`처럼 이름과 숫자를 함께 쓴다. 연속탄은 `위력 2×2`로 타격 수까지 드러낸다. 실제 표시값은 현재 총기/파츠가 반영된 값이며 위 예시는 기본값 예시다.
- 탄환의 `위력→적 HP`, `관통→적 장갑`, `명중→적 회피` 관계를 일관된 아이콘과 용어로 연결한다. 아이콘/색상만으로 의미를 전달하지 않는다.
- 아직 소개하지 않은 축은 실제 초반 전투에서도 작용하지 않게 만든 다음 화면에서 생략한다. 작동하는 규칙을 숫자만 숨기는 방식은 사용하지 않는다. 전체 수치는 선택형 상세에서 언제든 확인할 수 있다.
- 역할은 이름 옆/효과줄에서 `장갑 약화`, `균열 소모`, `2회 공격`, `다음 2발 강화`처럼 표현한다. 하나의 역할로 탄환을 고정 분류해 다른 조합 가능성을 가리지 않는다. 특히 '회피탄'처럼 플레이어가 회피한다고 오해할 이름은 쓰지 않는다.
- 명칭 후보: `수확탄→마무리탄`, `축전탄→강화탄`, `유도탄→조준탄`. 균열탄/파쇄탄은 각각 `장갑 약화`/`균열 소모`를 붙여 구분한다. 최종 이름은 화면에 넣고 역할을 설명할 수 있는지 확인해 정한다.
- 현재 클릭순 장전과 슬롯 회수는 유지한다. 수치 확인을 위해 매 탄마다 확인→추가의 두 번 조작을 강제하지 않는다.

## 2단계 — 예상 피해의 이유 연결하기

- 카드의 기본 수치와 탄창의 실제 예상 결과를 구별한다. 탄창에는 기존처럼 표적과 최종 피해를 표시한다.
- 선택한 슬롯/탄에만 공용 정보 영역에서 짧은 근거를 보여 준다. 예: `위력 5 − 남은 장갑 1 = 피해 4`, `명중 6 < 회피 8 → 피해 −2`. 숫자에 해당 표적 문자도 붙인다.
- 균열/강화가 만든 변화는 `균열로 장갑 3→1`, `강화로 타격당 +2`, `파쇄: 균열 2 소모 → +4`처럼 원인과 결과를 연결한다. 복잡한 계산식은 상세로 보낸다.
- 연속탄의 두 타격, 도약의 다른 표적 고정 피해, 남은 HP에 따른 피해 상한은 구분한다. 첫 표적의 감산 공식을 도약 보조 피해에 잘못 적용하지 않는다.
- 장전 순서를 바꾸면 바뀐 슬롯/표적 HP 예고를 짧게 강조한다. 카드 전체가 계속 번쩍이거나 장문의 조합 로그가 쌓이지 않게 한다.

## 3단계 — 초반에 배우는 규칙을 줄이기

최초 플레이에 적용하는 7교전 도입안이다. 배운 내용은 다음 교전에서도 반복해 사용한다. 매번 긴 튜토리얼을 반복하지 않도록 일반 런/경험자 건너뛰기를 별도로 고려하며, 건너뛰기가 저장된 캠페인의 규칙을 중간에 바꾸지는 않게 한다.

| 구간 | 새로 이해할 내용 | 제시할 상황 |
| --- | --- | --- |
| 1교전 | HP·거리·발사 순서, 다음 탄 강화 | 장갑/회피 감산 없는 적. 기본 공격과 쉬운 강화 연계의 작은 탄환 풀 |
| 2교전 | 장갑과 관통·균열 | 회피 감산 없는 장갑 적. 장갑을 낮추거나 파쇄하는 선택을 보여 줌 |
| 3교전 | 배운 연계를 다른 순서로 활용 | 장갑 규칙을 복습하며 연속 공격 등 선택 폭 확대. 신규 방어 축 없음 |
| 4교전 | 명중과 회피 | 장갑을 겹치지 않은 회피 적. 같은 탄의 명중 보조 전후를 비교 가능하게 구성 |
| 5교전 | 다수 표적·밀기·도약 | 이미 배운 방어 축을 단순 편성에 적용. 표적 전환과 보조 피해 소개 |
| 6~7교전 | 혼합 상황의 자유로운 조합 | 학습한 탄환/적을 섞어 시드별 변화와 빌드 선택 확대 |

- 적 풀만 제한하지 않고 시작 덱과 보상 풀도 같은 도입 단계에 맞춘다. 회피 설명 전에 회피 전용 보조탄을 보상으로 제시하는 식의 역전은 막는다.
- 처음 소개하는 효과는 해당 교전에서 실제 사용할 수 있게 보장한다. 그러나 정해진 탄만 눌러야 통과하도록 강제하지 않고 다른 합법 해법을 남긴다.
- 초반 풀 축소가 덱을 다 받는 상태로 이어져 랜덤성을 다시 지우지 않도록 덱/손패/공급 구성을 함께 조정한다. 첫 학습에서만 제한한 부분과 일반 런에서 변주할 부분을 명확히 구분한다.
- 단발/일제의 비용과 위력이 다르므로 같은 적 수치로 학습 예제가 성립한다고 가정하지 않는다. 두 총기에서 강화/균열 전후의 실제 차이를 확인한 뒤 수치를 정한다.
- 재료 선택의 변주는 배운 범위 안에서만 허용한다. 처음부터 가능한 모든 메커니즘을 무작위로 뽑지 않는다.

## 4단계 — 회피를 별도 축으로 둘 가치 검토

HP는 처치 목표, 장갑은 균열과 연결되는 축으로 유지한다. 가독성과 단계적 도입을 적용해도 회피가 장갑의 반복 계산처럼 느껴지거나 조준 계열 선택 이유를 만들지 못하면, 다음 제한 실험을 한다.

- A: 현행 명중/회피 수치를 뒤늦게 소개하는 방식.
- B: 일반 회피 수치를 없애고 후반 일부 적에게만 공개된 `회피 태세`를 부여한다. 명중 보조탄의 역할도 이 태세에 대한 대응으로 재설계한다. 태세 변화가 있다면 발사 전에 예측 가능해야 하며 확률 실패는 추가하지 않는다.

B는 규칙·탄환·파츠를 함께 바꿔야 하는 후속안이다. 우선순위를 1~3단계와 섞지 않는다. 단순히 숫자 이름만 바꾸는 것과 전략 축을 바꾸는 것을 구분한다.

## 작업 순서와 완료 판단

1. PC 화면에서 카드 공통 수치/역할/명칭 시안 적용. 전투 규칙은 그대로 두고 정보만 개선해 비교한다.
2. 현재 실제 예고 결과에 선택 탄의 감산/강화 근거를 연결한다. 그림·숫자·문장이 같은 의미인지 확인한다.
3. 최초 플레이용 초반 적/덱/보상 도입을 함께 구현한다. 시드 재현성, 교환, 저장/재개, 두 총기 캠페인 경로를 검증한다. 일반 런의 연계/랜덤성을 보존하는지도 별도로 비교한다.
4. 사람에게 처음 본 탄의 역할, 두 탄 중 해당 적에 유리한 것, 순서 변경으로 피해가 달라지는 이유를 설명해 보게 한다. 자주 틀리는 이유를 정보 누락/용어/학습량/규칙 중복으로 구분한다. 상세창을 반복해서 열어야 기본 비교가 되는 상태는 미완료로 본다.
5. 회피의 역할이 여전히 구분되지 않을 때만 A/B 후속안을 검토한다. 자동 검사 통과나 선택률만으로 직관성/재미를 판정하지 않는다.

검증 대상은 수치의 총기/파츠 반영, 다중 타격·보조 피해·균열·스침·처치 상한, 확정 전/후 정보 정합, 초반 도입 범위와 보상 도달성, 화면/터치 크기다. **APK는 요청 전까지 만들지 않는다.** 실제 학습 순서와 명칭은 위 안을 기준으로 화면/플레이 확인을 거쳐 확정한다.
