# 탄환 데이터 v5 마이그레이션 구현 계획

> 작성일: 2026-07-24
> 범위: Phase 12 ③ — 현대 구경 체계는 유지하고 탄환 역할·표기명·데이터 집합을 v5로 교체

## 목표

- 기존 탄환 21종을 역할 기반 27종으로 교체한다.
- CSV와 Godot 리소스가 서로 다른 값을 갖거나, 폐기 ID가 런타임 경로에 남는 상태를 허용하지 않는다.
- 시작 덱과 상점에서 v5 탄환을 실제로 획득할 수 있게 한다.
- 향후 CSV 칼럼 추가가 기존 인덱스를 밀어 조용히 잘못 읽히는 문제를 차단한다.

## 구현 단계

### 1. 데이터 계약 안정화

- `DataLoader._load_bullet_stats()`를 고정 인덱스가 아닌 헤더 이름 기반 파싱으로 전환한다.
- 데이터 검증기도 같은 헤더 계약을 사용한다.
- `id`, `display_name`, `class`, `is_basic`, `role`, 전투 스탯, 효과, 설명문을 필수 칼럼으로 검증한다.
- v5 역할(`standalone`, `setter`, `payload`, `utility`)과 확장 스탯 밴드(DMG 1~9, ACC 2~8)를 명시한다.

### 2. 27종 데이터 집합 교체

- 유지 9종, 기존 12종 교체, 신규 6종으로 최종 27종을 구성한다.
- `bullet_stats.csv`, `docs/handoff/reference/ammo_v5.csv`, `resources/bullets/*.tres`를 동일한 값과 설명문으로 맞춘다.
- 구형 인간 규격 같은 접두 수식은 붙이지 않고 `9×19mm`, `5.56mm`, `12 Gauge` 등 현대 구경 표기를 유지한다.
- 폐기된 12개 리소스 ID는 파일과 런타임 참조에서 제거한다.

### 3. 게임 진입 경로 갱신

- `RunManager.STARTING_AMMO_IDS`에 5개 클래스별 기본탄·셋업탄·페이로드탄을 선언한다.
- 전투 프리로드, 테스트 픽스처, 개발자 전투 진입 경로를 v5 ID로 교체한다.
- `MaintenanceOverlay.SHOP_BULLET_IDS`로 정비 상점 탄환 풀을 명시하고 유효한 리소스만 로드한다.

### 4. 회귀 안전망 추가

- `suite_ammo_integrity`를 전체 테스트 러너에 등록한다.
- 다음 조건을 실패 조건으로 고정한다.
  - CSV 행과 `.tres` 파일이 정확히 27개이며 ID 집합이 양방향 일치
  - 표기명·설명·클래스·전 스탯·효과 값 일치
  - CSV 13개 칼럼과 실제 `DataLoader` 결과가 27종 전부 일치
  - 폐기 ID가 스크립트와 테스트에 남지 않음
  - 5개 시작 덱이 기본탄·셋업탄·페이로드탄을 실제로 로드
  - 정비 상점 풀의 모든 ID가 CSV와 리소스에 존재

### 5. 문서와 관리 기록 동기화

- 탄환 확장 GDD, 콘텐츠 스코프, 마이그레이션 인수인계 문서를 실제 구현과 맞춘다.
- 프로젝트 트래커에서 Phase 12 ③을 완료 처리한다.
- 구현 계획·워크스루·일일 로그·마스터 아카이브에 결과를 기록한다.
