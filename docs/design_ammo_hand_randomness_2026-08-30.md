# 탄환 패 랜덤성·LIFO 조합 재미 구조 실험

> 기록일: 2026-08-30
> 상태: 선택형 A/B 프로토타입 구현 완료 · 사람 플레이 검증 대기
> 변경 원칙: 현행 GDD와 런타임은 프로토타입 A/B 검증 전까지 유지

## 1. 문제 진단

현행 전투는 `draw_pile`을 셔플하더라도 플레이어가 가방의 모든 전술탄을 직접 골라 장전할 수 있다. 적의 해법을 한 번 학습하면 매번 같은 탄환과 같은 순서를 꺼낼 수 있어, LIFO가 반복해서 풀어야 하는 조합 퍼즐보다 이미 아는 정답의 실행 절차로 굳는다.

현재 드래프트의 `획득/교체/건너뛰기`도 덱 희석 비용이 거의 없다. 덱이 커질수록 사용할 수 있는 선택지만 늘기 때문에, 제한된 패에서 최선의 조합을 만드는 덱빌딩의 긴장이 발생하지 않는다.

## 2. 핵심 가설

**입력은 랜덤하게 달라지되, 공개된 뒤의 선택과 전투 결과는 완전히 결정론적이어야 한다.**

```text
런 전술탄 덱
    ↓ seeded draw
공개 탄환 패
    ↓ 플레이어 선택
탄환 일부 선택 + LIFO 순서 설계
    ↓
결정론적 명중·관통·피해·거리 정산
```

목표 감정은 “좋은 탄을 뽑아서 이겼다”가 아니라 **“이번에 주어진 패가 달랐지만 잘 배열해서 이겼다”**이다.

## 3. 권장 1차 프로토타입

아래 수치는 확정 밸런스가 아닌 A/B 실험 시작값이다.

- 시작 전술탄 덱: 10~12발, 최소 3개 전술 역할 포함
- 공개 패: 전투 시작 시 전술탄 7발을 seeded draw
- 장전: 공개 패와 기본 보급탄만 사용해 총기 용량까지 자유롭게 LIFO 배열
- 기본탄: 항상 사용 가능하게 유지하여 무해법 패와 확정 패배 방지
- 유지: 선택하지 않은 탄은 패에 남기고 다음 장전에서 사용 가능
- 보충: 리로드 완료 시 패를 7발까지 다시 뽑음
- 순환: 유효한 전술탄은 현행처럼 버린 더미로 이동 후 순환, 실패한 전술탄은 소멸
- 예고: 리로드 선택 전에 다음 보충 탄환 1~2발을 공개하는 안을 함께 비교

## 4. 절대 유지할 결정론

다음 요소에는 랜덤성을 넣지 않는다.

- 장전 완료 후 탄환 순서
- 명중 여부와 피해량
- 관통·거리·적 행동 결과
- 이미 공개한 적 스탯과 태세 정보
- 대응 수단이 전혀 없는 강제 패배 패

랜덤성은 오직 **결정하기 전에 공개되는 탄환 후보**에만 사용한다.

## 5. 기대되는 구조 변화

- 같은 적도 매 전투 다른 탄환 조합으로 풀게 되어 장전 순서의 반복 고착이 줄어든다.
- 같은 탄을 여러 장 넣는 행위가 해당 탄의 등장 확률을 높이는 명확한 덱빌딩 선택이 된다.
- 탄환을 무조건 추가하면 패가 희석되므로 `획득/교체/건너뛰기`가 실제 갈등이 된다.
- 사용하지 않은 패를 남기는 판단으로 현재 전투와 다음 리로드 사이의 계획이 생긴다.
- LIFO는 랜덤으로 결정되는 것이 아니라, 랜덤하게 받은 재료를 최적화하는 플레이어의 핵심 기술로 강화된다.

## 6. A/B 검증 계획

### A안: 현행

- 전체 전술탄 직접 선택
- 원하는 탄을 매번 같은 순서로 장전 가능

### B안: 탄환 패

- 동일 런 덱에서 공개 패 7발
- 공개 패 + 기본탄으로만 장전
- 미사용 패 유지, 리로드 시 보충

동일한 총기·파츠·적 편성·seed에서 다음을 비교한다.

- 동일 장전 시퀀스 반복률
- 전투별 사용 전문축과 조합 종류
- 기본탄 반복 비율
- 전투당 의미 있는 장전 선택 수
- 무해법 패 발생 여부
- 판단 시간과 장전 피로
- “주어진 패를 풀었다”는 성공감과 재도전 욕구

## 7. 채택 조건

- B안에서 반복 장전 비율이 내려가고 서로 다른 유효 조합이 실제로 나온다.
- 기본탄 보장으로 무해법 패가 발생하지 않는다.
- 승패가 뽑기 운보다 공개 패의 선택·순서 차이로 설명된다.
- 사람 플레이에서 조합 성공감과 재도전 욕구가 증가하고 계산 피로가 허용 범위다.
- 기존 LIFO·거리 압박·결정론적 정산이 유지된다.

채택 조건을 충족하지 못하면 전체 시스템을 교체하지 않고 현행 구조로 복귀한다.

## 8. 다음 세션 시작 지시

1. 현행 전체 덱 접근 경로와 리로드·순환·소멸 계약을 테스트로 고정한다.
2. 프로덕션 규칙을 바로 교체하지 말고 개발자 QA 전용 `탄환 패 A/B` 프로토타입을 만든다.
3. 10~12발 덱·7발 공개 패·기본탄 보장의 무해법 여부를 결정론적 시뮬레이션한다.
4. 자동 지표와 사람 체감이 모두 확보된 뒤 GDD·드래프트·덱 정제 규칙 변경 여부를 확정한다.

## 9. 2026-08-31 구현 결과

- 프로덕션 기본값은 A안(전체 덱 선택)으로 유지했다.
- `CombatManager.configure_ammo_hand_prototype(true, 7, 2)`를 설정한 전투에서만 B안이 활성화된다.
- B안은 combat RNG의 seeded shuffle로 시작 패 7발을 만들고, 미사용 패를 유지하며 리로드 때 부족분만 보충한다.
- 다음 보충 순서 2발을 장전 UI와 QA 공개 상태에 표시한다.
- 기본 보급탄은 패 밖의 고정 선택지로 유지한다.
- 패 밖의 비공개 탄환은 UI와 블랙박스 QA 양쪽에서 선택할 수 없다.
- 플레이테스트 보고서에 초기 패·초기 예고·리로드별 패 전후 상태를 기록한다. 기존 shot 로그와 결합하면 장전 반복률·전문축·기본탄 사용률 비교가 가능하다.
- 개발자 테스트 메뉴에 동일 덱·동일 적·고정 시드 `731042`의 `A · 전체 덱`과 `B · 공개 패 7` 진입점을 추가했다.
- 자동 회귀: 3,618 통과 / 0 실패 / 기존 경보 3.

### A/B 인지성 보강 (2026-08-31 플레이 피드백)

- 문제: B안의 작은 공개 패 문구 외에는 두 안이 같은 전투 UI를 사용해, 규칙 차이가 단순 탄환 수 차이로만 보였다.
- A안은 파란 고정 배너로 `12발 전체에서 매번 원하는 탄을 자유 선택`을 표시한다.
- B안은 노란 고정 배너로 `무작위 공개 패 7발 안에서만 조합`을 표시한다.
- 개발자 메뉴 버튼, 전투 상단 배너, HUD 카운터, 가방 탭, 가방 내부 규칙 설명을 모두 A/B 전용 문구로 분리했다.
- 비교 variant를 QA 공개/오라클 상태와 플레이테스트 보고서에 함께 기록한다.
- 보강 후 자동 회귀: 3,629 통과 / 0 실패 / 기존 경보 3.

## 10. 다음 사람 플레이 절차

1. 개발자 테스트에서 `🅰 탄환 조합 A · 전체 덱`을 3회 플레이한다.
2. 이어서 `🅱 탄환 조합 B · 공개 패 7`을 3회 플레이한다.
3. 매 판 다음 네 항목을 1~5점으로 기록한다: 조합 고민, 성공감, 반복감, 장전 피로.
4. B안에서 패가 나빠서 진 것이 아니라 순서 선택 때문에 졌다고 납득되는지 별도로 적는다.
5. 다음 2발 예고가 리로드 계획에 실제로 쓰였는지 확인한다.
6. 사람 체감과 저장된 보고서를 함께 비교한 뒤에만 정식 규칙 채택 여부를 결정한다.

## 11. 2026-09-01 랜덤 체감·탄환 가독성 1차 구현

- 재현용 `B 공개 패 · 고정 비교`와 실행마다 신규 시드를 쓰는 `B 체감 · 매번 새 패`를 별도 진입점으로 분리했다.
- 첫 패 셔플·공개, 리로드 시 미사용 유지/신규 보충, 버린 전술탄 재혼합을 서로 다른 화면 상태로 표현한다.
- 공개 패 헤더에 공개·미공개·다음 보충 수를 표시하고, 다음 2발은 개별 탄환 칩으로 보여준다.
- 카드에는 4전문축의 한국어 역할명·기호, 역할별 핵심 결과 문장, 효과의 발동 조건→결과, 현재 대상 명중/관통 여부를 우선 표시한다.
- 기존 탄환 이미지를 48px 이상 주 이미지로 승격했으며, 전투 수치·공개 패 크기·결정론적 LIFO는 그대로 유지했다.
- 자동 회귀는 **3,655 통과 / 0 실패 / 기존 경보 3**이다. 정식 B안 채택 여부와 신규 탄환 이미지 제작 여부는 사람 플레이 결과 뒤에 판단한다.
