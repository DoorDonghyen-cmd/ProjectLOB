# 거시 UI/UX 구조 개편 계획

## 목표

전투, 지도, 보상, 상점, 빌드 편집이 서로 다른 목적과 화면 위계를 갖도록 재구성한다. 플레이어가 어느 화면에서 무엇을 결정해야 하는지 첫 시선에 알 수 있고, 모바일 가로 화면에서 핵심 행동이 긴 스크롤 아래로 밀리지 않게 한다.

## 화면 역할

- 지도: 런의 중심 화면. 건물 단면과 다음 목적지 확정에 집중한다.
- 전투: 전장과 탄환 순서 설계에 집중한다. 상단 정보와 보조 메뉴를 하나의 전투 헤더로 묶는다.
- 보상: 전투 결과 뒤 하나를 고르는 독립 선택 장면으로 만든다.
- 상점: 상품 비교와 구매에 집중한다. 장착과 보관함 편집은 빌드 작업실로 이동한다.
- 빌드 작업실: 덱, 장착 파츠, 보관함을 관리하는 전체 화면 작업 공간으로 만든다.
- 기록실과 설정: 진행을 방해하지 않는 보조 팝업으로 유지한다.

## 구현 순서

1. 도시 공통 상태 카드 여섯 개를 압축된 런 헤더 하나로 교체한다.
2. 덱·장비 팝업을 배경을 완전히 덮는 전체 화면 빌드 작업실로 전환한다.
3. 상점에서 장착 작업대 중복을 제거하고 빌드 작업실 진입 버튼을 둔다.
4. 지도 선택부를 하나의 목적지 시트와 단일 확정 행동으로 정리한다.
5. 보상 화면을 세 개의 동등한 선택 카드가 중심이 되는 구조로 정리한다.
6. 전투의 위치·상태·보조 메뉴를 하나의 전투 헤더로 통합한다.
7. 자동 UI 시나리오와 실제 렌더링 캠페인 재생으로 데스크톱 및 모바일 가로 레이아웃을 검증한다.

## 완료 기준

- 도시 화면마다 여섯 개의 큰 공통 상태 카드가 반복되지 않는다.
- 빌드 작업실은 `AcceptDialog`가 아닌 전체 화면 공간으로 열린다.
- 상점 본문에는 상품, 비교, 압축 코어만 남고 파츠 보관함은 중복 노출되지 않는다.
- 지도에서 노드 선택 후 하나의 명확한 확정 버튼으로 이동한다.
- 전투·보상·상점·빌드 화면의 제목, 색, 주 행동 위치가 구분된다.
- 기존 캠페인 기능과 저장 흐름이 회귀하지 않는다.
