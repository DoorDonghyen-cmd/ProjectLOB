# QA 리포트 계약

## 목차

1. 입력 계약
2. 결과 분류
3. 중요도
4. 통합 규칙

## 1. 입력 계약

모든 보고서에 다음 값을 기록한다.

- QA session ID
- Git commit과 dirty worktree 여부
- 테스트 모드와 범위
- QA 전용 사용자 데이터 경로
- 고정 시나리오 또는 gameplay seed
- 사용한 플레이 프로필
- 허용된 기존 이슈

## 2. 결과 분류

- `PASS`: 기대 결과와 일치하고 증거가 있다.
- `FAIL`: 같은 상태와 행동으로 재현되는 기능 결함이다.
- `INFRA`: 브리지, 실행 환경, 캡처 등 QA 장비의 문제다.
- `SIGNAL`: 재미·UX 문제 가능성이 있으나 기능 결함으로 확정하지 않는다.
- `BLOCKED`: 필요한 빌드나 상태가 없어 검증하지 못했다.

## 3. 중요도

- `높음`: 크래시, 데이터 손실, 진행 불가, 코어 전투 규칙 위반
- `보통`: 주요 기능 오동작, 반복 오입력, 의미 있는 선택을 무효화하는 UI
- `낮음`: 우회 가능한 표기, 정렬, 연출 문제

## 4. 통합 규칙

- 원본 보고서를 요약하기 전에 보존한다.
- 동일 재현 경로는 하나의 항목으로 합치고 발견 역할을 모두 기록한다.
- 기능 QA와 시뮬레이터가 다르면 실제 `CombatManager` 결과를 재실행한다.
- 경험 신호가 둘 이상의 독립 역할 또는 세 프로필에서 반복되면 `강한 신호`로 올린다.
- 단일 관찰은 `가설`, 촉감·피로도는 `인간 확인`으로 남긴다.
- 확정 버그에는 재현 단계, 기대 결과, 실제 결과, artifact 경로가 모두 있어야 한다.
