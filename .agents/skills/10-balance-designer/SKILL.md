# 10-balance-designer

[현재 프로젝트](../../CURRENT_PROJECT.md)에서 활성 저장소를 확인한다. 아래 문서 경로는 스킬 사본의 위치가 아니라 **활성 저장소 기준**이다.

## 참조와 작업 범위

- `docs/direction/current.md`에서 사용자 확정·디렉터 결정·구현·가설을 구분하고 이번에 바꿀 선택과 유지할 경험을 확인한다.
- 비교를 설계할 때 `docs/direction/development-workflow.md`의 **밸런스 판단과 비교 단위** 및 변경 영향 기준을 읽는다. 실제 계산은 Godot 프로젝트의 `redesign/content.gd`, `redesign/model.gd`, `redesign/campaign_content.gd`, `redesign/campaign.gd`와 해당 기능 문서에서 확인한다.
- 방법의 근거나 외부 자료가 필요하면 `docs/history/research/balance-methods-2026-11-06.md`에서 원문·적용 한계를 확인한다. 자료의 예제 수치나 도구를 현재 게임의 규칙·필수 의존성으로 만들지 않는다.

## 분석과 비교

- 현재 피해 계산과 행동 단위를 재사용한다. 발사한 탄 수·타격 횟수·적 행동 수를 구분하고 이전 CSV·구경·명중/회피 공식을 가져오지 않는다.
- 효과와 비용을 탄약·발열·점유·발사 위치·행동·다른 성장 기회로 분해한다. 합성/강화는 소모한 **전체 원본 묶음**과 결과를 비교한다. 지원·지속·광역 효과를 피해 점수로 환산할 때는 상황과 가정을 명시한다.
- 무기별 발사/재장전 주기, 파츠 발동, 적 수/장갑/증원과 접촉 시한을 함께 본다. 변경 영향에 맞는 대표 상황을 골라 처치선·오버킬·대응 여유·강제 중단·잔탄/비상 보급을 관측한다.
- 성장이나 보상을 바꾸면 같은 실제 획득 상태를 복제해 변경·유지·다른 소비 선택을 비교한다. 사격·냉각·교체·탄 포기와 이후 전투/보급까지의 영향을 확인하고, 대표 픽스처와 자연 획득 경로의 근거를 구분한다.
- 큰 피해를 내는 완성 조합은 조립/획득 조건·기회비용·대응 범위와 함께 평가한다. 쉽게 반복되어 다른 선택을 가리는 조합인지 살피며 모든 항목의 사용률·승률을 같게 맞추거나 모든 파츠에 같은 패널티를 붙이지 않는다.
- 경제는 획득량·소비처·가격·반복 구매·건너뛰기를 연결한다. 상점 없는 비교판이나 가까운 전투만의 결과를 전체 여정 경제의 결론으로 확장하지 않는다.

## 검증과 판단

- 자동 실험에서는 공개 정보로 행동하는 정책과 미래 드로/난수를 아는 탐색을 분리한다. 사용한 정보·정책·탐색 범위를 남기고 자동 정책의 성과를 사람의 숙련도나 승률로 부르지 않는다.
- 무작위 표적은 분포/범위와 여러 시드로 확인한다. 선택 지표는 제시·선택·거절을 구분하고 획득 시점·빌드·조우 맥락과 표본 수를 함께 기록한다. 보유 카드의 승률만으로 그 카드의 인과적 강함을 단정하지 않는다.
- 불법 명령·계산/저장 불일치 같은 기능 결함과 특정 정책의 패배·탐색 미해결을 구분한다. 탐색에서 경로를 못 찾았다는 이유로 승리가 불가능하다고 하지 않는다. 실패 분류를 수정할 때는 원본 증거와 근거를 보존하며 기능 오류를 관측값으로 숨기지 않는다.
- 강한 효과의 대가가 실제 선택을 바꾸는지, 사용/구매/강화를 하지 않을 합리적 이유도 남는지 평가한다. 자동 통과·평균 피해·특정 시드 완주만으로 최종 균형이나 재미를 확정하지 않는다. 효과의 역할이 없으면 수치 보정 외에 역할 변경/제거도 검토한다.
- 수치의 단일 원본은 현재 콘텐츠 데이터다. 현재 결정은 `docs/direction/`, 변경·원본 결과·미검증 범위는 `docs/history/`와 QA 기록에 둔다. 스킬에 날짜별 실험 로그·수치표·특정 무기 목록을 복제하지 않는다.
