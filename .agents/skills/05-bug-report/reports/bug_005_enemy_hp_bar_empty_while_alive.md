# 🐛 [버그 리포트] #005. 생존 몬스터의 HP 바가 피격 후 빈 상태로 표시됨

## 1. 개요 (Overview)

- **제보 일시**: 2026-07-26
- **상태**: `Closed`
- **중요도**: `보통`
- **관련 컴포넌트**: 전투 UI / 적 런타임 데이터

## 2. 현상 설명 (Description)

- 탄환이 적중한 뒤 몬스터의 실제 HP는 1 이상으로 생존해 있지만, 머리 위 HP 바의 채움 영역이 비어 있는 것처럼 표시된다.

## 3. 재현 경로 (Steps to Reproduce)

1. 일반 HP를 사용하는 몬스터와 전투를 시작한다.
2. 몬스터가 죽지 않을 정도의 피해를 입힌다.
3. 실제 `current_hp > 0` 상태에서 머리 위 HP 바의 채움 폭을 확인한다.

## 4. 원인 분석 (Root Cause)

- 수동으로 폭을 조절하는 `HpFill`이 `PanelContainer`의 직접 자식이었다.
- `PanelContainer`는 자식 Control의 크기를 자동 재배치하므로, 피격 시 `_refresh_hp_bar()`가 계산한 `offset_right`와 컨테이너 레이아웃이 같은 폭을 서로 갱신하는 구조였다.
- HP 비율의 분모도 CSV 동기화 전 원본 `.tres`의 `data.max_hp`를 사용해, 일부 적은 런타임 HP와 표시 기준이 달랐다.

## 5. 해결 방안 (Resolution)

- HP 배경을 자동 자식 배치가 없는 `Panel`로 교체하고 76×9px 크기를 명시했다.
- `HpFill` 폭은 `_refresh_hp_bar()`만 관리하도록 단일화했다.
- `EnemyInstance.max_hp`에 CSV 동기화 결과를 보존하고 HP 바가 해당 런타임 최댓값을 사용하도록 변경했다.
- 최종 보스 2페이즈 전환 시에도 `max_hp = phase2_hp`로 함께 갱신한다.

## 6. 검증 내용 (Verification)

- UI 스모크에서 HP 50%가 정확히 절반 폭(`offset_right = -38`)으로 갱신됨을 확인했다.
- HP 1 생존 상태에서 채움 막대가 완전히 사라지지 않고 9px 폭을 유지했다.
- HP 배경이 `Container`가 아니며 자식 폭을 자동 재배치하지 않음을 검증했다.
- 전체 자동 테스트 **2,543 통과 / 0 실패**, 전 스크립트 컴파일 및 4개 씬 로드 성공.
