# 🐛 [버그 리포트] #004. 보스 차징 카운터가 실전 전투에서 진행되지 않음

## 1. 개요 (Overview)

- **제보 일시**: 2026-07-26
- **상태**: `Closed`
- **중요도**: `높음`
- **관련 컴포넌트**: 세라프 프로토콜, L.O.B 코어, 적 전진·차징 정산

## 2. 현상 설명 (Description)

- 세라프와 L.O.B 코어가 차징 기믹을 보유했지만 실제 전투에서는 차징 카운터가 증가하지 않았다.
- 결과적으로 GDD에 명시된 4턴/3턴 포격과 호위 대열 2m 강제전진이 전혀 발동하지 않았다.

## 3. 재현 경로 (Steps to Reproduce)

1. 개발자 테스트에서 세라프 또는 L.O.B 코어 보스전을 시작한다.
2. 적 전진 턴을 각각 4회 또는 3회 진행한다.
3. 보스의 차징 카운터가 증가하지 않고 포격도 발동하지 않는다.

## 4. 원인 분석 (Root Cause)

- `EnemyInstance`는 두 보스에 `is_charger = true`를 설정했다.
- 그러나 `CombatManager._all_enemies_advance()`는 아키타입이 정확히 `CASTER`인 경우에만
  `advance_charger()`를 호출했다.
- 보스 아키타입은 `BOSS_CASTER_SPONGE`와 `BOSS_FINAL`이므로 차징 분기에 진입할 수 없었다.
- 이 분기만 단순 확장할 경우 강제전진 함수가 보스 자신도 호위로 취급해 2m 이동시키는 2차 결함도 있었다.

## 5. 해결 방안 (Resolution)

- 이동 정산과 차징 정산을 분리하고 런타임 `is_charger` 플래그로 차징을 판정하도록 변경했다.
- L.O.B 코어 페이즈 2는 SPD 1 전진과 3턴 차징을 동시에 수행한다.
- 포격 강제전진 대상에서 차저를 제외해 세라프와 코어 자신은 이동하지 않도록 했다.

## 6. 검증 내용 (Verification)

- 실제 `CombatManager` 편성으로 세라프 4턴, L.O.B 코어 3턴 차징과 호위 2m 강제전진을 검증했다.
- L.O.B 코어 페이즈 2의 동시 전진·차징을 별도 회귀로 고정했다.
- Godot 전체 자동 검증 결과: **2,460 통과 / 0 실패**.
