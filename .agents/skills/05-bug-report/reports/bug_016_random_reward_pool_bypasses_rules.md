# 🐛 [버그 리포트] #016. 무작위 보상 풀이 보류·고유 항목을 우회하고 암시장 결제가 소실될 수 있음

## 1. 개요 (Overview)
*   **제보 일시**: 2026-08-05
*   **상태**: `Verified`
*   **중요도**: `높음`
*   **관련 컴포넌트**: 스타팅 보너스, 암시장 이벤트, 가방, 아이템 풀

## 2. 현상 설명 (Description)
*   "무작위 1티어 파츠" 스타팅 보너스가 실제로는 파츠 디렉터리의 전 리소스를 후보로 사용하여 2~5티어, 총기 고유 파츠, 기능 보류 중인 컨버전 킷까지 지급할 수 있다.
*   암시장도 같은 방식으로 전 파츠를 추첨하며, 탄환은 고정 보급용 기본탄과 현재 총기 비호환 탄까지 후보에 포함한다.
*   암시장 파츠 구매는 크레딧을 먼저 차감하고 `add_to_backpack()`의 실패 반환을 무시하므로 가방이 가득 차면 보상 없이 결제만 소실될 수 있다.
*   스타팅 보증은 준비 화면에서 크레딧·가방에 즉시 지급하지만, 이후 `start_new_run()`이 두 값을 초기화하므로 실제 런에 보상이 전달되지 않는다.

## 3. 재현 경로 (Steps to Reproduce)
1. 스타팅 보너스에서 "무작위 1티어 파츠"를 반복 선택하거나 후보 풀을 검사한다.
2. 1티어가 아닌 파츠 또는 `CONVERSION_KITS_ENABLED=false`인 컨버전 킷이 후보에 포함됨을 확인한다.
3. 가방을 가득 채운 뒤 암시장 파츠 밀수를 구매한다.
4. 30 Cr가 차감되지만 파츠가 가방에 추가되지 않는 경우를 확인한다.
5. 준비 화면에서 스타팅 보증을 선택하고 런을 시작한다.
6. 선택한 50 Cr 또는 파츠가 런 초기화 후 사라지는 것을 확인한다.

## 4. 원인 분석 (Root Cause)
*   두 경로 모두 정식 상점의 `SHOP_GENERAL_PART_PATHS`, 호환 탄 목록, 컨버전 기능 플래그를 재사용하지 않고 `resources/parts` 또는 `resources/bullets` 디렉터리를 직접 전수 로드한다.
*   암시장 구매 콜백은 수용 가능 여부를 결제 전에 검사하지 않고 지급 실패도 처리하지 않는다.
*   스타팅 보증 지급 시점이 런 초기화보다 앞서 있어, 지급 상태가 초기화 대상과 함께 제거된다.

## 5. 해결 방안 (Resolution)
*   `ItemCatalog`를 추가해 일반 파츠 20종과 공용 전술탄 14종을 획득 경로 공통 정본으로 분리했다. 고유 파츠·비활성 컨버전 킷·기본 보급탄·총기 비호환 탄은 후보에서 제외한다.
*   스타팅 파츠 보너스는 정본의 1티어 일반 파츠만 추첨하고, 크레딧/파츠 선택을 대기 상태로 기록한 뒤 `start_new_run()` 초기화 이후 한 번만 적용한다.
*   암시장은 보유 중복 파츠를 제외하고 가방 포화 시 구매 버튼을 막는다. 지급 실패 시에는 차감한 크레딧을 전액 환불한다.

## 6. 검증 내용 (Verification)
*   `suite_campaign_integrity`에서 1티어 파츠 풀, 컨버전 제외, 전술탄 호환성·기본탄 제외, 스타팅 보너스 초기화 이후 1회 지급, 가방 포화 무결제, 암시장 정상 구매를 회귀 고정했다.
*   Godot 4.7 전체 자동 검증 **2,718 통과 / 0 실패 / 기존 경보 3**.
*   80개 스크립트 컴파일 및 4개 씬 로드 성공.
